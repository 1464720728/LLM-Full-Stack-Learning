# R01 从“找一段文字”到可验证的知识系统

本章先修是 Python 的列表、字典、函数、文件，以及“调用模型并不等于调用数据库”的认识。全部实验在普通 CPU 上完成，不需要模型 API、显卡或联网。完成后，你应能给一个问答错误定位到语料、检索、上下文、生成或引用，而不再笼统地说“模型不够聪明”。

## 1. 先把问题拆成可以检查的对象

设想有一本维修手册。别人问“更换过滤器前要做什么”，你不是凭记忆说出最像答案的话，而是先定位“更换过滤器”一节，再阅读前置步骤，最后指出答案来自哪一页。这个过程至少产生三样东西：搜索条件、候选证据、最终陈述。它们不能用一个字符串糊在一起。

语料 corpus 是系统允许搜索的材料集合；文档 document 是具有独立身份和版本的一份材料；片段 chunk 是用于搜索或放进上下文的较小内容；查询 query 是本次需求的表达；候选 hit 是某个片段和检索分数的组合；陈述 claim 是答案里可以判断真假的一句话；引用 citation 是把陈述连接到可复查证据的指针。

“有引用”不等于“正确”。某页真实存在，但可能根本不支持这句话；原文确实写了这句话，但原文本身可能过时或错误；某个文件相关，但当前用户可能无权读取它。因此系统要分别检查**可访问、可定位、可支持、可采用**。前三项都通过也不能自动保证第四项：例如过期制度对历史研究有用，对今日操作可能不适用。

一个最小的处理顺序是：确定调用者与范围，取得当前可见材料，计算相关程度，选择可承受的证据集合，把它们交给回答器，再检查输出能否回到来源。后面所有复杂技术，包括向量库、知识图谱、Agentic RAG，都可以放回这条顺序检查。

## 2. 为何“相似”不是“答案”

查询“哪些配置会增加 KV cache 显存”与文档“减少 KV cache 显存的方法”共享大量词，却可能包含方向相反的操作。“H100 上能运行吗”与“B200 上能运行吗”只差一个设备名，但该差异可能决定整个答案。检索算法通常只给候选排序，不承担最终事实判断。

把相关性看成一个针对任务的关系，而非文档的固有属性：同一篇论文对“谁首次提出”可能高度相关，对“生产系统怎么配置”则可能不够直接。标注集必须先声明任务。如果标注者把“提到问题名词”和“足以回答问题”混为一谈，再精确的指标也会把系统带向错误方向。

本卷使用一个完全虚构的小语料：KV cache、调度器、Agent、检索、依赖图、版本策略和一份受限资料。它没有真实公司材料，规模小到你可以逐行检查。小规模的价值在于可解释，不在于代表生产精度。后面用这套可观察系统理解机制，再迁移到真实框架和数据。

## 3. 手算一条问答链

假设数据库有三个片段：A 写“缓存保存 K 和 V”；B 写“调度器选择批次”；C 写“缓存可以复用过去 token 的计算状态”。查询为“缓存复用什么”。词法检索可能先给 C、再给 A。上下文预算只能容纳一个片段，于是回答器只看到 C。如果最终回答“缓存保存 K 和 V”，这个陈述可能常识上正确，但**不是由这次提供的 C 直接支持的**。审计时要把参数知识和当次证据分开。

再假设 C 只有管理员能读。正确系统先把 C 排除，之后 A 才参与排序。错误系统先从全部材料选择 top-1=C，再删除不可见项，结果为空。虽然没有直接展示 C，这个算法仍把管理员材料的存在影响到了普通用户结果，且损害召回。因此权限不仅是最终输出的格式过滤器，还是候选构造的约束。

如果文档 C 被更新为“此功能现已停用”，缓存中的旧片段还能被回答器引用，就形成新旧状态不一致。引用必须包含文档版本或不可变的片段身份，而不能只是一个可能指向新内容的文件名。

## 4. 阅读代码时先找数据结构

打开 `labs/knowledge/store.py`，先阅读 `Context` 和 `Chunk`，不要立即追踪 SQL。`Context` 携带租户、用户和组；`Chunk` 携带片段 ID、文档 ID、版本、来源、字符区间和原文。`frozen=True` 使 dataclass 实例不能随意改字段，帮助我们把某次检索到的片段当成快照。它并不让数据库不可变，也不解决进程间的并发问题。

然后打开 `retrieval.py` 中的 `Hit`。`score` 是排序依据，而不是事实概率。BM25 分数、余弦相似度和 RRF 分数各自有不同定义，不能因为都叫 score 就相加。再打开 `rag.py`：`Claim` 与 `Citation` 是不同对象，后者指向片段并保存引文。这个拆分允许检测“来源真的有，但回答歪曲了它”。

`answer_report` 是本卷的严格抽取式回答器：只返回当前可见来源里的原文字段，不让一个生成模型自由改写。这是刻意缩小能力边界以检查证据流，不能把它宣传成完整智能问答。它能告诉你检索是否工作；它不能充分理解中文否定、跨句推理或自然语言意图。

## 6. 故障定位方法

出现“回答不对”时，按以下顺序抓取中间产物。先打印文档是否进入数据库，再打印当前用户可见的 chunk 数量，再打印查询词元，再打印全部候选分数和 top-k，再打印真正交给回答器的上下文，最后检查陈述与引文。任何前一层为空，都不应优先调模型温度。

如果检索能找到证据而答案没有使用，检查上下文打包是否超限、重复片段是否挤占空间、回答器是否遵守引用契约。如果某次更新后旧答案仍出现，检查检索索引、缓存、图边、摘要和历史答案是否都记录来源版本。单看数据库最新行不足以证明整个系统已更新。

日志应保留可复查 ID 和版本；敏感文本不应无条件进入通用日志。课程可以打印虚构原文，实际部署时要区分调试日志与业务数据访问权限。

## 7. 练习与完整参考答案

**练习 1：术语归类。** 将“手册第 3 版”“第 100–280 个字符”“相似度 0.82”“停机后再更换”分别归到对象。答案：文档版本、片段区间、候选分数、陈述。分数不能替代支持该陈述的证据。

**练习 2：追踪空结果。** 查询未知词返回空数组，是否说明数据库为空？答案：不说明。运行 `store.counts()` 检查材料存在，再运行 `store.visible(ctx)` 检查可见性，最后检查 tokenizer 和评分。本实现只保留正分候选，未知词的所有分数为零。

**练习 3：实现来源集合检查。** 编写函数确认答案每个 `chunk_id` 都属于给定上下文。完整解如下：

```python
def sources_in_context(claims, context_entries):
    allowed = {entry["source_id"] for entry in context_entries}
    return all(claim.citation.chunk_id in allowed for claim in claims)
```

验收：空答案返回 True；一个伪造 ID 返回 False。True 只说明 ID 属于上下文，还要检查引文和语义支持，不能命名为 `answer_is_true`。

**练习 4：构造相关但不支持。** 写两句只差否定词的文档，提出同一个问题。参考解：“系统支持热更新”与“系统不支持热更新”。词法重叠可以很高，正确性相反。若将后一条引用在肯定答案后，应判为不支持，而不是“有来源所以通过”。

**练习 5：设计最小回归集。** 至少包含可回答、无答案、越权、旧版本、同名实体五类。参考验收表分别是：能找到标注来源；明确拒答；不可见资料不进入候选；旧引用失效；必须带实体 ID 或澄清。每类先写两例，形成十例人工可核验数据，不急着增加到几万条。

**掌握门槛：** 不看笔记画出一次问答的数据对象与检查点；能解释“引用存在”“引文匹配”“来源支持”“来源真实”四者的差别；能用中间结果定位一例失败。未完成这些要求时，先不要用更复杂的框架掩盖问题。

本章的历史入口是 [RAG 原始论文](https://arxiv.org/abs/2005.11401)；论文中的联合训练模型与今天工程上泛称的检索加生成流水线并非完全同一个实现。工程原则与本卷实验为独立教学设计。
