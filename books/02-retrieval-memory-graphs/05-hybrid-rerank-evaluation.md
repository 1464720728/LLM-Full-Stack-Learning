# R05 混合检索、重排与评价：让改进有可测依据

先修：BM25、向量相似度、Python 排序。完成本章后，你应能写 RRF、解释两阶段检索的性能边界、手算常用排名指标，并避免“挑几条成功案例”式评估。

## 小课一：先把召回、重排和选择分成三个问题

第一阶段召回的目标是从大语料中尽量找出可能有用的候选，通常宁愿保留一些噪声，也不愿过早漏掉关键资料。第二阶段重排的目标是在有限候选里更细地判断与问题的关系。第三阶段上下文选择则考虑预算、重复和覆盖，把真正适合送给模型的证据组合起来。这三件事相关，但不能由一个 top-k 参数替代。

例如问题要求比较两个配置。召回器找到十条材料，其中八条讲配置甲，两条讲配置乙；重排器可能把甲的八条都排在前面，因为它们的措辞与查询更接近；若直接取前三，最终上下文没有乙，比较任务无法完成。此时不是“相关性排序错得一无是处”，而是选择阶段还需要覆盖两侧证据。理解这个例子以后，再看 MMR 或多样性约束，就知道它们在解决什么。

候选数和最终上下文条数也应分开。BM25 可以先取二十条，向量检索取二十条，融合去重后得到三十条，重排后保留十条，再按 token 预算选择四条。每一步都可能丢失正确证据，因此应记录它在哪一阶段消失。只看最终回答失败，无法知道该增加召回预算、改重排器还是改打包策略。

本章先用完全可手算的列表理解融合，再用小函数计算指标。真正模型重排放在清楚的接口位置，并明确成本与输入限制。你不需要先拥有一个强大的神经模型，才能学会设计正确的候选数据结构、评价合同和消融实验。

## 小课二：为什么两个分数不能随意相加

BM25 分数可以大于一，余弦通常在负一到一之间，神经重排器可能输出未归一化 logit。它们的数值大小来自不同定义。把 BM25 的五分与余弦的零点八直接相加，实际上隐含地让前者占更大数值尺度；这不等于前者更可信，也不等于你有意选择了合理权重。

可以先做归一化再加权，但归一化方式也有假设。每个查询内的 min-max 会把最高分映射到一、最低分到零，即使这个查询的所有候选都很差，也会产生一个看起来满分的第一名。z-score 依赖均值与标准差，小候选集或极端分数可能使结果不稳定。学习到的标定需要独立数据，不能在测试集上调到最好后再报告同一测试分数。

排名融合绕过了一部分尺度问题：只看一个文档在各列表排第几，不直接使用原始分数。这会丢失“第一名远远领先第二名”之类信息，但换来更简单的跨检索器组合。它是一种取舍，不是所有情况下都最优。你应保留原始分数和名次，才能在融合后分析到底发生了什么。

若两个检索器实际上使用几乎相同的词法信息，例如 BM25 与 TF-IDF，它们的错误可能高度相关。融合两份相似列表并不会自动获得“多模态证据”。课程把这对组合作为接口教学基线，真实语义互补要用真正的 dense encoder 和任务评测证明。不能因为函数名叫 hybrid 就认为系统已经具备词法与语义双重能力。

## 小课三：逐项手算 RRF

RRF 为每个列表中的文档按名次贡献一个倒数项。某文档在第 r 名，贡献为一除以 c 加 r；c 是平滑名次差异的常数。一个文档在多个列表出现，就把各路贡献相加；没有出现的列表不贡献。原始论文曾在其研究设置中使用六十，但这不是所有任务必须遵守的自然常数。

设词法列表为 A、B、C，向量列表为 B、C、A，c 为六十。A 得到一除以六十一加一除以六十三，约零点零三二二六六；B 得到一除以六十二加一除以六十一，约零点零三二五二二；C 得到一除以六十三加一除以六十二，约零点零三二零零二。最终 B 第一、A 第二、C 第三。

这个结果为什么合理？B 在两路中分别排第二和第一，整体支持较强；A 虽然在一路第一，另一路第三；C 在两路都不是第一。RRF 不需要知道 BM25 的五分能否与余弦零点八比较，只需要名次。与此同时，如果某一路第一名的原始优势特别大，RRF 也不会自动保留这个幅度信息，这是它明确舍弃的部分。

```python
from collections import defaultdict

def reciprocal_rank_fusion(rankings, constant=60, top_k=5):
    if constant < 0 or top_k < 0:
        raise ValueError("nonnegative parameters required")
    totals = defaultdict(float)
    for ranking in rankings:
        unique = list(dict.fromkeys(ranking))
        for rank, identifier in enumerate(unique, start=1):
            totals[identifier] += 1/(constant+rank)
    return sorted(totals.items(), key=lambda item: (-item[1], item[0]))[:top_k]

result = reciprocal_rank_fusion([["A","B","C"],["B","C","A"]])
assert [identifier for identifier, _ in result] == ["B","A","C"]
```

这里先对每一路列表去重，并重新压紧名次。仓库参考 `rrf` 会跳过重复 ID 的额外贡献，但遍历名次仍来自原列表位置；正常检索器本来应返回唯一候选，因此常规输入下两者一致。若接入可能重复的外部检索器，要明确是否先规范化列表，避免重复项虽然不加分，却把后续名次向后推。接口的脏数据策略也属于融合算法的实际行为。

当 c 很小时，靠前名次的优势更突出。例如 c 为零，第一名贡献一，第二名二分之一，第三名三分之一。c 很大时，相邻名次贡献更接近，来自多路的重复支持相对更重要。参数调节应在验证集上做，并保留每题变化；不能看到一个例子里六十效果好，就认为其他值都不值得研究。

## 小课四：融合身份必须统一到什么粒度

若词法检索返回文档 ID，向量检索返回片段 ID，你不能直接把字符串放进同一个 RRF 字典。两个列表的候选单位不同。必须决定是把片段聚合成文档，还是让词法也在相同片段上检索，或者明确建立父子映射。否则看起来来自两路的同一材料可能被当成两个候选，真正不同的材料也可能被错误合并。

版本同样要参与身份。旧版文档片段与新版片段不能因为 doc_id 相同就被当成完全相同的证据。课程使用带版本绑定的 chunk_id，融合时以它为键；回答前仍然复查当前有效性。如果某一路索引落后，融合层应该标记或过滤过期候选，而不是让旧版高分覆盖新版来源。

重复内容还不等于独立来源。一个公告被十个网站转载，十份向量命中并不自动构成十个独立证据。对于事实核验，需要来源去重或至少保留转载关系；对于普通资料问答，也要避免重复段落耗尽上下文。融合候选身份与证据独立性是两种不同概念，前者可以靠稳定 ID 处理，后者通常需要更丰富的来源关系。

你可以为每个候选保存一张 provenance 表：来自哪些检索器、各自排名和分数、对应哪个文档版本、是否与其他候选共享来源。这样最终排序发生变化时，你可以解释是哪个分支加入了它，而不是只能看到一个失去来源的总分。可解释的数据结构会显著降低混合系统的调试成本。

## 小课五：重排器为什么能看见更多关系

双编码器预先分别编码查询和文档，比较时通常只做向量相似度；cross-encoder 则把查询与候选一起输入模型，让模型在共同上下文中判断相关性。它可以利用更细的词序、条件和匹配关系，但每个查询候选对都需要额外计算，不能像预编码文档那样把大部分工作提前完成。

假设召回一百个候选，每个候选都需要一次联合编码。即使批量处理，计算成本也随着候选数与输入长度增加。因此重排通常放在较小候选集上，而不是对整个百万文档库逐一执行。这个分工不是因为联合编码器只会处理少量文档，而是为了在质量与计算预算之间取得可用平衡。

重排输入也会被截断。若问题关键条件位于候选尾部，模型只看到开头，就可能错误判断相关性。接入时应记录查询与文档如何拼接、最大长度、截断方向以及是否按段落拆分。一个返回单一分数的接口隐藏了这些步骤，不代表它们不影响结果。

重排分数通常仍不是事实正确概率。模型可能判断“这段文字与问题很相关”，但文字本身可能是错误说明或反例。对于否定、版本、数字和条件，应建立专门测试。把重排器加入系统以后，仍然需要证据支持与来源验证，不能把所有后续责任合并成“reranker 已经检查过”。

课程的 `lexical_rerank` 仅计算查询词覆盖率，并给完整短语出现额外加分。它没有联合神经编码能力。阅读时先把覆盖率的分子和分母写出来：命中的独特查询词数量除以独特查询词总数，再加短语指示项。你可以用它透明地学习重排接口，再在相同候选和标签上比较真实 cross-encoder，清楚看到能力差别。

## 小课六：MMR 为什么可能选择分数稍低的材料

如果前三条候选都重复同一句解释，用户得到的信息可能少于“前两条相关解释加一条补充条件”。MMR 在每一步选择时同时考虑与查询的相关性，以及与已经选中材料的相似度。它的典型形式是相关性乘一个权重，再减去与已选集合最相似项的冗余惩罚。

假设候选 A 的查询相关性零点九，B 为零点八八，C 为零点七五。A 与 B 相似度零点九五，A 与 C 为零点二。先选 A 后，若相关性权重为零点七，B 的目标值为零点七乘零点八八减零点三乘零点九五，即零点三三一；C 为零点七乘零点七五减零点三乘零点二，即零点四六五。于是第二个选择 C，虽然它的原始相关性低于 B。

这不是故意选不相关资料，而是用一部分相关性换取互补信息。权重接近一时更重视相关性，接近零时更重视与已选项不同。过低的权重可能挑出偏题材料，因此多样性不是越高越好。最好先保证候选达到基本相关性，再在这个范围内优化覆盖。

```python
def select_mmr(ids, relevance, similarity, count, weight=.7):
    if not 0 <= weight <= 1 or count < 0:
        raise ValueError("invalid selection parameters")
    selected, remaining = [], list(ids)
    while remaining and len(selected) < count:
        def objective(identifier):
            redundant = max((similarity.get((identifier, old), 0)
                             for old in selected), default=0)
            return weight*relevance[identifier]-(1-weight)*redundant
        best = min(remaining, key=lambda item: (-objective(item), item))
        selected.append(best)
        remaining.remove(best)
    return selected

relevance = {"A":.9,"B":.88,"C":.75}
similarity = {("B","A"):.95,("C","A"):.2}
assert select_mmr(["A","B","C"], relevance, similarity, 2) == ["A","C"]
```

这个参考函数把相关性与相似度作为已知输入，便于手算。仓库版本使用同一个 TF-IDF 空间计算它们，因此仍然是词法多样性示例。真实系统可以使用 dense 相似度、来源去重或任务覆盖约束，但要保持尺度可解释。若相关性是几十的 logit，而冗余是零到一余弦，公式中的权重就不再具有你以为的平衡意义。

## 小课七：评价之前，先定义什么算一个正确证据

检索评价需要一份标准答案，但标准答案未必是唯一文档 ID。一个问题可能有多个支持来源，一条答案可能需要多个片段，多个片段也可能只是同一证据的重复。标注之前先确定评价单位：文档、片段、事实证据还是独立来源。单位不清楚，后面的指标公式再标准也可能回答错问题。

例如同一文档切成三个重叠片段，三个都含同一句答案。如果把三个 chunk 都标为相关，返回这三个片段可以得到很高的片段召回，却没有覆盖更多信息。若问题要求比较两个系统，来自第二个系统的证据反而可能被漏掉。你可以同时记录片段相关性和必要证据组覆盖，分别观察检索定位与任务充分性。

标注指南应定义等级。零表示不相关，一表示主题背景，二表示支持部分必要信息，三表示直接且充分支持答案。不是所有项目都需要四级，但每一级必须有具体例子。标注者之间的分歧不应该被悄悄平均掉；先检查他们是否理解了同一个任务、同一个资料版本和同一个支持标准。

没有标注的文档也不一定真的不相关。小评测集中常常只检查有限候选池，未判断项被当作零会引入偏差。你可以扩大候选池、合并多个检索器的结果供人工检查，并在报告中说明标注覆盖范围。不要把不完整标注得到的精确小数当作绝对真理，尤其是在比较召回风格差异很大的系统时。

评测资料还必须固定版本和权限范围。某题对公开语料有答案，对某个受限用户却不可回答；两种情形的标准答案不同。若标签来自全库，而测试查询只允许用户看一部分，系统可能被错误惩罚为漏召回。评价输入应包含与真实调用一致的身份上下文，不能把授权从质量实验中完全拿掉。

## 小课八：Precision 与 Recall 从分子分母开始

Precision@k 关心返回的前 k 个位置中有多少相关项。Recall@k 关心全部已知相关项中有多少进入前 k。两者的分子可以相同，分母不同，因此衡量的失败也不同。返回很多无关项会降低 precision，漏掉许多需要的相关项会降低 recall。

假设相关文档是 A、B、C，系统前五名为 A、D、E、B、F。前五里有两个相关项，所以 precision 是二除以五，等于零点四；recall 是二除以三，约零点六六七。若只返回 A，precision@1 为一，但 recall@1 只有三分之一。这个例子说明“第一条很准”与“证据覆盖完整”不能互相替代。

课程 `metrics` 的 precision 分母使用请求的 k，即使实际返回数量不足 k。这样在要求五条时只返回一条正确结果，precision@5 是五分之一。另一些评价可能用实际返回数量作分母，它们回答的是不同问题。报告中要说明约定，不要拿两种定义的数字直接比较。去重也应先明确，重复返回同一 ID 不应该获得多次相关性奖励。

若相关集合为空，recall 的通常分母为零，课程明确返回零。这是程序约定，不是说所有无答案问题都应该按普通 recall 解释。更有意义的做法是把无答案题单独统计拒答率和错误支持率。若你把大量无答案题混入平均 recall，会得到一个难以解释的总体值。

检索任务经常需要同时观察多个 k。小 k 反映靠前结果质量，大 k 反映候选召回能力。一个系统可能在前五更准，但前五十漏掉更多必要资料；另一个系统可能召回强但排序弱，适合接重排器。只报告一个最有利的 k 会隐藏这种差异，应该事先根据下游预算选择评价位置。

## 小课九：MRR 为什么特别关注第一条相关结果

对单个问题，倒数排名 RR 是第一条相关结果名次的倒数。第一名相关，得一；第二名才相关，得二分之一；第五名才相关，得五分之一；前 k 没有相关结果，得零。对一组问题取平均才是 MRR。课程函数为了接口简洁把每题这一项命名为 mrr，阅读时要知道它实际上是聚合前的单题倒数排名。

MRR 适合关心“用户多久看到第一条有用材料”的场景，但它不奖励找到第二条、第三条相关证据。两个系统都把 A 排第一，其中一个还找到 B、C，另一个没有，它们的 RR 可以完全相同。如果任务需要多个来源共同回答，只看 MRR 会漏掉重要差异。

假设四个问题的第一条相关名次分别为一、二、无、四，RR 是一、零点五、零、零点二五，MRR 为一点七五除以四，等于零点四三七五。请按问题逐行算，不要把所有返回文档混成一个长列表再找第一条相关。评价的基本单位是问题，混在一起会让早出现的简单题主导结果。

当问题只有一个明确正确文档时，MRR 很直观；当标签分级或答案需要多条时，应该结合其他指标。指标没有天然优劣，关键是它奖励的行为是否与你的任务目标一致。开发者必须能用一句具体话解释为什么选这个指标，而不只是因为论文里常见。

## 小课十：nDCG 怎样同时考虑等级与位置

DCG 先把相关性等级转换为收益，再按位置折扣。课程采用收益 `2^grade-1`，第一名折扣分母为一，第二名为 `log2(3)`，第三名为二。高等级内容获得更多收益，越靠后收益折扣越大。nDCG 再除以同一组标签在理想排序下能达到的 DCG，使分数在相应约定下归一化。

设 A 的等级三，B 为二，C 为一，D 为零。系统前三级为 B、D、A。B 的收益三，第一位无折扣；D 收益零；A 收益七，第三位除以二，所以 DCG 为三加三点五，等于六点五。理想前三级 A、B、C 的 DCG 为七加三除以 log2(3) 再加二分之一，约九点三九二八。nDCG 约零点六九二。

这个例子中第一条结果 B 已经相关，所以 RR 为一，但 nDCG 没达到一，因为更高等级的 A 被放到第三位，中间还浪费了一个位置给 D。不同指标对同一排序给出不同信号，不是彼此矛盾，而是关注不同目标。你应根据这个差异判断哪个机制需要改善。

```python
import math

def ranking_metrics(ranking, labels, k):
    if k <= 0 or any(grade < 0 for grade in labels.values()):
        raise ValueError("positive k and nonnegative labels required")
    ids = list(dict.fromkeys(ranking))[:k]
    relevant = {identifier for identifier, grade in labels.items() if grade > 0}
    correct = [identifier in relevant for identifier in ids]
    precision = sum(correct)/k
    recall = sum(correct)/len(relevant) if relevant else 0.0
    rr = next((1/(i+1) for i, yes in enumerate(correct) if yes), 0.0)
    dcg = sum((2**labels.get(identifier, 0)-1)/math.log2(i+2)
              for i, identifier in enumerate(ids))
    ideal = sorted(labels.values(), reverse=True)[:k]
    idcg = sum((2**grade-1)/math.log2(i+2) for i, grade in enumerate(ideal))
    return {"precision": precision, "recall": recall, "rr": rr,
            "ndcg": dcg/idcg if idcg else 0.0}

labels = {"A":3,"B":2,"C":1,"D":0}
values = ranking_metrics(["B","D","A"], labels, 3)
assert math.isclose(values["precision"], 2/3)
assert math.isclose(values["recall"], 2/3)
assert values["rr"] == 1
assert math.isclose(values["ndcg"], 6.5/(7+3/math.log2(3)+.5))
```

不同实现可能采用线性收益 grade 而不是指数收益，或采用其他折扣约定。报告必须写清公式。指数收益让三级与二级的差距更大，隐含更强地奖励高等级结果。若你的标注等级只是粗略顺序，没有这么明确的效用含义，应该思考这种收益映射是否符合任务，而不是把默认公式视为无需选择的事实。

## 小课十一：平均数之前，先做逐题配对比较

比较旧系统与新系统时，必须在相同问题上配对。假设三题旧 recall 为一、零、零点五，新为零点五、零点五、零点五。平均值都为零点五，但变化分别是负零点五、正零点五、零。新系统改善了一题，也破坏了一题。总体相同不意味着没有行为变化，尤其是受影响问题属于不同重要类别时。

把每题差值保存下来，统计均值、胜、负、平，并按问题类型分组。直接定义、同义表达、多跳、无答案、权限和版本冲突可以分别看。分组不是为了挑选好看的子集，而是为了定位机制。若 dense 分支只改善同义问题，却让精确错误码退步，你可以考虑保留词法路径和路由，而不是统一切换全部查询。

样本量很小时，不要过度解释几个百分点。一个问题的标签修正或偶然结果就可能明显改变平均数。对有随机生成的完整 RAG，还要区分检索确定性与生成波动，保留相同问题和多次运行。若比较只针对确定的检索器，没有必要人为重复同一计算一百次来制造看似很大的样本量；重复相同问题不等于增加独立信息。

可用 bootstrap 对问题级差值重采样，观察均值在样本重组下的变化范围，但这也依赖样本代表性和独立性假设。若很多问题来自同一篇文档或同一个模板，应考虑按来源组重采样，而不是把近似重复问题当独立证据。统计方法不能修复一个严重泄漏或偏置的评测集。

```python
import random

def paired_bootstrap_mean(before, after, repetitions=2000, seed=19):
    if len(before) != len(after) or not before:
        raise ValueError("aligned nonempty scores required")
    differences = [new-old for old, new in zip(before, after)]
    rng = random.Random(seed)
    means = []
    for _ in range(repetitions):
        sample = [rng.choice(differences) for _ in differences]
        means.append(sum(sample)/len(sample))
    means.sort()
    return {"mean_delta": sum(differences)/len(differences),
            "percentile_interval": [means[int(.025*repetitions)],
                                    means[min(repetitions-1, int(.975*repetitions))]]}
```

这里的区间只是教学的百分位 bootstrap 示例，没有自动处理相关样本、多重比较或标签不确定性。不要把函数返回一对数字就当成因果证明。它帮助你从“平均提升了一点”进一步问“这种提升在当前有限问题集上有多稳定”，而不是替代对实验设计的判断。

## 小课十二：消融实验怎样回答“到底是哪部分起作用”

假设你同时加入向量召回、RRF、重排和 MMR，最终指标提高了。这个结果说明组合有用，却不能说明每个组件都贡献了改善。某个组件可能没有作用，甚至有负作用，只是被其他组件的收益掩盖。消融实验通过有控制地去掉或替换一个组件，观察变化，帮助你解释复杂系统。

一个最小实验矩阵可以包括：仅 BM25、仅 dense、两者候选并集但无重排、RRF 融合、融合加重排、融合加重排加 MMR。每个设置使用相同语料快照、查询集和最终预算。若某个设置给模型四倍上下文，而另一个只给少量片段，你比较的就不只是检索策略，还混入了预算差异。

候选预算也要公平。两路各取二十再合并，与单路取二十不具有相同候选规模；它可能只是看了更多材料。可以同时报告固定最终候选数和固定总体计算预算两种视角，说明各自回答什么问题。工程选择有时允许多花成本换质量，但要把成本写出来，不能把额外资源当成算法免费优势。

记录每题在哪一层第一次成功包含必要证据。比如 BM25 前二十没有，dense 前二十有，融合后仍在，重排后掉出前五，最终回答失败。这个 trace 直接指向重排或预算选择，而不是召回不足。若只保存最终 nDCG，你可能看不到某个组件刚刚找回的好材料被下一层丢掉。

消融结果应包含失败案例，而不只包含平均表格。挑选有代表性的胜、负、平问题，逐项展示候选变化和证据。这里的案例选择应基于预先定义的类别或明确规则，避免只挑最漂亮的胜例。一个能够解释退步原因的报告，通常比只声称全面提升更有工程价值。

## 小课十三：评测泄漏会怎样制造虚假的进步

如果你反复查看测试集错误，再针对每个错误写特殊规则，测试集逐渐变成开发集。最后的高分不再代表对新问题的泛化。正确做法是区分训练、开发或验证、最终测试用途；小项目也可以简单分成用于调参的一组与最后一次检查的一组。数据少不是忽略边界的理由，而是更需要诚实说明结论范围。

近重复问题会让划分看起来随机，实际上泄漏。比如同一答案模板的十种改写分别落在训练与测试，模型可能只是记住了该来源或模式。按文档、主题或任务来源分组划分，往往比逐行随机更能检验迁移。具体分组方式取决于你希望系统泛化到什么：新措辞、新文档、新领域还是新用户。

检索数据还有一种特别常见的泄漏：把问题的标准答案文本直接加入文档标题、metadata 或查询改写提示，然后再评价召回。系统当然容易找到它，但这不对应真实使用条件。构造评测时应检查每个输入字段来自哪里，是否在部署时也能获得。答案标签只能用于评价或合法训练，不能偷偷进入测试查询流程。

调参次数也会影响解释。如果你试了一百种组合，只报告其中最好的一种在同一小验证集上的分数，偶然性会被放大。可以保留全部实验记录，使用独立测试集确认，并避免过度解读极小差异。统计显著性检验也不能自动纠正无限次反复试验带来的选择偏差，实验过程本身需要透明。

## 小课十四：质量、延迟和成本应该一起观察

重排器提高质量但让每个查询多花数秒，是否值得取决于任务。交互式助手、离线研究和批量资料整理有不同要求。不要把“更快”或“更准”当作脱离场景的唯一目标。先写出允许的响应时间、吞吐、预算以及失败代价，再比较方案。

延迟不只有平均值。少量特别慢的请求会影响交互体验，候选长度差异、批处理等待和外部 API 都可能产生尾延迟。小实验至少记录每题耗时，显示中位数与较高分位数，而不是只给总耗时除以题数。测量前固定数据和 warm-up，避免把首次加载模型的成本与稳定查询成本混在一起，除非你的场景本来就经常冷启动。

成本也要分阶段。向量编码可能在摄入时支付一次，重排在每次查询时支付，生成模型消耗输入输出 token，索引维护占用 CPU 与内存。一个方案在低查询量下便宜，在高查询量下可能很贵。你可以用虚构单价练习计算，但真实价格属于易变信息，使用时需要查看供应商当前正式说明，不能把教材中的假设费率当实时报价。

一个简单预算表记录每题召回次数、候选数、编码文本量、重排对数、上下文实际 token 数和生成输出量。若某次失败重试，又要区分已消耗与未发送的请求。没有 usage 的接口应保留未知，不把它当零。完整的质量改进报告应说明是否增加了这些资源，以及资源增加是否可接受。

## 小课十五：十二道分级练习与完整答案

**题一：两路分数。** BM25 分数五，余弦零点八，能否直接说前者更可信？不能。分数不是同一尺度，也不是同一概率。参考改进是保留各路原始值，先尝试明确的排名融合基线，再用验证集研究归一化或学习融合；任何权重都要记录依据。

**题二：手算 RRF。** 对列表 A、B、C 与 B、C、A，常数六十，最终 B、A、C。答案必须列出每项倒数贡献。把常数改成零后重新算，可以观察第一名优势变强。返回 top_k 与名次平滑常数是不同参数，不应都叫 k 而不说明含义。

**题三：重复候选。** 同一路列表出现 A、A、B，是否应让 A 获得两票？不应。参考实现先去重再赋名次；仓库会跳过重复加分但保留原始位置影响，接入前可以规范化。答案要说明自己采用哪一种排名合同，并为重复项写测试，不能只说“去重一下”却不定义后续名次。

**题四：身份粒度。** 一路返回 doc_id，一路返回 chunk_id，能否直接融合？不能。先统一到相同检索单位或建立明确聚合规则，并保留版本。否则同一文档的多个块可能被当成独立支持，或旧新版被错误合并。融合层的正确性依赖上游身份合同。

**题五：MMR 手算。** A 已选，B 相关性零点八八、与 A 相似零点九五；C 相关性零点七五、相似零点二；权重零点七。B 得零点三三一，C 得零点四六五，因此选 C。答案还应解释这是增加互补性，不代表 C 单独比 B 更相关。

**题六：Precision 与 Recall。** 相关 A、B、C，前五 A、D、E、B、F，答案为零点四与三分之二。若实际只返回 A，但请求 k 为五，课程 precision@5 是零点二。不要把实际返回长度当分母后再与课程结果比较，先核对指标定义。

**题七：MRR。** 四题首相关名次一、二、无、四，答案零点四三七五。它不能判断是否找到后续必要证据，因此多跳任务应结合证据覆盖。若两系统都首位相关但一个漏掉其他来源，MRR 无变化并不说明两者任务能力相同。

**题八：nDCG。** 等级 A三、B二、C一、D零，排序 B、D、A，DCG 为六点五，理想约九点三九二八，nDCG 约零点六九二。答案应明确使用指数收益与以二为底的对数折扣。改用线性收益是另一套合法定义，但不能混算。

**题九：无答案问题。** 没有相关文档时，普通 recall 是否足以评价？不足。课程返回零是边界约定，实际应单独评价是否正确拒答、是否伪造引用或错误使用无关资料。把无答案题全部混进一个平均检索分数，会丢掉你真正关心的风险。

**题十：平均相同。** 两系统平均 recall 一样，是否无需进一步分析？不是。查看逐题配对差值、胜负平和问题类别。一个系统可能改善同义词题却破坏版本题，工程意义与随机互相抵消完全不同。报告至少展示一条改善和一条退步的具体 trace。

**题十一：候选截断。** 正确证据在召回前二十里，但重排后掉出最终四条，下一步应该先增加向量索引预算吗？证据首先指向重排或选择阶段。应检查联合输入截断、相关性标签、重复片段和覆盖要求。盲目扩大召回可能只增加更多被同一重排错误排掉的候选。

**题十二：泄漏检查。** 随机把同一文档的十个改写问题分到训练与测试，能否证明对新文档泛化？不能。应按文档或来源分组划分，并明确评测目标。若目标只是已知资料上的新措辞，也要如实说明；不同泛化目标对应不同划分，而不是一套随机划分解决全部问题。

## 小课十六：Average Precision 怎样奖励多条相关结果靠前

MRR 只看第一条相关项，Precision@k 只看前 k 里有几个，Average Precision 则在每次遇到相关项时观察当前位置的 precision，再对相关项进行归一化。它鼓励多个相关结果尽量靠前。MAP 是对多个问题的 AP 取平均，不能把单题 AP 与全体 MAP 混为一谈。

设相关集合为 A、B、C，排序为 A、D、B、E、C。第一位 A 相关，当前位置 precision 为一；第三位 B 相关，precision 为三分之二；第五位 C 相关，precision 为五分之三。AP 为这三个数之和除以三，即约零点七五五六。若排序为 A、B、C、D、E，三个相关位置的 precision 都为一，AP 达到一。

若只评价到某个截断 k，需要明确分母采用全部已知相关数还是某种截断约定。本节使用全部相关数，使遗漏相关资料会受到惩罚。不同评价工具可能提供不同变体，因此报告应写清。课程主函数未实现 AP，下面给出独立完整参考，便于你理解并扩充自己的评测脚本。

```python
def average_precision(ranking, relevant, k=None):
    relevant = set(relevant)
    if not relevant:
        return 0.0
    ids = list(dict.fromkeys(ranking))
    if k is not None:
        if type(k) is not int or k <= 0:
            raise ValueError("positive integer cutoff required")
        ids = ids[:k]
    found, total = 0, 0.0
    for position, identifier in enumerate(ids, start=1):
        if identifier in relevant:
            found += 1
            total += found/position
    return total/len(relevant)

assert abs(average_precision(["A","D","B","E","C"], {"A","B","C"})
           -(1+2/3+3/5)/3) < 1e-12
assert average_precision(["A","B","C"], {"A","B","C"}) == 1.0
```

AP 仍然依赖二元相关标签，无法直接表达三级证据比一级背景重要多少，这正是 nDCG 等分级指标可以补充的部分。它也不能自动判断必要证据组合是否齐全。指标越多不等于报告越好，最好先选择与任务相关的主指标，再用少量辅助指标解释差异，避免读者面对十几个数字却不知道应该关注什么。

## 小课十七：证据覆盖可以被写成集合选择问题

对于比较或研究任务，可以把答案需要的信息点列成集合，例如硬件条件、版本条件、机制解释和验证方法。每个候选片段覆盖其中一部分。选择上下文时不仅考虑单条相关性，还要尽量在预算内覆盖这些必要信息点。这与普通 top-k 排序不同，因为一个分数很高的片段可能覆盖了已经拥有的信息，而一个稍低分片段补上关键缺口。

举例，A 覆盖硬件与版本，B 只覆盖硬件，C 覆盖机制，D 覆盖验证方法。若预算只能选三条，A、C、D 覆盖全部四类；A、B、C 虽然可能有更高独立相关性总分，却遗漏验证。你可以先用人工标注覆盖集合实现一个透明基线，再研究模型怎样预测覆盖。不要把预测出来的覆盖标签当成无误真值，仍然需要检查。

一个简单贪心策略是每步选“新增覆盖数量除以成本”最大的片段，再更新已覆盖集合。它不保证所有带权、带预算问题都达到全局最优，但容易观察。若使用它，要明确成本是字符、token、条数还是模型调用，不能在不同候选之间混单位。还应保留最低相关性门槛，避免为了新覆盖标签选入实际上不支持答案的材料。

这个思路与 MMR 有联系但不相同。MMR 用候选间相似度间接衡量冗余；集合覆盖直接使用信息需求标签。两个文本措辞不同，可能支持同一信息点；两个文本措辞相似，也可能分别给出不同版本的必要条件。因此文本相似度只是覆盖的代理，不能完全代替任务结构。多跳与 GraphRAG 章节会继续使用这种“需要什么证据”的视角。

## 小课十八：一套可以独立运行的离线评价台

下面给出一个最小评价台，把查询 ID、标签和多个系统的排名对应起来。它不调用模型，不读取网络，适合先确认评价代码本身。请将它与上面的 ranking_metrics 放在同一个练习文件，运行后核对每个问题的结果。

```python
import json

judgments = {
    "q1": {"A":3, "B":1},
    "q2": {"C":3, "D":2},
    "q3": {},
}
runs = {
    "lexical": {"q1":["A","E","B"], "q2":["E","C","F"], "q3":[]},
    "hybrid": {"q1":["B","A","E"], "q2":["C","D","F"], "q3":["E"]},
}

def evaluate_run(rankings, judgments, k=3):
    rows = []
    for query_id, labels in judgments.items():
        ranking = rankings.get(query_id, [])
        row = {"query_id": query_id, "ranking": ranking}
        if any(value > 0 for value in labels.values()):
            row.update(ranking_metrics(ranking, labels, k))
            row["kind"] = "answerable"
        else:
            row.update(kind="unanswerable", returned_any=bool(ranking))
        rows.append(row)
    answerable = [row for row in rows if row["kind"] == "answerable"]
    averages = {name: sum(row[name] for row in answerable)/len(answerable)
                for name in ("precision", "recall", "rr", "ndcg")} if answerable else {}
    return {"per_query": rows, "answerable_mean": averages}

reports = {name: evaluate_run(run, judgments) for name, run in runs.items()}
print(json.dumps(reports, indent=2))
```

逐项解释结果。q1 中 lexical 把最高等级 A 放第一，而 hybrid 把等级较低 B 放第一；两者都找到了 A 与 B，所以 recall 可以相同，但 nDCG 不同。q2 中 hybrid 同时找到了 C、D，lexical 只找到 C，因此 hybrid 的证据覆盖更完整。q3 没有答案，hybrid 仍返回 E，这应被单独记录为需要后续拒答或过滤处理的候选，而不是当成普通相关文档。

注意 `returned_any` 不是最终幻觉率。检索器返回一个无关候选，不必然意味着最终回答会编造事实；后续验证可能正确拒答。它只是无答案检索行为的一个观测。若你评价完整 RAG，应另记录最终是否拒答、是否引用无关资料以及是否产生无支持断言。阶段指标与端到端指标必须保持区别。

评价台还应检查查询 ID 是否缺失。上面为了简洁把缺失排名视为空列表，但真实发布验收可以选择直接报错，避免一个系统漏跑大量问题后被误当作合法拒答。记录运行失败、超时和业务拒答的不同状态很重要。不能把所有没有输出的情况都当成模型选择了谨慎拒答。

## 小课十九：三个故障案例的逐步诊断

**案例一：融合后质量反而下降。** 先看候选身份是否一致，再看两路是否都返回当前版本，最后看融合常数与候选截断。一个常见问题是新加入的检索器返回很多重复或背景资料，名次投票把真正答案挤下去。检查每题各路原始排名，而不是只看总分。修复可能是清理输入、调节候选预算或选择更互补的检索器，未必是换一种复杂融合公式。

**案例二：重排离线很好，线上很差。** 对比输入模板、截断、预处理、模型版本与候选分布。离线可能用完整文档，线上为了预算只传开头；离线候选都是人工筛过的，线上有大量噪声；离线把标准答案提示泄漏到输入里。逐项重放真实线上候选能帮助定位分布差异。不能只归因于“模型不稳定”而不检查数据路径。

**案例三：指标突然提高，但用户感觉没变化。** 检查是否改变了标签、去重单位、k、分母或无答案处理。把片段重复计为多个相关项、排除困难查询、把失败请求当缺失行，都可能提高平均值而没有实际改善。版本化评测配置，保留逐题记录，并对旧运行重新用新指标计算，才能区分系统改进与计分规则变化。

每个案例都应产生一个回归测试或数据验证规则。例如统一候选单位、拒绝混合版本、检查所有查询都有明确运行状态、记录重排实际输入长度。这些检查比在报告里写“注意公平比较”更有约束力，因为它们能在下一次运行中直接暴露同类问题。

## 小课二十：标注者分歧怎样处理

两个标注者对同一片段给出一级和三级，不一定有人粗心。可能一个在评价主题相关，另一个在评价答案充分；也可能一个注意到版本限制，另一个没有。先让他们分别写出支持理由和必要条件，再回到标注指南澄清。直接取平均为二，会把定义冲突藏进一个看似精确的数。

可以建立一份小的共同校准集，包含直接答案、背景材料、反例、过期资料、部分证据和无答案情况。讨论后形成判定示例，再独立标注新数据。对于仍有歧义的问题，可以保留争议标记或多个合理标签，并在敏感性分析中观察系统比较是否依赖这些少数争议项。评价的目的不是制造绝对客观的外观，而是让判断可解释、可复核。

如果使用模型辅助标注，也应把它当作一个可能出错的评审者。固定提示与模型版本，抽样人工复核，特别检查否定、数字、时间和来源角色。模型评审与被评价模型可能共享偏好或错误，不能因为评审过程自动化就认为消除了主观性。对核心验收集，保留原始证据和理由比只保存一个分数更重要。

最终交付应让另一个人拿到相同资料、标签和评价程序后，能够复算你的表格，并理解每个指标奖励什么行为。只有达到这个程度，混合检索、重排与多样性选择的改进才算形成了可积累的工程知识，而不是一次无法重现的漂亮演示。

## 补充推导：候选集合给后续系统设定了什么上限

假设一个问题需要证据 A 与 B，召回候选只包含 A、C、D。无论后续重排器多强，它都不能从这个集合里选择 B。若最终回答严格要求已有证据支持，那么当前候选集合已经决定这个问题不能完整回答。这种检查叫做观察候选集合的可达上限：先假设后续排序完全理想，看看现有候选最多能完成多少任务。

你可以在评测中计算“候选是否包含全部必要证据组”。如果某组有多个等价来源，只需满足其中一个；如果任务有两个必须分别满足的组，则两组都要覆盖。这个检查不需要生成模型，却能告诉你端到端失败是否可能仅靠重排解决。若候选上限已经低，优先改召回、查询规划或资料覆盖；若候选上限高而最终选择差，优先改排序和预算。

进一步可以构造一个 oracle 选择器：依据人工标签，从候选里挑选最有用的证据，仍然遵守实际上下文预算。它不是可部署系统，因为使用了标准答案信息；它是诊断工具，用于估计当前召回下后续选择还有多少提升空间。报告必须明确 oracle 使用了标签，不能把它的结果与真实无标签系统混为一谈。

如果连 oracle 在预算内也无法装下所有必要证据，问题可能是切块太大、资料重复或任务需要分阶段处理。此时继续训练重排器也不一定解决根本限制。你可以尝试更细的证据提取、父子块组合、分步回答或明确扩大预算，并分别评价它们的质量与成本。这说明评测可以帮助你选择架构，而不只是给最终系统打分。

## 补充推导：排序好，不代表分数可以当概率

一个重排器只要把相关文档排在无关文档前面，就可能获得很好的排序指标。它输出的分数可以整体加十或乘二，排名不变，但若你把分数直接当作“支持概率”，含义就完全不同。排序能力与概率标定是两项独立性质，不能由高 nDCG 自动推出分数零点九就代表九成正确。

若业务需要基于分数决定拒答，可以在独立验证集上研究阈值行为。对不同阈值，统计接受了多少真正支持的证据、误接受多少无关证据、拒绝多少本来可回答的问题。这个过程体现成本取舍：更严格阈值可能降低错误支持，也会增加拒答。阈值没有脱离场景的唯一最佳值。

标定模型也有分布边界。在普通定义题上得到的阈值，未必适用于多跳问题、不同语言、代码片段或新领域。上线后应按问题类别观察分数与结果，而不是永远相信一次离线标定。若模型版本或输入模板改变，重新检查分布是必要步骤。版本号不仅用于重现代码，也用于解释这些决策规则何时仍有依据。

## 补充工程：批量重排的身份与失败状态

批量请求多个查询候选对时，要为每个 pair 保留稳定身份。服务可能乱序返回，也可能部分失败。若仅按返回列表位置写回分数，一个候选可能拿到另一候选的高分，导致非常隐蔽的排名错误。正确适配器应检查数量、ID 唯一性、范围、有限值和模型身份，再重建输入顺序。

部分失败不能悄悄当成零分而不记录。零分可能表示模型明确判断不相关，缺失分数则表示没有完成判断。你可以选择退回原始排序、重试受限次数或返回降级状态，但必须在 trace 中保存实际路径。评价时把降级请求单独标记，才能知道质量变化是否来自模型本身还是服务可靠性。

也不要把同一候选的正文和 metadata 在异步过程中分别更新。重排输入对应哪个版本，返回分数就应绑定哪个版本；如果文档在请求期间被修改或撤权，最终选择前需要重新检查。一个分数即使计算正确，也可能已经属于过期证据。检索工程中的数值正确性、身份正确性和生命周期正确性始终需要一起维护。

最后做一次人工复盘：选择一条新系统改善的问题，画出旧与新两条候选流；再选择一条退步的问题，做同样比较。每条流至少写出召回候选、融合排序、重排输入、选择结果和指标。若你能明确指出“这个必要来源在这一层被找回”或“这个条件在这一层被截断”，就获得了可以行动的结论。若只能说“新方案平均高一点”，还不足以指导下一次修改。

复盘时也检查自己的标签。系统返回了一个原先没标注但确实支持答案的来源，可能说明标签不完整；系统引用了主题相近但否定结论相反的段落，可能说明标签定义太粗。评价程序与标注都需要维护。修正标签后应保留变更记录，并用同一新标签重新评价所有对比系统，不能只更新自己偏好的那一个。

完成本章的标志，是你能够同时解释算法选择与实验结论：为什么采用某种融合，为什么保留某个候选，为什么一个指标改善而另一个退步，当前证据能支持多大范围的结论。这样的评价能力会贯穿后续 RAG、记忆与图系统，帮助你判断复杂功能是否真的带来了可验证的收益。

### 对比实验要配对，而不是只报总平均

比较两个系统时使用同一组查询，记录每题前后指标差值。平均值提高 0.02 可能来自两道题大幅改善、八道题小幅下降；如果下降的是权限、事实版本或关键故障诊断任务，平均分不能掩盖风险。

`paired_delta` 返回每题差值均值、胜、负、平数量。这还不是统计显著性检验，但比独立抽取不同查询集合更可信。进一步可以做查询级 bootstrap 置信区间，重采样单位是查询而不是每个检索结果；若查询来自同一文档模板，可能还需要按主题或来源分组，避免把高度相关样本当成独立证据。

## 综合评测工作坊：缺失标注、配对比较与结果解释

建立评测集时，未标注文档不一定不相关。假设只给旧系统前十结果打标签，新系统找到一篇此前没出现的优质资料，若直接按零分处理，会低估新系统。反过来，把未标注都当相关也会虚高。应区分 judged 与 unjudged，采用候选池汇总后补标，报告标注覆盖与规则。评价函数需要一个明确世界，数据收集过程决定这个世界是否公平。

标注单位也必须一致。按文档打标签却按重叠 chunk 计数，可能让一份相关文档占据多个名次，Precision 看起来高但信息覆盖低。可以把结果先映射到 doc_id 去重，或使用片段级证据标签，明确分母。多版本资料还要标适用版本，旧版相关不等于当前问题相关。评价不应奖励系统找到了主题相近却时间错误的来源。

下面给出一个带标注覆盖统计的评测入口。它不擅自把未标注资料当已确认负例，而是同时输出已判定比例与按暂定零分得到的排名指标。正式结论应在标注充分后做，coverage 低的实验要先补数据，而不是立即调模型。

```python
def judgment_coverage(ranking, judgments, k):
    if type(k) is not int or k <= 0:
        raise ValueError("positive cutoff required")
    unique = list(dict.fromkeys(ranking))[:k]
    judged = [identity for identity in unique if identity in judgments]
    unjudged = [identity for identity in unique if identity not in judgments]
    return {"returned": len(unique), "judged": len(judged), "unjudged": unjudged,
            "judged_fraction_of_returned": len(judged) / len(unique) if unique else 0.0}

coverage = judgment_coverage(["A", "X", "A", "B"], {"A": 3, "B": 0}, 3)
assert coverage == {"returned": 3, "judged": 2, "unjudged": ["X"],
                    "judged_fraction_of_returned": 2/3}
```

这里先去重再截断，所以重复 A 不占第二个有效位置。B 有标签零，表示已判定不相关；X 没标签，表示未知。二者在当前 nDCG 实现里可能都得到零贡献，但数据含义不同，报告必须保留区别。否则标注不足会被误诊为检索质量差。

### 配对实验的逐题表比两个平均数更有用

同一批问题分别运行方案甲与乙，逐题计算指标差值。平均差值告诉总体方向，胜负平次数告诉变化分布，最差退化题告诉关键风险。若平均提高来自一个异常大改善，而大多数问题略退化，采用决定可能不同。任务类型切片也重要：精确错误码、概念同义、多跳、不可回答与旧版本问题不应只混成一个均值。

```python
def paired_report(before, after, groups):
    if set(before) != set(after) or set(before) != set(groups):
        raise ValueError("paired query ids must match")
    rows = [{"query_id": key, "group": groups[key], "before": before[key],
             "after": after[key], "delta": after[key] - before[key]}
            for key in sorted(before)]
    summary = {}
    for group in sorted(set(groups.values())):
        selected = [row for row in rows if row["group"] == group]
        deltas = [row["delta"] for row in selected]
        summary[group] = {"n": len(deltas), "mean_delta": sum(deltas) / len(deltas),
                          "wins": sum(value > 0 for value in deltas),
                          "losses": sum(value < 0 for value in deltas)}
    return {"rows": rows, "groups": summary}

paired = paired_report({"q1": .5, "q2": 1., "q3": .2},
                       {"q1": .8, "q2": .9, "q3": .6},
                       {"q1": "semantic", "q2": "exact", "q3": "semantic"})
assert paired["groups"]["exact"]["losses"] == 1
assert paired["groups"]["semantic"]["wins"] == 2
```

这个函数要求 query ID 集合完全一致，防止把甲难题缺失、乙只有简单题的结果平均比较。真实评测还要验证数值有限与指标范围，记录失败请求而不是从分母删除。一个方案超时的题不能悄悄不算，否则慢而不稳定的系统可能得到更漂亮质量分。

### 不确定性与显著性不能替代工程判断

bootstrap 对问题集合重采样，估计平均差值的不确定性；它假设样本能代表目标任务，不能修复标签偏差或数据泄漏。十个几乎相同模板题不是十个独立真实场景，置信区间可能过窄。若问题来自同一文档或同一用户任务，应考虑按组重采样，避免把相关样本当独立证据。

统计显著也不等于实际值得采用。平均 nDCG 提高很小但延迟翻倍，可能不划算；某个权限或版本负例退化，即使平均提高也不能忽略。报告应把不可违反的契约与可权衡的质量成本分开。权限正确性不是用平均分抵消的项目。

开发集用于选择参数，测试集用于最终比较。反复看测试结果再调 RRF 常数、候选数量与 reranker，相当于间接训练到测试集。保留一组未参与调参的问题，记录每次选择依据。数据少时也可以明确划分，宁可承认不确定性大，不把所有题都用来调到最好看。

### 完整消融实验的参考交付

固定切块、语料、权限与问题，依次运行 BM25、真实 dense、融合、融合加重排、融合加重排加多样性。每一步只增加一个机制，保存候选池与最终上下文。先看相关来源是否进入候选，再看名次，再看选择是否保留不同证据，最后看答案支持。若某一步退化，利用中间结果定位，不把所有改善归给最后一个模块。

报告至少列质量、调用数、已知费用、计量完整性、延迟分布与更新成本。可选模型未运行时只保留实验设计与 SKIP，不用教学 TF-IDF 结果代替真实 dense。任何“混合优于单路”的结论都应限定到实际数据与预算，不能从三文档课堂例子推广到所有领域。

### 同分、重复问题与失败请求的统计约定

同分结果需要稳定破平局规则，否则重复运行的名次可能变化，MRR 与 nDCG 也随之波动。按稳定 ID 排序是可复现基线，不代表语义最优。若真实系统随机打破平局，应报告重复运行分布，不能只挑最好一次。评测代码与线上排序必须使用同样约定，避免离线看似提高、实际部署不同。

问题去重同样重要。十条几乎相同的模板问句可能让某一主题在平均值中占过多权重。可以按任务族分组汇总，或同时报告逐题平均与逐组平均。两个统计回答不同问题：前者代表当前样本分布，后者避免大组垄断。没有天然唯一正确平均方式，关键是与目标使用分布一致并明确说明。

失败请求不能从结果文件中消失。超时、解析错误、预算耗尽分别记录状态，质量指标可以按预先约定计零或单独报告，但分母不能随方案悄悄变化。一个只在简单题成功返回的系统可能在成功子集上得满分，却总体不可用。把成功率与成功条件下质量一起报告，才能看清这种选择偏差。

最终采用决定应同时看逐题差异与关键负例。平均提高但错误版本题退化，可能需要路由保留精确版本过滤；语义题改善而错误码题变差，可以保留关键词路线。评测的作用是指导结构化改进，不是给所有任务选一个唯一冠军算法。

将指标定义、去重规则与失败计分一同版本化，才能让不同日期的评测结果真正可比较。
