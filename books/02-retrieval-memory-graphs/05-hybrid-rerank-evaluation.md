## 1. 为什么需要多个候选来源

产品编号、错误码、函数名和特定人名经常适合精确词法匹配；自然语言改写、同义表达和跨语言查询可能更需要语义表征。把两类候选结合，可以覆盖不同失败模式。但组合不是保证提升：如果两个检索器犯同样错误，融合只是给重复错误更多权重；如果其中一个索引过期，融合还可能把旧事实推上来。

因此先回答两个问题：每个检索器擅长哪些查询，新增一个检索器带来的独特相关候选是什么。可以统计相关材料集合的交集与差集，再决定是否值得增加模型费用和系统复杂度。本卷词法 BM25 与 TF-IDF 具有相近信息来源，融合主要用于学习接口和排名逻辑；要评估语义互补，需要换成真实学习表征并建立相应测试集。

直接把 BM25 分数 8.4 与余弦 0.79 相加没有稳定意义。二者范围与分布不同，而且 BM25 受语料统计影响。做分数融合时需要校准、归一化或训练权重，并验证跨查询稳定性。RRF 则用名次而不依赖原始分数量纲，适合当作一个透明基线。

## 2. RRF 的具体计算与实现边界

Reciprocal Rank Fusion 定义一个候选的融合分数为它在各列表中的 `1/(c+rank)` 之和，rank 从 1 开始，未出现的列表不贡献。常数 c 控制前几名之间的差距；c 较大时同一候选被多路检索命中的效果更明显，c 较小时最前面的名次更有影响。课程默认 c=60，是常见参考设置，不是万能最优值。

手算：列表 A 为 `[x,y]`，列表 B 为 `[y,z]`。c=60 时 x 得 1/61≈0.016393；y 得 1/62+1/61≈0.032522；z 得 1/62≈0.016129。因此 y 最前，即使它在 A 只是第二名。RRF 只使用排名，A 原分数是 100 还是 0.01 都不影响这一结果。

同一列表不能重复给某候选加分。本卷使用 `seen` 去重。若同一文档切出许多近似片段，它们的 chunk ID 不同，仍可能占据多个位置，所以片段级融合后通常还需要文档合并、多样性选择或父子结构控制。不能把列表内去重与跨片段语义去重混为一件事。

当一条候选流返回很少内容时，RRF 不会自动补充所有相关内容。候选池深度是另一个参数。重排器也只能在进入它的池子里重新排序，无法找回根本没召回的答案。应分别度量候选池 Recall@N 和最终结果 NDCG@k。

## 3. 重排器究竟多做了什么

双编码器 bi-encoder 可以预先编码全部文档，查询时只编码问题并做向量比较，适合大规模候选搜索。交叉编码器 cross-encoder 把查询与每个候选一起输入模型，让两者 token 之间交互，通常用于较小候选池的第二阶段。它用更多逐对计算换更精细的相关性判断。

“重排模型”也不是事实判官。它可能认为错误但主题相近的段落非常相关；它的训练域、语言、长度限制会影响表现。长候选被截断后，真正答案可能不在模型看到的部分。部署时要记录候选原长度与模型有效长度，而不只是最终分数。

本卷 `lexical_rerank` 是覆盖率加短语命中的可解释启发式：查询词覆盖比例加 0.25 的完整短语奖励。它不是 cross-encoder，也没有模型训练。使用它是为了演示“召回后再打分”的接口，不能把其输出作为先进重排性能。真实替换路径见 [Sentence Transformers 的 Retrieve & Re-Rank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)。

## 4. MMR：相关性之外还要避免重复

最大边际相关性 MMR 在逐个选择结果时考虑两项：候选与查询的相关程度，以及它与已选结果的最大相似程度。简化目标是 `λ*sim(query,candidate)-(1-λ)*max_sim(candidate,selected)`。λ=1 忽略多样性；降低 λ 会更强地惩罚重复。

为什么不总追求多样性？如果问题需要三个独立步骤，重复少很好；但如果两个几乎相同的段落只差一个关键版本条件，它们同时出现可能正是理解冲突所必需的。MMR 是选择策略，不是普适的真理。必须保留版本、标题和来源，使后续阶段能判断相似内容是重复还是冲突。

本卷 MMR 用当前候选的 TF-IDF 向量衡量相似性，仍是词法近似。它的价值在于每一步都可打印：已选集合、每个候选的相关项、重复惩罚、最终目标值。学会读这个轨迹，再迁移到真实 dense vectors。

## 5. 从一条排名手算评价指标

假设正确文档有 a、b，排名为 `[b,x,a]`，k=3。Precision@3=2/3；Recall@3=2/2=1；第一个相关结果在第 1 名，Reciprocal Rank=1。MRR 是多查询 reciprocal rank 的平均，不是一条查询内部取平均。

如果相关性分等级，a=2、b=1、x=0，可以用 DCG：每个名次的收益 `(2^grade-1)` 除以 `log2(rank+1)`。该排序 DCG=1+0+3/2=2.5；理想排序 `[a,b]` 的 IDCG=3+1/log2(3)≈3.63093，所以 NDCG@3≈0.68853。这个值不等于 2/3，也不等于召回率。

指标定义必须固定。返回结果少于 k 时，本卷 Precision 分母仍用 k，缺失位置相当于没有相关结果。重复 ID 会先去重；相关集合为空时 recall 和 NDCG 约定为 0。无答案任务最好另行评估拒答率与误答率，不要让“没有相关文档”的查询在平均 recall 中产生难以解释的效果。

## 6. 对比实验要配对，而不是只报总平均

比较两个系统时使用同一组查询，记录每题前后指标差值。平均值提高 0.02 可能来自两道题大幅改善、八道题小幅下降；如果下降的是权限、事实版本或关键故障诊断任务，平均分不能掩盖风险。

`paired_delta` 返回每题差值均值、胜、负、平数量。这还不是统计显著性检验，但比独立抽取不同查询集合更可信。进一步可以做查询级 bootstrap 置信区间，重采样单位是查询而不是每个检索结果；若查询来自同一文档模板，可能还需要按主题或来源分组，避免把高度相关样本当成独立证据。

调参集与最终测试集分开。增加 overlap、改 embedding、调 RRF 常数、改 reranker 提示词都会使用验证信息。重复在测试集上挑最优配置，本质上会让测试集变成验证集。

**练习 1：实现文档合并。** 片段结果按文档保留最高分，并用稳定 tie-break。完整解：

```python
def collapse_documents(hits):
    best = {}
    for hit in hits:
        key = (hit.chunk.tenant, hit.chunk.doc_id, hit.chunk.revision)
        old = best.get(key)
        if old is None or (-hit.score, hit.chunk.chunk_id) < (-old.score, old.chunk.chunk_id):
            best[key] = hit
    return sorted(best.values(), key=lambda h: (-h.score, h.chunk.chunk_id))
```

验收：同文档同版本多个块只留一个；不同版本不误合并。但真实检索应先保证仅当前版本可见，不能靠此函数解决过期问题。

**练习 2：算 c=0 的 RRF。** 同样 A=[x,y]、B=[y,z]，x=1，y=1/2+1=1.5，z=1/2。与 c=60 比较，前后名次分差显著增大，但本例第一名仍是 y。

**练习 3：候选池上限。** 100 个查询中只有 70 个的正确材料进入重排池，即使重排完美，单答案任务 top-1 成功率最多 70%。答案说明先修召回瓶颈，不能靠更贵 reranker 解决剩下 30 个。

**练习 4：指标欺骗。** 若重复返回同一正确文档十次，错误实现可能算 Recall>1。修复是对文档身份去重，并区分 chunk 与 document 相关性标注。测试 `metrics(['a','a'],{'a':1},2)` 应给 recall=1、precision=0.5。

**练习 5：完成一个消融表。** BM25、向量、RRF、RRF+重排、RRF+MMR 五种配置固定相同数据和权限范围，记录 Recall@候选池、NDCG@最终k、平均候选数与计算成本。参考结论允许“没有提升”，必须列出至少三条失败案例。无法保证各配置更强，正是实验要回答的事。
