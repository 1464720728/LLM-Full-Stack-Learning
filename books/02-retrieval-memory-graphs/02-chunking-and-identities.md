# R02 切块、字符区间、身份与摄入契约

先修：R01、Python 字符串切片、JSON、哈希的基本用途。你将写出不丢字、不死循环、能够追溯原文的切块器，并解释为什么“每段 500 token”不是一个完整的摄入方案。实验只需 CPU。

## 1. 为什么要切块，又为什么不能只关心块大小

整篇资料直接作为搜索单位，可能让少量有用内容被大量无关词稀释，也可能超过模型输入预算。把资料拆成小块，可以提高定位精度。但太小的片段可能失去主语、限定条件或表格标题。比如“这种配置不可用”没有前文就无法判断是什么配置；表格某一行脱离列名后，数字含义也会消失。

所以切块是在搜索粒度与上下文完整性之间选择。它影响召回、重复率、引用质量、向量成本和更新成本。不存在脱离数据的最佳长度。法律条款、代码函数、FAQ、日志和学术论文的结构不同，应该先理解结构再定策略。第一版原型可以采用简单规则，但必须保留原始文档与切片位置，使以后能更换切块器而不丢来源。

“chunk 是事实单位”也是错误假设。一块可能包含几个相互独立的事实，一条事实也可能跨越两个块。需要跨块推理时，可以先检索小块，再取邻接块或父级章节。父子检索的核心是两个粒度有明确映射，不是把所有相邻文本都无界添加进去。

## 2. 字节、字符和 token 是三种坐标

UTF-8 中一个汉字通常占多个字节；Python 字符串切片按 Unicode 码点索引；模型 tokenizer 把字符串编码成它自己的离散 token 序列。三者长度常常不同。`len("缓存")` 是 2，而 UTF-8 字节长度是 6；模型实际 token 数取决于 tokenizer，不能从这两个数直接推出。

课程 `Span.start/end` 明确定义为 Python 字符偏移，采用左闭右开区间 `[start,end)`。于是必须满足 `original[start:end] == span.text`。若在记录区间后又删除空格、规范化 Unicode 或把换行变成空格，区间就不再对应原文。正确选择是保留一个“规范化文本版本”作为新的基准并记录变换，或者在原文上切片；不要悄悄混用两个坐标系。

R01 的词法 tokenizer 也不是模型 tokenizer。它将英文单词和数字串作为词元，将常见 CJK 汉字单独作为词元。这样写是为了可读和离线运行；中文分词、繁简变体、特殊符号、代码和 emoji 都有边界。它足以教 BM25 统计，不应直接用于估算 API 账单。

## 3. 让切块循环始终向前

最直接的固定窗口算法设置 `end=min(start+size,len(text))`，输出区间，然后令下一起点为 `end-overlap`。必要条件是 `0 <= overlap < size`。若 overlap 等于 size，每次起点不变，程序会永远处理同一块。

结构边界使问题稍复杂。我们希望尽量在句号或换行附近结束，但如果向前回退太多，块长度可能小于 overlap，同样会导致不前进。本卷只在窗口后半段且超过 overlap 的位置寻找边界，因此可以保持 `next_start > start`。这是一条需要用测试证明的不变量，而不是“看起来一般不会发生”的经验。

手算例子：文本长 20，size=8，overlap=2，不考虑标点边界，区间依次为 `[0,8)`、`[6,14)`、`[12,20)`。原文覆盖长度是 20，存储字符总量是 24，重复 4 个字符。大文本的近似放大系数是 `size/(size-overlap)`；size=8、overlap=2 时约为 1.33，但首尾边界和结构切分会影响精确值。

重叠是减少断句损失的方法，同时会制造重复证据。之后的检索不能把同一来源相邻三块当成三个独立事实来源，否则“多来源一致”其实只是同一句话重复了三次。

## 4. 片段 ID 为什么包含版本

用内容哈希作为 ID 能检测相同字节，但不能独立表达权限、租户、来源和位置。同一公开句子出现在两份文档中，来源价值可能不同；同一文本存在于两个租户中，也不能因为哈希一样就将权限合并。

本卷 `digest` 将一组结构化字段编码成稳定 JSON 后做 SHA-256。chunk 身份由租户、文档 ID、版本、起止位置和原文组成。这样同一版本重建产生相同 ID；新版本即使某块文本没变，也有不同 ID。代价是更新会增加块身份变动，但引用失效关系更容易教学和审计。生产系统可以使用稳定段落 ID 与内容版本分离，前提是把这两种身份定义清楚。

不要用 `hash(text)` 作为持久 ID：Python 的进程级哈希不承诺跨运行稳定。也不要用标题作为唯一 ID：同名标题很常见，标题还会修改。文档 ID 表示你要跟踪的逻辑对象，revision 表示此对象一次不可变的内容和权限快照，chunk ID 表示快照内的可引用片段。

## 5. 摄入并不只是“读文件再 embed”

摄入包括解析、标准化、结构识别、身份分配、切块、元数据验证、访问权限、索引生成、发布。每一步都可能失败。PDF 解析可能把两列交错；表格可能丢列标题；OCR 可能把 0 识别成 O；HTML 可能带菜单、脚注或恶意文字。向量模型能正常返回数值，不表示原文解析正确。

本卷采用纯文本固定输入，避开复杂文件格式并明确保留这层边界。要添加 PDF，应先做“原页—抽取文本—切块”抽样检查，再做检索。解析器版本也应进入摄入指纹，否则换了解析算法却复用旧向量，系统会误认为内容未变化。

`ingest` 先生成所有 Span，再开启数据库写事务。这样切块参数错误不会产生半份文档。指纹包括正文、标题、来源、权限、切块参数和 tokenizer 版本。重试同一输入返回原 revision，改变权限也会生成新 revision。这比“只看正文哈希”的幂等设计更完整。

## 7. 练习与解答

**练习 1：手算窗口。** 长度 17，size=6，overlap=2，没有结构边界。答案是 `[0,6)`、`[4,10)`、`[8,14)`、`[12,17)`，存储总字符数 23。最后一块只有 5 字符，不应补空格伪造原文。

**练习 2：实现覆盖检查。** 完整参考解：

```python
def check_spans(text, spans):
    covered = set()
    previous = -1
    for span in spans:
        assert 0 <= span.start < span.end <= len(text)
        assert span.start > previous
        assert text[span.start:span.end] == span.text
        covered.update(range(span.start, span.end))
        previous = span.start
    assert covered == set(range(len(text)))
```

空文本配空 spans 可以通过；非空文本配空 spans 必须失败。这个教学检查使用集合，空间开销较大；生产校验可以扫描区间覆盖而不为每字符建集合。

**练习 3：字符坐标错配。** 将 `body.replace("\n", " ")` 放在切片之后会怎样？答案：如果只替换单字符，长度可能不变但引文不再等于原文；若删除换行，后续偏移也会移动。解决是保留原文并将展示文本与引用文本分开，或记录标准化后的明确基准版本。

**练习 4：测试最危险边界。** 构造 size=1、overlap=0；size=7、overlap=6；空文本；中文与换行混合；文档长度恰好整除步长。参考验收是完整覆盖、最大块长不超限、所有起点严格递增、切片一致。`test_chunk_coverage_many_sizes` 给出可执行参考。

**练习 5：设计代码检索切块。** 以函数为单位是否足够？参考答案：函数体要连同签名、模块路径和必要类上下文；过大函数仍需二次切分，并保留父函数 ID；跨文件调用关系不能仅靠物理相邻文本恢复。编程语言解析器能识别语法边界，但不自动决定检索相关性。
