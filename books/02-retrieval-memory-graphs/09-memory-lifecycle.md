# R09 Agent 记忆：写入、召回、修正与遗忘

先修：R08、Agent 状态与对话消息。你将构建可跨进程保留信息的记忆系统，且能解释每条信息为何被保存、何时失效、怎样纠正。全部演示使用虚构学习者，无模型调用。

## 1. 对话历史不是全部记忆

模型在一次请求中实际看到的输入叫上下文。会话历史可以成为上下文的一部分，但历史日志保存在磁盘，不表示每次都完整进入模型。检查点 checkpoint 保存一条工作流在某时刻的状态，用于恢复运行；长期记忆保存跨会话可复用的信息；缓存保存可复用计算结果。它们都可能“存数据”，但身份、生命周期和正确性要求不同。

例如“第 3 个工具正在执行”属于工作流状态；“学习者偏好先看数值例子”可以是长期偏好；“昨天某次任务失败，原因是版本不匹配”可以是一条事件记忆；“某 query 的向量”是缓存。把这些混在同一张无类型向量表里，会让召回、删除与恢复语义不清楚。

记忆不是越多越好。错误偏好会长期污染回答；过时项目状态可能引导错误行动；临时抱怨可能被误当永久性格。记忆系统的核心不只是存得住，还包括选择、证据、冲突、时效和控制权。

## 2. 三类长期记忆与两个独立维度

语义记忆 semantic memory 表示事实或相对稳定的知识，如某项目使用的语言；情景记忆 episodic memory 表示一次具体事件及其背景、行动和结果；程序性记忆 procedural memory 表示可以复用的做事方法或规则。这个分类有助于设计，但没有天然互斥的唯一真相。一条“执行前先跑测试”既可能是经验概括，也可能成为程序性规则。

另一个独立维度是作用范围：个人、团队、项目、会话。第三个维度是时间：何时记录、何时有效、何时过期。不要把“长期”理解成永不删除，也不要把“语义”理解成必然准确。任何记忆都需要证据和来源。

本卷 `Memory` 包含 tenant、owner、key、revision、kind、value、evidence、confidence、expires_at。owner 是记忆的归属身份，不能由任意调用者伪造。confidence 在本卷只是应用提供的信任标记，不是经校准的概率；0.9 不代表事实有 90% 真实机会。

## 3. 写入前应该发生什么

候选记忆通常来自用户明确陈述、工具结果、任务总结或模型推断。这四类来源可靠性不同。用户说“请记住我偏好代码先行”是明确写入意图；模型推断“他问了三次 CUDA，所以以后只想看 GPU 内容”则可能过度概括。

一个可执行写入策略可以检查：是否属于允许保存的类型；是否有明确来源；是否包含敏感或不必要信息；是否与已有记忆冲突；是否应设置 TTL；是否需要用户确认。这个策略不是固定道德口号，而是产品需求和数据治理的一部分。课程用显式 CLI 命令保存记忆，不自动推断真实用户偏好。

对话日志不应该全部复制进记忆 value。更合理的记录是一个具体事实，带原消息 ID 或工具执行 ID。证据可以帮助解释修正，但证据本身也可能包含敏感内容，因此要控制存储与展示范围。生产环境可以用受控事件引用，而非在每条记忆中复制完整原文。

## 4. 纠正与冲突不能靠“最新文本覆盖”糊过去

假设 revision 1 表示“偏好短例子”，用户后来明确更正为“希望完整推导”。本卷先把旧 active 版本改为 superseded，再插入新 active 版本。当前 recall 只返回新值，history 仍可用于管理审计。这样可以区分“旧信息曾经成立但被更正”和“旧信息从来就是错误写入”。

并发写入也需要 expected_revision。两个 Agent 同时基于 revision 1 推出不同更正，不能都认为自己成功成为唯一真实状态。一个先提交，另一个收到冲突后需要重新读取并决策。自动用时间戳最后写入覆盖虽然简单，但可能丢掉明确用户更正。

有些冲突可以同时存在。用户在工作项目偏好 Python、个人项目偏好 Rust，不应该把 key 都设为 `preferred_language` 然后互相覆盖。key 或 scope 应包含项目语境。关键问题不是“哪个值更新”，而是“它们描述的是不是同一个条件下的同一个事实”。

## 5. 召回是有预算的选择

把全部记忆注入每轮上下文，会增加成本和无关干扰，还可能泄露不该在当前任务出现的信息。召回应先按租户与 owner 限定，再按状态与有效期过滤，再根据任务选择，最后按上下文预算打包。

课程 `select_memory` 用 key 与值的词法重叠乘 confidence 排序，属于透明启发式。它只展示“候选—打分—预算”接口，不代表先进记忆召回。真实系统可以用向量、图关系、任务类型和最近使用等信号，但每个信号都应评估：频繁被错误召回的记忆不应该因“使用次数高”被永久强化。

记忆召回后可以在上下文标明它是用户明确要求、历史事件还是未经确认的推断。模型不应把“上次一次任务失败”过度推广成“该工具永远不可用”。对程序性记忆尤其要限制适用条件、环境与版本，否则经验会变成过期规则。

## 6. TTL、撤回与彻底删除的语义

TTL 指明某时刻之后不再作为 active recall 使用。本卷条件是 `expires_at > now`，所以恰好到期时不可见。测试通过注入固定 now，而不依赖真实时钟等待，可以快速可靠地覆盖边界。

retract 将当前记忆标为撤回，保留历史；forget 删除该 key 的全部 SQL 版本。它们不等价。若用户要求“不要再使用这个判断”，撤回可能合适；若要求删除数据，需要按约定清理历史、缓存、摘要与备份。课程 forget 只保证这张数据库表中的记录删除，不保证硬盘取证或外部系统同步消失。

遗忘后重建也不能复用旧版本号。例：线程 A 读到 x=old、revision=1；线程 B forget(x)，再写入 x=new；如果新版本又是 1，A 的 expected_revision=1 会错误通过。`memory_revision_counters` 保存 tenant/owner/key 的哈希及最后分配版本，不保存 value、evidence 或明文 key。forget 后 history 为空，但这个防 ABA 墓碑仍保留；重建以 expected_revision=0 断言“目前没有版本记录”，得到的 revision 是 2，而非再次得到 1。随后 A 的过期写入必须冲突。稳定哈希仍属假名元数据，不能称为全部信息删除。要求消除关联标识的系统需要换新身份代际并让旧客户端失效，而不是简单删除计数器。练习时先 forget，再关闭重开 SQLite，最后重建并尝试旧 expected=1，确认重启不影响保证。

遗忘不是失败，而是正确记忆系统的一部分。没有删除和修正能力的“长期记忆”很容易成为不断积累错误的历史仓库。

## 7. 从代码到完整生命周期

```bash
python -m labs.knowledge.lab 22-memory
python -m labs.knowledge.lab 23-ttl
python -m labs.knowledge.lab 24-forget
python -m labs.knowledge.memory_assistant demo
```

观察 revision 1 变 superseded，revision 2 是唯一 active；在 now=10 时 expiry=10 的记录不再返回；forget 后 history 为空。`memory_assistant demo` 使用独立的虚构命名空间，演示保存—纠正—读取—遗忘，不请求任何真实偏好。

持久化时用一个自己的临时文件路径，例如 `--db /tmp/course-memory.db`；在 Windows 可用自己创建的实验目录。路径是你的本地文件，不要提交数据库到公开仓库。先跑 remember，再退出进程跑 recall，才能证明跨进程持久化，而不只是同一对象在内存里有值。

## 8. 练习与参考解

**练习 1：分类。** “当前节点 waiting_for_tool”“昨天测试失败”“项目 X 默认 Python”“失败前保留日志”分别属于检查点状态、情景、语义、程序性候选。最后一条只有在有适用条件和证据时才适合推广成长期规则。

**练习 2：写 TTL 边界测试。** 完整解：

```python
from labs.knowledge.memory import MemoryStore
with MemoryStore() as memory:
    memory.remember("demo", "alice", "temporary.goal", "finish exercise",
                    "fictional-message-1", expires_at=100)
    assert len(memory.recall("demo", "alice", now=99)) == 1
    assert memory.recall("demo", "alice", now=100) == []
    assert memory.recall("demo", "bob", now=99) == []
```

**练习 3：修正并发冲突。** 先写 revision=1，再执行两次 expected=1 的不同修改。第一条成功到 2，第二条必须失败。参考处理是读取新值与新证据，形成显式冲突记录或请求确认，不是忽略 expected 参数。

**练习 4：会话偏好污染。** 用户说“这次回答短一点”，能否存为永久 `preferred_length=short`？答案：不能从这句话推出永久偏好。应该保存在当前任务约束或带会话范围/短 TTL 的记录，除非用户明确要求长期保存。

**练习 5：程序性记忆改进。** 把“使用工具 A”改成可评估规则。参考字段包括触发条件、适用环境版本、步骤、成功判据、失败恢复、证据任务 ID、最近验证时间。用两个满足条件和两个不满足条件的任务测试，防止规则被无条件注入。

**掌握门槛：** 能给一条记忆回答“谁的、是什么、为何保存、何时有效、怎样更正、怎样删除”；能实现隔离、CAS、TTL 与全版本删除测试。真实框架概念见 [LangGraph Memory](https://docs.langchain.com/oss/python/concepts/memory) 和 [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)，注意 checkpointer 与 store 的职责分离。
