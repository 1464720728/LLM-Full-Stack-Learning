# R03 从词频到 BM25：亲手实现可解释检索

先修：R02、字典与 Counter、对数和分数。目标是从文档计数推导一条实际排序，逐项核对分数，并能修改实现而知道改变了哪个假设。使用标准库，不下载模型。

## 1. 一个词出现十次，真有十倍相关吗

只看关键词是否出现，会让包含一次“缓存”的长文章和专门讲缓存的短说明得分相同。只看出现次数，又会让重复关键词的垃圾文本占优势。还要考虑一个词在整个语料中有多常见：“系统”可能几乎每篇都有，“预抢占”可能只在少数相关资料中出现。检索分数需要综合词在当前文档里的强度、词在语料里的区分力，以及文档长度。

这里有两个容易混淆的频率。`tf(t,d)` 是词 t 在文档 d 中出现的次数；`df(t)` 是有多少篇文档至少包含一次 t。文档里出现一千次也只给 df 贡献 1。设总文档数为 N，逆文档频率 IDF 随 df 增大而下降，强调稀有词的区分能力。

本卷使用一个常见的非负 BM25 IDF 变体：

\[
\operatorname{IDF}(t)=\ln\left(1+\frac{N-\operatorname{df}(t)+0.5}{\operatorname{df}(t)+0.5}\right).
\]

不同实现的平滑方式可能不同，有的经典写法会给常见词负分。对照库时必须先核对公式，不要看见结果不一样就断言代码错误。我们在代码和测试中锁定这一个变体。

## 2. 完整评分公式逐项拆解

对查询中每个不同的词累加：

\[
\operatorname{score}(q,d)=\sum_{t\in\operatorname{unique}(q)}
\operatorname{IDF}(t)\frac{f(t,d)(k_1+1)}{f(t,d)+k_1(1-b+b|d|/\operatorname{avgdl})}.
\]

f 是词频，|d| 是本 tokenizer 计算出的文档词元数，avgdl 是当前索引语料的平均长度。k1 控制词频饱和程度；b 控制长度归一化，0 表示忽略长度，1 表示完全使用相对长度项。这里取 k1=1.2、b=0.75 作为教学默认，不能保证适合你的语料。

先令文档长度等于平均长度。长度项变为 k1，f=1 时词频因子是 1；f 从 1 增加到 2 会提高分数，但不会翻倍；f 很大时因子趋近 k1+1。饱和机制表达了一个经验：重复提及会增加相关迹象，但边际收益递减。

文档更长时，`|d|/avgdl` 更大，分母增加，同样词频的贡献变小。它不是“长文档一定不重要”，而是抑制长文档仅因词多而占优势。对于长手册中一个非常具体的章节，合理切块通常比盲目调 b 更关键。

## 3. 从三个小文档手算到浮点数

文档 0：`cat cat dog`，长度 3；文档 1：`cat fish`，长度 2；文档 2：`dog fish`，长度 2。N=3，avgdl=7/3，cat 的 df=2。其 IDF 为 `ln(1+1.5/2.5)=ln(1.6)`，约 0.4700。

查询只含 cat。对文档 0，f=2，长度项为 `1.2*(0.25+0.75*3/(7/3))≈1.45714`，贡献约为 `0.4700*4.4/3.45714≈0.5982`。对文档 1，f=1，长度项约 1.07143，贡献约 `0.4700*2.2/2.07143≈0.4992`。文档 2 没有 cat，贡献为零。应得到 0 排在 1 前，2 不进入正分结果。

不要把小数近似写死成严格相等断言。浮点测试应使用容差或 `assertAlmostEqual`，同时用独立手算表达式检验。若测试只复制实现一模一样的循环，即使两边都把 df 算错，也可能同时通过。

查询 `cat cat` 在本实现中与 `cat` 相同，因为我们对查询词去重。这不是所有 BM25 系统的统一规则，而是明确选择的 query term frequency 契约。查询侧是否重复加权应与使用场景和参考库一致。

## 4. 源码阅读路线

`BM25.__init__` 中第一步将每个 chunk 词元化，得到一个 Counter。`self.lengths` 对 Counter 的 values 求和，所以词出现两次算两个词元。`self.df` 遍历 Counter 的键，所以每文档每词只算一次。请亲手打印二者，确保能从数据结构看出数学含义。

`contributions` 返回字典而不是立即只返回一个总分，这是调试设计。你可以看到某篇文档是因为哪些词得分，检查意外命中是否由常见词、数字或分词造成。`search` 再对贡献求和，并交给 `_rank`。排序先按负分数，再按 chunk ID，给同分结果一个稳定次序。稳定排序不等于检索更准确，但让回归测试和差异分析更可复现。

未知查询词没有文档词频，因此虽然平滑 IDF 可以算出一个数，最终贡献仍为零。空索引和平均长度为零必须显式处理，否则会出现除零。代码对空材料返回空结果；对负 k 拒绝，而不是让 Python 的负切片产生意外语义。

## 5. 倒排索引与本实验的规模边界

当前实现为了透明，扫描全部文档并逐文档计算贡献。若有百万个片段，扫描成本会变得明显。倒排索引把“词→包含该词的文档与词频”存起来，查询只访问相关词的 posting lists。它改变执行方式，不要求改变评分公式。

一个简单倒排表可以是 `postings[term][doc_id]=tf`。文档长度保存在另一张表，df 等于 posting list 中不同文档数。查询时对出现过查询词的文档累加贡献，再取 top-k。更新与删除时，不仅要修改正文，还要更新 postings、df、总长度与 N。若漏减 df，分数会悄悄漂移，不一定抛异常。

权限也会影响统计口径。本实验先取可见文档，再构建 BM25，因此普通用户与管理员的 N、df、avgdl 可能不同。同一公开文档对两个用户的分数不同是合理的。生产引擎可能用全局统计加受限候选过滤，需要评估是否泄露不应暴露的语料统计以及是否影响排序公平性。

故障注入：把 df 的构造改成遍历所有词元，而非每文档的唯一词。出现次数多的词会让 df>N，可能导致奇怪 IDF。修复后增加不变量 `0<=df<=N`。另一种故障是把中文整段当一个词；表面上索引成功，查询某个子词却完全找不到。这属于 tokenizer 契约问题，不是 BM25 公式问题。

## 7. 练习与参考答案

**练习 1：边界推导。** 文档长度等于平均长度、f=1 时词频因子是多少？答案为 `(k1+1)/(1+k1)=1`；f 趋无穷时趋近 k1+1。这个推导解释了饱和，而非死记参数。

**练习 2：写倒排表。** 完整参考函数如下：

```python
from collections import Counter, defaultdict
from labs.knowledge.text import tokenize

def build_postings(texts):
    postings = defaultdict(dict)
    lengths = []
    for doc_id, text in enumerate(texts):
        counts = Counter(tokenize(text))
        lengths.append(sum(counts.values()))
        for term, frequency in counts.items():
            postings[term][doc_id] = frequency
    return dict(postings), lengths
```

验收：前三个示例中 `postings['cat']=={0:2,1:1}`，lengths 为 `[3,2,2]`。进一步评分时只访问查询词 postings，但要保持与扫描版本的排序一致。

**练习 3：重复查询词。** 去掉 unique 后会怎样？答案：`cat cat` 使该词贡献加倍；这可能不改变只有该词时的排序，但会改变与其他词混合查询的相对权重。不能只用单词查询测试两版本一致。

**练习 4：删除影响。** 删除文档 0 后 cat 的 df 从 2 变成 1，N 从 3 变成 2，avgdl 从 7/3 变成 2。三项都需要更新。新 IDF 为 `ln(1+1.5/1.5)=ln2`。即使文档 1 没改，其得分也会变化。

**练习 5：公平比较分词器。** 给两分词器相同语料、相同查询、相同 relevance 标注，分别检索；记录正确来源的 Recall@k 和失败类别。不要用“词数更少”作为优劣结论，尤其中文术语与错误拼写需要单独样本。

**掌握门槛：** 不借助现成库手写 BM25，能够解释每个计数的来源，手算一例并通过空库、未知词、重复查询和长度边界测试。继续阅读 [Stanford 信息检索教材](https://nlp.stanford.edu/IR-book/html/htmledition/irbook.html) 与 [Haystack BM25 检索器](https://github.com/deepset-ai/haystack/blob/main/haystack/components/retrievers/in_memory/bm25_retriever.py)，重点比较契约和存储责任。
