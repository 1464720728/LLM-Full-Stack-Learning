# R04 向量检索：几何、学习表征与近似搜索

先修：R03、向量点积与平方根。目标是区分“把内容变成向量”“用某个距离比较向量”“用索引加快搜索”三层，并能实现精确搜索作为任何加速实现的正确性基准。本章不要求 GPU。

## 小课一：坐标是约定，维数相同不代表可以比较

向量可以先理解成一张有固定列顺序的数字表。例如三列依次表示 cache、request、token，文本“cache cache token”对应二、零、一。若另一套系统把列顺序改为 token、cache、request，同一文本会写成一、二、零。两个数组长度都为三，却不能直接逐项相乘，因为第一列代表的对象已经不同。

神经 embedding 的坐标通常不对应可命名的单词，但“坐标系必须一致”的要求仍然存在。两个模型都输出一千零二十四维，不代表它们的第一维、第二维具有可直接对齐的意义。即使同一模型名字背后的权重被服务提供方更新，旧文档向量与新查询向量也未必继续兼容。维数检查能发现一类错误，不能证明语义空间一致。

你可以用一个二维旋转例子体会。旧空间里文档向量 a 为一、零，查询 q 也为一、零，点积是一。若只把查询空间旋转九十度，q 变成零、一，点积变成零；若文档和查询同时做同一正交旋转，点积又保持不变。问题不是旋转本身，而是两边采用了不一致的变换。

因此一个向量索引的身份应包括编码器权重或可用的版本标识、输入模板、池化方式、维数、归一化规则和距离类型。对外部 API 无法获得精确权重版本时，至少记录供应商返回的模型身份、请求模型别名、日期和自己能核对的配置，并把未锁定的部分写清楚。不能用一个文件夹名“最新向量”承担全部版本责任。

初学时最好的检查是用两三条固定文本重复编码，打印形状和有限值，再用已知相似与不相似对做基本 sanity check。重复输入输出相同不证明语义质量好，只能帮助发现服务、预处理或版本变化。后续还必须有独立的任务相关性标注集，才能判断向量是否真的适合你的资料。

## 小课二：点积、欧氏距离与余弦为什么会给不同排名

点积把对应坐标相乘后求和。它同时受方向与长度影响。欧氏距离关注两点的绝对位置差异。余弦把点积除以两边长度，主要比较方向。三个量都可以合理，但对应不同的训练与检索契约。选择哪个量应依据模型训练目标和实际评测，不是因为“余弦”这个名字更熟悉。

令查询 q 为一、零，候选 a 为一、零，候选 b 为十、一。点积分别是一和十，所以点积喜欢 b。余弦分别是一和十除以根号一百零一，后者约零点九九五，所以余弦喜欢 a。欧氏距离方面，a 距离零，b 距离根号八十二，也喜欢 a。这个简单反例证明没有归一化时，三者不能随意替换。

如果文档和查询都归一化为单位向量，则平方欧氏距离等于二减二倍点积。推导只需要展开 `(x-y)·(x-y)`：得到 x 的平方长度加 y 的平方长度减两倍点积；前两项都是一，所以结果成立。此时最大点积、最大余弦与最小平方欧氏距离具有相同排序。注意前提是两边都按同样规则归一化，不是只给查询除以长度就足够。

平方距离与距离本身也有区别。平方根是单调递增函数，因此用于排序时通常可以省略平方根，仍然得到同样顺序；但用于阈值和显示时，数值尺度不同。若你把“距离小于零点五”的阈值直接用于平方距离，就改变了筛选条件。接口字段应写清 squared_l2 还是 l2，不能统一叫 distance 后让调用者猜。

零向量需要单独处理，因为它没有方向，余弦分母为零。把它当作全零分、直接丢弃或报错都可以是明确设计，但必须说明。课程词法 cosine 在分母为零时返回零；真实 dense 检索适配器跳过零向量，并在查询为零向量时返回空。不同接口的选择与用途有关，不能盲目把一个约定移到另一个地方。

## 小课三：数值稳定性不是只有训练时才重要

最直接的范数计算是平方、求和、开方。若坐标约为一乘十的三百零八次方，坐标本身仍可能是有限浮点数，但平方会溢出为无穷大。若坐标约为一乘十的负三百零八次方，平方可能下溢为零。于是你可能把一个合法方向误判成零向量，或者得到无意义的 NaN 相似度。

课程 `cosine_topk` 先找最大绝对坐标 scale，再把所有坐标除以 scale。缩放后的绝对值不超过一，随后计算范数就不容易发生平方溢出。最后再把缩放向量除以它自己的范数，得到单位向量。整体缩放不会改变方向，因此这个处理保持余弦的数学定义，同时改善有限精度下的计算行为。

```python
import math

def stable_unit(vector):
    if not vector or any(not math.isfinite(x) for x in vector):
        raise ValueError("finite nonempty vector required")
    scale = max(abs(x) for x in vector)
    if scale == 0:
        return None
    scaled = [x / scale for x in vector]
    length = math.sqrt(math.fsum(x*x for x in scaled))
    return [x / length for x in scaled]


def stable_cosine(a, b):
    if len(a) != len(b):
        raise ValueError("dimension mismatch")
    left, right = stable_unit(a), stable_unit(b)
    if left is None or right is None:
        return None
    return max(-1.0, min(1.0, math.fsum(x*y for x, y in zip(left, right))))

assert math.isclose(stable_cosine([1e308, 1e308], [1, 1]), 1.0)
assert math.isclose(stable_cosine([1e-308, 1e-308], [1, 1]), 1.0)
assert stable_cosine([0, 0], [1, 1]) is None
```

最后把结果限制在负一到一，是为了处理舍入后可能略超出数学范围的末位误差，不是为了把任意错误结果强行变合法。若向量含 NaN 或无穷大，必须在前面拒绝；不能先计算，再把 NaN 当零。维数也必须先检查，因为 zip 默认截断较长序列，可能让两个不兼容向量产生一个看起来正常的相似度。

请把极大值、极小值、全零、含 NaN、维数不符和反向向量分别列为测试。普通随机正态向量通常无法覆盖这些边界。数值代码的正确性不是“在一个随机例子上误差很小”就结束，而是明确输入范围、运算稳定性和异常状态。这个思想与你以后写 GPU 算子时完全相通。

## 小课四：精确搜索的矩阵形状与内存访问

若有 N 条文档，每条 d 维，可以把文档向量按行堆成矩阵 D，形状为 N×d。一个查询 q 形状为 d，点积得分向量是 D 乘 q，形状为 N。若一次有 B 个查询，查询矩阵 Q 为 B×d，得分矩阵是 Q 乘 D 的转置，形状为 B×N。每个轴的语义必须说清，不能只看数组能否相乘。

```python
import numpy as np
D = np.array([[1., 0.], [0., 1.], [1., 1.]])
Q = np.array([[1., 0.], [0., 1.]])
scores = Q @ D.T
assert scores.shape == (2, 3)
assert np.array_equal(scores, [[1., 0., 1.], [0., 1., 1.]])
order = np.argsort(-scores, axis=1, kind="stable")
print(order)
```

第一行查询与三个文档的点积是一、零、一；第二行是零、一、一。稳定排序使同分候选保持输入顺序，但生产身份通常需要显式 ID 破同分。你可以把排序前文档顺序打乱，观察返回位置如何变化，再把位置映射回稳定 ID。索引内部位置与业务身份不是一回事，向量库删除或重建时尤其容易混淆。

一次性物化 B×N 得分矩阵可能占用大量内存。即使原始向量能够放下，批量查询的中间矩阵也可能超预算。一个简单解决方案是按文档块或查询批次计算，维护每个查询的 top-k。这个问题与模型注意力的分块计算有相似的内存思想，但检索 top-k 和 softmax 归一化是不同运算，不能直接套用同一个更新公式。

精确搜索不一定意味着低效。小到中等语料上，连续矩阵运算可以很好利用 CPU 或 GPU 的向量化能力，复杂索引的构建和访问开销可能反而不划算。是否需要 ANN，应根据语料规模、维数、查询量、延迟要求和更新频率判断。先测精确基线，再增加复杂结构，是一个有证据的工程顺序。

## 小课五：手写一个二维 IVF，观察边界漏召回

IVF 的基本想法是先把向量分到若干粗分区，查询时先找较近分区，再只扫描这些分区里的向量。分区中心通常通过训练得到；本节为了让所有数都能手算，直接指定两个二维中心。这样能清楚分开“中心怎样获得”和“有了中心怎样查询”两个问题。

```python
import numpy as np

class TinyIVF:
    def __init__(self, vectors, centers):
        self.vectors = np.asarray(vectors, dtype=np.float64)
        self.centers = np.asarray(centers, dtype=np.float64)
        if self.vectors.ndim != 2 or self.centers.ndim != 2:
            raise ValueError("matrices required")
        if self.vectors.shape[1] != self.centers.shape[1] or not len(self.centers):
            raise ValueError("compatible nonempty centers required")
        distances = ((self.vectors[:, None, :] - self.centers[None, :, :])**2).sum(2)
        assignments = distances.argmin(1)
        self.lists = [np.flatnonzero(assignments == i).tolist()
                      for i in range(len(self.centers))]

    def search(self, query, k, nprobe):
        if not 1 <= nprobe <= len(self.centers):
            raise ValueError("nprobe outside center count")
        query = np.asarray(query, dtype=np.float64)
        if query.shape != (self.vectors.shape[1],):
            raise ValueError("query dimension mismatch")
        center_distances = ((self.centers - query)**2).sum(1)
        nearest = np.argsort(center_distances, kind="stable")[:nprobe]
        candidates = [j for i in nearest for j in self.lists[int(i)]]
        ranked = sorted(candidates, key=lambda j: (float(((self.vectors[j]-query)**2).sum()), j))
        return ranked[:k]

vectors = [[0., 0.], [.49, 0.], [.51, 0.], [1., 0.]]
index_ivf = TinyIVF(vectors, [[0., 0.], [1., 0.]])
assert index_ivf.search([.505, 0.], 2, 1) == [2, 3]
assert index_ivf.search([.505, 0.], 2, 2) == [2, 1]
```

构造阶段先算每个文档到每个中心的平方距离，得到 N×C 矩阵。`argmin(1)` 为每条文档选择最近中心；随后每个 list 保存属于该中心的原始文档位置。查询阶段先排序中心距离，选择 nprobe 个中心，再展开它们的成员列表，并对候选做精确距离排序。

在例子中，查询位于零点五零五，最近的文档是零点五一和零点四九。但只探测右侧分区时，左侧的零点四九根本没有进入候选，第二名变成一。它的距离明显更远。把 nprobe 增加到二以后，候选覆盖全部文档，恢复精确排序。这个过程展示了 ANN 的一个核心事实：错误可能发生在候选生成阶段，后续对已有候选做再精确的排序也无法找回根本没看见的点。

本节 TinyIVF 没有训练中心、压缩向量、并发更新或高效倒排存储，不应当成 Faiss 的实现复刻。它的价值在于把分区与搜索预算的取舍变成可以观察的十几行逻辑。进入真实 Faiss 前，先能解释每一项候选为什么出现或缺失，后面的 nlist、nprobe 才不会只是调参名字。

## 小课六：聚类中心怎样从数据中得到

最基本的 k-means 反复执行两步：把每个点分给最近中心，再把每个中心移动到它所拥有点的平均位置。目标是减少点到所属中心的平方距离总和。它优化的是几何重建目标，不直接知道哪份文档对用户问题相关。因此即使聚类目标很好，也不自动保证检索任务最佳。

用一维数据零、零点二、零点八、一，初始中心零和一。分配后，前两点属于第一个中心，后两点属于第二个；更新中心得到零点一和零点九。再次分配不变，说明在这个小例子上达到了稳定状态。若初始中心都挤在一边，过程可能经过不同路径；若某个中心没有点，需要明确处理空簇，不能对空集合取平均后得到 NaN。

真实向量空间维数更高，训练样本是否代表未来查询资料分布很重要。用一种语言或主题的数据训练粗分区，再大量加入另一类资料，分区质量可能下降。更新索引时要观察各分区大小是否极不均衡、查询是否总访问少数拥挤分区，以及召回与延迟是否改变。索引训练不是一次完成后永远有效的仪式。

学习实验可以先固定随机种子和少量数据，记录每轮中心、分配和目标值。目标值通常应不增加，但因为空簇重置等工程选择，具体实现需要明确条件。不要只看最终聚类图好看就结束；打印每个点的分配能帮助你发现距离轴写错、广播维度错和更新均值的索引错误。

## 小课七：HNSW 的图搜索为什么能减少距离计算

把每个向量看成图上的一个节点，把一部分近邻关系保存为边。查询不再从第一条文档开始顺序扫描，而是从入口节点出发，比较它与邻居谁更接近查询，逐步走向有希望的区域。这个想法类似在陌生城市里根据路标逐步接近目的地，但“路标是否足够好”和“是否愿意绕一点路探索”都会影响最终能否找到真正最近点。

HNSW 使用多层邻近图。上层节点较少，适合较大尺度地移动；下层节点更多，提供更细的局部探索。查询通常先在稀疏上层寻找接近目标的入口，再在底层维护一组候选继续搜索。层次结构不是知识图谱中的概念层级，边也不表示“依赖”或“属于”；它们服务于向量空间中的导航。

只做贪心移动有一个明显风险：当前节点的每个邻居都比它更远，但真正最近点藏在一个需要暂时绕远的区域。于是算法陷入局部停点。维护更宽的候选集合能探索多条路线，降低漏召回风险，却增加距离计算和内存访问。搜索宽度参数控制的正是这种预算取舍，不是把图变成绝对正确的证明。

下面实现一个有界的单层图探索器。它不是完整 HNSW，没有多层构建和邻居选择启发式；它帮助你看见候选堆、访问集合和探索预算三个对象怎样配合。不要把这个短程序的性能或准确率标成 HNSW 实测。

```python
import heapq

def graph_candidates(vectors, adjacency, query, entry, max_visits):
    if max_visits <= 0 or not 0 <= entry < len(vectors):
        raise ValueError("valid entry and positive visit budget required")
    def distance(index):
        if len(vectors[index]) != len(query):
            raise ValueError("dimension mismatch")
        return sum((a-b)**2 for a, b in zip(vectors[index], query))
    frontier = [(distance(entry), entry)]
    queued = {entry}
    examined = []
    while frontier and len(examined) < max_visits:
        score, node = heapq.heappop(frontier)
        examined.append((score, node))
        for neighbor in adjacency.get(node, []):
            if not 0 <= neighbor < len(vectors):
                raise ValueError("invalid edge target")
            if neighbor not in queued:
                queued.add(neighbor)
                heapq.heappush(frontier, (distance(neighbor), neighbor))
    return sorted(examined), {"visited": len(examined), "queued": len(queued)}

vectors_graph = [[0.], [2.], [4.], [6.], [8.]]
edges_graph = {0:[1,4], 1:[0,2], 2:[1,3], 3:[2,4], 4:[0,3]}
ranked, statistics = graph_candidates(vectors_graph, edges_graph, [5.9], 0, 4)
assert ranked[0][1] == 3
```

最小堆 frontier 保存待探索节点，按到查询的距离优先取出。queued 记录已经入堆的节点，防止图中的环导致重复入队；examined 记录真正被展开的节点。入队数量与访问数量不同，预算应明确限制哪一个。一个系统如果只限制最终返回数量，却允许无限遍历，仍然可能消耗大量资源。

真实 HNSW 还需要在建图时选择连接，控制每层邻居数量，并兼顾局部近邻与导航可达性。M、构建搜索宽度与查询搜索宽度分别影响图连接、构建质量和查询探索，不能把它们都理解成“返回几个结果”。返回 k 是最终接口需要多少个近邻；内部探索通常需要比 k 更多的候选才能获得较好召回。

HNSW 的图结构会占用原始向量之外的内存。若你只计算四乘维数乘向量数，就漏掉邻接列表、层级信息、ID、分配器和运行时对象。构建过程也可能需要额外临时内存。评估是否适合一台机器时，必须测实际进程峰值或使用明确的实现估算，不能把原始向量字节数当成整个索引占用。

## 小课八：PQ 怎样用有限码本表示很多向量

Product Quantization 可以从一个简单问题开始：四维向量每个坐标都保存浮点数，需要四个数；能否把前两维与后两维分别替换成一个小编号？为前两维准备一组代表点，称为第一段码本；为后两维准备另一组代表点，称为第二段码本。每个向量在每段选择最近代表点，只保存两个编号。

假设第一段码本只有 `(0,0)` 与 `(1,1)`，第二段码本只有 `(0,1)` 与 `(1,0)`。向量 `(0.1,0.2,0.8,0.1)` 前段更接近第零个代表点，后段更接近第一个，所以编码为 `[0,1]`，重建向量为 `(0,0,1,0)`。你用更少信息表示了原向量，但产生了重建误差。这是压缩的基本取舍，不是无损编码。

```python
import numpy as np

codebooks = [np.array([[0.,0.],[1.,1.]]),
             np.array([[0.,1.],[1.,0.]])]

def pq_encode(vector, codebooks):
    vector = np.asarray(vector, dtype=np.float64)
    widths = [book.shape[1] for book in codebooks]
    if sum(widths) != len(vector):
        raise ValueError("subspace widths do not cover vector")
    codes, start = [], 0
    for book, width in zip(codebooks, widths):
        part = vector[start:start+width]
        codes.append(int(((book-part)**2).sum(1).argmin()))
        start += width
    return codes

def pq_decode(codes, codebooks):
    if len(codes) != len(codebooks):
        raise ValueError("one code per subspace required")
    return np.concatenate([book[code] for book, code in zip(codebooks, codes)])

codes = pq_encode([.1,.2,.8,.1], codebooks)
assert codes == [0,1]
assert np.array_equal(pq_decode(codes, codebooks), [0.,0.,1.,0.])
```

程序先检查所有子空间宽度之和是否覆盖整条向量，防止把尾部维度默默丢掉。每段单独计算到码本代表点的平方距离，选最小编号。解码则取出对应代表点并拼接。真实系统通常会训练码本，并使用紧凑整数存储；这里使用 Python 列表只是为了观察机制，并没有实现实际内存压缩收益。

为什么叫“乘积”量化？如果每段有 K 个代表点，分成 m 段，那么组合上可以表示 K 的 m 次方种重建向量，而不必显式保存所有组合。每段只存 K 个小向量，组合由各段编号决定。这个结构利用了子空间分解，但也忽略了一部分跨段相关性。不同旋转或分段策略可能改变重建误差，因此分段不是完全无关紧要的实现细节。

若每段有二百五十六个代表点，一个编号可用八位，也就是一字节。分成 m 段时，每条编码约需 m 字节，不含码本、ID 和其他结构。与 d 维 float32 的四乘 d 字节相比，可以大幅降低编码数据量。但压缩率不等于检索质量，必须测近邻召回与任务效果；码本训练和重建误差的分布也需要检查。

## 小课九：不重建全部向量也能估计距离

给定查询 q，PQ 的一个常见计算思路是先为每段建立查找表：查询对应子向量到该段每个码本代表点的距离。某条压缩文档的近似距离，就是按它的各段编号查表再求和。这样不用为每个候选重建完整浮点向量，也不用逐坐标做全部乘减。

```python
def pq_distance_table(query, codebooks):
    query = np.asarray(query, dtype=np.float64)
    tables, start = [], 0
    for book in codebooks:
        width = book.shape[1]
        part = query[start:start+width]
        tables.append(((book-part)**2).sum(1))
        start += width
    if start != len(query):
        raise ValueError("query dimension mismatch")
    return tables

def pq_approx_distance(codes, tables):
    if len(codes) != len(tables):
        raise ValueError("code/table count mismatch")
    return sum(float(table[code]) for code, table in zip(codes, tables))

q = np.array([.2,.1,.9,.2])
tables = pq_distance_table(q, codebooks)
reconstructed = pq_decode(codes, codebooks)
assert np.isclose(pq_approx_distance(codes, tables), ((q-reconstructed)**2).sum())
```

这个断言证明查表结果等于查询到重建向量的平方距离，不是查询到原始向量的精确距离。二者可能不同，排名也可能变化。理解这一点非常重要：算法实现可以完全正确地计算了一个近似距离，而检索仍然因压缩误差漏掉真正近邻。调试时先检查近似计算是否符合定义，再研究近似定义带来的质量损失。

把 IVF 与 PQ 组合时，误差来源至少有两层：粗分区可能没访问某个文档，压缩距离又可能在已访问候选内部改变排序。增加 nprobe 主要缓解第一类问题，增加码本容量或保留更多原始信息主要影响第二类。若你只知道最终 recall 下降，却不拆误差来源，就容易调错参数。

一种常见补救是先用压缩索引召回更多候选，再用原始向量精确重排。它能纠正候选内部的压缩排序错误，但不能找回完全没有进入候选的文档。保存原始向量还会增加存储与访问成本，因此这不是免费的万能方案。完整实验应记录候选数、重排成本和最终召回，不能只展示精确重排后的最好数字。

## 小课十：把表征误差、索引误差和任务误差拆开

设一个问题的正确答案在文档 C。编码器却把无关文档 A、B 映射得更接近查询。精确搜索返回 A、B，ANN 也返回 A、B，近邻 recall 可以达到一，但任务失败。此时继续提高 HNSW 搜索宽度不会改变编码器定义的邻近关系。你需要检查训练数据、输入模板、切块或混合检索，而不是只优化索引。

反过来，编码器的精确前两名是正确资料 C、D，但 ANN 只返回 C 和无关 A。近邻 recall 为二分之一，任务是否失败取决于问题是否需要 D。如果 C 已经足够回答，最终任务可能仍然成功；如果必须组合 C、D，答案证据就不完整。这个例子说明近邻 recall 和任务指标相关但不等价。

再加上回答生成阶段：C、D 都进入上下文，模型仍然写错条件。这时检索与索引可能都达到目标，问题在证据使用或验证。一个完整评测报告应至少保存精确近邻集合、ANN 集合、人工相关性标签、实际上下文以及最终断言。它们支持不同层面的诊断，不能只留最终平均分。

预算扫描也应分别观察质量与成本。对同一批查询，在相同硬件、线程、数据和 warm-up 条件下改变搜索预算，记录每题召回、批次耗时、尾延迟以及索引内存。小规模教学实验不必追求复杂统计，但必须保持可比较条件。某次运行较快可能来自缓存热身或系统负载，不能自动归因于参数更好。

## 小课十一：从平均词向量走向真实文本编码器

课程微型学习器把词向量平均，方便你完整推导梯度。真实文本编码器通常会先对 token 序列做上下文计算，再把一串 token 表示汇总成一个句子或段落向量。汇总方式称为池化，可能取特定位置，也可能对有效 token 求平均，或使用模型专门训练的输出。你必须遵循模型约定，不能看到最后一层张量就随便沿某个轴平均。

平均池化时要考虑 padding。假设两条文本分别有三和五个有效 token，为组成矩阵，短文本补两个占位位置。若把五个位置全部平均，短文本的表示会被 padding 污染或缩放；正确做法通常根据有效位置 mask 求和，再除以有效 token 数。空文本的有效数可能为零，需要明确拒绝或采用专门表示，不能让除零产生 NaN 后继续进索引。

查询与文档的输入模板也可能不同。检索任务中的短查询与长文档承担不同角色，某些模型训练时使用不同前缀或编码路径。把一条查询当作文档模板编码，可能仍返回形状正确的数组，却降低任务效果。接口适配时应把 query encoder 与 document encoder 的职责分开，即使它们最终调用同一个权重模型。

截断是另一个不能隐藏的行为。文档超过编码器输入长度时，若只保留开头，后半段的信息没有进入向量。后续 ANN 再准确，也无法利用从未编码的内容。切块、标题增强和长文编码策略应该与实际模型输入限制共同设计，并在元数据里记录截断是否发生。不要把“API 请求成功”误当成全文已经被完整表示。

## 小课十二：补完多正例目标，而不是把正确文档当负例

前面的微型学习器假设每个查询只对应同一行的一个正确文档。真实资料中，同一问题可能有多个正确来源。若其他正确文档也放在同一个 batch，却被当作负例，训练会把本应接近的材料推远。一个明确的多正例目标是：分子对所有正例的指数分数求和，分母对全部候选求和，再取负对数。

设每行 logits 为 s，正例集合为 P，则损失是 `logsumexp(s_all)-logsumexp(s_positive)`。对每个 logit 的梯度等于全候选 softmax 概率，减去仅在正例集合上归一化的概率；非正例在后一项为零。若只有一个正例，这就退化为普通交叉熵。这个推导直接告诉你代码应该怎样写，而不需要凭猜测修改标签矩阵。

```python
import numpy as np

def multi_positive_loss_gradient(scores, positive):
    scores = np.asarray(scores, dtype=np.float64)
    positive = np.asarray(positive, dtype=bool)
    if scores.ndim != 2 or positive.shape != scores.shape:
        raise ValueError("matching two-dimensional arrays required")
    if not np.isfinite(scores).all() or not positive.any(axis=1).all():
        raise ValueError("finite scores and at least one positive per row required")
    all_max = scores.max(axis=1, keepdims=True)
    all_exp = np.exp(scores-all_max)
    all_prob = all_exp/all_exp.sum(axis=1, keepdims=True)
    positive_scores = np.where(positive, scores, -np.inf)
    positive_max = positive_scores.max(axis=1, keepdims=True)
    positive_exp = np.exp(positive_scores-positive_max)
    positive_prob = positive_exp/positive_exp.sum(axis=1, keepdims=True)
    all_lse = all_max[:,0]+np.log(all_exp.sum(axis=1))
    positive_lse = positive_max[:,0]+np.log(positive_exp.sum(axis=1))
    loss = float(np.mean(all_lse-positive_lse))
    gradient = (all_prob-positive_prob)/len(scores)
    return loss, gradient

scores = np.array([[2., 1., 0.]])
mask = np.array([[True, True, False]])
loss, gradient = multi_positive_loss_gradient(scores, mask)
assert loss >= 0
assert np.isclose(gradient.sum(), 0)
for column in range(3):
    epsilon = 1e-6
    plus, minus = scores.copy(), scores.copy()
    plus[0,column] += epsilon
    minus[0,column] -= epsilon
    numerical = (multi_positive_loss_gradient(plus, mask)[0]
                 - multi_positive_loss_gradient(minus, mask)[0])/(2*epsilon)
    assert np.isclose(numerical, gradient[0,column], atol=1e-7)
```

这个目标奖励正例集合总概率，不要求所有正例得分一样高。因此它与“对每个正例分别做交叉熵再平均”不是同一个目标。后者可能更强调均匀提高所有正例，前者可能主要依靠其中容易的正例获得较低损失。选择哪种目标要看训练意图与评测，不能把所有支持多正例的公式混称为完全等价。

如果你把这个函数接回 TinyDualEncoder，先用它替换 grad_scores 的计算，再保留查询侧和文档侧两条参数梯度。训练数据要有明确的正例布尔矩阵，不再只靠行号推断。先运行有限差分，再观察 loss，最后使用独立查询评价。一次完整改造应包含数据合同、损失、梯度和测试四部分，而不只是增加一行 mask。

## 小课十三：归一化编码器的梯度为什么不能省略

若编码向量 x 被归一化为 u=x/||x||，损失对 u 的梯度不能直接当作对 x 的梯度。归一化改变了方向与长度之间的关系：沿当前方向放大 x 不会改变 u，因此这一方向的无效梯度应被投影掉。设下游梯度为 g，则对 x 的梯度是 `(g-u*(u·g))/||x||`，前提是范数非零。

可以用二维例子验证。x 为三、四，范数五，u 为零点六、零点八；若下游梯度 g 恰好等于 u，括号里得到零，因为只沿当前向量方向改变大小不会改变归一化结果。若 g 与 u 正交，投影项为零，梯度只需除以五。这个几何解释帮助你理解公式，而不是把矩阵微分结果当成需要死记的符号。

在实际训练中，通常还会使用小的数值保护或明确处理零范数，但不同保护方式会改变零附近的函数与梯度。你必须让解析梯度与 forward 使用完全相同的定义，并用有限差分检查。不能 forward 用 `max(norm,epsilon)`，backward 却假装一直在非截断区域。看似只是数值细节，实际上影响你是否实现了同一个函数。

## 小课十四：真实 Embeddings 适配器的一次请求怎样被验证

课程 `EmbeddingClient` 把真实联网放在显式授权入口后面。默认实验使用注入的离线 transport，返回人为构造的向量，目的是测试协议和数据管道。只有 `--live` 才读取你配置的模型接口并发送四条虚构文本。拥有聊天模型 API 不等于该服务提供 embeddings；必须先确认服务支持相应接口和模型，不应把聊天返回的一串数字当成稳定编码器协议。

一次批量请求的响应可能按不同顺序返回，因此不能直接按列表位置把向量配给文档。适配器读取每个 item 的 index，检查它是合法整数、没有重复、范围正确，再按原请求顺序重建 rows。若三个文档的向量被错配，所有维数检查都可能通过，但检索身份完全错误。这是一个典型的数据对齐错误，需要专门的乱序响应测试。

响应还要检查维数一致、坐标有限、模型身份存在，以及不同批次是否返回相同模型身份。请求了固定 dimensions 时，返回长度必须符合。没有 usage 字段时，记录未知，而不是零消耗；部分批次有计数、部分没有时，只能报告已知部分与不完整状态。数据缺失不应该被一个方便的默认零掩盖。

向量生成完成后，课程 dense_search 会再次检查当前权限与版本。因为编码过程可能花时间，在调用前可见的文档，返回时可能已经被撤权或更新。第二次检查只能保护最终返回；若真实 API 接口本身不允许接收某类资料，还需要更早的数据出口授权。不要把“最终没有显示”误当成“数据从未发送到外部”。

真实练习先使用仓库四条虚构输入，不发送公司资料。记录请求模型、返回模型、维数、距离规则、输入模板和实际 usage 状态。然后在自己有权使用的小语料上建立精确基准，再考虑缓存和 ANN。缓存键至少绑定文档版本、编码器身份和预处理规则，不能只用正文字符串或 doc_id。

## 小课十五：十二道验收题与参考答案

**题一：同维数模型混用。** 两个模型都输出七百六十八维，能否直接用新查询向量检索旧文档向量？答案是否定的，维数只证明数组可以相乘，不证明坐标空间兼容。完整迁移应重编码文档、建立对应新索引、在固定查询集比较，并把查询编码器与索引作为一个版本对切换。若服务只提供可变别名，应记录这个未锁定边界。

**题二：手算排序差异。** q 为一、零，a 为一、零，b 为十、一。答案：点积偏好 b，余弦偏好 a。计算必须写出 b 的范数为根号一百零一。若把 b 先归一化，再计算点积，排序会与余弦一致，但那已经改变了输入，而不是证明原始点积本来就等价。

**题三：为什么省略平方根不改排序。** 因为平方根在非负数上严格单调，距离与平方距离对候选的大小顺序相同。阈值数值则必须相应平方或开方，不能照搬。答案还应指出这个结论针对合法非负距离，不是允许 NaN 或溢出的结果继续排序。

**题四：极值余弦。** 为什么两个一乘十的三百零八次方坐标不能直接平方？平方可能超过浮点范围。参考修复是先按最大绝对值缩放，再求范数和单位向量。测试既要包含极大值，也要包含极小值和全零；只修溢出而未考虑下溢，仍然可能把合法方向当成零向量。

**题五：IVF 漏掉谁。** 对本章零、零点四九、零点五一、一，查询零点五零五，只探测右侧分区，返回哪些位置？答案是二和三，精确结果是二和一。增加候选内部排序精度无法发现左区零点四九，因为它未进入候选；增加 nprobe 才直接针对这次漏召回来源。

**题六：HNSW 参数与返回 k。** 搜索宽度是否等于返回条数？不等于。返回 k 是输出需求，内部搜索宽度决定探索候选预算。只探索 k 个节点通常不足以保证找到好近邻，扩大搜索可能提高召回也会增加工作。不能把一次参数提高后结果没变化解释成该参数永远无效，可能只是这个简单查询已经容易。

**题七：PQ 编码。** 使用本章两个码本，向量零点一、零点二、零点八、零点一编码为零、一，重建为零、零、一、零。查表距离等于查询到重建向量的距离，不是到原向量的精确距离。你应手算至少一组原始距离与重建距离的差，才能理解压缩误差不是程序 bug。

**题八：两层误差。** IVF-PQ 结果差，应该先增大 nprobe 还是增加码本精度？不能凭最终分数直接决定。先在已访问候选上使用原始向量精排，观察误差是否主要消失；再扩大探测分区，观察候选覆盖。这个分解实验分别诊断压缩排序误差与分区漏召回，比一次同时改全部参数更可解释。

**题九：多正例。** 为什么同一问题的另一篇正确文档不能总当 in-batch negative？因为这会给训练错误监督，把应接近的资料推远。参考完整解是构建正例矩阵，使用本章多正例损失与梯度函数，有限差分核对后再接回共享参数的两条梯度路径。仅复制训练行并没有改变单对角线目标的假设。

**题十：池化与 padding。** 三个有效 token 加两个 padding，能否直接对五行求平均？通常不能，除非模型契约专门如此定义。应使用有效位置 mask 求和，并除以有效 token 数；空输入单独处理。检查输出维数不能发现这个错误，因为错误平均仍然产生同样维数。

**题十一：批次乱序。** 请求 A、B、C，响应列表顺序为 C、A、B，但 index 正确，怎样恢复？创建长度三的空列表，按每项 index 写入对应位置，同时拒绝重复、越界和缺失。不能先排序文档文本再猜配对，也不能忽略 index 仅相信响应顺序。错配后相似度算法再正确也会引用错误文档。

**题十二：无 usage。** 供应商不返回 token 计数时，报告应写零还是未知？答案是未知。零意味着已知没有消耗，未知意味着没有足够信息判断。可另外保存有报告的批次小计和完整性标记，但不要把部分小计显示为全部费用。这个原则适用于所有观测数据，不仅是 API 计费。

## 小课十六：完整实验路线与交付标准

第一轮只做二维和三维手算，完成点积、余弦、平方距离以及零向量边界。第二轮用 NumPy 构建精确搜索，明确矩阵轴和稳定身份。第三轮运行 TinyIVF 与单层图探索，逐个记录哪些候选被访问，制造边界漏召回。第四轮实现 PQ 编码和查表距离，分别比较压缩前后的近邻。每轮都保留一份可以解释每个数的样例，避免只在大随机数据上看一个平均指标。

第五轮运行课程微型双编码器，检查共享参数梯度和训练集拟合。增加一个多正例案例，用完整损失函数替换目标并做有限差分。第六轮才连接真实 embeddings 接口或本地模型，并保留精确搜索作为索引基线。第七轮按可选工作簿安装 FAISS，使用固定数据、单线程和 warm-up 对照 Flat 与 HNSW。没有安装或没有执行的步骤必须明确标记，不能用前一轮教学实现的成功替代它。

最终报告应把表征质量、近似索引质量、回答质量分成三栏。记录实际硬件、依赖版本、数据快照、编码器身份、向量维数、归一化与距离规则、索引参数、候选数、任务标签和时间测量方法。若数据量只有几千条，CPU 足够完成本章的大部分机制验证，不需要为了“学习向量检索”长时间占用共享 H100。

掌握本章以后，你应当能读懂真实向量检索代码里的 encode、normalize、add、search 和 rerank 分别承担什么工作，能把 shape 错、身份错、度量错、索引漏召回和语义表征不足分开定位。做到这一点，再去比较各种库和模型，才是在比较可解释的工程选择，而不是追逐一个无法说明含义的排行榜数字。

## 源码检查站：逐行读懂可选 FAISS 对照实验

打开 `labs/knowledge/faiss_lab.py`，先看依赖导入。NumPy 与 faiss 放在函数内部的 try 块中，缺少依赖时返回明确的 SKIP 状态，不会自动安装、下载模型或初始化 GPU。这是实验资源合同的一部分。你在普通 CPU 环境运行时，应先读状态字段，不能只看到程序退出码为零就把实验写成已经完成。

随后检查规模约束：k 必须至少为一且不大于文档数，维数与查询数必须为正，课程还限制最大文档数、维数和查询数。它们防止一个入门实验因为输错参数意外消耗大量内存。生产基准可以采用更大规模，但应在有计划的环境中单独调整，而不是让教材默认命令直接占满服务器。

随机数据用固定 seed 构造，再转成 float32。固定 seed 让输入可重建，float32 与 FAISS 常见输入契约一致。接着 `normalize_L2` 对文档与查询都做归一化，因此后面的内积索引可以被解释为余弦排序。如果删除其中一边的归一化，实验就改变了比较对象；若只看代码仍然能运行，很容易漏掉这种语义变化。

`IndexFlatIP` 建立精确内积基线，add 把文档向量加入索引，search 返回得分与内部位置。课程把这些位置作为精确近邻集合 ground。真实项目还要保存从内部位置到业务 chunk_id 的映射；如果重建后顺序不同，必须同步更新映射。不能把某次运行中的行号写进长期引用后期待它永久有效。

HNSW 索引使用同一批已经归一化的文档，并明确内积度量。构建参数与搜索参数分开设置，随后记录构建耗时。每个搜索预算先用一条查询 warm-up，再计时整批查询。这样减少首次初始化开销对测量的影响，但并不自动消除操作系统调度、CPU 频率和其他负载的影响。报告中的时间是一次实验观测，不应当作普遍保证。

近邻 recall 的计算把每条查询的精确 top-k 与近似 top-k 转成集合，求交集数量再除以 k，最后对查询平均。它不使用人工相关性标签，所以不能称为问答准确率。若两个候选距离完全相同，精确 top-k 的身份选择还可能受到同分规则影响；研究严格的 ANN 评价时，应注意这种边界，避免把同样好的等距点误当成严重质量退化。

最后，程序把依赖版本、数据规模、线程数、度量与限制一起写入结果。你复制实验时应保留这些字段，而不是只截取最快的一行。若想研究线程扩展，先改变线程参数并重新测完整曲线；若想研究语义质量，换成真实模型向量并加入人工任务标签。一次只改变一个问题，结果才容易解释。

## 阈值实验：为什么余弦零点八不是通用通过线

某个模型在某套数据上，相关文本的余弦可能集中在零点七附近；另一个模型的相关与不相关样本都可能集中在更高区间。相似度范围受训练、归一化、数据领域和输入模板影响，因此不能把一个网上常见阈值直接当成通用事实。阈值应在独立标注集上观察误报与漏报，并结合拒答代价选择。

建立一个小验证表，分别收集真正支持答案、主题相关但不支持、完全无关、语义相反四类对。打印各类分数分布，再尝试不同阈值，记录留下多少正确证据与多少错误候选。若相反陈述也常有高相似度，说明语义邻近不能替代断言支持判断。此时继续提高阈值可能同时删掉有用证据，正确方向是加入更精细的重排或验证机制。

阈值还应绑定到模型和资料快照。换模型后即使排序相近，分数分布也可能移动；继续使用旧阈值会改变拒答率。上线迁移时同时比较排名指标、阈值后的证据覆盖和拒答比例，而不是只验证向量维数没变。若系统使用多个检索器，每个原始分数的阈值也应有各自依据，不能把 BM25、余弦与重排 logit 放在同一刻度上。

一个完整的迁移记录至少保留旧模型与旧索引、新模型与新索引、相同问题集合、逐题候选差异以及回滚办法。切换后若发现质量退化，应能恢复一整套兼容版本，而不是只把查询模型名字改回去，却仍然搜索新坐标空间中的文档。这是向量检索里最基本的版本一致性要求。

### 进阶必做：亲手训练一个微型双编码器

到目前为止，词法向量仍无法知道 feline 与 cat 的对应关系。现在直接训练一个小模型，让你看到“语义靠训练形成”在代码里到底是什么意思。运行：

```bash
python -m labs.knowledge.neural_encoder
python -m unittest tests.test_knowledge_neural -v
```

这里只需要 NumPy。程序不下载预训练权重，不使用 API，不占 GPU。训练集只有四对虚构查询与文档：feline pet→cat animal、canine pet→dog animal、key value reuse→cache token、queued jobs→scheduler request。示例会显示损失下降，以及第一条训练查询从错误首位变成正确首位。它证明模型参数能通过监督改变检索空间，**不证明获得了通用语言语义能力**。我们特意输出这个限制，避免把训练集拟合当成泛化。

#### 词表与可学习参数

设词表大小V，向量维数d，参数矩阵E的形状为`[V,d]`。第i行就是第i个词的可学习向量。初始化用固定随机种子和小正态分布。此时 feline 与 cat 的向量没有预先设定的关系；它们接近与否只是随机。

`features(texts)` 把每句话转换为词频平均的行向量X，形状`[batch,V]`。例如句子“red red apple”，red维是2/3，apple维是1/3，其余为0。句子编码就是`X @ E`，等价于对出现词的向量按次数求平均。这个编码器不理解词序，因此“dog bites cat”与“cat bites dog”得到同样向量，这个局限能用一行测试证明。

平均词向量模型不等于Transformer。它没有注意力、位置编码和上下文依赖，无法处理复杂否定与组合语义。但矩阵形状、可学习参数、相似度、损失与反向传播这条链和更复杂模型具有可迁移的结构。

#### 一批正负样本如何构造监督

每一行查询qi与同一行文档di是正对；同一batch其他文档当作负对。查询矩阵Q=`Xq @ E`，文档矩阵D=`Xd @ E`，相似度S=`Q @ D.T / temperature`，形状`[batch,batch]`。对角线表示正对，非对角线表示这次训练中的负对。

“in-batch negatives”不保证所有非对角线都真的不相关。如果两个查询都可以由同一文档回答，把它强行当负例会引入错误监督。真实检索训练需要处理同义问题、重复材料与难负例，本玩具数据通过手工构造减少歧义。

对每行scores做softmax得到候选概率分布P。损失是对正确列的负对数概率取平均，即`L=-mean(log(P[i,i]))`。这里概率表示当前batch内分类分布，不是文档事实真假的概率，也不是整个语料库中答案完整性的概率。

#### 手算二选一的一次损失

假设某查询对两个文档的logits是[2,0]。softmax先减最大值2，得到[0,-2]，指数为[1,0.135335]，归一化得到约[0.880797,0.119203]。如果第一个是正确文档，损失为`-ln(0.880797)≈0.126928`。如果第二个才正确，损失约2.126928。错误而自信会被更重惩罚。

减最大值不改变softmax，因为所有指数共同乘了同一个系数，分子分母约掉。这样可以防止大正数exp溢出。代码直接用稳定log-sum-exp求损失，避免先softmax后log时某个很小概率下溢成0。

temperature缩小会放大logits差异，使分布更尖锐，也会改变梯度尺度。不能把它当生成模型temperature：两者都影响softmax形状，但这里是训练对比目标的参数，不是生成时的采样设置。

#### 反向传播不是神秘的黑箱

令Y为单位矩阵，即正确位置为1，其余为0。对batch平均交叉熵，`dL/dS=(P-Y)/batch`。这意味着正确项的梯度通常为负，梯度下降会提高它；错误项梯度为正，梯度下降会降低它。

由于`S=Q Dᵀ / τ`，矩阵链式法则给出：

```text
grad_Q = grad_S @ D / temperature
grad_D = grad_S.T @ Q / temperature
```

又因为Q=XqE，D=XdE，两个分支共用E，所以参数梯度要把两条贡献相加：

```text
grad_E = Xq.T @ grad_Q + Xd.T @ grad_D
```

这个加号很关键。若只更新查询侧，文档侧仍然通过同一个参数影响损失，却没有被完整计算，梯度就是错的。共享参数的反向传播应汇总所有使用路径，这个思想以后读Transformer权重绑定或多分支计算也会反复出现。

#### 用有限差分证明梯度，而不只看loss下降

错误梯度有时也能让loss暂时下降，所以“训练成功”不是充分验证。选一个参数E[r,c]，分别加上与减去很小ε，重新计算损失，用`(L_plus-L_minus)/(2ε)`近似偏导，再与解析梯度比较。本卷测试选择几个坐标，ε=1e-6，使用float64控制数值误差。

有限差分开销大，不适合验证百万参数全部坐标，但对小模型抽点检查很有用。ε太大会有截断误差，太小则被浮点舍入淹没。测试时还要关闭随机dropout或固定所有随机状态，否则两次损失差异不全来自那个参数。

训练函数使用简单梯度下降，步数250，学习率0.15，并在梯度范数超过5时按比例裁剪。裁剪是限制步长方向的尺度，不是修复错误梯度。课程没有加入复杂优化器，因为当前目标是完整理解参数如何被更新，而不是追求最强效果。

#### 如何证明你没有把拟合误当能力

先打印训练查询排名，再单独提出训练没有出现的词。代码对全未知查询返回空结果，而不会把零向量随便排出的第一文档当答案。对于词表里有词但组合没见过的查询，模型仍可能有得分，但不能保证正确。

至少构造三类评估：训练原句、词序改写、含全新概念的查询。词序改写通过是因为平均池化天然忽略顺序，不是学到了复杂语言理解。新概念失败是模型规模与训练信息不足的合理结果。只有用独立相关性标注集并避免训练数据泄漏，才能谈检索泛化。

**附加练习 A：** 删除共享参数梯度中的文档分支，运行有限差分测试。预期失败；恢复后通过。写出失败坐标与误差，比仅观察loss曲线更能证明你掌握了反向传播。

**附加练习 B：** 把搜索相似度从原始点积改为余弦，重新评测。训练用点积、搜索用余弦不是自动等价；若希望一致，可以在训练中引入归一化并推导其梯度，或明确记录这是一个后处理策略。

**附加练习 C：** 为同一查询添加两个都正确的文档。当前单对角线目标会把另一个正确文档当负样本。参考修正方向是多正例损失，例如分子对所有正例分数求指数和，分母对全部候选求和，再完整推导与测试。不能只复制一行数据后声称训练支持多个正例。

**附加练习 D：** 给编码器加入保存/加载参数的功能。必须同时保存词表顺序、维数、权重、tokenizer版本和训练配置；只保存矩阵而丢掉词到行的映射，加载后会把向量赋给错误的词。加载时校验V与d，拒绝形状不匹配。

这一小模型给你一个真正可修改的学习器。之后阅读Sentence Transformers的encoder、pooling、loss和evaluator时，可以把复杂实现映射回这四个已掌握的对象，而不是只调用encode后把返回的数组当成无法理解的魔法。

## 综合工作坊：同一维度的模型迁移为何仍需重建索引

把旧编码器看成一个坐标变换，文档与查询必须使用同一变换。假设旧文档向量分别是东西方向与南北方向，查询指向东西；新编码器把所有表示旋转九十度。如果只更新查询编码器，查询会命中原来南北文档，虽然所有数组仍二维、有限且归一化。这个反例证明维度检查只能发现形状错误，不能证明坐标兼容。

```python
import numpy as np

old_documents = np.array([[1.0, 0.0], [0.0, 1.0]])
old_query = np.array([1.0, 0.0])
rotation = np.array([[0.0, -1.0], [1.0, 0.0]])
new_documents = old_documents @ rotation.T
new_query = old_query @ rotation.T
assert int(np.argmax(old_documents @ old_query)) == 0
assert int(np.argmax(old_documents @ new_query)) == 1
assert int(np.argmax(new_documents @ new_query)) == 0
```

第一条是旧系统正确，第二条只升级查询而混用旧索引，排名错，第三条两边一起变换后恢复。正交旋转保持同空间点积，所以第三条与第一条一致。真实模型升级不只是旋转，语义分布也可能改变，因此重建后还要做任务评价，不能认为坐标一致就质量一定提高。

模型配置身份应包含权重或可用版本标识、输入模板、池化、截断、维数、归一化与距离类型。服务只提供别名时，记录未固定限制，并用固定文本探针观察变化。探针相同输出不是完整质量证明，但能帮助发现明显漂移；任务相关性标签仍是选择模型的依据。

### 一次完整迁移的状态与验收

先冻结旧语料快照与旧索引，保存一组查询的精确结果、相关性标签和运行配置。用新编码器构建独立新代际，禁止向旧索引追加不同空间向量。构建清单逐个核验 chunk 身份、向量数量、维度与有限值，完成后在开发集比较 Recall、MRR、nDCG 与成本。最终切换时让查询编码器与索引指针作为一对发布。

回滚也必须成对。只把查询模型退回旧版、索引仍新，会再次混空间。可以把 active_generation 指向包含 encoder_config 与 index_path 的不可变配置对象，发布只切换一个指针。外部数据库与模型服务之间没有自动事务时，运行器先读取该配置快照，再执行整次查询，避免中途分别读取最新模型与最新索引产生组合错误。

更新期间旧资料引用仍需当前权限复核。新索引构建可能持续很久，某文档在等待期间被撤权，不能因为它已编码就允许发布给所有人。内容代际与授权状态可以分开处理，但最终工具发送与输出边界必须检查当前权限。向量本身可能泄露信息，因此外部服务与存储也属于数据流的一部分。

### 编码输入模板的隐性影响

有些检索编码器区分 query 与 document 的输入前缀或指令。即使权重相同，漏掉模板可能改变表示质量；把标题、正文与元数据按不同顺序拼接，也会改变 token 序列。索引配置应记录实际送入编码器的文本格式，而不是只记录原文 hash。否则缓存可能复用旧模板向量而查询使用新模板。

截断也要可观察。长文尾部包含关键否定或条件，编码器只看前半段，检索表示不会包含那些信息。把 chunk 切得足够短可以减少问题，但字符数与模型 token 数不等价。真实实验记录输入 token 统计或截断标记，构造答案位于尾部的反例，验证不是仅因为首段关键词多就排前。

池化需要正确处理 padding。若平均池化把补齐位置也算进去，不同 batch 最大长度会影响同一文本向量，重复编码可能因同批其他文本变化而变。固定单文本与混合长度批次对比，是一个有价值的编码器回归。是否应该精确相同取决于模型与数值配置，但明显长度依赖应追踪 mask 与 pooling。

### ANN 调参的完整因果链

先固定编码向量，建立精确 Flat 结果作为邻居金标，再改变 HNSW 的搜索参数或 IVF 的探测桶数。这样质量差异来自近似搜索，不混入编码器变化。测量包含预热、重复批次、固定线程与报告分位数，避免单次计时噪声。小规模近似索引可能比 Flat 慢，这是管理开销占主导的合理结果，不应删掉。

再固定 ANN 参数，改变编码器，使用任务相关标签评价语义质量。两套实验分开，才能知道该调索引还是换表示。若精确邻居本身不相关，ANN Recall 再高也无济于事；若精确排名很好而近似漏掉关键文档，才需要增加搜索预算或改索引结构。

最后把索引检索放回完整 RAG。相关候选进入 top-k 仍不保证上下文保留、引用正确或答案支持。记录候选召回、上下文覆盖与最终支持三个阶段，避免把答案改善全归给一个向量参数。工程评价需要沿数据流分解，才能合理使用个人显卡或服务器资源。

### 训练样本里的假负例与任务迁移

双编码器批内负例假设其他文档不是当前查询的正例，但一批中可能有两篇都正确回答同一问题。若只把对角线当正例，训练会把另一个正确来源推远，这叫假负例。多正例目标、样本去重与标签检查可以缓解，不能仅靠增加 batch 解决。batch 越大，负例更多，也可能引入更多未标注正例。

训练损失下降只证明模型更适合当前训练目标，不证明真实检索更好。构造独立查询与措辞变化，检查是否只是记住词共现；加入同名不同项目、否定与版本差异，检查表示是否丢掉关键区分。课程 TinyDualEncoder 的平均词特征没有词序能力，因此某些错误是模型结构边界，不是训练轮数不够。

迁移到真实预训练编码器后，仍需相同任务标签。通用语义相似可能把相反但同主题句子拉近，技术错误码则可能需要关键词路线。混合检索的价值来自互补信号，但融合与重排也必须评测。不要把 dense 视为 BM25 的必然替代，它们解决的匹配问题有交集也有差异。

最后保留精确搜索作为长期测量尺。任何压缩、量化或近似索引升级，都先和同一向量空间的精确结果比较，再回到语义标签与答案支持。这样你能把数值误差、近似误差与任务误差逐层分开。
