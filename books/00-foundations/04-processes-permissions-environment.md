# F04 进程、权限、环境变量：谁在运行，凭什么能访问

> 先修 F03。实验：`python -m labs.foundations.permissions` 与 `python -m labs.foundations.process_runner`。本章不修改系统权限，不终止他人进程。

## 1. 程序是一份说明，进程是一次执行

磁盘上的 Python 脚本可以同时启动十次，形成十个进程。每个进程有进程 ID、当前目录、环境变量、打开的文件和内存。它们可能读取同一份代码，却拥有不同状态。容器里一个服务占用 GPU，最终也对应主机上的进程及其资源；容器并没有让资源消耗消失。

Shell 启动子进程时，会把某些状态传给它。子进程继承环境变量副本，通常继承标准流等文件描述符，但不能简单修改父进程的工作目录。你运行一个脚本，脚本里 `cd /tmp`，脚本退出后当前 Shell 通常不会因此留在 `/tmp`。因为改变的是子进程自己的目录。

观察时先定位自己的 PID：`ps -u "$USER" -o pid,ppid,stat,etime,args`。其中 PPID 是父进程 ID；elapsed time 是已运行时长；args 帮你识别具体命令。命令行可能包含敏感参数，因此不要随意公开完整进程列表。对模型 API 密钥，应避免放在命令行参数里。

## 2. 前台、后台和终端会话

前台作业占用终端交互；末尾加 `&` 可让 Shell 后台运行，但这不自动保证 SSH 断开后仍存活，也不自动提供重启管理。`Ctrl+C` 通常向前台进程组发送中断信号，程序可能捕获它并做清理。`kill PID` 默认发送终止信号，让程序有机会释放资源；强制终止会绕过正常清理，不适合作为第一选择。

本课程不让你根据模糊名字批量终止服务器进程。先确认进程属于自己、命令和工作目录正确，再处理。GPU 服务器上尤其如此：`pkill python` 可能影响别人的训练或服务。

进程结束与文件删除是两件事。停止 Docker 容器不会删除镜像；删除镜像也不等于终止已经运行的进程。程序停止后，它写入持久文件的内容通常仍然存在。

## 3. 读懂 `rwx` 与八进制

普通 Unix 权限分成所有者、组、其他人三组，每组有读 r、写 w、执行 x。每组可以用三位二进制表示，r=4、w=2、x=1。所以 6=4+2 表示 rw-，4 表示 r--，0 表示 ---。

`640` 对应所有者 rw-、组 r--、其他人 ---，合并为 `rw-r-----`。实验会打印这个结果。`755` 是 rwxr-xr-x，适合某些可执行程序或目录，并不是所有文件都应该给执行权限。

目录的 x 表示可穿过，r 表示可列举名称，w 影响目录条目修改。删除一个文件主要涉及父目录的写和执行权限，还可能受 sticky bit、ACL、挂载选项等约束；不能只看被删文件自己的写权限。本实验仅模拟最普通的九位权限，不覆盖 ACL、setuid、sticky bit 或强制访问控制。

`umask` 从程序请求的权限中屏蔽某些位。新普通文件常请求 `666`，目录常请求 `777`；`umask 022` 后分别得到 `644` 和 `755`。这是按位运算 `requested & ~mask`，不是普通十进制减法。比如从 666 减 022 恰巧看起来合理，不代表可以把所有情况当算术减法。

## 4. 环境变量与 PATH

环境变量是一张字符串键值表。Shell 变量未必自动传给子进程；`export` 标记变量进入子进程环境。下面是一次只对某条命令生效的设置：

```bash
COURSE_MODE=demo python -c 'import os; print(os.environ["COURSE_MODE"])'
```

`PATH` 是寻找可执行文件的目录列表，Linux 常用冒号分隔。输入 `python` 时，Shell 按规则查找；输入 `/usr/bin/python3` 时，路径已明确。`command -v python` 能观察解析结果。不要把工作目录或陌生可写目录随便放在 PATH 前面，否则同名程序可能被意外执行。

API 密钥也是环境变量常见用途，但环境变量不是加密存储，也不是绝对秘密空间。日志和诊断脚本不应全量打印环境。用 `.env.example` 展示变量名称时填写占位符，真实值放在不提交版本控制的位置。

## 5. 用 subprocess 正确启动程序

读取 `process_runner.py`。关键表达式是：

```python
subprocess.run(
    [sys.executable, "-c", "...", text],
    text=True, capture_output=True, timeout=3, check=True,
)
```

列表中每项是一个参数。`shell=False` 是默认值，因此 `text` 内的 `;`、`$()`、`*` 不会被 Shell 当语法执行。实验传入 `hello; this is one argument`，子程序应原样输出，而不是把分号当成新命令。

`capture_output=True` 捕获 stdout 和 stderr；`text=True` 将字节转换为字符串；`timeout=3` 设置超时；`check=True` 让非零退出变成 `CalledProcessError`。这些都是显式合同。没有 timeout 的外部命令可能无限挂住；没有检查退出码的程序可能把失败输出当成功数据继续处理。

注意：参数列表只能避免 Shell 注入，并不保证目标程序本身安全。若工具允许任意路径、任意可执行文件或危险选项，仍然可能造成损害。Agent 执行工具时还需要限制可执行程序、工作目录、资源和权限。此实验固定执行当前 Python，只用来展示参数边界。

## 6. 常见故障的因果树

`Permission denied`：可能文件不可读、父目录不可穿过、程序不可执行、文件系统禁止执行，或其他访问控制。先看 `ls -l`、路径各层和实际用户，不要直接 sudo。

`command not found`：可能没安装、PATH 没包含、命令名拼错，或当前 Shell 与预期不同。先 `command -v`，再查已知安装位置。

程序“卡住”：可能等待 stdin、等待网络、死锁、正常计算或父进程没读管道。先检查日志、CPU 使用和它在等待什么，避免把所有慢都归结为 GPU。

退出码 0 但结果不对：这是语义错误，操作系统不负责判断你的业务是否正确。后续测试章要用断言补上这层合同。

## 7. 六个练习与答案

**F04-1 权限手算。** 把 750 转为符号表示。答案 rwxr-x---。再把 rw-rw-r-- 转回八进制，答案 664。

**F04-2 umask 反例。** 请求权限 640，mask 为 027，计算结果。答案是 640；已关闭的位不会因为算术“减去”而借位，使用按位 AND 才正确。

**F04-3 继承实验。** 用 `COURSE_MODE=demo python ...` 运行后，在父 Shell 查看变量是否存在。答案：这种前缀赋值仅作用于该命令的环境；不要据此期待父 Shell 永久改变。

**F04-4 参数字面性。** 把 `process_runner` 输入改为 `'; echo SHOULD_NOT_RUN'`。验收：整串只成为输出，不执行 echo。参考答案是保持参数列表和默认 `shell=False`。

**F04-5 非零退出。** 写一个固定子程序 `raise SystemExit(7)`，分别使用 check=True/False。答案：前者抛异常，后者返回 `returncode=7`。你应知道错误在哪里被转换成异常。

**F04-6 最小执行合同。** 设计一个只允许运行固定分析脚本的函数，参数只能是课程目录内输入文件，且有三秒超时。验收：绝对路径、越界路径和任意命令字符串都拒绝。参考组合：F02 的路径验证、固定 argv 列表、timeout、退出码检查；同时注明路径检查不是完整沙箱。

## 掌握门槛
