# F10 命令行、配置、日志与接口：让别人能正确使用你的程序

> 先修 F06–F09。实验：`python -m labs.foundations.cli --count 7 --batch-size 3`。本章把一个函数包装成可使用、可排错、可自动化的工具。

## 1. 命令行不是函数的随意字符串版

操作系统传给程序的命令行参数通常是字符串。业务函数需要整数、路径、布尔等类型，因此入口层负责翻译与校验。一个好的入口让错误尽早发生，并明确告诉使用者哪项输入不合法。

`argparse`负责解析参数、生成帮助、处理缺失参数和错误退出。我们的positive函数把字符串转为整数，并拒绝非正数。它抛ArgumentTypeError，解析器把它变成适合命令行用户的提示。

```bash
python -m labs.foundations.cli --help
python -m labs.foundations.cli --count 5 --batch-size 2
```

第二条输出`[[0,1],[2,3],[4]]`。把batch-size改为0应失败，不应进入业务循环，更不能死循环。默认值7和3只为方便演示，用户显式传参应覆盖默认。

## 2. 三层拆分：适配、业务、输出

入口层解析命令行，业务层执行batches，输出层序列化JSON。好处是测试业务时不需要模拟终端；测试入口时可以给main传参数列表，不需要启动新进程；真正端到端测试再启动程序检查退出码。

不要把每个函数都写成直接调用`sys.argv`、`print`和`sys.exit`。这样函数只能活在一个入口里，很难作为Agent工具或HTTP API复用。核心函数返回数据；入口决定呈现与退出。

退出码应与数据输出分开。正常JSON写stdout，诊断写stderr；失败返回非零。这使Shell管道和自动化系统能做正确决定。若日志混进stdout，一个下游JSON解析器会看到“INFO starting...”而失败。

## 3. 配置文件、环境变量、命令行如何共存

一个工程可能从默认值、配置文件、环境变量、命令行四处获取配置。关键不是全部都支持，而是优先级明确。例如：默认值 < 配置文件 < 环境变量 < 命令行。最终生效配置可以打印非敏感部分，便于复现。

JSON配置容易解析，但不能写注释；TOML与YAML有自己的语法与类型规则。后缀不决定谁读取它：只有你的程序或框架明确加载该文件，配置才会生效。一个叫`task.toml`的文件不会因为名字特别就自动控制系统。

密钥不宜写进公开配置或命令行示例。可以在示例文件中列出变量名和占位符，在运行时从环境读取。配置快照记录模型名、预算和协议等非敏感参数，密钥字段应固定显示为已设置/未设置，而非原值。

## 4. 日志是带上下文的事件记录

日志至少回答何时、哪个任务、处于什么阶段、发生了什么。自由文本适合人读，JSONL结构化日志便于程序统计。JSONL通常一行一个完整JSON对象，便于追加和逐行读取；它不是一个外层大数组。

一个课程记录合同：

```json
{"request_id":"a","latency_ms":10,"tokens":3,"status":"ok"}
```

request_id连接同一请求的多个事件；latency_ms带单位，避免秒毫秒混淆；tokens明确是数量；status受允许集合约束。字段设计要服务于排查与统计，不是把所有内部对象原样dump。

Python logging提供日志级别、格式、handler等机制。DEBUG适合开发细节，INFO记录主要过程，WARNING表示可继续但异常，ERROR表示某个操作失败。级别是应用约定，不应把所有事件都打ERROR来引人注意。

## 5. 时间、计时与可复现性

记录事件发生时间和测量耗时是两个任务。墙上时钟可以用于时间戳，但可能受时间同步调整；单调时钟更适合测量持续时间。使用`time.perf_counter()`测量CPU程序片段，不要用打印时间字符串再相减。

测量很短的操作时，单次结果可能受调度和缓存噪声影响。需要预热、重复、合理统计并注明环境。GPU计算常异步提交，直接测Python函数返回耗时可能只测到排队时间，GPU卷会加入同步与事件计时。本章先建立“测量方法是结果的一部分”的习惯。

随机实验应记录种子，但种子不是全栈确定性的保证。文件遍历顺序、并发调度、浮点归约顺序、网络返回都可能变化。稳定输出常需显式排序、固定数据和明确时间字段，而不是只调用一次random.seed。

## 6. 版本化一个小工具的输出

机器读取的JSON报告是接口。新增字段通常容易兼容，重命名或改变字段含义会破坏下游。F15报告包含schema_version=1，让读者知道按哪套合同解释。

不要把同一个字段有时写整数、有时写错误字符串。没有均值时用null，并由schema说明；“0”会误导使用者认为平均耗时真的为零。错误记录使用独立errors数组，包含行号和原因，不包含未经必要审查的完整原始敏感行。

命令行帮助也属于接口。每个选项应该说明单位、默认行为、是否联网、是否写文件。后续GPU实验的`--device`、`--iterations`和预算参数都遵循这一原则。

## 7. 七个练习与参考答案

**F10-1 添加参数。** 给CLI加入`--start`整数参数，使range从start开始。验收：start=10、count=5、batch=2得到[[10,11],[12,13],[14]]。参考：只在入口构造range，batches无需修改。

**F10-2 失败退出。** count传入`abc`。验收：stderr有可理解错误，退出非零，stdout没有半份JSON。参考：使用argparse类型转换而不是在输出阶段才发现。

**F10-3 配置优先级。** 用字典模拟默认、文件、CLI三层合并。验收：未提供的CLI项不覆盖文件值；显式0与“未提供”区分。答案：用None或单独sentinel表示未提供，不要用`value or default`误吞合法零。

**F10-4 日志脱敏。** 给含api_key的配置生成诊断摘要。验收：输出无原密钥，也不包含可恢复密钥的大段片段。参考：只输出`api_key_set: bool(value)`。

**F10-5 单位核对。** 250毫秒转换成秒与每秒请求率的理想单串行上界。答案0.25秒、4请求/秒；这不是实际并发服务吞吐保证，还需要考虑其他阶段。

**F10-6 stdout合同。** 在CLI中加日志但保持JSON输出可被`python -m json.tool`解析。答案：日志写stderr；结构化结果独占stdout。

**F10-7 输出版本。** 为报告新增一个字段同时保持schema_version策略。答案必须说明是否改变已有语义；仅新增可选字段与改变tokens含义属于不同兼容性级别。

## 掌握门槛

你能把一个纯函数包装成帮助清晰、输入受控、错误可理解、输出可解析的CLI；能记录足够诊断信息，同时避免泄露密钥。这样的工具已经可以成为后续Agent可调用工具的一部分。
