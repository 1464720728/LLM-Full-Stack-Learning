# 工作簿 E：把数学公式变成手算、循环、NumPy和训练步骤

你将用同一份极小数据穿过四种表示：纸上数字、Python循环、NumPy向量化、参数训练。目标不是背住公式，而是知道公式中每个符号在代码里对应哪个对象、哪个轴、哪一次求和。所有实验只用CPU与NumPy。

## E1 先学会把求和符号展开

看到$\sum_{i=1}^{3} x_i$，先写成$x_1+x_2+x_3$。例如x=[3,5,0]，总和8。平均值是总和除以项数，8/3。符号i只是遍历位置的索引，不是额外数据。

Python代码可以写：

```python
x = [3, 5, 0]
total = 0
for value in x:
    total += value
mean = total / len(x)
```

这里Python索引通常从0开始，数学书常从1开始；它们可以表达同一组元素，只要范围一致。把公式直接照抄成range(1,n)会漏掉边界，因为Python的右端不包含。

**练习：** 把$\sum_{i=0}^{2} i^2$展开为0²+1²+2²=5，再写循环验证。接着把平方和与和的平方区分：0²+1²+2²=5，而(0+1+2)²=9。后面方差、范数和注意力公式中，括号位置都不能随意交换。

## E2 点积、范数和余弦相似度逐个手算

向量a=[1,2]、b=[2,1]，点积为1×2+2×1=4。L2范数是平方和开根号，二者都为√5。因此余弦相似度为4/(√5×√5)=0.8。

把b放大成[20,10]，点积变40，范数变10√5，余弦仍0.8。点积受长度影响，余弦把长度归一化。检索系统选择哪一种相似度，要看embedding训练和索引合同，不能因为余弦范围看起来直观就随意替换。

零向量没有可定义的余弦，因为分母为0。实现时要明确拒绝、返回特定值或使用约定的平滑方法；不同策略可能改变检索排序。不要悄悄加一个很大的epsilon让结果“能跑”却不解释偏差。

```python
import numpy as np
a = np.array([1., 2.])
b = np.array([2., 1.])
score = (a @ b) / (np.linalg.norm(a) * np.linalg.norm(b))
assert abs(score - 0.8) < 1e-12
```

**验收：** 自己用for实现点积与范数，再和NumPy比。先用长度2，再用长度5；不同长度必须拒绝，不能zip默认截短导致静默少算。

## E3 矩阵乘法不再只看shape

取A=[[1,2],[3,4]]、B=[[5,6],[7,8]]。C[0,0]=1×5+2×7=19；C[0,1]=1×6+2×8=22；C[1,0]=3×5+4×7=43；C[1,1]=3×6+4×8=50。

写三重循环时，外两层遍历输出位置，内层遍历归约维度：

```python
A = [[1, 2], [3, 4]]
B = [[5, 6], [7, 8]]
C = [[0, 0], [0, 0]]
for i in range(2):
    for j in range(2):
        for k in range(2):
            C[i][j] += A[i][k] * B[k][j]
assert C == [[19, 22], [43, 50]]
```

初始化C不能写`[[0,0]]*2`然后原地修改，因为两个行引用会共享同一列表。这是Python对象知识与数学实现的交叉点：公式正确，也可能因为数据结构别名而算错。

将维度推广为M、K、N后，朴素乘加工作量与MKN成正比。GEMM Kernel优化会改变数据搬运、分块与并行方式，但目标仍是这些输出元素及归约关系。你先能实现慢而正确的参考，才有能力判断快速实现是否正确。

## E4 轴和归约：sum(axis=...)到底在消掉什么

取X=[[1,2,3],[4,5,6]]。沿axis=0求和，消掉行轴，得到[5,7,9]；沿axis=1求和，消掉列轴，得到[6,15]。axis不是“向哪个方向看起来移动”，而是被归约掉的轴编号。

`keepdims=True`保留长度1的轴，前者shape[1,3]，后者[2,1]。这样便于与原数组广播。例如每行减去该行均值，`X-X.mean(axis=1,keepdims=True)`正确；若不保留轴，shape[2]与[2,3]不能按你想的方式匹配。

现在把每一行视为一个token的特征，按特征轴归一化；再把每一列视为跨样本统计，观察不同axis会得到完全不同含义。RMSNorm、LayerNorm、softmax等算子都必须指定正确归约轴。只看输出shape合法不足以证明语义正确。

**练习：** 用不相等的轴长2×3×5构造数组，写出对最后一维求和后的shape[2,3]；使用keepdims后[2,3,1]。再手算一个固定元素对应哪5项相加。

## E5 从频数到概率，不把样本比例当绝对真相

假设十次请求中7次成功，观察成功率0.7。这是样本比例，不是系统真实成功概率已被精确证明为0.7。再测十次可能得到6次或8次；随机样本、任务差异与环境变化都会造成波动。

对固定概率p的独立伯努利试验，单次结果是0或1，期望为p；n次平均的方差为p(1-p)/n。样本量增大通常能减少这类抽样噪声，但Agent任务未必独立同分布，重复同题也可能共享环境或缓存。统计模型的假设要先检查。

这里只要求你理解两点：一次成功不证明永远成功，一次失败不证明能力不存在；比较两个系统时，应控制任务、输入、环境和统计口径。后续评测卷会进一步建立置信区间、配对比较和确定性分析。

**手算题：** p=0.5、n=100时，平均值标准差为√(0.25/100)=0.05。这是模型下的标准差，不是“结果必定在±5%内”。不要把标准差和绝对误差上界混淆。

## E6 softmax的一次完整计算

取logits=[0,ln3]。指数后为[1,3]，总和4，概率[0.25,0.75]。给两项同时加100，指数分别乘exp100，分子分母共同抵消，所以概率不变。

实际代码先减最大值ln3，得到[-ln3,0]，指数[1/3,1]，归一化仍是[1/4,3/4]。这个例子可以完全手算，帮助你理解稳定softmax不是经验魔法，而是利用数学不变性重新组织数值计算。

如果两项差异很大，较小项的指数在有限精度中可能下溢为0。避免溢出并不意味着恢复了实数全部精度。对于交叉熵，直接log-sum-exp通常比先得到极小概率再log更稳定；对于低精度Kernel，要检查误差是否会影响后续决策。

运行`python -m labs.foundations.numerics`，把打印的概率总和与1比较，再把输入整体平移，验证结果近似不变。测试用近似比较，因为浮点计算不是符号代数。

## E7 从损失到梯度：先用一条直线学习

我们希望模型拟合三对数据：x=[0,1,2]，y=[1,3,5]。肉眼看真实关系y=2x+1，但让程序只知道可调参数w、b，预测$\hat y=wx+b$。

损失定义为平均平方误差：$L=(1/n)\sum_i(wx_i+b-y_i)^2$。它衡量预测误差，不是模型参数大小。开始w=0、b=0时预测全0，残差e=[-1,-3,-5]，平方和1+9+25=35，平均35/3≈11.666667。

求导得到：$\partial L/\partial w=(2/n)\sum_i x_i e_i$，$\partial L/\partial b=(2/n)\sum_i e_i$。你可以逐项用链式法则得到：平方对残差导数2e，残差对w导数x，对b导数1。

代入：dw=(2/3)(0×-1+1×-3+2×-5)=-26/3≈-8.666667；db=(2/3)(-1-3-5)=-6。负梯度表示沿增大参数方向移动会在局部降低损失。

## E8 第一轮梯度下降必须亲手算

学习率η=0.1，更新w←w-ηdw，b←b-ηdb。新w=0.8666667，b=0.6。新预测为[0.6,1.4666667,2.3333333]，残差约[-0.4,-1.5333333,-2.6666667]。新损失约3.207407，比11.666667小。

注意减的是梯度，不是把参数直接设成梯度；两个梯度都应基于同一轮旧参数计算，再同时更新。若先更新w，再用新w重新算db，却仍称为同一轮普通梯度下降，你已经改变了算法。

运行：

```bash
python -m labs.foundations.linear_regression
```

本环境参考输出：

```text
initial loss=11.666667 dw=-8.666667 db=-6.000000
after one step loss=3.207407
final weight=1.999998 bias=1.000003 loss=0.000000000004
```

最后几位可能受环境数值细节影响，验收应按容差与损失条件。这里只是三点一维回归，不能从收敛两百步推断大模型训练也同样简单；它负责展示训练循环的核心因果链。

## E9 逐行读训练代码

`loss_and_grad`先把输入转float64数组，确认一维、长度匹配且非空，再检查有限值。residual是整条残差向量；`np.mean(residual**2)`计算损失；另外两项计算解析梯度。

train初始化w、b、history。每轮先计算loss与两个梯度，把更新前loss加入history，再更新参数。循环结束后再计算一次最终loss加入，因此history长度为steps+1。若你画图时横轴只给steps个点，就会维度不匹配，这属于记录口径问题。

为什么检查学习率有限且正？NaN学习率会污染所有参数，负学习率可能变成沿梯度上升；steps必须非负整数，bool不应意外当1轮。严格输入合同让故障更接近源头被发现。

## E10 用有限差分验证解析梯度

先不相信自己的求导。固定w=0.7、b=0.4，分别把w加减很小h，计算损失差商，近似dw；再固定w，把b加减h近似db。与解析结果近似相等，是很有价值的独立检查。

测试`test_gradients_match_finite_difference`正是这样做。它没有把解析公式再抄一遍当预期，而是用另一种数值途径检查。有限差分也有误差，因此选择float64和适中h；不能把h无限缩小后要求精确位相等。

高维模型每个参数做有限差分会非常贵，但小模型、随机抽样参数或方向导数检查仍有价值。后续手写Transformer反向传播时，先对极小shape做梯度检查，再扩规模，会比直接训练大模型等loss异常更有效。

## E11 学习率、归一化与“训练没下降”的排查

把rate从0.1改到很大，损失可能振荡甚至发散；这不一定是梯度公式错，而是步长不适合当前损失曲率。把输入x放大100倍，梯度尺度与曲率改变，同一学习率也可能不再稳定。

如果损失完全不变，检查参数是否真的更新、是否每轮又重新初始化、是否更新了局部副本、是否学习率为零、是否用了错误的返回值。若损失变NaN，检查输入有限性、溢出和除零。不要第一反应就换优化器或换GPU。

对这个凸二次小问题，可以用已知解析解w=2,b=1作为验收。对复杂模型没有这种显式答案时，仍可以做小数据过拟合、梯度检查、形状检查、损失趋势和独立参考比较。方法会随着规模升级，但证据意识不变。

## E12 从基础训练连接到Transformer

线性层是更高维的wx+b；矩阵乘法批量计算多个样本与特征；非线性把简单线性组合变成更丰富函数；softmax把分数变概率；交叉熵提供训练目标；反向传播把链式法则应用到计算图；优化器根据梯度更新参数。

注意力引入输入相关的权重，MoE引入路由与条件计算，线性注意力与状态模型改变历史信息聚合方式，但它们仍必须交付明确的张量运算和梯度/状态规则。你学会逐项展开公式、核对shape、写参考循环和做数值验证，就获得了理解这些结构的共同工具。

不要跳过CPU小例子直接追求Tensor Core性能。一个正确的慢参考让你能判断快速Kernel是否算对；一个手算例子让你能判断两个实现的轴、mask、归一化和缓存状态是否对应。同样，不要只停在CPU例子：达到基础验收后，按后续Kernel卷逐步迁移到GPU并测量。
