# F05 网络、SSH、tmux、HTTP 与 JSON：让两台机器可靠地说话

> 先修 F01–F04。离线实验：`python -m labs.foundations.http_message`、`python -m labs.foundations.json_contract`。真正的网络演练只连接你自己控制的课程服务。

## 1. IP、端口、协议分别回答什么问题

IP 地址帮助网络把数据送到某台主机或某个网络接口；端口帮助操作系统把连接交给某个服务；协议规定双方如何解释数据。它们不是同一个东西。`http://127.0.0.1:8765/tasks` 的 scheme 是 http，host 是 127.0.0.1，port 是 8765，path 是 /tasks。

`127.0.0.1` 是当前网络环境中的回环地址。你在 PC 访问它，是 PC；你在服务器访问它，是服务器；在普通独立网络命名空间的容器内访问它，是容器自己。它不自动指向“真正部署模型的那台机器”。

`0.0.0.0` 用作监听地址时通常表示绑定所有 IPv4 接口。它不是给客户端填写的通用远程服务器地址；客户端通常使用实际 IP 或域名。绑定地址决定服务在哪些接口接受连接，防火墙、路由、容器端口映射和服务鉴权还会影响能否访问。

把服务绑定到 127.0.0.1 有助于基础课程减少误暴露。以后需要 LAN 服务时，你要明确哪个接口、谁能连接、是否涉及密钥与公司数据，再决定绑定和访问控制。基础 HTTP 练习不需要把服务开放给整个网络。

## 2. 从域名到返回文本，中间有哪些步骤

一次常见 HTTPS 请求可以粗分为：解析域名、建立 TCP 连接、完成 TLS 握手、发送 HTTP 请求、服务器处理、接收 HTTP 响应、解析应用数据。HTTP/3 使用 QUIC 等不同传输，入门实验先聚焦 HTTP/1.1 和常见 TCP 场景，不把这个链条当所有协议的唯一路径。

`Connection refused` 常表示目标地址可到达但该端口没有接受连接的服务，或有主动拒绝；timeout 可能来自路由、防火墙、服务无响应或请求本身很慢；HTTP 404 表示你已经收到了 HTTP 响应，只是资源路径等未匹配。三种错误发生在不同层，排查方法不同。

常用观察命令：

```bash
ss -ltn
curl --noproxy '*' --fail-with-body --connect-timeout 3 --max-time 10 \
  http://127.0.0.1:8765/health
```

这条 curl 需先在 F16 启动课程服务。`--noproxy '*'` 告诉 curl 这次请求不要走代理；星号加引号，避免被 Shell 展开。`--connect-timeout` 限制连接阶段，`--max-time` 限制整个请求，`--fail-with-body` 让 HTTP 错误反映到退出码并保留响应体。系统旧版 curl 若不支持该选项，先查看 `curl --help all`，不要误以为是服务器失败。

## 3. HTTP 是有结构的消息，不是“往 URL 发一段话”

HTTP 请求包含方法、路径、头部和可选正文。GET 常用来读取；POST 常用来提交或触发动作；但真正行为由服务器实现决定。不能仅凭方法名就断言“无副作用”。响应包含状态码、头部和正文。

F16 的创建请求正文如下：

```json
{"title":"实现第一个 Agent 工具","idempotency_key":"practice-1"}
```

头部 `Content-Type: application/json` 告诉接收方如何解释正文；`Content-Length` 表示字节数而非中文字符数。正文编码成 UTF-8 后再计算长度，这解释了为什么不能直接把 Python 字符串的 `len` 当 HTTP 字节长度。

200 表示该 API 的成功响应，201 常用于已创建，400 表示请求不符合合同，404 表示资源或路由不存在，409 可以表达冲突，413 表示请求体过大。课程服务给这些状态码具体业务含义；生产 API 应阅读它自己的合同。

## 4. JSON 语法正确，不等于数据可用

JSON 支持对象、数组、字符串、数值、布尔和 null。对象键必须是字符串；JSON 不支持 Python 单引号字典语法，也不支持尾随注释。`{"tokens": true}` 是合法 JSON，但 tokens 如果必须是整数数量，就不符合业务要求。

运行 `json_contract.py` 会得到 `Request(request_id='r1', tokens=12)`。源码先 `json.loads` 解析，随后检查顶层类型、精确字段集合、request_id 内容与 tokens 类型。为什么使用 `type(tokens) is int` 而不是只用 `isinstance(tokens, int)`？在 Python 中 bool 是 int 的子类，因此 `isinstance(True, int)` 为真；对 token 数量，接受 True 当作 1 往往不是你想要的合同。

严格拒绝额外字段适合教学合同，因为拼错字段会立刻暴露。生产系统也可能选择向后兼容地忽略未知字段，但那必须是明确的版本策略。无论选择哪种方式，都不应让“我没考虑过”变成隐含规则。

## 5. SSH：远端执行和本地转发

SSH 不只是“另一个终端”，它建立认证与加密通道。命令形态为 `ssh 用户@主机`。用户名、主机和端口由你有权使用的环境提供，不把公司的真实地址写进公开仓库。首次连接时要核对主机指纹，而不是机械接受所有提示。

连接成功后，`pwd`、`python`、`docker` 都运行在远端，除非你明确调用本地程序。传输文件可以使用 scp 或其他受控同步工具；Git 同步源码通常更能保留变更历史，但不要用 Git 存储模型权重、缓存和真实密钥。

若服务只监听服务器的 127.0.0.1，可以使用本地转发：

```bash
ssh -N -L 8765:127.0.0.1:8765 USER@HOST
```

这里 `USER@HOST` 是占位符，不能直接执行。含义是本地 8765 的连接经过 SSH 通道，再从远端访问远端的 127.0.0.1:8765。两个 127.0.0.1 的视角要分清。若本地端口被占用，可以把左边改成 8766，远端仍是 8765。`-N` 表示不执行远端命令，仅保持转发。

## 6. tmux：会话保留与进程管理的边界

在服务器创建自己的 tmux 会话：`tmux new -s course`。按 `Ctrl+b` 再按 `d` 可以分离；`tmux ls` 查看会话；`tmux attach -t course` 重新连接。tmux 让终端会话在 SSH 断开后仍可保留，但它不是集群调度器，不会自动申请 GPU、限制显存或避让公司任务。

在 tmux 里也应给实验明确结束条件：小输入、有限迭代、超时和日志。一次 Kernel 验证可能几秒就足够，不必把模型服务长期挂着才能学习。若 GPU 作业中断，先看进程是否仍在运行，避免误启动第二份重复作业。

## 7. 七个练习与答案

**F05-1 URL 拆解。** 运行 http_message 实验，解释 query 中 `status` 和 `limit` 为什么是列表。答案：同一键可重复出现，如 `?x=1&x=2`；`parse_qs` 保留多个值。片段 `#local-note` 不作为 HTTP 请求路径的一部分发送给服务器。

**F05-2 三层失败。** 分别描述没有监听服务、未知路径、非法 JSON 的预期现象。答案：连接失败、HTTP 404、HTTP 400。不要把三者都记录成“API 不能用”。

**F05-3 字节长度。** 编码含“学习”的请求体，比较 `len(text)` 与 `len(text.encode('utf-8'))`。验收：HTTP 长度使用后者。

**F05-4 合同拒绝。** 为 json_contract 添加 4 个错误输入：缺字段、额外字段、tokens 为 true、空 request_id。验收：全部拒绝，并解释每条违反什么规则；测试中已有参考。

**F05-5 端口转发画图。** 用三行文字说明浏览器、SSH 客户端、远端服务的地址。验收：不把本地回环和远端回环混为一谈。答案：浏览器访问本地转发端口；SSH 加密通道到远端；远端连接自己的服务回环端口。

**F05-6 tmux 故障记录。** 在自己的会话内运行短小 CPU 程序，分离后重新附加。验收：知道分离不是停止；结束会话前确认只属于本课程。

**F05-7 请求重试的危险。** POST 创建任务超时后是否能直接重试？答案：第一次可能已经成功，只是响应丢失。需要幂等键或其他去重合同。F16 将实际实现“同键同参数返回同一任务，同键不同参数返回冲突”。

## 掌握门槛

你能从地址、端口、传输、HTTP 和数据合同五层定位一个请求失败；能通过 SSH 管理自己的远端练习，并且不会把 tmux 当 GPU 调度系统。
