# F06 Python 从零到函数：把一段思路变成可检验的步骤

> 先修 F01；F02–F05 的操作会在本章得到语言层解释。实验：`python -m labs.foundations.python_values`、`python -m labs.foundations.functions`。

## 1. 变量不是装数据的盒子，而是名字到对象的绑定

执行 `x = [1, 2]`，可以理解成创建一个列表对象，再让名字 x 指向它。执行 `y = x` 不会复制列表，而是让 y 指向同一对象。随后 `y.append(3)` 改变对象，x 观察到的也变成 `[1, 2, 3]`。

```python
x = [1, 2]
y = x
y.append(3)
assert x == [1, 2, 3]
assert x is y
```

`==` 比较相等关系，`is` 比较是否同一对象。不要用 `is` 比较一般数字或字符串的值，即使某些小对象缓存让你的实验偶然通过。

不可变对象如整数，不能原地修改数值。`a = 1; b = a; a = 2` 是把 a 重新绑定到另一个整数对象，b 仍指向原来的值。列表可变、整数不可变，是后面函数副作用和共享状态的重要基础。

## 2. 先掌握四种容器的用途

列表保持顺序、允许重复、可变，适合请求序列。元组保持顺序、通常表示固定结构的组合，如 `(request_id, latency)`。字典把键映射到值，适合按 ID 查对象。集合记录成员关系并去重，不适合依赖位置。

字典查找平均性能通常很好，但这不意味着任何输入和实现下都绝对 O(1)。此时重点是学会选择表达业务关系的结构：你需要“第几个”，还是“某个 ID 对应什么”，还是“有没有出现过”？

```python
requests = [{"id": "a", "tokens": 3}, {"id": "b", "tokens": 5}]
by_id = {row["id"]: row for row in requests}
seen = set(by_id)
assert by_id["b"]["tokens"] == 5
assert "a" in seen
```

这段代码并未复制内部字典。修改 `by_id['a']['tokens']` 也会影响 requests 中对应记录。这可能是你想要的共享，也可能是错误，要自己决定。

## 3. 浅复制为什么仍然会串改

实验中 `original=[[1,2],[3,4]]`，`shallow=original.copy()` 创建新外层列表，但两个内层列表仍共享。向 `shallow[0]` 追加 9，原始列表也变了。`deepcopy` 递归复制常见容器，因此 deep 保持原值。

画引用关系比记口诀有效：外层有两个列表对象 A、B，它们第一个元素都指向内层对象 C；复制外层不等于复制 C。Agent 会话历史如果在多个请求间共享同一列表，类似错误可能造成上下文串话。选择不可变数据、显式复制或明确所有权，都比事后“偶尔清空一下”可靠。

深复制也不是万能解药：文件句柄、数据库连接、GPU 张量等对象可能不能按你想的方式复制，而且复制大对象昂贵。先理解状态归谁所有，再选择复制策略。

## 4. 控制流：程序沿哪条路执行

`if` 根据条件选择分支；`for` 从可迭代对象中逐个取值；`while` 在条件成立时重复。缩进属于 Python 语法，不能随意改变。

```python
total = 0
for tokens in [3, 5, 0]:
    if tokens < 0:
        raise ValueError("negative tokens")
    total += tokens
assert total == 8
```

逐行执行表：初始 total=0；第一次加3得到3；第二次加5得到8；第三次加0仍是8。循环结束后 total 存在。你必须能手算这种状态变化，才能读懂更复杂的调度器。

`range(3)` 产生 0、1、2，不包括3。索引越界是新手常见错误。`for item in items` 往往比手写索引更直接；需要索引时用 `enumerate(items)`。同时遍历两个序列可以用 zip，但长度不同时默认截到较短者；严格要求等长时要显式验证，或使用支持严格模式的写法。

## 5. 函数是有合同的局部计算

函数合同包含输入允许什么、返回什么、会不会修改外部状态、可能抛什么错误。`batches(values,size)` 的合同是把所有输入保持原顺序分成大小不超过 size 的批次，size 必须是正整数。

读 `functions.py`，从 `range(7), size=3` 追踪：current 依次变成 `[0]`、`[0,1]`、`[0,1,2]`；达到3后加入 result，并把 current 重新绑定到一个空列表。最终尾部 `[6]` 也要加入结果。若忘记最后一段判断，尾批就被丢弃。

关键不变量：已经放入 result 的元素加上 current 的元素，等于已经读过的输入前缀；每个完整批次长度为 size；任何元素恰好出现一次。以后写 Token 调度、分页 KV 与数据加载器，仍会使用这种不变量思维。

为什么 `current=[]` 而不是 `current.clear()`？result 保存的是对原 current 列表的引用。若加入 result 后又 clear 同一个对象，已保存的批次也被清空。重新绑定到新列表才保留过去的批次。

## 6. 参数、返回值与副作用

`return` 把值交给调用者；`print` 把文字写到输出流。打印了结果但没有 return 的函数，调用者拿到的是 None。这是最常见的“明明显示5，为什么变量是None”原因。

默认参数在函数定义时求值。不要写 `def collect(x, bucket=[]): ...` 并期待每次调用得到新列表。常用方式是 `bucket=None`，进入函数后再创建列表。更好的设计可能根本不让函数维护隐含累积状态。

`token_cost` 中星号后的 `input_rate`、`output_rate` 必须按名称传入，减少两个相似数字写反。费率是纯假设练习，不是任何供应商的实时报价：1000 输入 token×每百万2，加200输出×每百万8，总价 `(2000+1600)/1e6=0.0036`。单位写清楚，就不会把“每百万”当“每千”。

## 7. 类型提示告诉读者意图，不自动执行校验

`def batches(values: Iterable[int], size: int) -> list[list[int]]` 表示意图，但 Python 默认不会因为传错类型就按注解自动拒绝。运行时校验要自己写；静态检查器可以在运行前发现部分不匹配。二者解决不同问题。

本课程边界处用显式校验，因为外部输入可能来自 JSON、命令行和模型工具调用。内部已建立合同的函数可以减少重复校验，但这种取舍要基于调用边界，而不是到处加断言。`assert` 可用于程序内部不变量与测试，用户输入错误通常应抛明确异常；优化模式可能移除 assert。

## 8. 八个练习与参考思路

**F06-1 别名预测。** `a=[1]; b=a; a=[2]` 后 b 是什么？答案 `[1]`，重新绑定 a 不修改原列表。再比较 `a=[1]; b=a; a.append(2)`，此时 b 为 `[1,2]`。

**F06-2 浅复制反例。** 用三层列表展示只复制第一层仍共享哪些对象。验收：使用 `is` 证明身份关系，不只看值相等。

**F06-3 修复尾批。** 先故意删除 `if current` 分支，写一个失败测试，再修复。验收：输入长度为0、1、3、4时都保留所有元素。

**F06-4 拒绝非法批次。** size=0、-1、True 应怎样处理？参考实现全部拒绝。True 虽然可当1参与算术，但不符合“明确整数批次参数”的合同。

**F06-5 实现去重保序。** 输入 `['a','b','a','c']` 输出 `['a','b','c']`。参考算法：seen集合判断是否出现，result列表记录首次出现顺序。验收：空输入正确，重复项不改变第一次的位置。

**F06-6 纯函数改造。** 把“读取文件、解析、统计、打印”拆成四个函数，说明哪些纯、哪些有副作用。答案：解析和统计可设计为纯函数；读取和打印触及外部世界。F15 使用这个分层。

**F06-7 单位测试。** 手算 5000输入、1000输出，假设费率1与3每百万。答案0.008；为结果写近似比较而非依赖浮点文本完全一致。

**F06-8 不看参考重写 batches。** 验收包括扁平化后等于原输入、所有批次长度在1..size、除尾批外均满。现有测试对多个长度和size组合做了这种性质检查，而非只测一个样例。
