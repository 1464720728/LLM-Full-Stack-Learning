# F06 Python 从零到函数：把自然语言要求变成可运行的程序

本章的起点不是“已经会写函数，只差几个语法点”，而是你能够打开终端，知道怎样运行一个 Python 文件。我们要把最基本的计算、名字、容器、条件、循环、函数一步一步建立起来，最后独立写出批处理器和请求统计器。你现在不需要模型 API，不需要 GPU，也不需要先学一个框架。

主实验为 `python -m labs.foundations.python_values` 和 `python -m labs.foundations.functions`。先读懂本章中的短程序，再去阅读这两个模块。短程序可以分别保存为自己的练习文件；不要把十个互不相关的小例子全部粘进同一个文件后只看最后一行输出。

## 第一课：Python 究竟在执行什么

### 1.1 从文字到动作的三个层次

先看 `print(2 + 3)`。屏幕上的字符是一段源代码。Python 解释器读入代码，检查它是否符合语法，并按照语言规定计算表达式、调用函数。终端只是把键盘输入送给某个程序，把程序输出展示给你；它不会因为你写了“帮我算一下”就自动理解自然语言需求。只有符合当前程序语法的输入才有相应含义。

这句话中至少藏着三个需要分开的对象。源代码是你保存的文本；解释器是执行这些文本的程序；正在运行的解释器进程具有自己的内存和执行位置。关闭进程并重新运行，不会自动恢复上一次定义的变量。文件仍在磁盘上，但上次进程内存中的名字与对象已经结束了生命周期。因此“代码文件没有删，为什么变量没了”不是矛盾：文件和运行状态是不同的东西。

在交互解释器里输入 `2 + 3`，它通常会展示计算结果。在普通脚本里单独写 `2 + 3`，结果被计算出来后没有被保存或输出，你可能看不到任何东西。脚本希望向人展示结果，就明确调用 `print`；希望把结果留给后续步骤，就把它绑定到一个名字。交互界面的自动显示是一种界面便利，不是表达式自带的副作用。

```python
answer = 2 + 3
print(answer)
```

第一行先计算右边，得到整数对象所表示的值五，再把名字 `answer` 绑定到这个对象。第二行先查找 `answer` 当前指向的对象，再调用 `print` 把可读表示写入标准输出。计算顺序很重要：赋值不是从左向右“把 answer 塞进算式”，而是先求右侧的值，再更新左侧的名字。

### 1.2 表达式、语句、值不要混在一起

表达式回答“这个东西计算之后是什么值”，例如 `2 + 3`、`len("cat")`、`score >= 60`。语句规定程序要做的动作或组织方式，例如赋值、条件分支、循环、函数定义。一个语句内部可以包含多个表达式。`total = price * count` 是赋值语句，其中 `price * count` 是表达式；它的结果是一个值，`total` 是随后绑定这个值的名字。

注释从 `#` 开始，用来写给阅读代码的人，通常不参与运行。注释应该解释意图或约束，例如“价格以分为单位，避免小数货币舍入问题”；把 `total += price` 注释成“给总数加上价格”，通常没有增加读者已经无法从代码直接看到的信息。初学阶段可以临时写详细语法注释帮助自己，熟练后再保留真正解释原因的注释。

语法错误意味着解释器无法按语言结构解析这段代码，例如括号没闭合或冒号缺失。运行时错误意味着语法可接受，但实际执行某一步时遇到问题，例如用零作除数。逻辑错误则可能完全没有异常：程序运行了，也输出了一个数字，只是这个数字不符合需求。三者需要不同的排查思路，不能把“没有红色报错”当成“程序正确”。

## 第二课：先认识最常见的值与运算

### 2.1 整数、浮点数、布尔值和空值

整数可以表示数量、索引、计数，例如三个请求、七个 token。浮点数用于近似表示实数，例如延迟 `0.15` 秒。Python 整数与多数固定宽度 GPU 整数不同，普通 Python 整数可以按需要使用更多存储来表示更大的数，但这不意味着内存和计算代价无限为零。进入 NumPy 后又会遇到固定宽度整数，不能把两者的溢出行为混为一谈。

浮点数通常不能精确表示任意十进制小数。你写下 `0.1` 时，内存中一般保存最接近它的一个有限二进制数。于是 `0.1 + 0.2` 的展示结果可能不是你直觉中的整齐 `0.3`。这不是 Python 随机算错，而是表示方式和舍入规则的结果。本章先记住：对一般浮点计算结果，测试应根据问题选择容差；F14 会把表示、误差和稳定性完整展开。

布尔值 `True` 与 `False` 表示两个逻辑状态，常见于条件判断。`None` 通常表示“这里没有一个正常结果”“尚未设置”或某种明确约定的缺失状态。它不等于数字零，也不等于空字符串。零可以是有效的计数，空字符串可以是有效的文本，而 `None` 可能表示计数根本还没计算。把三者都视作“反正没有东西”，会丢失业务信息。

```python
count = 0
name = ""
result = None
print(count == 0)
print(name == "")
print(result is None)
```

前三行创建三种不同状态。后三行分别验证它们。检查 `None` 通常使用 `is None`，这是判断是否为同一个特殊空值对象；比较两个计数是否数值相同，使用 `==`。不要因为某次实验中小整数的 `is` 恰好为真，就把身份判断用成普通数值比较。

### 2.2 运算符不是随意的数学装饰

`+`、`-`、`*` 是加、减、乘；`/` 是通常的除法，整数相除也可能返回浮点数；`//` 表示向下取整的除法；`%` 是与整除配套的余数；`**` 表示幂。向下取整不等于简单截掉小数部分：`-7 // 3` 是 `-3`，不是 `-2`。它和余数满足 `a == (a // b) * b + (a % b)`，前提是除数不是零。

页表、分批和张量索引会反复用到整除与余数。例如每页四个 token，逻辑位置六应该位于第 `6 // 4 = 1` 页的第 `6 % 4 = 2` 个槽位。这里的页与槽位都从零计数。你不是为了背 `%` 才学余数，而是为了把一个大位置拆成“第几块、块内第几个”。

`==` 检查相等，`!=` 检查不等，`<`、`<=`、`>`、`>=` 比较大小。单个 `=` 是赋值，它改变名字的绑定；两个 `==` 计算一个布尔结果，不改变被比较对象。初学者看到 `x = 3` 后再写 `x == 5`，并不会让 x 变成五，这一行只计算“x 是否等于五”。如果不打印或保存这个布尔值，脚本中可能没有任何可见效果。

运算有优先级，但代码可读性比故意利用复杂优先级更重要。`2 + 3 * 4` 先乘后加得到十四，`(2 + 3) * 4` 得到二十。业务公式涉及多个单位时，建议用括号和中间变量把含义写清楚。将每百万 token 费率直接乘 token 数而忘记除以一百万，语法和运算都合法，却会造成一百万倍的逻辑错误。

### 2.3 字符串是文本，不是自动识别的数字

`"12"` 是两个字符组成的字符串，`12` 是整数。`"12" + "3"` 拼接成 `"123"`；`12 + 3` 得到十五。Python 不会在一般加法中自动猜测你想把数字文本变成整数。显式转换 `int("12")` 会解析文本，`str(12)` 会产生可读文本。解析可能失败，例如 `int("twelve")`，因此来自文件、命令行或网络的数字文本需要验证和异常处理。

字符串可以被索引和切片。`text[0]` 取第一个字符，`text[-1]` 取最后一个字符，`text[1:4]` 取从一到三的字符，不包含右边界四。字符串本身不可变，不能通过 `text[0] = "A"` 原地修改一个位置。你可以建立新的字符串，再把原名字重新绑定到它，例如 `"A" + text[1:]`。

`len(text)` 数的是 Python 字符串中的 Unicode 码点数量，并不保证等于用户视觉上的字符数，也不等于 UTF-8 字节数。一个组合字符或表情可能涉及多个码点。对本章的简单英文例子可以直接按字符理解，但处理文件大小和网络长度时，要回到 F02 的编码与字节定义，而不是把所有长度都叫“字符串长度”。

## 第三课：名字、对象、类型与身份

### 3.1 “变量是盒子”在哪里会误导你

为了入门，可以暂时把变量想象成带名字的位置，但一旦研究可变对象，这个比喻就容易产生错误。更准确的模型是：对象持有值和类型，名字绑定对象。两个名字可以指向同一个对象；把一个名字重新绑定，不会自动改变另一个名字；修改共同对象，则所有仍指向它的名字都能观察到变化。

```python
a = [1, 2]
b = a
b.append(3)
print(a)
a = [9]
print(b)
```

执行第一行后，有一个列表对象，内容是一和二，名字 a 指向它。第二行没有复制列表，只让 b 也指向相同对象。第三行调用这个列表的 `append` 方法，给共同对象追加三，因此第四行输出 `[1, 2, 3]`。第五行创建另一个列表并让 a 改为指向它；b 仍指向旧列表，所以最后输出仍是 `[1, 2, 3]`。

这段例子同时包含“修改对象”和“重新绑定名字”，二者观察结果不同。不要用“给 a 赋值了”笼统概括所有情况。`a = [...]` 通常更新名字绑定，`a.append(...)` 修改已有列表，`a[0] = ...` 修改已有列表的一个元素引用。Agent 历史、缓存页表、请求队列都可能因为混淆这三种动作而产生串改。

### 3.2 值相等与同一对象

`[1, 2] == [1, 2]` 检查两个列表的内容是否按相等规则相同，结果为真。它们仍可以是两个独立列表对象。`is` 检查身份，表达的不是“内容一样”，而是“就是同一个对象”。当你怀疑两个请求共享了不该共享的状态时，身份检查很有用；当你只是判断用户输入是否等于某个数字时，使用值比较。

`type(x)` 返回对象的类型，`isinstance(x, T)` 判断对象是否属于某类及其子类关系。需要特别注意，Python 中布尔值在类型体系上与整数有继承关系。对于要求“必须明确给一个整数数量”的接口，`isinstance(True, int)` 会为真，这未必符合你的合同。课程的分批函数使用 `type(size) is int`，因此拒绝布尔值。其他 API 可能愿意接受整数子类，需要根据合同选择规则，而不是机械地到处使用同一种检查。

类型提示不会替代运行时检查。写 `size: int` 是向读者与静态分析工具表达意图，Python 默认不会据此自动拦截字符串或布尔值。外部边界接到 JSON 后，仍需要明确验证允许的类型、范围和缺失字段。内部函数如果已经由上游建立可靠合同，可以减少重复检查，但需要知道这个保证来自哪里。

### 3.3 对象引用的手工账本

| 步骤 | a 的目标 | b 的目标 | 原列表内容 | 新列表内容 |
|---|---|---|---|---|
| `a=[1,2]` | 原列表 | 未定义 | `[1,2]` | 不存在 |
| `b=a` | 原列表 | 原列表 | `[1,2]` | 不存在 |
| `b.append(3)` | 原列表 | 原列表 | `[1,2,3]` | 不存在 |
| `a=[9]` | 新列表 | 原列表 | `[1,2,3]` | `[9]` |

这个表不是为了记录一个玩具程序，而是在训练一种普遍调试能力：先追踪“谁拥有哪份状态”，再追踪“哪一步修改了它”。如果你只看最后打印的值，常常知道错了，却不知道从哪一步开始错。给对象起临时名称、记录引用关系，可以把看似神秘的共享状态错误变成可逐步核对的事实。

## 第四课：四种容器解决四种不同问题

### 4.1 列表：顺序与位置

列表适合表达一串有顺序的项目，例如对话消息、请求顺序、批次中的 token。列表允许重复，长度可以变化，可以通过整数位置访问。`append` 在末尾增加一个元素；`extend` 逐个增加另一个可迭代对象中的元素；二者不等价。向 `[1]` 追加 `[2,3]` 得到 `[1,[2,3]]`，扩展它则得到 `[1,2,3]`。

切片 `items[start:stop:step]` 通常产生新的外层列表，因此 `items[:]` 可以复制列表外层。切片右边界不包含在结果中，这种半开区间有一个实际好处：长度等于 `stop-start`，相邻片段 `[0:k]` 与 `[k:n]` 能无重叠地覆盖整体。页块、批次和张量切片都采用类似思路。对初学者而言，最可靠的方法是写出索引一行与值一行，对照取出的具体位置，而不是靠直觉猜最后一项有没有包含。

修改列表时要注意遍历语义。如果边遍历边删除当前列表中的元素，后续元素的位置会移动，循环可能跳过原本应该处理的元素。若目标是筛选，通常创建新列表更清楚：保留符合条件的元素，然后替换旧结果。原地修改并非一律错误，但需要对迭代器如何推进有明确认识，F07 会继续解释这个协议。

### 4.2 元组：一个有固定位置语义的组合

元组常用于返回多个相关结果，例如 `(success, value)` 或 `(request_id, latency)`。逗号决定元组结构，单元素元组要写成 `(value,)`；只有括号的 `(value)` 仍是原来的表达式。元组自身不能追加或替换元素引用，但其中可以包含可变对象。如果 `pair = ([1], 2)`，你不能执行 `pair[0] = [9]`，却可以修改内层列表 `pair[0].append(3)`。

因此“元组不可变”应严格理解为元组结构中的元素引用不可替换，不应扩大成“从元组能到达的所有内容都永远不可变”。这个区别与浅复制问题是同一类引用语义。为了避免读者误解，数据合同中最好说明哪些对象可以被修改，哪些只读，而不是仅凭外层容器的类型判断所有权。

解包把一个固定结构拆到多个名字，例如 `request_id, latency = ("r1", 0.2)`。元素个数不匹配会报错，这是帮助你发现数据结构与假设不符的检查。不要为了“避免报错”随意吞掉多余字段；先确认数据是否真的变更了格式。对多个相同单位的值，使用具名字段可能比依赖位置更容易阅读，后续会学习字典与类的取舍。

### 4.3 字典：从键找到对应值

字典表达键到值的映射，例如请求 ID 到请求记录、配置名到配置值。键需要能够作为哈希键使用，常见选择是字符串、整数或由不可变元素构成的元组。列表通常不能直接作为键，因为它可变，不适合维持稳定哈希查找语义。字典中的键必须唯一，给同一个键再次赋值会替换对应值，而不是自动保存两份历史。

`data[key]` 在键不存在时抛出 `KeyError`，适合“缺失就是错误”的合同。`data.get(key, default)` 在缺失时返回默认值，适合“缺失允许且默认值有明确含义”的合同。两者不是谁更高级的问题。如果一个服务配置必须包含模型名称，使用 `.get("model", "")` 可能把真实配置错误推迟到更难理解的位置；直接拒绝缺失往往更清楚。

字典推导式 `by_id = {row["id"]: row for row in rows}` 是一种紧凑写法，其含义可以展开成：建立空字典；逐个取 row；读取 row 的 id；把这个 id 对应到 row。它不会复制 row。如果 rows 中两个元素的 id 相同，后一个会覆盖前一个。你必须决定重复是合法更新还是输入错误，再选择是否在赋值前检查 `if key in by_id`。

### 4.4 集合：只关心是否出现过

集合适合成员判断、去重与集合运算，不表达重复次数，也不适合依赖某个元素的位置。`set(["a","b","a"])` 只保留两种不同成员，但不要把它转换回列表就声称保持了原输入顺序。若需要“首次出现顺序不变的去重”，应同时维护集合和列表：集合负责快速判断是否出现过，列表负责保存首次出现顺序。

这个组合说明，数据结构的选择不是在四种容器中永远只能选一种，而是按不同责任组合它们。检索系统可能用字典保存文档，用集合保存权限主体，用列表保存排名结果，用元组表达一个不可变键。重要的是每种结构在此处承担什么语义，而不是把所有数据塞进一种看起来方便的格式。

## 第五课：浅复制、深复制与共享状态

### 5.1 外层独立不等于内层独立

```python
from copy import deepcopy

original = [[1, 2], [3, 4]]
shallow = original.copy()
deep = deepcopy(original)
shallow[0].append(9)
print(original)
print(shallow)
print(deep)
```

`original.copy()` 创建一个新的外层列表，但把原外层中的元素引用复制过去。因此 original 和 shallow 不是同一个外层对象，却仍指向同样的两个内层列表。修改 shallow 的第一个内层列表，original 看到的第一个内层列表也变化。deepcopy 对这里的普通嵌套列表递归复制，因此 deep 保留原内容。

运行结果应该是 original 和 shallow 都包含 `[1,2,9]`，deep 的第一行仍是 `[1,2]`。要证明你理解了原因，除了比较值，还应检查 `original is shallow` 为假，`original[0] is shallow[0]` 为真，`original[0] is deep[0]` 为假。这三条观察分别对应外层新建、内层共享、递归复制。

### 5.2 为什么不能遇到问题就深复制

深复制可能昂贵，也不总能表达正确语义。数据库连接、打开的文件、线程锁、网络会话并不是普通值容器，复制它们可能没有合理含义。模型权重或很大的数组复制后会增加内存与耗时。某些对象的自定义复制行为也可能不同于你的直觉。因此处理共享状态的第一步是定义所有权与生命周期，而不是到处加 `deepcopy`。

假设工具调用返回一个结果字典，运行器把它加入历史，同时缓存也保存这个字典。如果后续步骤给字典增加一个字段，过去的历史可能被悄悄改写。你可以选择在记录历史时创建不可变快照，或者保证后续不再修改结果对象。两种设计都可以正确，关键是让读者和调用者知道谁能修改，谁只是读取。复制是一种实现手段，不是所有权设计的替代品。

再看 `rows = [[0] * 3] * 2`。这会把同一个内层列表引用重复两次，因此修改第一行第一个位置也会改变第二行同位置。若希望独立两行，应写成 `[[0] * 3 for _ in range(2)]`，每次循环创建一个新内层列表。两者打印的初始值完全一样，所以必须通过修改其中一处的反例才能看出差别。

## 第六课：条件分支把合同变成执行路径

### 6.1 条件是一个值，不是自然语言判断

`if condition:` 先计算 condition，再根据真假选择是否执行缩进块。`else` 表示其余情况，`elif` 表示继续检查另一条件。条件不会自动理解你对业务的模糊描述；“有效请求”必须拆成具体规则，例如 ID 非空、token 数为整数且非负、模型字段在允许集合中。

```python
tokens = 7
if tokens < 0:
    category = "invalid"
elif tokens == 0:
    category = "empty"
else:
    category = "nonempty"
print(category)
```

这段代码按顺序检查。第一条件为假，于是进入第二条件；第二条件也为假，执行 else。只有一条分支会给 category 赋值。若你用三个独立的 if，就不再是同一条互斥分支链，后面的条件仍可能执行并覆盖前面的结果。阅读程序时应先确认这些分支是否互斥，而不是只看它们缩进长度相似。

### 6.2 真值与缺失值的区别

Python 中空列表、空字典、空字符串、数字零和 None 在条件上下文中通常都被视为假。但它们的业务含义可能完全不同。假设 `limit=0` 表示不允许任何请求，`limit=None` 表示使用默认上限，写 `if not limit: limit=10` 就会把明确的零也改成十。正确判断应当是 `if limit is None`，因为此处只想识别缺失，而不是识别所有假值。

`and` 与 `or` 采用短路求值：如果左侧已足够决定结果，右侧不再计算。这可用于避免不合法访问，例如先检查列表非空，再访问第一个元素。但是它们返回的是参与判断的操作数之一，不一定是严格的布尔值。`name or "anonymous"` 是一种选择默认值的写法，仍然需要确认空字符串是否应该触发默认，而不是机械地在所有配置上使用。

### 6.3 提前返回与嵌套的取舍

若输入非法，可以尽早抛出异常或返回明确错误，让后面的主逻辑基于已经建立的前提运行。这样比在每一层都增加 `if valid` 更容易阅读。早返回不是为了减少几行代码，而是使函数结构清楚地分成“边界校验”和“正常计算”。不过，如果函数已经产生外部副作用，失败时就还需要清理与恢复，不能以一条 return 把责任隐藏掉。

## 第七课：循环是状态的逐步演化

### 7.1 for 循环中的变量从哪里来

`for value in values:` 不是一次把整个 values 塞进 value，而是从可迭代对象逐个取得元素，每次把 value 绑定到当前元素，再执行循环体。循环结束时，不代表 value 自动消失；在普通函数或模块作用域中，名字通常仍保留最后一次绑定。但如果输入为空，循环体从未执行，依赖循环后一定存在该名字就可能出错。

```python
total = 0
for value in [3, 5, 0]:
    total = total + value
print(total)
```

| 轮次 | 本轮 value | 更新前 total | 右侧表达式 | 更新后 total |
|---|---:|---:|---|---:|
| 初始 | 无 | 无 | 直接绑定零 | 0 |
| 一 | 3 | 0 | 0+3 | 3 |
| 二 | 5 | 3 | 3+5 | 8 |
| 三 | 0 | 8 | 8+0 | 8 |

每次赋值都先读取旧 total，再计算新值，最后重新绑定 total。数学上看起来奇怪的 `total = total + value`，在程序里表示状态更新，不是声称两个不同的数永远相等。你应能逐轮填写这个表，之后才能可靠地理解分页计数、累计损失和请求调度预算。

### 7.2 range、enumerate、zip 分别解决什么

`range(n)` 表示从零到 n 之前的整数序列，右边界不包含。`range(start, stop, step)` 允许指定起点和步长。它不是必须先创建一个装有所有整数的大列表；在需要迭代时逐个提供相应值。`range(7)` 配合批大小三会产生七个元素，而不是包含七的八个元素。

`enumerate(items)` 同时给出位置和元素，因此可以写 `for index, item in enumerate(items)`。它比手动维护一个计数器更直接，减少忘记递增或递增位置不正确的错误。若业务序号希望从一开始，可显式使用 start 参数；这只是展示编号改变，列表实际索引仍从零开始。

`zip(left, right)` 把多个序列按位置配对，默认会在较短的那个结束时停止。因此 lengths 不等的两个输入可能悄悄丢弃尾部。对于 q/k/v、预测与标签、请求与结果这类要求一一对应的结构，静默截断非常危险。使用显式长度检查，或者在所支持版本中使用严格 zip，才能把数据不一致变成可见错误。不要把“不抛异常”当成输入匹配的证据。

### 7.3 while、break、continue 与终止条件

while 在每次进入循环前检查条件，适合重复次数由运行状态决定的场景，例如“还有待执行工具且预算未耗尽”。它比固定列表遍历更灵活，也更容易因为状态不更新而无限循环。设计 while 时要明确写下三个量：开始条件是什么，每次迭代有什么进展，什么条件保证结束。

break 立即离开当前这一层循环，不会自动退出整个函数；continue 跳过本轮剩余语句，进入下一轮判断。若计数器更新放在 continue 之后，它可能永远执行不到。一个可靠习惯是先用很小的输入手工追踪所有分支，再增加复杂处理。真实工具循环还会加入时间、模型调用数、token 等多种预算，但最基本的终止思维就在这里形成。

## 第八课：函数从“重复几行”走向明确合同

### 8.1 定义函数与调用函数是两件事

```python
def add(a, b):
    result = a + b
    return result

answer = add(17, 25)
print(answer)
```

执行 `def` 时，Python 建立一个函数对象，并把名字 add 绑定到它；函数体不会立即用未知的 a 和 b 计算。执行 `add(17,25)` 时，才创建这次调用的局部执行环境，将形参 a、b 分别绑定到实参所表示的对象，执行函数体，最后把 return 表达式的值交给调用者。

形参是函数定义中的名称，实参是调用时提供的对象或表达式结果。说“参数错了”时，最好进一步指出是名称写错、位置对应错、类型不符合、范围非法，还是语义单位不一致。不同错误需要不同修复。函数接口越清楚，调用者越容易在运行前发现自己的理解与合同不一致。

局部名字 result 属于这次调用。另一次调用会有自己的局部绑定，不会因为同名就自动共享。函数仍可能通过参数引用修改外部对象，也可能读取或修改全局状态，所以“函数内部的变量是局部”不等于“函数绝对没有副作用”。区分名字作用域与对象所有权，是理解函数行为的关键。

### 8.2 return 与 print 的区别

print 把可读文本写到输出流，主要供人或其他程序观察；return 把对象交回调用者，供下一步计算。一个函数如果只是打印结果而没有明确 return，正常结束时返回 None。于是屏幕上显示五，但 `answer = function()` 中 answer 仍可能是 None。这个现象说明输出通道与函数返回通道完全不同。

设计可以复用的计算函数时，优先让它返回结果，把展示留给外层。这样同一函数既能被命令行调用，也能被 HTTP 服务、Agent 工具或测试调用。若函数内部直接打印一堆说明，机器调用者就不得不从混杂文本中重新解析结果，增加了本来不需要的耦合。

return 还会结束当前函数后续执行。因此将清理代码放在 return 后面是无效的。资源清理通常使用上下文管理器或 finally，本卷 F08 会完整展开。此时先记住：任何控制流出口都需要被纳入推理，不能只分析正常从第一行走到最后一行的路径。

### 8.3 参数传递并不自动复制容器

调用 `append_one(items)` 时，如果函数内部执行 `items.append(1)`，调用者的列表也会变化，因为形参绑定的是同一个列表对象。若函数内部执行 `items = [1]`，它只是把局部名字改绑到一个新列表，不会让调用者的原名字自动改绑。这里与前面的 a、b 别名例子是同一条语言规则，并没有一种神秘的“函数特例”。

因此函数合同应说明是否修改输入。对排序接口，`sorted(values)` 返回新的排序结果，`values.sort()` 修改原列表，这种区别会影响调用链中其他引用能观察到的状态。选择哪种方式要看所有权和性能，不应把“少分配一次列表”作为忽略副作用的理由。

## 第九课：默认参数、作用域与函数组合

### 9.1 默认参数的求值时机

默认值通常在函数定义执行时求值，而不是每次调用时重新创建。`def collect(x, bucket=[]):` 里的列表因此可能在多次调用之间共享。第一次追加一个元素，第二次调用又追加另一个，结果会同时包含两次内容。它不是解释器随机保留数据，而是两个调用都使用了同一个默认对象。

```python
def collect(x, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(x)
    return bucket

first = collect("a")
second = collect("b")
print(first, second)
```

使用 None 作为“没有显式提供列表”的标记，进入函数后再创建新列表，可以避免共享默认状态。这里不能写 `if not bucket`，因为调用者可能故意传入一个空列表并希望函数修改它；把它替换成新列表会改变合同。如果根本不需要累积接口，更简单的纯函数设计可能是直接返回新值。

### 9.2 位置参数与关键字参数

两个含义相似、类型相同的参数特别容易传反，例如输入费率和输出费率。使用关键字能把语义写在调用现场。函数定义中单独的 `*` 表示后面的参数必须通过名称传入。课程 `token_cost` 因此要求 `input_rate=...` 与 `output_rate=...`，减少“两个浮点数放错位置但程序照常运行”的风险。

参数名称是接口的一部分。给内部局部变量改名通常不影响调用者，但改变公开关键字参数名可能破坏已有调用。你会在后面的版本管理中看到，接口兼容性不是只看返回类型，还包括参数名称、默认值、错误行为和副作用。现在练习给函数写清楚合同，就是在建立这种工程意识。

### 9.3 从大函数拆成数据流

考虑“读取日志、解析 JSON、筛选成功请求、统计延迟、打印报告”。把全部内容写进一个长函数，最初看起来方便，但测试统计逻辑时就可能必须准备文件和终端。拆成读取、解析、筛选、统计、展示几个步骤后，中间计算可以直接接收普通 Python 值，更容易独立核对。

纯函数可以理解为：在相关输入相同的条件下，返回相同结果，并且不偷偷修改外部可观察状态。真正是否纯还取决于是否读取时间、随机数、全局配置等环境。我们不要求所有函数都纯，文件读取和网络请求本来就需要触及世界；目标是把这些边界清楚分离，让复杂系统中大部分逻辑可以用小输入可靠测试。

## 第十课：完整实现一个分批器

需求：给定任意可迭代输入和正整数批大小，将元素按原顺序分组，每个批次最多 size 个元素，最后不足一批也必须保留。空输入返回空列表。非法 size 必须在开始消耗输入前拒绝。返回结果的批次应是彼此独立的列表，不能因为继续处理后续数据而改变过去批次。

```python
def batches(values, size):
    if type(size) is not int or size <= 0:
        raise ValueError("positive integer size required")
    result = []
    current = []
    for value in values:
        current.append(value)
        if len(current) == size:
            result.append(current)
            current = []
    if current:
        result.append(current)
    return result
```

第一段校验把“明确正整数”变成可执行规则。result 保存已完成批次，current 保存尚未完成的当前批次。每读到一个 value，就把它追加到 current。当 current 达到 size，当前列表整体加入 result，然后把 current 改绑到一个全新的空列表。循环结束后，若 current 非空，说明还有尾批，必须保存。

为什么不是 `current.clear()`？因为 `result.append(current)` 保存的是同一个列表对象的引用。如果随后清空这个对象，result 中已经保存的批次也被清空。重新绑定到新列表则不修改旧对象。这是前面引用语义在真实算法中的第一次集中应用；如果你理解了对象与名字，就不需要把这行当成神秘口诀。

对输入零到六、size 为三，状态如下。第一个元素后 current 是 `[0]`，第二个后是 `[0,1]`，第三个后整批 `[0,1,2]` 被加入 result，current 变成新空列表。第四到六个元素形成 `[3,4,5]`。最后一个元素六留在 current，循环结束后保存尾批 `[6]`。输出为三批，长度依次三、三、一。

算法不变量是：已经保存批次中的所有元素，接上 current 中元素，恰好等于已读取输入前缀，且顺序不变。每次 append 把新读到的一个元素加在末尾，保持这个性质；转移完整 current 到 result 不改变元素序列；最后保存尾批使所有输入都进入结果。因此我们能解释为什么不丢失、不重复、不重排，而不只是碰巧看到某个样例正确。

## 第十一课：用小算法理解数据结构与复杂度

### 11.1 去重保序的两种实现

最直观的写法是建立 result，对每个元素检查 `if value not in result` 再追加。它很容易理解，但列表成员查询可能需要从头比较多个元素。若输入有 n 个不同元素，第一次比较很少，后来比较越来越多，总比较次数大约是一加二一直加到 n，规模增长接近平方。

如果元素可作为集合成员，可以另外维护 seen 集合，平均情况下成员查询更快。result 仍负责顺序，因此两种结构各司其职。不能只写 `list(set(values))`，因为那没有保留首次出现顺序的合同。也不能盲目假设任何对象都可放进集合：列表等可变容器通常不能直接作为哈希成员，需要换一种身份定义或使用其他算法。

```python
def unique_first(values):
    seen = set()
    result = []
    for value in values:
        if value not in seen:
            seen.add(value)
            result.append(value)
    return result
```

### 11.2 时间复杂度是在描述增长，而不是秒数

说一个算法平均时间复杂度为线性，表示输入规模扩大时，主要操作数量大致按一次方增长；不是保证每台机器上每个元素恰好一微秒。常数、缓存、解释器、数据类型、输入分布都影响实际耗时。复杂度帮助你比较规模趋势，计时实验帮助你判断具体环境，两种证据不能互相替代。

分批器需要读取每个元素一次，并保存全部返回内容，因此时间随输入元素数线性增长，返回结果占用的元素引用数量也线性增长。若改成生成器逐批产出，函数自身可以只保留当前批次，但调用者如果立刻 `list(...)` 收集所有批次，总内存仍然会增长。算法资源成本取决于整个消费方式，不只取决于某个函数内部看起来短不短。

### 11.3 为什么先写清楚再优化

初学者常因为听说推导式、向量化或某个库很快，就急于把所有循环改写成短表达式。若你尚不能解释循环不变量，紧凑写法会隐藏错误。先写清楚、可逐步打印、边界明确的版本，建立可靠参考，再优化并比较结果，这个顺序会一直延续到 CUDA 与 Triton 算子开发。

优化应针对可观察瓶颈。一个只有几十个请求的配置解析器，用线性扫描可能足够简单可靠；一个每秒处理大量 token 的热点路径则需要更仔细的数据结构与内存设计。不能只因为某个写法理论上更快，就忽略其复杂度、所有权或输入限制。正确性参考的价值在于，你之后可以用它验证更复杂版本没有改变合同。

## 第十二课：三个必须亲手制造的错误

**错误一：把返回值写成打印。** 写一个只 `print(a+b)` 的函数，再把它的调用结果赋给 answer，打印 answer。你会看到第一行数字，第二行 None。修复是让函数 return 值，并在调用者处 print。验证时不应只看屏幕是否出现过正确数字，而应直接断言函数返回对象等于预期。

**错误二：所有批次一起清空。** 在 batches 中把 `current=[]` 改为 `current.clear()`。输入六个元素时，过去保存的列表可能都指向同一个被反复修改的对象。用身份检查和逐轮打印定位共享。修复后，不仅比较嵌套列表值，还检查两个批次不是同一列表对象，再修改一个批次确认另一个不变。

**错误三：循环提前跳过更新。** 写 while 循环，在某分支执行 continue，而计数器递增放在它后面。先使用有限的外层测试保护或逐步调试观察，不要在共享服务器无限打印。修复方法是保证每条路径都会推进终止相关状态，或者重新组织循环，使递增发生在不会被跳过的位置。验证不只是“这次停了”，而是逐条分析所有分支为何能结束。

**错误四：默认列表串话。** 连续调用带可变默认参数的函数，观察第二次结果混入第一次数据。将默认值改为 None 并在函数内创建新列表，再验证显式传入列表仍按合同被修改。这个测试需要覆盖“未传参数”和“显式传空列表”两个情况，才能抓住 `if not bucket` 造成的新错误。

## 第十三课：十二道分级练习与完整参考解

### 题一：表达式与赋值追踪

给出 `x=3; y=x+2; x=10` 后两个名字的值，并解释为什么 y 不跟着变。答案是 x 为十、y 为五。第二条语句计算当时 x 的值加二，得到一个整数，再绑定给 y；它没有保存一个会自动重新计算的公式。要让 y 随 x 更新，需要再次执行计算，或设计具有这种依赖关系的系统。

### 题二：字面量解析

实现函数接受字符串形式的非负整数，不接受空串、负数或小数。这里采用明确的十进制数字字符合同，不自动接受空格和正负号。

```python
def parse_count(text):
    if not isinstance(text, str) or not text or not text.isascii() or not text.isdecimal():
        raise ValueError("ASCII decimal digits required")
    return int(text)

assert parse_count("007") == 7
```

答案刻意要求 ASCII，是为了避免“看起来是数字”的其他 Unicode 字符带来的合同变化。若业务愿意接受周围空格，应先明确说明再使用 strip，而不是在没有讨论的情况下悄悄放宽输入。测试至少包含零、前导零、空串、负号、小数点、字母和非字符串对象。

### 题三：去重保序

实现 `unique_first(["a","b","a","c"])` 返回首次出现顺序。完整实现见第十一课，关键是集合记录已见成员，列表记录输出顺序。验证还应包括空输入、全部相同、全部不同，以及修改返回列表不会修改输入列表的外层结构。输入元素本身若是可变对象，需要另行定义身份与复制合同。

### 题四：统计词频

```python
def frequencies(words):
    counts = {}
    for word in words:
        counts[word] = counts.get(word, 0) + 1
    return counts

assert frequencies(["a", "b", "a"]) == {"a": 2, "b": 1}
```

逐步解释：第一次遇到 a，默认计数零加一；遇到 b 同样建立计数；再次遇到 a，读取已有一再加一。字典的默认值零符合“尚未出现等于出现零次”的业务合同，所以此处使用 get 合适。若统计对象包含缺失名称，是否使用特殊键应由输入规范决定。

### 题五：安全求平均

```python
def mean(values):
    total = 0.0
    count = 0
    for value in values:
        total += value
        count += 1
    if count == 0:
        raise ValueError("mean of empty input is undefined")
    return total / count

assert mean([2, 4, 6]) == 4.0
```

空输入没有定义为零，因为零可能是有效平均值，不能用它掩盖缺数据。这里假设输入元素已经是允许的数值；若函数处在外部边界，需要进一步拒绝字符串、非有限值等。本题重点是理解累计和、计数与最终除法的责任，而不是把所有业务验证塞进一个练习。

### 题六：按预算取前缀

```python
def take_prefix(costs, budget):
    if type(budget) is not int or budget < 0:
        raise ValueError("nonnegative integer budget required")
    used = 0
    accepted = []
    for cost in costs:
        if type(cost) is not int or cost < 0:
            raise ValueError("nonnegative integer costs required")
        if used + cost > budget:
            break
        accepted.append(cost)
        used += cost
    return accepted, used

assert take_prefix([2, 3, 4], 5) == ([2, 3], 5)
```

这是前缀合同：遇到第一项放不下就停止，不跳过去寻找更便宜的后续项。若想“跳过放不下的项目继续挑”，需要把 break 改为另一策略，但那已是不同问题。验收应包括恰好用满、预算零、项目成本零、第一项超预算，以及非法负成本。

### 题八：不修改原输入的排序报告

```python
def ranked_copy(rows):
    return sorted(rows, key=lambda row: row["score"], reverse=True)

rows = [{"id": "a", "score": 2}, {"id": "b", "score": 5}]
ranked = ranked_copy(rows)
assert [row["id"] for row in rows] == ["a", "b"]
assert [row["id"] for row in ranked] == ["b", "a"]
```

lambda 表示一个简短匿名函数，此处接收 row 并返回排序键 score。sorted 返回新的外层列表，但里面仍是原字典引用，所以这不是深复制报告。若后续需要修改报告里的记录而不影响输入，应显式复制每条记录，或更好地建立只包含报告所需字段的新字典。

### 题十：把收费公式拆成可检查步骤

```python
def hypothetical_cost(input_tokens, output_tokens, input_rate, output_rate):
    if min(input_tokens, output_tokens, input_rate, output_rate) < 0:
        raise ValueError("negative quantity")
    input_cost = input_tokens * input_rate / 1_000_000
    output_cost = output_tokens * output_rate / 1_000_000
    return input_cost + output_cost

cost = hypothetical_cost(5000, 1000, 1, 3)
assert abs(cost - 0.008) < 1e-12
```

费率完全是假设练习，不能当任何供应商报价。五千输入乘每百万一元得到零点零零五；一千输出乘每百万三元得到零点零零三；总计零点零零八。将两项分别计算能帮助排查单位错误，比一个长表达式更容易手算核对。

### 题十一：重复 ID 应报错而不是覆盖

```python
def index_unique(rows):
    result = {}
    for row in rows:
        key = row["id"]
        if key in result:
            raise ValueError(f"duplicate id: {key}")
        result[key] = row
    return result
```

与普通字典推导式相比，差别不在结果形式，而在重复输入的语义。若重复 ID 表示无效数据，就必须在覆盖之前检查。若业务需要保留全部版本，则应该映射到列表或使用复合键，不能用一个会覆盖的结构来承载多版本合同。

### 题十二：完整请求统计器

```python
def summarize_requests(rows):
    result = {"requests": 0, "successes": 0, "tokens": 0}
    seen = set()
    for row in rows:
        rid = row["id"]
        if rid in seen:
            raise ValueError("duplicate request id")
        seen.add(rid)
        tokens = row["tokens"]
        if type(tokens) is not int or tokens < 0:
            raise ValueError("invalid token count")
        if type(row["ok"]) is not bool:
            raise ValueError("ok must be boolean")
        result["requests"] += 1
        result["successes"] += int(row["ok"])
        result["tokens"] += tokens
    return result

rows = [{"id": "r1", "tokens": 3, "ok": True},
        {"id": "r2", "tokens": 5, "ok": False}]
assert summarize_requests(rows) == {"requests": 2, "successes": 1, "tokens": 8}
```

这里的合同明确统计所有请求的 token，而成功数只统计 ok 为真的请求。如果你想只累计成功请求 token，需要改变需求和对应测试，不能在实现中自行猜测。这个小项目已经包含字典、集合、循环、条件、类型验证、异常和返回值，是后面日志分析工程的核心缩影。

## 函数调用的放大镜：调用栈、递归与组合

当一个函数调用另一个函数时，程序不会把两个函数的局部名字混成一团。可以把每次尚未结束的调用理解为一张工作记录：它保存本次局部绑定、接下来要执行的位置，以及返回后交给谁。内层函数结束后，控制权回到外层原来调用它的位置，返回值参与外层后续计算。这种后进先出的调用关系通常用调用栈描述。它不是你必须手动创建的Python列表，而是理解执行过程的一种模型。

假设外层函数先计算两笔费用，再求总和。它调用第一次费用函数时暂停在这一行；费用函数计算并返回后，外层把结果绑定给第一项；第二次调用建立另一份局部记录，两次函数中的同名局部变量互不混淆。最后外层把两项相加返回。若第二次调用抛出未处理异常，正常返回链就被异常传播取代，堆栈记录能告诉你错误经过哪些调用层。F09读取traceback时会再次利用这个模型。

递归是函数在执行中再次调用自身。它不是一种自动更快的算法技巧，而是用相同问题定义处理更小子问题。考虑非负整数的阶乘：零的阶乘定义为一；正整数n的阶乘为n乘以n减一的阶乘。正确实现必须同时包含最小情况和规模递减。计算三的阶乘时，最外层等待二的阶乘，二等待一，一等待零；零返回一，然后逐层乘回去，得到一、二、六。

如果只写“返回n乘以自身处理n减一”，没有零的基本情况，递归不会按数学定义终止。即便包含基本情况，若允许负数输入而只检查是否等于零，负数会继续变得更小，永远无法达到零。由此可见，终止证明依赖输入合同、基本情况以及每次递归的进展，缺少任何一项都不完整。Python通常对递归深度有限制，不能为了处理很长序列盲目增加限制；普通累积任务用循环往往更适合。

一个实用练习是先用循环算阶乘：结果从一开始，逐个乘上一到n；再写递归版本；对零、一、五比较结果；拒绝负数、浮点数与布尔值。两种实现计算同一数学对象，但保存中间执行状态的方式不同。循环显式维护当前乘积，递归通过尚未返回的调用记录保留待完成乘法。观察这种差别，会帮助你理解后续图遍历中的显式栈与递归遍历。

函数组合也不意味着必须增加嵌套深度。把解析结果赋给一个具名中间变量，再传给统计函数，往往比连续套几层函数更容易调试。中间变量可以记录数据类型与单位，例如已经验证的请求列表、以秒为单位的延迟列表、最终统计字典。每一层的合同成立，下一层才有可靠前提；若上游返回的是文本而下游期待数字，不应依靠下游猜测并悄悄修正。让边界清楚，会使整个程序逐层可检查。
