# 工作簿 W3：从 Dense Attention 到在线注意力，再读真实 FlashAttention

这是本卷最重要的贯通练习。它把模型公式、数值稳定性、分块状态、掩码、设备索引与真实源码连接起来。建议分多次完成，每次都留下可运行检查点。完成标准是你能独立重写与解释，不是能复述“减少HBM访问”。

## 阶段一：为最简单的 Attention 建立接口

先只做单头、无batch、无dropout的注意力。Q形状Nq×D，K形状Nk×D，V形状Nk×Dv。输出Nq×Dv。D用于query/key点积，Dv决定输出向量宽度，二者不必相等。很多教学示例总设D=Dv，会掩盖V地址误写成D的错误，因此本工作簿主动使用D=5、Dv=3。

写输入检查：三者二维，Q/K最后维相同，K/V行数相同，D和Nk非零。先不支持因果mask，避免同时引入位置语义。数学步骤S=QKᵀ/sqrt(D)、P=softmax(S)、O=PV，每一步写shape。S为Nq×Nk，P同shape，O为Nq×Dv。这张表以后会对应到每个块张量的维度。

构造Nq=1、D=1、Nk=3、Dv=1。令Q=[1]，K为 `[0,ln2,ln4]`，V为 `[10,20,30]`。缩放sqrt(D)=1，所以分数恰好是K。输出必须为170/7。这不是随机例子，而是专门让指数变成易算的整数比例。

## 阶段二：写出 Dense Oracle 并观察内存

用稳定Softmax完成dense实现。验证输出170/7，再换成两个query，确认每行独立处理。不要在在线实现完成后才写oracle，否则容易让二者共享同一种错误假设。

记录每个中间张量的元素数。若Nq=Nk=N，S有N²个元素，P也有N²个元素。N从1000变成2000，中间矩阵元素数变为四倍。Q/K/V自身随N线性增长，而S/P平方增长。这个差异是在线分块的动机之一。

但注意力的算术量并不会因为不保存S/P就自动从二次变线性。算法仍需处理相关query-key配对。你必须把“存储中间矩阵”和“执行点积配对”分开讨论，才能理解FlashAttention与线性注意力不同。

## 阶段三：只处理一个Query，建立状态语义

建立三个变量m、l、u，分别代表已处理key的最大分数、缩放分母、缩放加权分子。初始化m为负无穷，l=0，u为Dv维全零。此时还没有任何有效key，输出u/l尚未定义；不要在初始化后立刻计算结果。

每次读一个key，把它视为大小1的块。计算score，与m取最大，得到新尺度m'；计算alpha=exp(m-m')；计算新项p=exp(score-m')；更新u=alpha*u+p*v、l=alpha*l+p、m=m'。迭代结束输出u/l。

请按下表手算，不打开代码：第一项后m=0、l=1、u=10；第二项后m=ln2、l=1.5、u=25；第三项后m=ln4、l=1.75、u=42.5。每一步当前输出分别为10、50/3、170/7。

你需要能回答为什么旧u和旧l乘相同alpha。因为它们都用旧最大值m作为指数基准，改变基准后每一旧项都乘exp(m-m')。若只缩放l、不缩放u，相当于分子分母使用不同单位，比例不再有意义。

运行：

```bash
python -m labs.kernels.workbook attention
```

它同时展示故意漏掉u重缩放的错误轨迹：10、20、约34.2857。第二步就已经偏离50/3。发现错误发生于新最大值增大的那一步，便能定位重缩放，而不是盲目调整最终除法。

## 阶段四：从逐key改为key块

块内有多个score时，先求块最大值，再与旧m合并。p变成一组指数权重，分母新增sum(p)，分子新增p@Vblock。若Dv>1，每个输出维度共用同一组p，但对V的不同列求加权和。因此u的shape为Dv，而l和m是标量；多query版本则分别为Nq×Dv和Nq。

取block=2，前三项分成 `[0,ln2]` 和 `[ln4]`。第一块最大值ln2，p为[.5,1]，l=1.5，u=25；第二块alpha=.5，新增p=1，得到l=1.75、u=42.5。与逐key最终一致。这种块划分不变性应当成为测试属性。

选择Nk=7、block=3时，最后一块只有一个key。CPU切片自然只返回一个元素；GPU块张量会有额外lane，必须通过token<N mask让它们对最大值、分母和分子都不产生贡献。无效score应为负无穷，不能只把无效K/V填零：零K会得到score=0，仍可能吸收概率，即使对应V是零，也会稀释真实输出。

## 阶段五：向量化所有Query

现在让m/l长度为Nq，u形状Nq×Dv。每个key块产生scores形状Nq×BK，按最后维求最大值和sum。`alpha[:,None]`把每行缩放应用于该行全部输出维度。如果忘记新增轴，某些shape不兼容；若Nq恰好等于Dv，还可能沿错误方向广播而不报错。

本卷 `online_attention` 使用显式二维数组与keepdims思路。读每个表达式时，先写结果shape再读数值。`p@Vblock`形状Nq×Dv，这是块贡献；`u*alpha[:,None]`同shape，这是旧贡献在新尺度下的表示；二者可相加。用形状证明可以在运行前发现许多错误。

测试Nq≠Nk且无因果mask的矩形情况，例如Nq=3、Nk=7、D=4、Dv=2。数学上完全合法。随后用Nq=Nk的自注意力建立因果版本。不要因为第一组案例是方阵，就把方阵偷偷写进所有地址公式。

## 阶段六：因果关系是位置语义

等长自注意力中，第i个query只能看j≤i的key。建立显式布尔mask矩阵，先在dense oracle中应用，再在online每个块中应用。对于row0，第一块只有key0有效；后续块可能全无效。你必须保证这些块既不改变结果，也不会制造NaN。

CPU参考对全无效状态采取有限最大值保护。设备教学实现依赖自注意力第一块至少包含key0，因此在进入后续全无效块前已经有有限m。这是一个明确可解释的前提，不是通用Attention保证。扩展任意mask时，可能所有key都无效，必须重新定义输出与安全状态。

对于decode，Nq=1而Nk是整个历史长度，query的逻辑位置通常是历史末尾，不是矩阵行号0。有效条件应考虑位置offset。例如Nk=7、Nq=1、offset=6，唯一query可以看key0..6。若直接用j≤row，只看得到key0，输出仍有合法shape且不报错，却语义严重错误。这种错必须由位置语义测试抓住，单看CUDA是否越界没有帮助。

实现扩展时新增 `query_position_offset`，并规定它是标量还是每请求不同。先做单请求标量，dense mask采用 `j<=offset+i`，online采用同一语义但独立生成。测试offset=0、Nk-Nq与超出范围的错误处理，不要默默裁剪未定义输入。

## 阶段七：CUDA逐线程版让状态透明

`cuda/numerical.cu` 的online attention让一个线程负责一个query。它逐key读取K和V，保留m、denominator和最多16维numerator局部数组。这个版本不追求高性能：多个线程会重复读取K/V，点积是标量循环，Dv上限固定。但它清楚展示了在线状态能放在局部变量中，而无需存储完整S/P。

逐项核对地址：Q为row*D+z，K为token*D+z，V为token*Dv+z，输出为row*Dv+z。注意D与Dv的差异。因果判断在处理某key前跳过未来token；因为每线程独立，没有Block屏障，所以这一分支不会破坏块级同步协议。

局部数组可能被编译器放入寄存器，也可能因索引/资源压力溢出。源代码里写“local array”不是片上存储保证。编译器资源报告和最终指令才提供更具体证据。这正好连接K15的编译知识。

Host验证同时跑causal与noncausal，用double dense计算参照。N=7、D=5、Dv=3使三个重要维度不相等，帮助抓地址混淆。实际GPU运行后保存结果和环境；本次交付未编译执行CUDA，不能把本段已存在误报为已在H100通过。

## 阶段八：Triton逐Query块版

Triton `_attention`的每个Program负责一个query，但一次读取BK个key。q的逻辑宽度补齐到BD；keys形状BK×BD；按维1求和得到BK个score。values形状BK×BV；p[:,None]*values再沿key维归约得到BV个分子贡献。

这里有两种padding必须分别处理。head维D补齐时，把无效q/k元素设为零，点积不变；key维N补齐时，必须把无效score设负无穷，避免进入Softmax。V维Dv补齐时零填充并在最终store mask。三个维度都叫“补齐”，但对应单位元与mask位置不同，不能套一个统一做法。

读完每行，写变量shape：q `[BD]`；keys `[BK,BD]`；score/p `[BK]`；values `[BK,BV]`；numerator `[BV]`。m/l是标量。与CPU多query版相比，Nq这个维度已经被Grid分配给不同Program，所以Kernel内部没有Nq维状态。这是从全局张量分解到程序实例的重要转变。

本例用tl.sum做点积，便于理解，不是高吞吐FlashAttention。下一步的优化方向是让一个Program同时处理多个query，产生BM×BK分数Tile并使用适合的矩阵路径。但改动也会增加累加器大小、掩码复杂度与资源压力，不是只把grid变小。

## 阶段九：建立比随机对比更强的验收

第一类测试是dense与online数值一致，覆盖多个block大小。第二类是未来非干扰：修改未来K/V后，早期query输出不得变化。第三类是Value线性性：在固定Q/K、无dropout时，Attention对V是线性映射；对两个V输入，检查f(V1+V2)约等于f(V1)+f(V2)。第四类是常值V：若所有有效V相同，输出应为同一常向量。第五类是极端score：一个key远大于其他key时，输出应接近其V且仍有限。

这几类测试分别覆盖分块状态、mask语义、加权和、归一化和数值稳定。它们能发现不同错误，不能只靠增加随机seed数量替代。选择可解释的失败数据，会让调试效率远高于“某个随机case错了”。

对于全掩码行，先决定输出是零、错误或其他明确行为，再写测试。不能用某个库在一个版本的结果偶然为零，就推断这是所有Attention API统一约定。

## 阶段十：沿固定源码定位同一个不变量

本卷锁定的Triton源码commit为 `0861b90f695e3c866f6f7eadd4be8339378ab017`。在 `python/tutorials/06-fused-attention.py` 中定位 `_attn_fwd_inner`，不要先逐行翻译所有描述符与调参代码。先找到旧最大值、新最大值、alpha、分子累加和分母更新，分别映射到自己的m/l/u。

你会发现真实实现可能使用以2为底的指数、不同初始值、经过排列的累加器以及多个阶段。这时不要以变量名字看起来一样就认定状态语义完全相同。检查尺度因子放在哪里、哪个变量已经乘过log2(e)、输出何时归一化。若初始化l为1而m为负无穷，第一轮alpha为0，旧l贡献仍被清零；这是一例需要理解公式而非机械对齐初值的差异。

FlashAttention Hopper的 `hopper/softmax.h` 在固定commit `4616f5116d33e3ba3cbb71d582caffcfcb49649c` 中有Softmax状态和输出重缩放。先定位行最大值、行和与重缩放函数，再看这些状态如何对应矩阵累加器布局。你现在应能解释“为什么输出累加器也要缩放”，而不是把它当成神秘性能技巧。

源码阅读交付一页映射表：你的变量、真实符号、尺度语义、何时更新、谁消费。不要把整份第三方源码复制进教材；链接固定commit并记录自己的解释，既可复现也尊重项目许可。

## 阶段十一：性能实验从清楚的边界开始

先比较输出，再测设备执行。小N下，在线实现未必比dense库组合快，尤其教学实现没有高效矩阵路径。大N下，dense参考可能先受显存容量限制，但不能为了展示优势就把GPU占满。按16、64、128等有界尺寸逐步验证，确认内存与时间后才扩展。

报告至少分冷启动、稳态设备时间、峰值显存和真实输入尺寸。在线算法降低中间存储，不代表Q/K/V或所有缓存消失；也不代表模型支持上下文长度自动变大。模型位置编码、框架KV管理、算子支持和显存预算共同约束实际服务。

如果你加入batch、GQA或paged KV，先分析索引语义，再做性能。错误地重用别的请求的K/V可能得到数值正常但内容混乱的输出；这比单纯越界更难发现。因此最终综合测试应包含不同请求带可区分的合成数据，验证隔离。

## 加练：用错误案例理解实现边界

先做“缩放位置”实验。公式要求点积分数除以sqrt(D)。若你把这个缩放移到Softmax之后，数学结果会改变，因为Softmax是非线性的。选D=4、两个分数差较大的例子，手算缩放前后概率。正确做法可以把比例合并到Q/K或指数实现的系数中，但必须证明最终指数自变量相同。源码中的log2(e)系数就是这种需要严格跟踪的变换，而不是任意经验常数。

再做“常数平移”实验。对同一query的所有有效分数加同一常数，输出应不变；对不同key加不同常数则会改变权重。若你的online实现每个块分别减块最大值，却没有用alpha统一不同块尺度，就相当于给不同块施加了不一致的归一化基准。你可以选择第一块分数都很小、第二块分数都很大，使错误极其明显。这个反例比均匀随机数据更能击中核心不变量。

第三个实验是“mask位置”。先在score上mask，再Softmax；与先Softmax、最后把无效概率乘零比较。后者没有重新归一化，会让有效概率和小于一。若再额外归一化，数学上在有有效项时可恢复某些情况，但数值范围、全mask与性能都需要重新分析。实际Kernel通常选择直接在score阶段建立合法集合，使分母从一开始就只计算有效项。

第四个实验是“缓存读错请求”。建立两条很短序列，它们的V分别全为1与全为100。正确attention输出也分别在相应范围。如果分页索引把第一条请求指向第二条V，即使所有地址都在显存分配范围内，输出仍会显著错误。这个案例说明内存安全与语义隔离不同，也把算子学习连接到框架KV页表。你不必现在实现整个PagedAttention，但应理解测试必须覆盖不同请求的身份与逻辑位置。

第五个实验是“在线不代表低误差绝对保证”。改变块大小会改变归约顺序，float32结果可有微小差异。用float64 oracle观察误差分布，并对同一输入多次运行检查重复性。跨配置数值差异、同配置运行抖动和算法定义错误是三种不同现象，应分别报告。这样你未来研究确定性推理时，就不会把固定seed当作所有层级的解决方案。

最后把学习结果向另一位初学者讲一遍：先用三个key解释分母为什么变化，再用两块解释旧状态为何要换尺度，再用一个未来token解释因果掩码。对方若能照着你的地址表重写小程序，说明讲解真正连接到了实现；若只能重复“在线归一化、分块复用”这些词，就继续补充中间状态、具体下标和失败例子。教学本身也是检查理解漏洞的有效任务。
