# K06　GEMM：从三个循环到分块复用与 Tensor Core

先修 K01–K05。目标：从数学定义推导一个正确的 tiled GEMM，解释每个线程与每份数据的责任，并能阅读更复杂实现的分块层级。

## 1. 三个维度分别在做什么

矩阵 A 为 M×K，B 为 K×N，C 为 M×N：`C[i,j]=sum_k A[i,k]*B[k,j]`。M、N 决定有多少输出，K 是每个输出的归约维。通常把一次乘法与一次加法计为两个 FLOP，主计算量约 `2MKN`。不能把输出元素数 `MN` 当成计算量。

最直接的 Kernel 让每个线程负责一个 C 元素，沿 K 循环。它非常适合建立正确性，但邻近线程会重复读取 A 或 B。一个 A[i,k] 对同一输出行的多个 j 都有用，一个 B[k,j] 对同一输出列的多个 i 都有用；分块优化正是在保存这种复用。

手算 A=`[[1,2,3],[4,5,6]]`，B=`[[1,0],[0,1],[1,1]]`。结果为 `[[4,5],[10,11]]`。请把 C[1,0] 的三项写出来：`4*1+5*0+6*1=10`。之后任何复杂 Tile 都不改变这个归约关系。

## 2. Tile 是工作与数据的分组

让一个 Block 计算 C 的 T×T Tile。每轮沿 K 取 T 个位置，从 A 装入 T×T 子块，从 B 装入 T×T 子块，所有线程协作读到 Shared Memory，再执行 T 次乘加。每轮有 `2T³` FLOP、理想输入读取 `2T²` 个元素，所以在 float32 下，这一局部主循环的算术强度约 `T/4` FLOP/byte。注意它忽略输出写入、跨 Block 复用、缓存、边界与其他开销，不是整个 GEMM 的最终强度。

Tile 变大增加复用，但需要更多 Shared Memory 和寄存器，并可能减少并发驻留。性能设计没有“Tile 越大越好”的单调法则。小问题上过大 Tile 还会浪费大量补齐计算。你需要针对形状与硬件测量，而不是背一个万能值。

## 3. 两次屏障各保护什么

[basics.cu](../../labs/kernels/cuda/basics.cu) 的 `matmul<T>` 每轮包含：加载 A/B、屏障、计算、屏障。第一次保证消费者开始读取时，其他线程负责的数据已经就绪。第二次保证下一轮写入不会覆盖仍被其他线程读取的旧 Tile。把第二次删掉，可能在轻量测试中看似正常，却隐藏跨 Warp 时间差导致的竞争。

越界线程不能简单提前返回，因为它们还要参与 Block 屏障。正确做法是：无效 A/B 元素加载为零，所有线程参与同步，最后只有合法输出位置写回。这也解释了为何要用 `19x23` 乘 `23x17` 这类形状验收，而不是永远只测 1024 的整数倍。

## 4. 寄存器分块与 Tensor Core

更高性能实现通常让一个线程保存多个输出累加器。一个加载的 A 或 B 值可以被重复用于多个乘加，从而增加寄存器内复用。这与 Shared Memory 分块是不同层次：前者作用在线程/指令附近，后者作用在 Block 协作范围。

Tensor Core 为特定矩阵乘加形状和数值格式提供专门执行路径。它不是调用 `@` 就必然用到的独立“万能矩阵处理器”。指令对操作数布局、协作线程、数据类型、维度与累加方式有明确要求。Hopper 的 WGMMA 与 Blackwell 某些数据中心路径的指令组织又不同，见 K16。先读懂数据流，再学习如何满足指令契约。

GEMM 后常带 bias、激活、缩放、类型转换，这部分叫 epilogue。将它融合可以减少中间 C 的写回与再次读取。但若后处理太复杂，增加寄存器活跃范围，收益可能被资源压力抵消。融合应从明确的读写流量变化出发，而不是以代码行数判断。

## 6. 练习与参考答案

1. **手算 FLOP。** M=4、N=5、K=6，主 GEMM 约多少 FLOP？答案 240；精确加法次数可写成 `MN(K-1)`，但常用吞吐约定把 FMA 计二操作。
2. **尾部。** T=16、M=19、N=17、K=23，Grid 和 K 轮数分别是多少？答案 Grid 为 2×2，K 为两轮。第二轮只七个 K 元素有效，其余加载零。
3. **故障。** 把 B 的索引写成 `B[col*K+k]`，什么测试更容易发现？答案：B 非方阵、元素带行列可辨识编码；正确行优先索引为 `k*N+col`，不能用只含常数的 B。
4. **实现。** 为 CPU `tiled_matmul` 支持独立的 BM/BN/BK。参考：三个循环分别步进相应 Tile，切片自然处理尾部；测试所有三个维度均不整除。
5. **优化推理。** 将 bias 融合到 epilogue，省去多少输出张量流量？参考：相较独立 bias 算子，可省一次读取和一次写入中间 C；若 C 为 MN 个 float32，理想节省约 `8MN` 字节，但缓存会影响真实 HBM 流量。
6. **源码拓展。** 阅读 CUTLASS 官方 Efficient GEMM，画出 Threadblock、Warp、Instruction 三层 Tile。验收：选定一个具体实例，写清每层形状与数据生命周期，不能只抄三层名字。
