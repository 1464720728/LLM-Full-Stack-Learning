# K06 矩阵乘法：从三个循环、地址轨迹到共享内存分块与Tensor Core

矩阵乘法是理解模型计算与GPU优化最重要的交汇点之一。线性层、注意力中的两个大乘法、专家网络以及许多卷积变换，最终都会出现类似的数据复用关系。本章的目标不是记住一个最快的tile尺寸，而是让你能够从空文件写出正确实现，逐个解释线程索引与同步，再读懂高性能实现为什么采用分层分块。

先修K01至K05。你需要知道行优先地址、线程与block、shared memory、屏障和归约。不会矩阵数学也可以开始：第一课从一个输出元素的乘加解释，后续每次优化都保留同一数学定义。本章CPU参考可以直接运行；CUDA与Tensor Core部分是待具备对应环境后执行的实操，不把代码展示当成设备验证。

## 第一课：矩阵乘法究竟把什么变成什么

### 1. 三个维度的角色

设A有M行K列，B有K行N列，结果C有M行N列。C的第i行第j列，是A第i行与B第j列逐项相乘后求和。共同维度K表示需要配对的项数，所以A的列数必须等于B的行数。M与N决定输出有多少个位置，K决定每个位置需要累积多少项。

写成公式就是Cᵢⱼ=ΣₖAᵢₖBₖⱼ，k从零到K减一。公式中的i、j是自由索引，决定我们正在计算哪一个输出；k是归约索引，最终被求和消去。把这两类索引区分清楚，比一开始背矩阵形状更重要，因为后面的分块与并行都是在决定谁负责自由索引、谁遍历归约索引。

例如A为两行三列，第一行一、二、三，第二行四、五、六；B为三行两列，依次是一、零；零、一；一、一。C第一行是四、五，第二行是十、十一。C的一行不能只与B的一行相乘，因为内积需要沿B的列取数。很多初学者写错B索引，根源就是脑中仍按“对应行相乘”理解。

### 2. 把四个输出完整展开

左上角是一个一加二个零加三个一，得到四。右上角是一个零加二个一加三个一，得到五。左下角是四个一加五个零加六个一，得到十。右下角是四个零加五个一加六个一，得到十一。这四个输出之间没有直接依赖，可以分配给不同线程；每个输出内部的三项需要合并。

注意A的第一行被两个输出重复使用，B的第一列也被两个输出重复使用。矩阵乘法比普通逐元素乘法更有优化空间，正是因为相同输入对多个输出有贡献。若把每个输出当成完全独立的点积，就会重复从较远的存储层读同样的数据；分块的目标是把这份重复转成近处复用。

矩阵乘法一般不满足交换律。A乘B与B乘A可能连shape都不同，结果更不必相同。某些方阵或特殊输入会让错误交换不易察觉，因此测试不应永远使用方阵、单位矩阵或全一矩阵。最有效的初始测试通常是小型非方阵，并让各元素能体现行列位置。

### 3. GEMM比裸矩阵乘法多了什么

GEMM通常指一般矩阵乘法接口，常见形式为D=αAB+βC。α与β是缩放系数，C是已有矩阵，D是结果。有的接口允许原地覆盖C，有的要求独立输出；有的允许A或B按转置视图读取。接口名相同并不意味着所有布局与别名行为相同。

本章先实现α为一、β为零的C=AB，再逐步加入偏置与激活。这样做是为了把数学主循环和输出后处理分开理解。若一开始同时处理转置、缩放、批次、低精度、复杂激活与不规则步长，很难定位某个错误到底来自哪一层。

计算量常用约二乘M乘N乘K个浮点操作估计，因为一次乘加计作一次乘法加一次加法。精确数学操作计数可以写为MN次长度K的点积，每点积K次乘法与K减一次加法。但报告GPU吞吐时通常采用前一种约定，因此必须注明口径，不能把每条融合乘加指令只算一次后与其他报告直接比较。

## 第二课：用三个循环写出可信参考

### 1. 最小实现与必要检查

~~~python
import numpy as np

def matmul_scalar(a, b):
    a = np.asarray(a, dtype=np.float64)
    b = np.asarray(b, dtype=np.float64)
    if a.ndim != 2 or b.ndim != 2:
        raise ValueError('two matrices required')
    if a.shape[1] != b.shape[0]:
        raise ValueError('inner dimension mismatch')
    m, k_size = a.shape
    _, n = b.shape
    c = np.zeros((m, n), dtype=np.float64)
    for i in range(m):
        for j in range(n):
            accumulator = 0.0
            for k in range(k_size):
                accumulator += a[i, k] * b[k, j]
            c[i, j] = accumulator
    return c

a = np.array([[1, 2, 3], [4, 5, 6]])
b = np.array([[1, 0], [0, 1], [1, 1]])
assert np.array_equal(matmul_scalar(a, b), [[4, 5], [10, 11]])
~~~

外层i选择输出行，中层j选择输出列，最内层k遍历点积。accumulator必须在每个新输出开始时清零；若放在j循环外，第二列会混入第一列的总和。c只在点积完成后写一次，所以每个输出拥有独立且完整的生命周期。

把输入转成float64是参考选择，并不表示目标GPU实现也必须采用float64。参考用于减少比较过程中的额外误差，目标实现可能输入半精度、内部单精度累加、最后再转成输出类型。测试时应把目标实际收到的输入值转换成参考精度计算，而不是拿原始高精度数据与已量化输入的结果混为一谈。

K可以为零，此时每个点积是空和，结果为零矩阵。M或N为零时输出为空。教学CPU函数自然支持这些情况；GPU wrapper可以选择直接返回空输出而不launch，或者明确限制维度为正。重要的是接口合同与测试保持一致，不能让launch配置在零维时产生未定义行为。

### 2. 数组索引如何变成线性地址

对于连续行优先A，A[i,k]的元素偏移是i乘K加k；B[k,j]偏移是k乘N加j；C[i,j]偏移是i乘N加j。指针以元素为单位移动，只有计算分配字节数时才再乘元素字节大小。三种矩阵的行宽不同，不能看见“矩阵”就统一乘K。

在前面的两乘三与三乘二例子中，C[1,0]读取A偏移三、四、五，以及B偏移零、二、四。A地址连续，B地址隔一项。计算C[1,1]读取相同的A偏移三、四、五，以及B偏移一、三、五。这一组具体地址直接展示了A行复用以及B列访问的步长。

若B是转置视图，数学上仍读取B[k,j]，物理地址则应由实际stride决定。强行套k乘N加j只适用于连续行优先合同。高性能Kernel常通过wrapper限制布局，或者为常见转置模式生成不同专用路径；通用步长支持与最快连续路径之间存在工程取舍。

### 3. 循环交换改变局部性但不改变数学

可以把循环顺序改成i、k、j：固定A[i,k]，让它与B第k行所有列相乘，并累加到C第i行。这样B与C在最内层沿连续列访问，常比i、j、k顺序更适合普通CPU缓存。前提是C事先清零，且各项仍恰好累加一次。

~~~python
def matmul_ikj(a, b):
    a = np.asarray(a, dtype=np.float64)
    b = np.asarray(b, dtype=np.float64)
    if a.ndim != 2 or b.ndim != 2 or a.shape[1] != b.shape[0]:
        raise ValueError('compatible matrices required')
    m, k_size = a.shape
    n = b.shape[1]
    c = np.zeros((m, n))
    for i in range(m):
        for k in range(k_size):
            value = a[i, k]
            for j in range(n):
                c[i, j] += value * b[k, j]
    return c
~~~

这段代码没有减少数学乘法次数，改变的是数据访问顺序与复用机会。Python解释器开销会掩盖很多硬件效应，因此不要拿两个Python循环的耗时直接推断GPU策略。学习阶段先用它确认“数学等价”和“执行组织不同”可以同时成立，之后再在编译代码和真实设备上测量。

### 4. 带stride矩阵乘法：让逻辑坐标与物理布局分离

为了确认自己真正理解地址，把CPU参考改成显式storage和stride。设A逻辑shape为M乘K，但物理行stride可以大于K，例如每行后面有padding；也可以交换两个stride表示转置视图。数学循环仍是i、j、k，只有读取地址改变。这能把“矩阵乘法公式”和“连续内存假设”彻底拆开。

~~~python
def strided_matmul(a_storage, b_storage, m, n, k_size,
                   a_strides, b_strides, a_offset=0, b_offset=0):
    a_storage = np.asarray(a_storage, dtype=np.float64).reshape(-1)
    b_storage = np.asarray(b_storage, dtype=np.float64).reshape(-1)
    if min(m, n, k_size) < 0:
        raise ValueError('nonnegative sizes required')
    if len(a_strides) != 2 or len(b_strides) != 2:
        raise ValueError('two strides per matrix required')
    c = np.zeros((m, n), dtype=np.float64)
    for i in range(m):
        for j in range(n):
            total = 0.0
            for k in range(k_size):
                ai = a_offset + i * a_strides[0] + k * a_strides[1]
                bi = b_offset + k * b_strides[0] + j * b_strides[1]
                if not 0 <= ai < a_storage.size:
                    raise ValueError('A address out of storage')
                if not 0 <= bi < b_storage.size:
                    raise ValueError('B address out of storage')
                total += a_storage[ai] * b_storage[bi]
            c[i, j] = total
    return c

a_padded = np.array([1, 2, 3, 999, 4, 5, 6, 999])
b_data = np.array([1, 0, 0, 1, 1, 1])
out = strided_matmul(a_padded, b_data, 2, 2, 3, (4, 1), (2, 1))
assert np.array_equal(out, [[4, 5], [10, 11]])
~~~

A的物理行宽是四，但逻辑列数是三。哨兵九百九十九不属于矩阵，正确实现从不读取它。若错误地把A行stride当成K，第二行将从哨兵开始，结果会明显异常。这个测试比随机padding值更容易定位地址错误，也适合验证子矩阵和转置路径。

边界检查在每次访问时执行，便于教学定位；生产代码通常在wrapper阶段验证可达地址范围，避免在内层重复检查。若支持负stride，需要K01中的最小与最大可达偏移分析；如果GPU接口只支持正stride或连续输入，应明确拒绝，而不是碰巧在部分负stride输入上工作。

注意storage参数本身被reshape为一维只是教学表示。若调用者传入非连续NumPy数组，reshape可能复制，从而改变我们想讨论的底层共享关系。严谨使用本函数时，应传入明确的一维storage与单独的逻辑视图描述，不应把任意数组视图当作原始storage。这是接口边界，不是数学公式问题。


## 第三课：最朴素的CUDA矩阵乘法

### 1. 一个线程负责一个输出

~~~cpp
__global__ void matmul_naive(const float* a, const float* b,
                             float* c, int m, int n, int k_size) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;
    if (row >= m || col >= n) return;
    float accumulator = 0.0f;
    for (int k = 0; k < k_size; ++k)
        accumulator += a[row * k_size + k] * b[k * n + col];
    c[row * n + col] = accumulator;
}
~~~

二维block中的x方向对应输出列，y方向对应输出行。通常相邻x线程组成连续的线性线程序列，这有利于同一k时相邻线程读取B的一段连续列并写连续C。这里没有block内屏障，所以超界线程提前返回是安全的；后面加入共享内存时，同样的return方式就可能破坏同步。

若block为十六乘十六，grid的x维是N向上除以十六，y维是M向上除以十六。主机代码用(N+十五)/十六得到整数向上取整，但大尺寸要防止加法溢出，或采用更稳健的整除加余数判断。网格顺序与行列索引必须一致，不能启动按M、N排列却在Kernel中按N、M解释。

每个线程的accumulator保存在私有状态中，其他线程不需要访问。输出C的每个合法元素只被一个线程写入，因此不需要原子操作。对于初学者，先证明唯一写者和完整覆盖，再考虑优化，是最可靠的起点。

### 2. 用小网格逐个核对

设M为三、N为五，block为四列两行，则grid为两列两行。block(零,零)负责输出行零、一以及列零至三；block(一,零)负责相同行的列四至七，其中只有列四有效。block(零,一)负责行二、三和列零至三，其中只有行二有效；右下block只剩输出[二,四]合法。

总共启动三十二个线程，却只有十五个输出。这个例子不是性能建议，而是展示边界屏蔽如何保持正确性。若只检查启动线程数等于或大于输出元素数，并不能保证覆盖正确；二维映射中可能有重复或遗漏，必须结合坐标公式逐项验证。

当K为三时，每个合法线程执行三次乘加。一个输出线程结束得早，不影响其他输出，因为它们不共享中间状态。设备上的执行顺序可以任意交错，只要输入没有被并发修改、输出地址互不重叠，数学结果仍可独立解释。

### 3. 它为什么会重复读取

考虑同一输出行的N个线程。每个线程都遍历同一行A，因此从逻辑加载角度看，A的每个元素会被这些线程多次请求。硬件可能通过广播、缓存或合并机制减少某些实际访存，但代码没有显式组织跨线程复用。不能把逻辑加载次数直接等同HBM事务数，也不能因为存在缓存就认为组织复用没有意义。

同一输出列的M个线程也会重复使用B的相同列。一个block若覆盖多行多列，就存在把A子块与B子块装入shared后供多个线程消费的机会。我们接下来计算这种复用的收益，但仍会区分理想数据量与真实硬件流量。

### 4. 批量矩阵乘法多出来的轴

若有B组独立矩阵，A的shape为B乘M乘K，另一输入为B乘K乘N，输出为B乘M乘N。每个batch独立执行同样的矩阵乘法，可以把batch编号放进grid第三维，或在线性program编号中解码。关键是batch偏移分别使用各矩阵实际stride，不能统一乘MN。

例如两组A都是二乘三，连续存储时第二组A从偏移六开始；B矩阵每组三乘四，第二组从偏移十二开始；输出每组二乘四，第二组从偏移八开始。三个batch stride不同。把它们都写成“batch乘矩阵大小”而不明确是哪一个矩阵，很容易造成地址错误。

广播批量乘法还允许某个输入在batch轴只有一组，供所有batch复用。这时该输入的有效batch stride可视作零，类似K01广播。输出仍需要独立batch存储，不能也使用零stride，否则多个batch会写同一位置。读取共享与写入共享的合法性必须分开判断。

注意力多头计算经常把batch与head合并成一组批量维，再执行每头的QK转置或PV乘法。但reshape是否需要复制、head维是否连续、GQA是否让多个query head共享一个KV head，都需要单独推导。不要仅因为形状能写成三维，就认为每个batch都使用相同的连续stride公式。


## 第四课：分块的数学不变量

### 1. 把归约维切成连续区间

将K按长度BK切分，每个区间贡献一个部分乘积。C等于所有区间对应的A子矩阵乘B子矩阵之和。关键不变量是：完成前q个区间后，accumulator包含且只包含这些区间内k的乘积总和。下一轮只增加新k范围，不重置已经完成的结果。

M与N也可分成BM乘BN的输出块。一个block负责固定输出块，在K方向依次处理所有区间。输出块之间互不重叠，所以每块拥有自己的累加器；K分块只改变这个累加器如何逐步获得全部贡献，不改变最终输出所有权。

如果误把accumulator放在K块循环内部初始化，最后只保留最后一个区间。若每轮把累加器直接覆盖到C而不是累加，还可能看起来“每个块都算了”，却没有合并。一个K大于BK且只有前半段非零的测试，可以直接暴露这种错误。

### 2. 完整二乘二分块手算

取A为两行四列，第一行一、二、三、四，第二行五、六、七、八；B为四行两列，依次是一、二；三、四；五、六；七、八。BK为二。第一轮使用A前两列与B前两行，得到[[七,十],[二十三,三十四]]。第二轮得到[[四十三,五十],[九十一,一百零六]]，最终相加为[[五十,六十],[一百一十四,一百四十]]。

手算C[零,零]第一轮为一乘一加二乘三等于七，第二轮为三乘五加四乘七等于四十三，总和五十。C[一,一]第一轮为五乘二加六乘四等于三十四，第二轮为七乘六加八乘八等于一百零六，总和一百四十。每个输出都跨两轮保留累加器。

这种手算非常适合用来理解双缓冲：双缓冲不会改变两轮贡献，只是尝试让第二轮数据搬运与第一轮计算重叠。若还不能准确列出每轮A与B元素，先不要引入异步搬运和多阶段流水线，否则同步问题会掩盖最基本的数据分组错误。

### 3. 非整除维度如何保持定义

设M为十九、N为十七、K为二十三，方形tile为十六。输出网格为二乘二，K方向有两轮。最后一轮只有七个真实k位置，其余九个槽位填零。右侧输出块只一列有效，底部输出块只三行有效，但所有线程仍可能参与加载与屏障。

A加载的合法条件同时检查输出行和当前k；B加载同时检查当前k和输出列。只检查输出坐标是不够的，因为最后K块可能越界。最后写C只检查输出行与列，因为K维已经通过中性填充值处理。把这三个不同mask分开写，是避免边界错误的关键。

### 4. Split-K的收益、代价和后处理顺序

当M与N很小而K很大时，按输出块划分可能产生很少block，无法提供足够并行任务。Split-K把归约维拆给多个block，让它们各计算部分点积。这增加并行度，但引入部分结果存储与最终归约。它适合解决某些形状的并行度不足，不是默认比普通GEMM更好。

假设输出只有一个十六乘十六块，K被分成四段，则普通方案只有一个输出block，Split-K可以生成四个部分block。每个partial是十六乘十六个累加值，若保存float32，四份共四千零九十六字节。最后归约还要读取这些partial并写最终输出。这个额外流量与launch成本必须被更好的并行利用抵消，优化才有意义。

后处理必须注意可分配性。加法可以在合并后做一次bias，不能让四个partial各加同一个bias再相加，否则bias被加四次。ReLU更不能随意放到每个partial上，因为ReLU(a+b)通常不等于ReLU(a)+ReLU(b)。例如部分结果为负二与三，最终ReLU为一，而分别ReLU再相加为三。

~~~python
def split_k_reference(a, b, parts):
    a = np.asarray(a, dtype=np.float64)
    b = np.asarray(b, dtype=np.float64)
    if a.ndim != 2 or b.ndim != 2 or a.shape[1] != b.shape[0]:
        raise ValueError('compatible matrices required')
    if parts <= 0:
        raise ValueError('positive split count required')
    k_size = a.shape[1]
    edges = np.linspace(0, k_size, parts + 1, dtype=np.int64)
    partials = []
    for index in range(parts):
        begin, end = int(edges[index]), int(edges[index + 1])
        partials.append(a[:, begin:end] @ b[begin:end, :])
    return np.sum(np.stack(partials), axis=0), partials

total, partials = split_k_reference(a, b, 3)
assert np.allclose(total, a @ b)
~~~

这个参考允许空分段，空矩阵乘得到零贡献；GPU实现可以限制parts不超过K，或跳过空任务。np.linspace生成近似均分的整数边界，测试应检查首边界零、末边界K、边界非递减，保证每个k恰好落在一个区间。分块平衡不是正确性的必要条件，但影响负载分布。

浮点归约次序也随Split-K改变。即使每份partial都正确，最终舍入可能与单block顺序不同。需要合理误差比较，不能要求所有精度与形状都逐bit一致；若业务要求确定性，应固定分段与合并顺序，并说明跨架构仍可能存在差异。


## 第五课：共享内存分块的完整CUDA实现

~~~cpp
template<int T>
__global__ void matmul_tiled(const float* a, const float* b,
                             float* c, int m, int n, int k_size) {
    __shared__ float tile_a[T][T];
    __shared__ float tile_b[T][T];
    int tx = threadIdx.x;
    int ty = threadIdx.y;
    int row = blockIdx.y * T + ty;
    int col = blockIdx.x * T + tx;
    float accumulator = 0.0f;
    int rounds = (k_size + T - 1) / T;
    for (int round = 0; round < rounds; ++round) {
        int a_col = round * T + tx;
        int b_row = round * T + ty;
        tile_a[ty][tx] = row < m && a_col < k_size
                        ? a[row * k_size + a_col] : 0.0f;
        tile_b[ty][tx] = b_row < k_size && col < n
                        ? b[b_row * n + col] : 0.0f;
        __syncthreads();
        for (int kk = 0; kk < T; ++kk)
            accumulator += tile_a[ty][kk] * tile_b[kk][tx];
        __syncthreads();
    }
    if (row < m && col < n)
        c[row * n + col] = accumulator;
}
~~~

### 1. 每个线程先当搬运者，再当计算者

这个版本要求block维度恰好是T乘T。每个线程向tile_a与tile_b各写一个元素，因此T平方个线程合作搬入两个T平方子块。线程计算自己负责的一个C元素时，会读取tile_a的一整行和tile_b的一整列。搬入的某个元素不只由搬入它的线程使用，而是被同block内多个线程复用。

例如T为二，线程(tx一,ty零)负责输出块的右上角。它搬入A子块的右上元素和B子块的右上元素，随后计算时读取A子块第一行两项与B子块第二列两项。其中部分数据由另一个线程搬入，所以不能只依赖程序中“我的load写在计算之前”；必须确保其他线程的写入也已完成。

shared下标ty、tx表示子块内坐标，global下标row、col和round表示完整矩阵坐标。把局部与全局坐标混用，可能访问超出shared数组或读取错误输入。读代码时给每个变量写上“全局行”“局部列”“归约块号”，比只记住变量名更有帮助。

### 2. 第一条屏障建立生产完成条件

所有线程写完当前tile后执行第一条屏障。它保证当任何线程开始读取shared用于乘加时，当前block内参与线程在屏障前的相应写入已对协作读取可见。没有这条屏障，先调度的warp可能读取尚未由另一个warp写好的槽位。

这条屏障不是为了等待全GPU，也不保证其他block的工作完成。每个block有自己的shared数组实例，彼此不需要共同完成一个tile。将block局部数据流误想成全局共享，是初学者理解CUDA同步时常见的偏差。

### 3. 第二条屏障保护旧数据不被覆盖

乘加结束后，线程将进入下一轮加载，重新使用同一片shared数组。如果某个warp计算较快，开始覆盖下一轮tile，而另一个warp仍在读取上一轮数据，就出现读写竞争。第二条屏障确保所有消费者完成当前tile使用后，才允许任何线程重用存储。

删除第二条屏障有时不会立刻失败，因为小输入、特定调度和缓存状态可能让线程进度碰巧接近。偶尔通过不是正确性证明。可以构造多个warp、多个K块和不同计算负载放大风险，但最终应依靠数据依赖分析说明屏障必要，而不是等待某一次随机失败。

### 4. 为什么尾部线程不能提前退出

在naive版本中，超界线程直接return没有问题，因为没有集体屏障。此处超界输出线程仍可能负责搬入其他有效输出需要的A或B元素，并且仍必须参与block屏障。把naive的边界return原封不动复制到tiled版本，是非常典型的迁移错误。

正确方式是让无效加载写入零，让全部线程沿相同屏障路径执行，只在最终输出阶段限制合法写回。这里的零具有乘法累加中性作用：任意合法值乘零不改变总和。若填充未初始化值或NaN，即使最后输出mask正确，中间归约仍会污染合法结果。

## 第六课：把复用收益算成可检验的数字

### 1. 一个输出块的一轮数据量

一个BM乘BN输出块，每轮沿K读取BK个位置，需要A的BM乘BK个元素与B的BK乘BN个元素。执行约二乘BM乘BN乘BK次浮点操作。若输入元素各占s字节，则理想主循环输入流量为s乘BK乘(BM+BN)。

相除得到理想局部算术强度二乘BM乘BN除以s乘(BM+BN)。当BM与BN都等于T、输入为四字节时，得到T除以四。这个推导中的BK约掉了，说明仅在此简化模型下，增加归约块长度不直接提高输入复用比；它仍会影响同步频率、shared占用和流水线组织。

这不是整个Kernel的最终算术强度。模型忽略输出写回、可能读取已有C、边界padding、跨block缓存复用和临时数据。把T除以四直接乘GPU峰值带宽预测实测速度，会漏掉很多限制。正确用法是比较设计趋势，并把假设逐条写清。

### 2. 用十六与三十二作对照

T为十六时，一轮计算八千一百九十二FLOP，读取五百一十二个float，共二千零四十八字节，强度为四。T为三十二时，一轮计算六万五千五百三十六FLOP，读取二千零四十八个float，共八千一百九十二字节，强度为八。复用比提升一倍，但线程数若仍是一线程一输出，也从二百五十六变成一千零二十四。

更大的线程块可能触及硬件或编译配置限制，也可能降低同时驻留的block数。shared占用从两千零四十八字节增长到八千一百九十二字节，寄存器与调度成本也可能变化。因此“复用比更高”只是一个有利因素，不足以推出“整体更快”。

对非常小的矩阵，大tile还会执行大量填零乘加。例如M与N都为十七时，使用三十二方块启动一个大块，输出位置只有二百八十九个合法，而计算槽位有一千零二十四个。一个更小tile可能有更多block，但更少无效工作。形状分布决定优化目标，不存在对所有模型层都最优的固定tile。

### 3. 输出流量与β路径

若C=AB且输出float32，最终至少要写MN个元素。若计算D=αAB+βC且β非零，还需要读取已有C。β为零时某些实现可以跳过C读取，但不能先读取未初始化C再乘零，因为NaN乘零仍可能传播，且无意义读取本身也违反良好接口设计。

当K很大，主循环工作通常占比更大；当K很小，输出读取、后处理与launch开销可能变得显著。理解这个比例有助于解释为什么相同M、N下，改变K会影响最佳策略。性能分析要从完整算子的数据流出发，而不仅盯住矩阵乘指令。

## 第七课：线程内寄存器分块

### 1. 一个线程拥有多个输出

共享内存分块让一个block复用输入，寄存器分块进一步让一个线程用一组输入更新多个累加器。假设一个线程负责两行两列的输出小块，它保存四个accumulator。每个k读取两个A值与两个B值，进行四次乘加。相同A值分别乘两个B值，相同B值分别乘两个A值。

这相当于对一个小外积做更新。若A片段为a零、a一，B片段为b零、b一，则四个更新分别是a零b零、a零b一、a一b零、a一b一。把这个二乘二例子画成四个输出格，就能看清输入复用如何发生在同一线程的寄存器内部。

~~~python
def outer_update(acc, a_fragment, b_fragment):
    acc = np.asarray(acc, dtype=np.float64).copy()
    aa = np.asarray(a_fragment, dtype=np.float64)
    bb = np.asarray(b_fragment, dtype=np.float64)
    if acc.shape != (aa.size, bb.size):
        raise ValueError('fragment shape mismatch')
    for i in range(aa.size):
        for j in range(bb.size):
            acc[i, j] += aa[i] * bb[j]
    return acc

assert np.array_equal(
    outer_update(np.zeros((2, 2)), [2, 3], [5, 7]),
    [[10, 14], [15, 21]])
~~~

### 2. 累加器数量为何重要

一个RM乘RN寄存器tile需要至少RM乘RN个累加标量，还要保存地址、循环变量和输入片段。输出tile增长时，累加器数量按面积增长。寄存器资源有限，过多活跃状态可能降低驻留warp数，甚至导致spill到local memory，从而引入额外设备内存访问。

不能仅根据源代码中声明的数组长度准确推断最终寄存器数。编译器可能展开、复用、消除或溢出变量，实际结果需要看编译报告和底层代码。源级估算用于提出风险与候选配置，最终验证要结合工具输出与测量。

线程负责多个输出也改变输出映射。必须明确线程编号如何映射到寄存器tile的起点，以及内部小循环如何覆盖完整block输出tile。一个常见错误是线程步长仍按单输出设计，导致相邻线程的小tile重叠。用所有输出写者计数的CPU模拟，可在GPU运行前发现这类问题。

### 3. 三层tile分别解决什么

threadblock tile决定一个block负责哪块输出与需要多少shared数据；warp tile决定一个warp内部协作的输出范围；instruction tile决定一条矩阵乘加指令消费与产生的片段。层次之间存在整除、布局和资源约束，不是三个任意填写的数字。

例如你可以先在纸上选择block输出六十四乘六十四，由四个warp各负责三十二乘三十二的象限，再把每个warp输出拆成若干更小的指令片段。这只是结构示例，不是对任何具体指令支持形状的承诺。真正实现时必须查目标架构、数据类型和所选指令的合同。

阅读CUTLASS时，看到多个Shape类型不要急着把它们都理解成同一矩阵shape。先判断它属于问题规模、block任务、warp任务还是指令操作数。然后追踪一个输出元素从全局坐标到block局部、warp局部和寄存器片段的位置，逐层确认坐标变换。

### 4. 一个线程内四输出映射的完整地址练习

考虑一个block输出八行八列，由四乘四个逻辑线程组成，每个线程负责两行两列。令线程坐标为ty、tx，则它的输出起点是二乘ty、二乘tx，内部偏移ri、rj各取零或一。最终输出坐标为二乘ty加ri、二乘tx加rj。

线程(ty一,tx二)负责行二、三与列四、五，共四个输出。线程(ty一,tx三)负责同样两行与列六、七，两者没有重叠。将所有十六个线程的四个输出列出，恰好覆盖六十四个位置。若误写起点为ty、tx而不是乘二，输出小块会严重重叠，右下区域还会遗漏。

每个k上，线程(一,二)读取A的行二与三的当前k元素，以及B当前k行的列四与五元素。四个乘积分别累加到自己的四个寄存器。若A值为二、三，B值为五、七，当前贡献就是十、十四、十五、二十一。下一k轮只更新累加器，不改变输出归属。

~~~python
def register_tile_owners():
    owners = np.zeros((8, 8), dtype=np.int64)
    for ty in range(4):
        for tx in range(4):
            for ri in range(2):
                for rj in range(2):
                    owners[2 * ty + ri, 2 * tx + rj] += 1
    return owners

assert np.all(register_tile_owners() == 1)
~~~

真实GPU实现还要考虑线程线性编号、warp排列和合并访存，因此这个映射只是正确性起点。它没有自动保证shared读取无bank冲突，也没有说明最佳寄存器数量。把这些问题分层分析，才能知道一次优化改变了数学覆盖、存储布局还是硬件调度。


## 第八课：流水线与双缓冲的正确顺序

### 1. 为什么要重叠搬运与计算

普通tiled实现每轮先加载，再等待，再计算，再等待。若硬件与编程机制允许，下一轮数据搬运可以与当前轮计算重叠，从而减少纯等待时间。双缓冲为当前轮与下一轮各保留一套存储，避免下一轮写入直接覆盖当前数据。

假设有三轮数据。预热阶段先准备第零轮；稳定阶段计算第零轮同时准备第一轮，计算第一轮同时准备第二轮；收尾阶段计算第二轮。总时间不再简单等于每轮加载加计算，但实际重叠程度受依赖、资源、指令与硬件调度影响。时间线必须包含预热与收尾，小问题上这两部分可能占很大比例。

双缓冲不是把数组第一维改成二就自动获得异步。普通同步加载仍可能按程序依赖顺序执行；要实现真正有效的流水线，需要适当的异步搬运或编译器调度，并满足目标平台的机制要求。教学先证明缓冲区所有权，再讨论具体异步指令。

### 2. 用槽位状态证明不会覆盖

每个缓冲槽可抽象为四个状态：空闲、正在装入、可以消费、正在消费。生产者只有在槽位空闲时才能开始装入；消费者只有在数据就绪后才能读取；所有消费者完成后，槽位才重新空闲。双缓冲将轮次q映射到槽q模二，但这个取模只决定位置，不自动完成状态转换。

第零轮和第二轮使用同一槽。如果第二轮装入开始时，第零轮仍有消费者读取，就会覆盖旧数据。必须有明确的完成信号保证复用安全。相反，如果消费者在第一轮装入完成前开始读第一槽，就会读取旧值或未完成数据。这两种错误分别是“过早复用”和“过早消费”。

异步完成与线程到达屏障也不是完全同一概念。某些机制需要等待特定异步事务组完成，再建立消费者可见性；不同API有不同要求。不能把普通__syncthreads机械替换成某个wait函数，必须查所用指令的内存与同步合同。K16与K17会在硬件边界清楚后继续讨论。

### 3. 一个CPU状态机模拟

~~~python
def simulate_double_buffer(rounds):
    states = ['free', 'free']
    log = []
    if rounds == 0:
        return log
    states[0] = 'ready'
    log.append(('load', 0, 0))
    for current in range(rounds):
        slot = current % 2
        assert states[slot] == 'ready'
        states[slot] = 'reading'
        next_round = current + 1
        if next_round < rounds:
            next_slot = next_round % 2
            assert states[next_slot] == 'free'
            states[next_slot] = 'ready'
            log.append(('load', next_round, next_slot))
        log.append(('compute', current, slot))
        states[slot] = 'free'
    return log
~~~

这个模拟只检查缓冲区依赖，不模拟真实并发时间，也不证明某个CUDA异步实现符合硬件内存模型。它的用途是帮助你在引入低层API之前，先把轮次、槽位和生命周期写清楚。完成后应尝试故意提前加载第二轮，看断言如何发现槽零仍在读取。

## 第九课：Tensor Core的数学与执行合同

### 1. 专门的矩阵乘加操作

Tensor Core相关指令执行特定形状与类型的矩阵乘加，基本数学形式仍然是D=AB+C。它们的优势来自专用执行路径与协作数据组织，不是改变矩阵乘法定义。程序员必须让操作数布局、数据类型、累加类型和协作线程满足所选接口的要求。

标量FMA通常可以想成一个线程更新一个或少数标量，矩阵指令则由一组线程共同提供分布在寄存器或其他规定存储位置中的片段。一个逻辑矩阵片段不一定由一个线程完整持有。若把每个线程的寄存器数组当成普通连续小矩阵，就容易误读指令布局。

先学习较高层的矩阵片段接口，再阅读PTX中的具体操作数映射，是合理路径。不同架构的指令组织可能涉及warp、warp group或不同存储资源，不能把某个接口的规则推广到所有Tensor Core。特别是消费级Blackwell与数据中心Blackwell的能力边界，不能仅由营销代号推断。

### 2. 输入精度与累加精度是不同选择

假设输入先转成较低精度格式，再以float32累加。乘积所依据的是已经舍入后的输入，累加精度提高只能减少后续求和误差，无法恢复输入中已经丢失的位。比较参考时，应同时报告相对于原始高精度问题的总误差，以及相对于量化后输入的计算误差。

某些矩阵路径还会对float32输入采用不同的内部乘法精度策略。接口选项、框架默认值和硬件支持可能随版本变化，因此实际实验必须记录精度配置，不能仅看到输入dtype为float32就宣称每次乘法都等价于严格float32标量乘法。

累加器最终写成较窄输出类型时还会再次舍入。完整数值链条应写为输入编码、乘法方式、累加方式、后处理和输出编码五个阶段。K11会详细讲量化与打包，本章先建立“dtype不是一个标签就能概括全部计算”的认识。

### 3. 为什么布局变换会成为核心工作

矩阵指令要求参与线程在规定位置提供片段，而全局矩阵通常按行优先或列优先存储。中间需要把数据从global搬到shared，再按特定方式送入寄存器或指令可消费的布局。这个搬运与重排过程可能占用相当多的指令、shared容量和同步。

因此高性能GEMM代码常有大量看似与乘法无关的布局、迭代器、swizzle和pipeline类型。它们不是无意义复杂化，而是在满足复用、bank访问、指令片段和异步执行之间的约束。阅读时应先画数据从哪来、被谁读取、最终归哪个输出，再逐个理解布局变换的作用。

一个简化思考题是：若global中同一行连续存储，而消费者需要同一列的片段，直接按列读取可能不合并；先协作按行装入shared，再以适合消费者的布局读取，可以把两个访问目标分开实现。shared转置与padding就是早期训练，后续复杂swizzle仍在解决类似问题。

### 4. 指令片段的阅读方法：先知道哪些映射不能猜

读到矩阵指令时，先记录逻辑操作形状，例如每次计算多少行、多少列、多少归约元素，再记录协作线程集合、输入类型与累加类型。接着查每个lane持有哪些逻辑元素，以及操作数从寄存器还是指定存储空间提供。最后才讨论某个寄存器编号对应哪个矩阵坐标。

不同接口可能故意把片段内部布局当作不透明实现细节。此时你可以通过官方load、mma、store接口完成正确操作，但不应自行假设fragment数组顺序等于行优先顺序。若需要按元素修改累加片段，应确认所用接口允许的操作范围和布局稳定性，不能从一次调试打印推广成通用合同。

为了训练这种谨慎，先做一个抽象练习：假设四个参与者协作持有二乘四矩阵，每人保存两个元素。行条带分配、列条带分配和交错分配都能覆盖相同逻辑矩阵，但参与者零的第二个寄存器可能对应完全不同的位置。仅知道“每人两个寄存器”不足以恢复矩阵布局，必须知道映射规则。

Tensor Core实现中的数据搬运、shared布局和片段布局需要相互匹配。global读取合并良好并不保证shared消费无冲突；shared无冲突也不保证片段顺序符合指令要求。每一层都要有独立证据，最终通过完整数值测试确认组合正确。


## 第十课：Epilogue、融合与别名合同

### 1. 主循环之后还有什么

矩阵乘法的主循环结束后，输出往往还需要缩放、加偏置、激活、残差或类型转换。这部分常称为epilogue。若单独执行，每个阶段可能读取和写回整个MN输出；融合到GEMM最后写回前，可以利用仍在寄存器中的累加器完成部分操作。

例如C=AB+b，b长度为N，按列广播。每个输出使用b[j]，不是b[i]。当M与N相等时，错误下标可能不会越界，却会把偏置加到错误方向。用M不等于N且偏置各项不同的测试能快速定位这种问题。

### 2. 理想节省与实际代价

若GEMM先写float32中间C，随后bias算子再读取C并写最终结果，融合理想上省掉一次中间读取与一次中间写入，即约八乘MN字节。bias自身仍需要读取，实际HBM流量还受缓存与调度影响，因此这个数字是逻辑张量流量估计。

融合也可能增加寄存器活跃范围、指令数与编译复杂度。复杂激活或多个残差输入可能让epilogue成为显著开销。若后处理需要跨输出归约，例如对整行归一化，它就不再是简单独立逐元素收尾，需要考虑block分工是否覆盖完整归约范围。

### 3. 原地写入为什么需要证明

允许D与C别名通常较容易，因为每个输出只读取对应旧C再覆盖；允许D与A或B别名则危险得多，因为某个block可能覆盖另一个block尚未读取的输入。不能仅因为单线程CPU循环某次碰巧正常，就给并行算子开放这种别名。

接口中应明确哪些输入可与输出共享storage。若不支持，wrapper可检测或要求调用者遵守，并在测试中包含明显重叠案例。自定义算子接入框架时，别名与mutation还会影响autograd和编译器，K10会继续解释。

## 第十一课：错误实现的定位流程

### 故障一：把B行宽写成K

错误地址为b[col*k_size+k]，正确连续行优先地址为b[k*n+col]。使用方阵且对称B时错误可能部分隐藏。改用三行两列、每个位置填十乘行加列的编码，逐个打印C[零,零]读取的B地址，错误会立即暴露。

修复时不要只交换两个变量让测试变绿，而要重新写出B的shape、行stride和逻辑索引。正确理由是第k行跨过k个完整的N元素行，再进入第col列。这个解释可以迁移到任意非连续布局，而记忆某个字符串不能。

### 故障二：每个K块重置累加器

错误版本在round循环内写accumulator=零，导致最终只保留最后一块贡献。构造K为五、BK为二，并把最后一个k位置对应A与B全设零。正确结果仍来自前四项，错误结果却接近零。这比普通随机误差更容易判断缺失了哪部分。

修复后为每轮保存CPU trace，检查累加器前缀不变量。第一轮等于前两项，第二轮等于前四项，第三轮等于全部五项。只比较最终结果虽然能发现错误，却不如中间轨迹直接指出状态生命周期。

### 故障三：尾块加载没有填零

错误版本只在合法时写shared，非法时什么也不做。shared槽会保留上一轮数据，因此最后K块的无效位置重复贡献旧乘积。若K刚好整除tile，错误完全不会出现；这就是必须测试非整除K的原因。

正确版本在每轮对每个shared槽都赋值，合法读取输入，非法明确写零。输出mask只能阻止非法输出写回，不能消除合法输出内部已经累加的错误尾项。把输入mask与输出mask混为一谈，是这一故障的核心。

### 故障四：删除复用屏障

错误版本加载后有屏障，计算后没有屏障。它可能在单warp小tile上碰巧工作，但多warp版本存在下一轮生产者覆盖上一轮消费者数据的风险。修复是恢复保护复用的同步，或使用经过证明的双缓冲协议；不能用“我的GPU没复现”替代正确性分析。

诊断时分别记录当前round、shared槽和生产消费线程，写出一个快warp进入下一轮、慢warp仍在上一轮的合法交错。只要存在一个违反依赖的执行顺序，就不能声称代码正确，不必等待每次运行都失败。

### 4. 从计数走向性能假设

建立性能假设时，先把时间粗分成launch与调度、输入搬运、主循环计算、同步等待和输出后处理。对于大矩阵，某些项可能被重叠；对于小矩阵，固定开销可能占主导。不要把总时间简单平均分给所有项，更不要在没有测量证据时把慢归因于某一个硬件单元。

如果增加tile后速度下降，可能是寄存器压力、shared占用、任务数减少、边界浪费或编译生成变化。可以依次查看编译资源报告、有效输出比例、block总数与性能计数，而不是立刻继续增大tile。每个假设应对应一个可观察量与一个受控实验。

例如保持M、N不变只增加K，若小K时差距大、大K时差距缩小，可能说明固定开销在小问题中更重要；但也可能涉及不同算法选择。为了区分，必须固定实现路径并记录编译特化。框架库可能根据shape切换Kernel，所以“同一个API”不等于“同一段设备代码”。

一次合格的性能记录应同时保存正确性结果。优化后快了但误差变大，可能是采用了不同精度策略，而不只是更好调度。只有在合同一致或差异明确可接受时，速度比较才有意义。理解这一点，才能从“跑分”进步到有证据的算子工程。


## 第十二课：十二道递进练习与完整答案

### 练习一：输出shape和计算量

题目：A为四乘六，B为六乘五，求输出shape与常用FLOP计数。答案：输出四乘五，共二十个输出，每个长度六点积，约二百四十FLOP。若精确区分独立乘法与加法，则一百二十次乘法、一百次加法；性能报告需注明采用的约定。

### 练习二：写出一个输出的全部地址

题目：连续A为三乘四，B为四乘五，计算C[二,三]访问哪些元素偏移。答案：A偏移八、九、十、十一，B偏移三、八、十三、十八，C写偏移十三。A行宽四，B与C行宽五；偏移单位均为元素。

### 练习三：实现独立BM、BN、BK的CPU分块

~~~python
def matmul_tiles(a, b, bm=3, bn=4, bk=2):
    a = np.asarray(a, dtype=np.float64)
    b = np.asarray(b, dtype=np.float64)
    if a.ndim != 2 or b.ndim != 2 or a.shape[1] != b.shape[0]:
        raise ValueError('compatible matrices required')
    if min(bm, bn, bk) <= 0:
        raise ValueError('positive tiles required')
    m, k_size = a.shape
    n = b.shape[1]
    c = np.zeros((m, n))
    for row in range(0, m, bm):
        for col in range(0, n, bn):
            for start in range(0, k_size, bk):
                for i in range(row, min(row + bm, m)):
                    for j in range(col, min(col + bn, n)):
                        for k in range(start, min(start + bk, k_size)):
                            c[i, j] += a[i, k] * b[k, j]
    return c

rng = np.random.default_rng(6)
a_test = rng.normal(size=(5, 7))
b_test = rng.normal(size=(7, 9))
assert np.allclose(matmul_tiles(a_test, b_test), a_test @ b_test)
~~~

这里用显式标量循环保留全部索引，便于证明每个k区间不重叠且覆盖完整。min处理最后一块，不需要实际构造padding数组。这个CPU参考验证数学分块，不代表GPU共享内存实现已经正确。

### 练习四：计算尾部mask

题目：M十九、N十七、K二十三，T十六，右下block第二个K块中线程(tx三,ty二)做什么。答案：输出行十八、列十九，因此输出无效。A读取行十八、列十九合法；B读取行十八、列十九因列超界无效，填零。线程仍参与屏障和计算，最后不写输出。

这个答案展示了“输出无效”不代表“所有输入加载都无效”。该线程加载的A可能被同block其他合法列的线程消费。提前return会同时破坏搬运覆盖与同步。

### 练习五：算局部强度

题目：BM六十四、BN三十二、BK十六，输入两字节，忽略输出求主循环强度。答案：计算量二乘六十四乘三十二乘十六，输入字节二乘十六乘九十六，强度约二十一点三三FLOP每字节。BK约掉，但其资源与同步影响仍保留在真实实现中。

### 练习六：验证输出所有权

~~~python
def output_writers(m, n, block_rows, block_cols):
    count = np.zeros((m, n), dtype=np.int64)
    for by in range((m + block_rows - 1) // block_rows):
        for bx in range((n + block_cols - 1) // block_cols):
            for ty in range(block_rows):
                for tx in range(block_cols):
                    row = by * block_rows + ty
                    col = bx * block_cols + tx
                    if row < m and col < n:
                        count[row, col] += 1
    return count

assert np.all(output_writers(19, 17, 16, 16) == 1)
~~~

结果每个位置都为一，证明此映射下合法输出恰好一个写者。它不证明输入地址、同步或数值计算正确，所以只能作为整体测试中的一层，不能代替结果比较。

### 练习七：加入按列bias与ReLU

~~~python
def matmul_bias_relu(a, b, bias):
    product = matmul_scalar(a, b)
    bias = np.asarray(bias, dtype=np.float64)
    if bias.shape != (product.shape[1],):
        raise ValueError('one bias per output column required')
    return np.maximum(product + bias[None, :], 0.0)

assert np.array_equal(
    matmul_bias_relu([[1, -2]], [[1, 2], [3, 4]], [1, 10]),

~~~

点积先得到负五、负六，加偏置后一项负四、一项四，再经ReLU得到零、四。显式None轴表达按列广播，避免把一维bias含义留给读者猜测。

### 练习八：设计捕捉重复尾项的输入

题目：K五、BK四，如何让未清零尾槽的错误明显。答案：令前四个k上的A与B都为一，最后一个k的A或B为零。正确点积为四；若最后轮后三个无效槽保留上一轮的一，可能错误增加三，得到七。这个构造直接对应旧shared数据重复使用。

### 练习九：输入舍入与累加误差分开

a_original = rng.normal(size=(3, 5))
b_original = rng.normal(size=(5, 4))
a_low = a_original.astype(np.float16)
b_low = b_original.astype(np.float16)

### 练习十：双缓冲轮次与槽位

### 练习十一：Split-K的正确合并

题目：把K分成两组，由两个block分别计算同一输出块，应如何避免写冲突。答案：先各写独立partial缓冲，再单独归约两个partial并做一次最终epilogue；或采用明确定义的原子累加方案并处理初始化与数值顺序。不能让两个block直接普通store到同一C。

答案至少包括问题shape、A/B布局与stride、输入/累加/输出精度、是否转置、αβ、后处理、设备型号、编译与运行版本、暖机次数、计时边界、重复次数和误差标准。还应说明是否计入分配、主机传输与编译，以及基线库是否使用相同精度策略。

## 第十三课：矩阵乘法反向与训练中的布局变化

### 1. 从一个标量输出推导输入梯度

前向C等于AB，设损失对C的上游梯度为G。A的某个元素A[i,k]会影响同一输出行的所有C[i,j]，对每个输出的影响系数是B[k,j]。因此A梯度是沿j求和的G[i,j]乘B[k,j]，矩阵形式为dA=GB的转置。

同理，B[k,j]会影响同一输出列的所有C[i,j]，影响系数为A[i,k]。对i求和得到dB=A的转置乘G。这里的转置来自依赖关系，而不是为了让shape勉强匹配。虽然shape检查能帮助发现错误，但仅靠拼出可相乘维度不能替代推导。

如果A为M乘K，B为K乘N，则G为M乘N。dA使用M乘N与N乘K相乘，得到M乘K；dB使用K乘M与M乘N相乘，得到K乘N。前向与两个反向矩阵乘法的归约维分别是K、N、M，所以它们可能具有不同的最佳分块与布局策略。

### 2. 完整小例子与数值检查

~~~python
def matmul_backward(a, b, grad):
    a = np.asarray(a, dtype=np.float64)
    b = np.asarray(b, dtype=np.float64)
    grad = np.asarray(grad, dtype=np.float64)
    if a.ndim != 2 or b.ndim != 2 or a.shape[1] != b.shape[0]:
        raise ValueError('compatible matrices required')
    if grad.shape != (a.shape[0], b.shape[1]):
        raise ValueError('gradient shape mismatch')
    return grad @ b.T, a.T @ grad

a_small = np.array([[1., 2.], [3., 4.]])
b_small = np.array([[5., 6.], [7., 8.]])
upstream = np.array([[1., 0.], [0., 2.]])
da, db = matmul_backward(a_small, b_small, upstream)
assert np.array_equal(da, [[5, 7], [12, 16]])
assert np.array_equal(db, [[1, 6], [2, 8]])
~~~

上游只对C左上角赋权一、右下角赋权二，所以损失等于C左上角加两倍C右下角。A左上元素只通过左上输出贡献五，A右上元素贡献七；A第二行分别通过右下输出贡献十二与十六。这四个数与公式一致，能够帮助你理解矩阵反向并非神秘的新运算。

B左上元素只与A第一行第一项相乘进入有权输出，梯度为一；B右上元素与A第二行第一项相乘进入权重二的输出，梯度为六。继续展开得到第二行二与八。手算后再做中央差分，可以同时检查推导与实现，而不是让两个可能相同的代码错误互相验证。

训练框架通常可以通过stride表达转置，而不必立即复制整块矩阵。GEMM实现是否支持该布局、是否选择专用转置路径，决定实际搬运成本。看到反向公式中的转置符号，不应立刻把它等同于一次完整设备内存转置Kernel；数学转置、视图转置和物理重排是三种不同层次。

## 第十四课：打包成本、缓存复用与最终工程判断

### 1. 预处理何时值得做

某些矩阵布局不适合目标高性能路径，可以先将权重打包成更方便读取的格式，再执行多次GEMM。若权重在许多请求中重复使用，打包成本可能被摊薄；若每次调用权重都变化，预处理可能反而成为主要开销。判断时应计算整个使用周期，而不是只计打包后的单次Kernel时间。

设一次打包耗时P，原始每次乘法耗时T₀，打包后耗时T₁，总共使用R次。只有当P加R乘T₁小于R乘T₀，预处理才在该简化时间模型下有收益。等价地，R需要大于P除以T₀减T₁。若T₁并没有更小，就不存在靠增加复用次数获得收益的理由。

这个模型还没计入额外显存、缓存占用和权重更新后的失效。训练中参数每步更新，打包状态可能必须重建；推理中权重长期固定则更适合一次预处理。量化权重的打包与尺度布局也属于同类问题，K11会把数值编码加入这份成本账本。

### 2. block执行顺序只能影响机会，不能作为正确性依赖

若相邻输出块共享A或B子块，把它们安排在接近的任务顺序中，可能提高缓存复用机会。但普通grid并不承诺严格按某个顺序执行所有block，也不保证共享数据始终留在缓存。调度与缓存策略可以影响性能，却不能成为数学正确性的前提。

因此把block编号重新映射到二维tile坐标时，首先证明映射是一一对应且覆盖完整输出。随后才测量缓存命中与性能变化。若映射遗漏或重复tile，即使某些输出恰好相同，也不能算优化成功。用不同值输入、写者计数和不规则网格，是必要的验证组合。

### 3. 线性任务编号与二维输出块的往返

假设输出网格有三行四列，共十二个tile。采用行优先任务顺序时，任务号p对应tile行p整除四、tile列p模四。任务五因此对应行一列一，任务十一对应行二列三。逆映射是行乘四加列。正向与逆向往返必须恢复原编号，才能证明没有因为重排而遗漏或重复。

若改成列优先顺序，任务号p对应tile行p模三、tile列p整除三。任务五此时对应行二列一，与前一种顺序不同，但仍然覆盖同一组十二个tile。性能可能因相邻任务共享不同输入区域而变化，数学结果不应改变。这是一个很适合先在CPU上枚举验证、再搬进GPU调度器的练习。

最后一组不完整的分组调度最容易出错。若每组计划处理四个tile行，而总行数只有六，第二组只有两行有效；计算组内解码时必须使用实际组高，否则某些任务会映射到越界行或重复列。先枚举小网格并检查集合大小，再运行大矩阵，能够显著减少调度优化中的隐蔽错误。

### 4. 本章最终交付检查

能够从零写出标量参考、显式stride参考、naive CUDA和shared tiled CUDA，并解释两条屏障的不同责任，是本章的基本完成线。能够手算局部复用比、说明寄存器分块代价、正确安排Split-K的最终激活，是进入更复杂实现前的准备。

更深入的完成线是选一个固定版本的真实GEMM实现，追踪一块输入到一块输出的全部布局与生命周期，并用自己的测试验证受支持的边界。暂时不能编译特定GPU路径时，保留清楚的未验证项；已经完成的CPU推导与检查依然有价值，但不应扩张成没有证据的性能结论。


## 第十五课：逐级小项目与验收

第一阶段完成CPU标量、循环交换和分块三个版本，使用同一组小型非方阵与尾部测试。保存每个版本的数学合同与一个完整手算例子。不要把NumPy内部调用的高性能矩阵乘法耗时与Python教学循环直接比较后得出硬件结论。

第二阶段完成naive CUDA与shared tiled CUDA。先用十九乘二十三与二十三乘十七的矩阵验收，逐个输出比较，并检查设备错误。当前仓库的basics.cu提供完整主机分配、复制、启动、比较与清理流程；阅读时要把主机资源生命周期与设备计算分开标注。

第三阶段加入独立BM、BN、BK或线程内多输出，并保留旧实现作为基线。每次只改变一种组织方式，重新检查尾部、所有权和误差。若想加入双缓冲，先完成CPU状态机，再逐条验证生产、就绪、消费与复用条件。

第四阶段阅读固定来源中的CUTLASS Efficient GEMM与具体实例，填写一张数据路径表：global矩阵坐标、block tile坐标、shared布局、warp任务、指令片段和最终输出。最终交付不是一张“快了多少”的截图，而是可复现代码、错误案例、正确性结果和有边界的性能解释。

验收还应包含输入不被意外修改的检查：调用前保存输入副本，调用后逐元素比较。矩阵乘法结果正确并不排除某个错误的临时缓冲复用了输入存储；这种副作用可能在下一层计算才暴露，必须在算子边界及时发现。
