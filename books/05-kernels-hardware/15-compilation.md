# K15　从 Python/CUDA/Triton 到硬件：编译链的可观察边界

先修 K02 构建、K08 JIT。目标：知道源代码、IR、PTX、目标机器代码与运行时各负责什么，遇到编译或兼容性问题能定位层级。

## 1. 一条常见 CUDA 路径

CUDA C++ 文件包含 Host 与 Device 部分。构建工具调用编译器处理它们，设备代码可能生成 PTX 和/或某些架构的 cubin，Host 部分与运行库链接成可执行程序。运行时根据设备与产物，装载适合的代码；必要时驱动可把支持的 PTX 编译为目标设备机器代码。

PTX 是虚拟指令集/中间层，不是最终 GPU 直接执行的所有物理指令表示。SASS 常用于指代特定 NVIDIA 架构的本机指令反汇编。看到 PTX 中一条指令，不能保证它在所有目标上都对应一条同样成本的 SASS。

`nvcc --ptx` 可以用于观察设备代码的 PTX，`cuobjdump` 或 `nvdisasm` 可在适用环境下检查二进制。工具具体参数随版本变化，应先看本机 help 与官方文档。不要把反汇编里的寄存器编号当成源代码变量名；优化可能合并、消除或重排变量。

## 2. 编译器优化的是程序表示

前端理解语言与类型，构造中间表示；中间优化做常量传播、死代码删除、循环变换等；后端处理目标指令、寄存器分配和调度。真实编译器常有多层 IR，而不是一条完全固定的三步管线。

例如 `y=x*2+0` 可简化；若某个数组值永远不影响输出，相关计算可能被删除。基准若算完结果却从不使用，编译器可能优化掉你的工作。因此性能测试必须确保结果可观察，但不能用会彻底改变执行行为的方式过度干扰。

寄存器分配把大量逻辑临时值映射到有限物理资源。活跃范围越长，资源压力越大。Kernel Fusion 增加可复用中间值，也可能延长其存活时间，最终产生 spill。这解释了为什么减少启动次数不保证整体更快。

## 3. Triton 与图编译是不同层次

Triton 编译块级 Kernel，涉及张量布局、并行映射和设备指令。PyTorch 等框架的图编译还可能先捕获 Python/算子图、进行图层融合、选择后端，再生成或调用 Kernel。`torch.compile` 不等于“把全部 Python 一次变成一个 CUDA Kernel”，它可能产生多个图段和多个设备调用。

Graph break 表示某些代码无法在当前图捕获路径继续，执行被切分。它不是数学错误的同义词，但会影响优化机会和开销。动态 shape 可能触发 guard、重编译或多版本缓存；应区分正确支持动态与稳定复用已编译实例。

## 4. 静态、动态与运行时调度

编译器可以提前决定布局和部分调度；运行时根据实际输入、设备与请求状态选择实例、分配缓冲区、提交工作。JIT 把编译放在程序运行过程中，说明“编译阶段”和“运行阶段”不是绝对互斥的时间段，但职责仍可区分。

在推理框架里，CPU scheduler 决定这轮有哪些请求、模型 runner 准备张量、编译与 Kernel 后端生成或选择程序、CUDA runtime/driver 提交执行、GPU 硬件调度 Warp。把所有“调度”都混称为同一个组件，会导致定位错误：请求排队问题不能靠只读 SASS 解决，指令数据依赖问题也不能靠改 HTTP 并发解决。

## 5. 兼容性有多个方向

编译目标架构、驱动支持的 PTX 版本、Toolkit、PyTorch 内置 CUDA 运行组件、Triton 后端和实际 GPU 是不同版本轴。`nvidia-smi` 上的 CUDA 字样通常表示驱动支持能力，不一定是当前环境安装的 nvcc Toolkit 版本。`torch.version.cuda` 也不必等于 `nvcc --version`。

架构专用特性有更严格的兼容边界。某些带 `a` 或家族目标的代码，不应被当作通用 PTX 的完全前向兼容例子。具体以 NVIDIA 的编译器和兼容指南为准。把 H100 的专用 WGMMA 路径直接搬到 RTX5070Ti，不能只依赖“后者名字更新”。

## 6. 一次源码到产物的实验

在独立构建目录编译 `basics.cu`，保留编译命令与输出；生成 PTX 并寻找 add 的地址计算、load、add、store；比较 `-O0` 与优化构建的产物，但不要预设每个版本都保留同样的符号。然后改变 block-independent 的常量，观察哪些表达式被提前计算。

没有 nvcc 时，先用 C++ `layout.cpp` 做同样的 CPU 编译与汇编观察：这可以练习从源代码到产物的阅读方法，却不能被记录成 CUDA 编译验证。本次交付只验证了 C++ 构建与 Python 语法，GPU 编译仍需实际环境。

## 7. 练习与参考答案

1. **分类。** 找不到 Python 模块、Triton JIT 不支持某操作、驱动无法装载目标代码、Kernel 数值错误，分别定位哪里？答案依次依赖环境、编译前后端、运行装载兼容、程序语义/数值；不是全部重装 CUDA。
2. **特化。** 为什么常量 Tile 可能让编译器展开循环？答案迭代次数与尺寸在编译期已知；但代码膨胀与寄存器压力也可能增加。
3. **产物阅读。** 在 add 的 PTX 找到内存读写和浮点加法，说明哪些部分是索引。验收以实际产物为准，不强求某个固定指令名或行号。
4. **精度。** 编译器把乘加融合成 FMA，是否一定逐 bit 等于先乘后加？答案不一定，FMA 通常只有一次最终舍入；数学等价不能取代数值契约。
5. **动态形状。** 为十种长度记录首次与第二次调用时间，区分编译缓存命中。参考：记录配置和时间，不用单次极短差值判断；确认各次输入的实际 shape/dtype/device。
6. **工程任务。** 为自己的 GPU 环境制作版本清单：OS/WSL、驱动、GPU capability、nvcc、Python、PyTorch、Triton、代码 commit。验收不得把 `nvidia-smi` 的字段误写成“已安装 Toolkit”。

掌握门槛：能沿源代码→编译表示→设备产物→装载→执行逐层定位；知道哪些兼容性证据需要运行，哪些可以静态核对。
