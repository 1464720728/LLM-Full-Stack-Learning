# K10　Kernel 进入框架以后：算子契约、反向传播与编译

先修 K05 的反向推导、Python 类和 K09。写一个 GPU 函数只完成了一部分工作。框架还需要知道它的输入输出结构、是否修改输入、如何传播梯度、如何在只看形状时推理输出，以及如何参与编译。

## 1. Operator 与 Kernel 的职责

数学算子定义“计算什么”，Kernel 定义某个平台上的执行方式，框架算子接口还定义调用契约。一个算子可以有 CPU、CUDA、不同 dtype 或布局的多个 Kernel。反过来，一个融合 Kernel 也可以实现多个数学步骤。

最重要的契约包括：参数类型、形状关系、设备、dtype、输出布局、别名关系、可变性、异常条件。假如接口声称不修改输入，实际 Kernel 却写入输入，编译器可能基于错误假设重排读写，产生难以复现的问题。别名并不是“两个 Python 变量同名”，而是底层存储可能重叠。

## 2. 手写 autograd 的责任

[custom_autograd.py](../../labs/kernels/custom_autograd.py) 中的 `RMSNorm` 演示 `torch.autograd.Function`。forward 保存 x、w、inv，backward 收到上游梯度 g，按 K05 的公式返回 dx、dw 和 eps 的 None。返回顺序必须与 forward 参数对应；权重梯度要归约所有批次/行维度。

保存中间张量会消耗内存。可以在 backward 重算某些值，换取更少保存，但这会增加计算，并且必须维持相同数值语义。生产融合算子常在保存、重算和数据精度之间权衡。不能为了省内存，把反向真正需要的输入忘掉。

forward 数值正确不代表 backward 正确。反向数值正确也不代表所有框架契约正确。例如输出错误别名、fake 实现给错 stride、编译时数据依赖分支，都可能在其他执行模式失败。

## 3. gradcheck 与 opcheck 各检查什么

`gradcheck` 用数值差分检验梯度公式，通常采用 double 和小尺寸，使误差容易控制。它不能证明你注册了正确的别名或编译规则。`torch.library.opcheck` 检验注册契约与相关子系统行为，不取代独立的数值正确性测试。二者互补。

本例的第二部分注册一个简单平方算子，附 fake 实现和 autograd。它用于理解接口流程，并非建议把所有可组合 PyTorch 表达式都包装成自定义算子：能够由现有算子自然表达的函数，通常可以先让框架直接处理。自定义边界更适合已有外部实现、特定融合或需要稳定封装的情况。

fake 实现只用元数据推导结果，不应该读取输入值。输出 shape 正确而 stride 错误也可能违反契约。若真实实现总返回连续输出，fake 却保留输入的任意非连续步长，就不能认为“形状一样就算对”。因此支持非连续输入时，必须同时检查真实与 fake 输出布局。

## 4. 前向融合与训练支持分阶段

本卷 Triton 算子首先面向推理，没有注册梯度。用户可以在不需要梯度的上下文调用它们，不能直接认为把它放进训练模型就会自动反传。若要添加训练支持，先实现 CPU/PyTorch backward，再选择是否把 backward 也写成 Kernel，最后做梯度和框架集成验证。

例如 RMSNorm backward 同时包含逐元素计算和跨行权重梯度归约。dx 可以按行独立计算，dw 则要跨行聚合，可能需要额外阶段或原子操作。前向“一行一个 Program”的映射不意味着反向所有输出也能用完全相同的布局完成。

## 5. 实操与调试流程

```bash
python -m labs.kernels.custom_autograd
```

无 PyTorch 时输出 SKIP。具备 PyTorch 的 CPU 环境即可完成，不需要占用 H100。首先运行原始版本，随后故意删去 RMSNorm backward 的第二项，观察 gradcheck 失败。再恢复公式。这个过程帮助你确认检查器确实覆盖目标逻辑。

需要调试 backward 时，把损失定义为输出与固定随机 g 的内积，这样上游梯度可控，避免整个模型训练把问题掩盖。对每个输入元素计算有限差分，用最大误差定位索引，再检查对应轴和广播。不要从一万步训练发散倒推某个三行公式。

## 6. 练习与参考答案

1. **链式法则。** 平方算子 y=x² 的 backward 为什么要乘上 g？答案：g 是后续损失对 y 的梯度，链式法则为 `dL/dx=(dL/dy)*2x`；只返回 2x 仅在特定损失下碰巧正确。
2. **权重梯度。** x 为 `[B,T,D]`，w 为 `[D]`，dw 应沿哪些轴求和？答案 B、T 两轴，保留 D。用 B=2、T=3、D=5 构造测试。
3. **别名。** 一个声明返回新张量的算子直接返回输入 x，为什么有问题？答案输出与输入共享存储，违反 fresh output 契约；即使数值正确，后续写入和编译分析会出错。
4. **fake。** 给一个输入转置视图，真实平方输出布局与 fake 是否一致？参考：检查 shape、stride、device、dtype、storage offset。若当前实现支持范围不清，应限制连续输入，或让 fake 精确模拟真实输出元数据。
5. **训练实操。** 用 RMSNorm 接一个线性层训练拟合小数据，分别使用内置表达式与自定义 backward，比对第一步参数梯度。验收先比梯度，再比损失下降，不能只看最终“似乎学会了”。
6. **工程任务。** 为一个 Triton 前向写框架包装文档，列明推理-only、支持 dtype/布局、是否可编译、是否有 fake/反向验证。参考答案必须区分“未实现”与“本机未执行”，不能用一个未验证标签覆盖所有状态。

掌握门槛：能为简单算子写正确前后向并通过数值检查，理解注册契约与数学误差是独立维度。更复杂算子可以逐步提升，不能跳过这层责任。
