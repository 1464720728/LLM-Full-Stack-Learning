# K08　Triton 的思维方式：一个 Program 处理一块数据

先修 Python 函数、K01 地址与 K03 CUDA 组织。目标：读懂 Triton Kernel 的块级向量表达式、掩码和启动配置，知道哪些事在 Python 发生、哪些由编译器处理、哪些在 GPU 执行。

## 1. Python 外壳不等于 Python 在 GPU 跑

Triton Kernel 常写在 `.py` 文件中，并加 `@triton.jit`。这些函数体使用 `triton.language` 的运算，经过编译器生成 GPU 代码。普通 Python 包装函数负责检查参数、分配输出、计算启动网格，然后调用 Kernel。二者看起来处于同一语言文件，执行职责却不同。

`tl.arange(0,BLOCK)` 表达一块逻辑索引，不是创建一个普通 Python list；`tl.load` 表示设备内存读取；`tl.store` 表示写回。你不能在 Kernel 内任意调用 Python 的网络库、文件操作或操作普通复杂对象。理解这条界限，就不会把 Triton 当成“所有 Python 函数加一个装饰器就能上 GPU”。

## 2. Program ID 与数据块

向量加法中，一个 Program 处理 BLOCK 个逻辑元素：`offset=program_id*BLOCK+arange(0,BLOCK)`。N=10、BLOCK=8 时，Program 0 覆盖 0..7，Program 1 覆盖 8..15。第二块只有两个合法元素。

```bash
python -m labs.kernels.run --lab 15
```

你应看到有效计数 `[8,2]`。读 `_add`：加载 A/B 时用 `i<N`，无效位置填零；写 C 时也用同一掩码。只给 load 加掩码、不保护 store，仍会越界。掩码值与填充值是两件事：掩码决定是否访问存储，`other` 决定未访问位置在后续计算中的逻辑值。

一个 Triton Program 通常被降低为一组 GPU 线程共同执行，但不能把一个 `tl.arange` 元素机械地等同于一个固定 CUDA 线程。布局和每线程持有元素数可能由编译器决定。先用块级语义证明数学正确，再通过编译产物理解物理映射。

## 3. constexpr 与特化

`BLOCK: tl.constexpr` 表示编译期常量，可用于静态块形状、分支和展开。不同 BLOCK 或某些输入属性可能产生不同编译实例。首次调用包含 JIT 开销，之后可复用缓存；因此冷启动与稳态性能必须分开测量。

N 是否需要设为 constexpr，要根据代码和特化策略决定。本教学代码为了简洁把 N 放在编译期，意味着不同长度可能触发新编译。真实服务面对大量动态长度时，需要评估这种特化数量。不能把首次请求很慢全部归因于模型计算，也不能把所有动态值都特化以追求局部最优。

## 4. 包装函数也是算子的一部分

`triton_ops.py` 的 `_check` 明确要求 CUDA、float32、连续张量和同设备。包装函数检查形状相同，分配输出，N>0 才启动。空向量返回空输出，不创建无意义的零大小 Grid。这个“入口契约→分配→启动→返回”结构与框架自定义算子十分接近。

教学限制只支持部分形状，不是缺陷隐藏，而是使第一版算法可被完整证明。扩展时应先写新契约和测试，例如支持 fp16、非连续步长或广播，再改 Kernel。直接删除检查并不等于实现了新能力。

## 5. GPU 实操步骤

先完成 CPU 参考测试；在 Win11 上优先采用与主流 Linux GPU 工具链相容的 WSL2 环境，驱动与 Toolkit 区别见 K16。不要在公司共享 Python 环境直接升级包。创建独立环境，按 PyTorch 和 Triton 官方兼容信息安装，并把版本记录下来。本仓库不硬编造一个“所有机器通用”的最新组合。

```bash
python -m labs.kernels.gpu_check
# 先选择分配给你的设备，再明确授权本次运行：
CUDA_VISIBLE_DEVICES=0 python -m labs.kernels.gpu_check --run
```

第一条不会使用 GPU；第二条只做小规模正确性检查。缺少依赖时输出 SKIP，绝不能记作 PASS。若编译失败，保存最小形状、设备 capability、torch/triton 版本与第一条编译错误。先让向量加法过关，再调矩阵乘法，避免同时改变多个未知因素。

## 6. 练习与参考答案

1. **覆盖。** N=513、BLOCK=256，需要几个 Program、尾部几个元素？答案 3 个，最后一个只有 1 个；写出 mask 最后一行。
2. **编程。** 从 add 改成 `z=alpha*x+y`。参考：alpha 可先做运行时标量；形状和 dtype 契约保持一致；测试 alpha=0、1、负数和不整除 N。
3. **故障。** `tl.load(...,mask=i<N)` 没有提供明确的 `other`，随后归约所有 lane，有什么问题？答案：无效 lane 的值不可被当成正确单位元；求和用零、最大值常用负无穷，各算子不同。
4. **特化。** 连续运行 N=1000、1001、1000，为什么时间可能差异很大？答案：前两个配置可能分别编译，第三个复用；同时还有首次上下文初始化与缓存等因素，需用重复稳态测量拆开。
5. **契约。** 给 add 支持非连续一维切片。参考：传入各自 stride，在地址式中使用；输出可保持连续。测试 `x[::2]`，并验证包装不偷偷把成本藏到 `.contiguous()`。
6. **源码拓展。** 阅读官方 Vector Addition 教程，将每个语句标为 Host 逻辑、编译期信息或设备计算。验收不是翻译注释，而是解释删掉某一 mask 或改动 Grid 后的后果。
