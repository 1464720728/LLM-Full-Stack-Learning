# K07　把 FlashAttention 的核心算法亲手推出来

先修 K05 Softmax、K06 GEMM，以及模型卷的 Q/K/V 与因果掩码。目标是理解精确注意力为什么可以不保存完整分数矩阵，写出分块在线算法，并逐项证明状态更新正确。

## 1. 二次矩阵从哪里出现

单头注意力输入 Q 为 Nq×D，K 为 Nk×D，V 为 Nk×Dv。先算 S=`QKᵀ/sqrt(D)`，再逐行 Softmax 得到 P，最后 O=`PV`。S 和 P 的尺寸为 Nq×Nk。当自注意力长度是 N 时，它们各含 N² 个元素。直接实现会把这些中间结果写入显存，后续算子再读取。

FlashAttention 的重要思想是重新组织计算和数据搬运，按块处理 Q/K/V，并在线维护 Softmax 的必要统计量。它针对相同注意力定义重排计算，并非自动把精确注意力替换成线性注意力。浮点执行顺序不同会有舍入差异，因此“数学等价”不等于逐 bit 相同。

## 2. 一行 Softmax 只需要三个运行状态

考虑固定一个 query。我们已经读到一部分分数 s 和对应值向量 v，保存三个量：

- `m`：到目前为止所有分数的最大值；
- `l=sum exp(s-m)`：按当前最大值缩放后的分母；
- `u=sum exp(s-m)*v`：按同样尺度保存的未归一化加权分子。

输出是 `u/l`。重点在于 u 不是已经除过分母的输出。实现也可以保存归一化输出，但更新公式会随之变化。把两种状态定义混在一起，是在线注意力最常见的错误之一。

新块的最大分数是 `m_b`，新的全局最大值 `m'=max(m,m_b)`。旧统计量原先按 m 缩放，必须乘 `alpha=exp(m-m')` 才变成新尺度。新块各项按 `p_j=exp(s_j-m')` 计算，于是：

\[
l'=\alpha l+\sum_{j\in block}p_j,\qquad
u'=\alpha u+\sum_{j\in block}p_jv_j.
\]

所有旧项和新项都拥有同一个指数基准 m'，因此最后的比例就是完整 Softmax 加权和。这个证明不依赖块的大小，也不要求所有分数同时存在。

## 3. 一个可以拿纸算的完整过程

设分数依次为 `0,ln2,ln4`，对应标量值 `10,20,30`，每块一项。初始化 `m=-inf,l=0,u=0`。

第一块：`m'=0, alpha=0,p=1`，得到 `l=1,u=10`。

第二块：新最大值为 ln2，旧缩放因子为 1/2，新项 p=1。得到 `l=1.5,u=25`。当前输出为 `25/1.5=16.666…`，与权重 `[1,2]` 的加权平均一致。

第三块：新最大值为 ln4，旧缩放仍为 1/2，新项 p=1。得到 `l=1.75,u=42.5`，输出 `42.5/1.75=170/7≈24.2857`。一次性计算得到 `(10+40+120)/(1+2+4)=170/7`，完全吻合。

如果忘记给旧 u 乘 alpha，第三块的分子就不在统一尺度上。若只重缩放分母、不重缩放分子，会得到另一个同样错误的值。每一步都打印 m/l/u，比只打印最终误差更能定位问题。

## 4. 因果掩码与全无效块

自注意力中的 query i 只允许读取 key j≤i。一个后续 key 块对于较早 query 可能完全无效。无效分数应贡献零分母和零分子，而不应该改变已有最大值。本卷 CPU 实现用 `-inf` 表示无效分数，并对尚无有效分数的状态做有限值保护，避免 `-inf-(-inf)`。

这里明确采用长度相同的自注意力因果定义。对于解码时 `Nq=1,Nk>1`，逻辑 query 位置通常不是零，而可能是完整历史的末尾；不能原封不动使用 `key_index<=query_row_index`。生产实现有位置偏移、不同对齐方式、分页 KV 和可变长请求，这些是接口语义的一部分。本例对矩形因果输入主动拒绝，防止静默使用错误的掩码。

## 6. 为什么这个 CPU 实现不是高性能 FlashAttention

它仍用 NumPy 创建块分数矩阵，无法证明真实 GPU 寄存器/Shared Memory/HBM 行为。真正高性能实现还要设计 Q 的 Tile、K/V 搬运、Tensor Core 指令、Warp 协作、反向重计算、不同长度调度和硬件流水线。本卷 Triton 流式注意力一次一个 query，刻意使代码可读，并不宣称达到 FlashAttention 性能。

掌握这条边界非常重要：你可以先完整理解算法与数值不变量，再阅读 FlashAttention 的 `softmax.h` 与主循环。此时看到 `row_max`、`row_sum`、累加器重缩放、`exp2` 等名称，就能知道它们在维护什么。`exp2` 需要相应的 log2(e) 缩放，不能把 `exp` 机械替换成 `exp2`。

## 7. 练习与参考答案

1. **手算。** 把上面的三个分数分成前两项一块、最后一项一块，复算结果。答案仍为 170/7；块内先求最大值 ln2 和对应 `[.5,1]`，再按新尺度更新。
2. **故障注入。** 删除 `numerator*alpha` 中的 alpha，构造分数递增的例子。参考答案：第一块最大值较小、后来最大值增大时就出错；若所有块最大值相等，错误可能被掩盖。
3. **边界。** 用 N=7、block=3、D=5、Dv=2 验证。答案要求最后块仅一项有效，不能把 padding key 当作分数零的有效位置。
4. **掩码。** 修改未来 K 和 V，验证早期行不变；再删除因果掩码，确认测试能失败。验收强调测试确实能抓住目标 bug，而不是永远 PASS。
5. **接口扩展。** 为矩形解码添加 `query_position_offset`。参考：有效条件是 `j<=offset+i`；测试 offset=Nk-Nq，并与显式 dense mask 比较。不能默默把所有矩形输入都当作同一种对齐约定。
6. **源码拓展。** 在 FlashAttention 的 online Softmax 代码中定位最大值、分母、输出缩放三处。验收提交自己的状态含义表和一个跨块手算例子；无需先读懂全部模板。

掌握门槛：不看书推导 m/l/u 更新；独立写出稳定流式注意力；用块大小、尾部与因果非干扰三类测试验收。
