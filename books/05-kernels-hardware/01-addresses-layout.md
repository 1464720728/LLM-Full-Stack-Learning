## 第一课：计算机保存的是字节，矩阵的行列来自我们的解释

### 1. 一个地址究竟在指什么

先想象一本每页都有编号的练习本。编号能告诉你去哪里，但编号本身没有告诉你那一页写的是汉字、整数还是照片。内存地址也有类似作用：它定位存储中的位置，而数据类型告诉程序怎样解释该位置开始的一串比特。比喻到这里就应该停止，因为真实系统的地址通常是虚拟地址，不能把一个进程看到的地址直接当成显存芯片上的物理坐标。

一个 bit 只能表达两个状态，通常写成零和一。八个 bit 构成一个 byte，也就是字节。四字节的整数和四字节的浮点数都占四个字节，但它们对这三十二个比特的解释不同。把存储里相同的四字节强行按照另一种数据类型读取，通常不会得到同一个数学数值。这就是为什么数据类型既是数值问题，也是寻址问题。

在本章的简化模型里，存储是一条按字节编号的线。设某段存储的首地址为一千，连续放置四字节的元素，那么第零个元素从一千开始，第一个从一千零四开始，第二个从一千零八开始。第一个元素的四个字节占据一千到一千零三。下一个元素从一千零四开始，两个元素之间没有缝隙，也没有重叠。

这里必须区分“第几个元素”和“第几个字节”。假设元素下标是六，元素大小是四字节，那么元素相对于存储首地址的偏移是二十四字节。写地址计算时漏掉乘四，或者在已经以字节为单位的步长上再次乘四，都属于单位错误。程序里的数值虽然都是整数，但物理意义并不相同，就像三米不能直接与四秒相加。

### 2. 从十二个数建立一块可核对的存储

下面的程序明确要求四字节整数，避免不同环境默认整数宽度造成干扰：

~~~python
import numpy as np

storage = np.arange(12, dtype=np.int32)
print(storage)
print(storage.itemsize)
print(storage.nbytes)
~~~

第一行导入 NumPy 并取一个较短的名字。第二行创建从零到十一的十二个整数；右端点十二不包含在结果里。参数 dtype 决定每个元素采用哪种存储解释。itemsize 是单个元素的字节数，结果为四。nbytes 是这个数组逻辑元素占据的总字节数，因此结果是十二乘四，等于四十八。

这段程序没有创建“十二个独立 Python 整数对象组成的列表”。NumPy 数组的数据区采用统一的数据类型和规则布局；Python 列表通常保存对对象的引用，不能把列表内存结构直接套进这里的连续四字节模型。你在 Python 中写出来的括号相似，底层存储合同却不同。以后看到 Torch 张量、NumPy 数组和普通 list，先确认具体对象类型，而不是根据打印外观猜测存储方式。

现在把它解释为三行四列：

~~~python
matrix = storage.reshape(3, 4)
print(matrix)
print(matrix.shape)
print(matrix.strides)
print(np.shares_memory(storage, matrix))
~~~

输出中的第一行矩阵数据是零、一、二、三；第二行是四、五、六、七；第三行是八、九、十、十一。shape 是三和四，表示两个逻辑轴的长度。strides 在 NumPy 里以字节为单位，因此输出十六和四：行下标增加一，移动十六字节；列下标增加一，移动四字节。最后一行返回真，说明这两个数组视图能够访问同一块数据。

### 3. 为什么“几维”不等于物理空间有几维

二维数组不是内存长出了两条轴，三维数组也不是显存出现了立体格子。维度描述的是允许使用几个下标来定位一个逻辑元素。把二十四个元素解释为二乘三乘四时，可以使用批次、行、列三个下标；把同一批元素解释为六乘四时，只需要行、列两个下标。只要解释方式合法，这些维度可以映射回同一条线性存储。

在神经网络里，四维张量可能表示批次、头、序列位置和特征。但“第四维”本身没有固定业务含义。另一个接口可能把序列放在第二维，把头放在第三维。形状中的数字相同，也不能证明语义相同。例如两个形状都是二乘三乘四的张量，一个的三表示 token 数，一个的三表示注意力头数，将它们直接相加可能在数值上可执行，却在模型意义上错误。

因此，阅读算子接口需要两张表：第一张写各维长度和步长，第二张写每个轴代表什么。前者解决地址问题，后者解决计算问题。只打印 shape 不足以完成调试，因为相同 shape 可以对应不同的轴语义和不同的存储布局。

## 第二课：形状、步长和起始偏移各自承担什么责任

### 1. 把张量拆成数据和描述

为了学习，可以把一个张量看成两部分。第一部分是底层存储，里面有实际字节。第二部分是描述信息，包括数据类型、形状、步长、逻辑起始位置以及所在设备。不同框架内部还有许多其他字段，但这些已经足以解释本章的寻址问题。

形状回答“哪些下标是合法的”。如果形状为三乘四，那么行下标可以是零、一、二，列下标可以是零、一、二、三。步长回答“某个下标加一时，地址移动多少”。起始偏移回答“逻辑上的第一个元素从底层存储的哪个位置开始”。这三者不能互相替代：形状相同的两个视图可以拥有不同步长，步长相同的两个切片也可以从不同位置开始。

设底层存储的字节起点是 p，逻辑起点在存储中的元素偏移是 o，每个元素占 b 个字节，下标为 i，元素步长为 s。多维寻址就是先把每个下标乘以对应步长，再加起始偏移，最后把元素数换算成字节数。二维时写成：

~~~text
element_offset = o + row * stride_row + col * stride_col
byte_address   = p + element_offset * itemsize
~~~

公式有一个容易忽略的约定：这里的 p 是底层存储首地址，而不是已经加过起始偏移的逻辑首元素地址。许多真实 API 返回的 data pointer 已经指向视图的首元素。这时不能又把同一个 storage_offset 加一次。读接口说明时，一定要先问“这个指针以什么为零点”。

### 2. 完整手算一次二维地址

仍然使用三行四列的连续数组。令 p 为一千，o 为零，元素步长为四和一，元素宽度为四字节。求逻辑位置第一行之后、第二列之后，也就是下标一和二的地址。

首先检查合法性：行一小于三，列二小于四，均非负，因此逻辑下标合法。行贡献是一乘四，得到四个元素；列贡献是二乘一，得到两个元素；总偏移是六个元素。六乘四得到二十四字节，加到首地址一千上，得到一千零二十四。该位置存放的数值恰好是六，但“偏移等于数值”只是因为我们使用了递增测试数据，并不是张量寻址的普遍性质。

如果把数组填成全一，寻址错误可能仍打印一。这正是为什么调试布局时应该优先使用递增整数，而不是全零或全一。数值具有辨识度，错误位置才会暴露。随机数也有辨识度，但递增整数更方便你反推出错误地址，例如读到九就立即知道它访问了底层第九个元素。

下面的表把一整行的映射列出来：

| 逻辑下标 | 行贡献（元素） | 列贡献（元素） | 总元素偏移 | 字节地址 |
|---|---:|---:|---:|---:|
| (1,0) | 4 | 0 | 4 | 1016 |
| (1,1) | 4 | 1 | 5 | 1020 |
| (1,2) | 4 | 2 | 6 | 1024 |
| (1,3) | 4 | 3 | 7 | 1028 |

沿列前进一次，地址增加四字节。换到下一行的第一列时，不能在列三的地址上再加一整行步长，因为“行加一、列回零”同时发生。正确方式是重新代入下标二、零，得到一千零三十二。多维循环的下标重置与地址变化需要一起理解。

### 3. 推出连续三维步长，而不是背答案

形状为二乘三乘四，最内层最后一维每前进一步只跨一个元素，所以最后步长是一。中间维前进一步要越过完整的一行四个元素，因此步长是四。最外层维前进一步要越过三行，每行四个元素，因此步长是十二。得到元素步长十二、四、一。

求下标一、二、三的偏移：一乘十二，加二乘四，再加三乘一，等于二十三。数组总共二十四个元素，从零开始编号的最后一个就是二十三，因此这个结果还可以用边界直觉核验。若算成二十四，常见原因是把某个轴的长度直接当成了最后合法下标。

连续步长可以从右往左递推。设当前累计乘积一开始是一，遇到最后一维就把一记作它的步长，然后累计乘积乘以该维长度；继续往左重复。这个过程不是 NumPy 专属技巧，而是把嵌套循环展平的直接结果。阅读后面的 C++、CUDA 和 Triton 时，你会不断看到同一规则以不同语法出现。

## 第三课：转置改变索引关系，未必搬运数据

### 1. 先写数学关系，再看实现

对三行四列矩阵 A 做转置，得到四行三列矩阵 T。定义关系是 T 的位置 j、i 等于 A 的位置 i、j。例如 T 的二、一应当等于 A 的一、二，数值都是六。这个定义只规定逻辑对应关系，没有规定必须复制数据。

原矩阵的寻址是 i 乘四加 j。把 i、j 调换后，转置视图的寻址是 j 乘四加 i。如果现在用 r、c 表示转置后的行列，就得到 c 乘四加 r。因此转置视图的元素步长是第一维一、第二维四。形状交换，步长也交换，就能读取正确位置，无需把十二个元素重新排列一遍。

转置后的逻辑第一行是零、四、八。它们在底层存储中相隔四个元素，所以逻辑相邻不代表物理相邻。这个区别会直接影响 GPU 线程访问是否合并，但在讨论性能前，先确保你能解释为什么它们在地址上相隔十六字节。

~~~python
import numpy as np

a = np.arange(12, dtype=np.int32).reshape(3, 4)
t = a.T
assert t.shape == (4, 3)
assert tuple(s // t.itemsize for s in t.strides) == (1, 4)
assert t[2, 1] == a[1, 2] == 6
assert np.shares_memory(a, t)
~~~

程序中的整除把 NumPy 的字节步长换成元素步长。对于这个数组，每个步长都恰好是元素宽度的整数倍，因此换算有意义。不要只抄输出中的数字，因为换成八字节数据类型后，字节步长会翻倍，元素步长却保持相同。

### 2. 为什么对象不同，修改却会互相影响

a 与 t 是两个数组对象，包含不同的形状和步长，因此 a is t 为假。但它们的数据可能来自同一块存储。执行 t 的二、一位置赋值为九十九，会改变底层偏移六的值；之后读取 a 的一、二，也会看到九十九。这叫存储别名，或者共享内存。

对象身份、数学值相等和存储共享是三个不同关系。两个独立复制的数组可以值完全相等，但互不影响；两个共享存储的视图可以形状和值的排列不同，却会互相影响；同一个对象当然与自己共享存储，但反过来不成立。调试时只用等号比较数据，无法判断别名；只用 is 判断对象身份，也无法判断是否共享数据区。

在原地算子中，别名是正确性合同的一部分。假设你想把矩阵转置到自己原来的存储里，简单按照顺序逐元素覆盖可能先写掉后面还需要读取的值。方阵的原地转置可以用精心设计的成对交换实现；非方阵则涉及更复杂的置换环，不能把“读一个写一个”的逐元素模板直接套用。

### 3. 连续副本解决什么，又付出什么

当后续算子只接受连续行优先布局时，可以建立一个符合要求的副本。NumPy 中可用 ascontiguousarray。它的语义是返回符合指定连续布局要求的数组；如果输入本来符合要求，可能直接复用；否则需要分配并复制。它不是无条件复制，也不是无成本地改变一个标记。

~~~python
packed = np.ascontiguousarray(t)
assert packed.shape == t.shape
assert np.array_equal(packed, t)
assert packed.flags.c_contiguous
assert not np.shares_memory(packed, a)
~~~

在这个转置例子里，packed 的逻辑值排列为零、四、八、一、五、九等，并被重新存成行优先顺序。t 和 packed 的 shape 相同，逐元素值相同，但步长不同，底层物理顺序也不同。这样建立副本后，后面的简单 Kernel 可以按行连续读取，但复制成本应当计入完整操作。

什么时候应该支持任意步长，什么时候应该先整理成连续数据？如果一个张量会反复被很多算子消费，提前整理一次可能值得；如果只做一次很短的计算，复制成本可能比计算大得多；如果布局本来就适合某个高效算子，强行整理反而浪费。正确决策需要把调用链一起考虑，不能只比较某一个内部 Kernel 的计时。

## 第四课：切片让逻辑大小、覆盖跨度和分配大小分开

### 1. 从每隔一列取元素开始

令 s 等于 a 的所有行、每隔两列取一次。对于三行四列数组，保留下来的列是零和二，结果形状是三乘二。行下标增加一仍跨过四个底层元素，列下标增加一却跨过两个底层元素，所以元素步长是四和二。

取 s 的二、一位置。它对应原数组 a 的二、二。按新描述算偏移：二乘四加一乘二，得到十。逻辑数组只有六个元素，但访问到了原存储的第十个元素。这没有越界，因为逻辑大小和底层存储跨度不是同一个量。逻辑元素个数回答有多少个可见位置；存储跨度回答这些位置最远覆盖到哪里。

如果只根据逻辑大小六分配六个元素，却把步长四、二原样套到新分配上，就会出问题。因为最大偏移十超出了长度六的存储。一个合法的视图描述不只需要各维下标合法，还需要所有映射后的地址都处于其实际可访问的存储范围内。

### 2. 起始偏移怎样进入计算

现在取 a 的后两行、从第一列之后开始的两列，即 a[1:,1:3]。结果形状是二乘二，元素步长仍为四和一，逻辑起点对应原数组的下标一、一，底层偏移为五。结果的四个值分别来自偏移五、六、九、十。

如果一个指针已经指向值五的位置，那么相对该指针的四个偏移是零、一、四、五。如果你还在公式里再加一次五，就会把起始偏移计算两遍。相反，如果指针仍指向底层值零的位置，却漏掉起始偏移，就会读到零、一、四、五。你看到的两个常见错误恰好互为镜像，所以记录指针基准比随意加减一个常数可靠。

在后续分页 KV Cache 中，页表先找到某个物理页的基址，再计算页内位置。这个页基址已经包含了前一层地址翻译，页内算子不应该重新加上逻辑页号对应的整段偏移。虽然实现比本章复杂，基本原则相同：每一层偏移只加一次，单位和基准必须写清楚。

### 3. 空切片和长度为一的维度

空切片没有任何合法元素。例如某个轴长度为零，则整个张量的元素数也是零。描述里可能仍有步长信息，但不能据此读取“第零个元素”，因为根本没有合法的第零个下标。一个健壮的算子入口要明确空输入的输出和是否需要启动 Kernel，而不是默认每个维度至少有一个元素。

长度为一的维度则不同，它有一个合法下标零。这个维度的步长不会影响任何实际元素地址，因为下标永远乘以零。于是连续性判断不能只机械地把每个 stride 与某个标准值逐项比较。某些长度为一的轴拥有不同步长，仍然可以表现为连续有效数据。框架对这些退化维度有具体定义，写通用布局检查时要覆盖它们。

初学时可以采用更保守的策略：教学 Kernel 明确只接受普通连续输入，调用框架提供的连续性判断；在专门学习 stride-aware 算子时，再详细定义空维和长度一维的处理。保守限制是合法设计，关键是入口检查、文档和实现保持一致，不能一边声称通用支持，一边只测一组普通矩阵。

## 第五课：广播为什么常常不复制数据，为什么写入时更危险

### 1. 先从数学上的重复开始

假设有一个长度三的向量 b，数值为十、二十、三十，要给一个二行三列矩阵的每一行加上它。数学上可以先把 b 复制成两行，再逐元素相加。但是为了读取，每个输出行都能直接使用同一份 b，因此实际没有必要建立重复副本。

把 b 看成形状一乘三，再逻辑扩展成二乘三。如果行步长设为零，列步长设为一，那么位置零、二和位置一、二都映射到 b 的第二号下标，读到三十。零步长的意义不是不合法地址，而是该轴变化不会改变地址。

广播的兼容性从右往左比较形状。两个对应轴长度相等，或者其中一个为一，就能按常见数组广播规则匹配；缺少的前导轴可以当作长度一。例子中二乘三与三匹配，因为后者可理解成一乘三。二乘三与二一般不能按这个规则相加，因为最右侧三与二既不相等，也没有一。不要依据“都是两个数或者两行”进行直觉匹配。

### 2. 为什么只读安全不代表写入安全

读取广播输入时，不同输出线程读同一个位置，通常符合算子定义。写入广播输出时，多个逻辑输出位置却可能竞争同一个物理地址。假设两行各自算出不同结果，都要写回零步长视图，两个结果无法同时存在于同一个位置。问题不是加一个同步屏障就能解决，而是输出定义本身存在冲突。

如果任务是“把多行贡献加到一个向量”，那是归约，应明确求和语义并选择相应实现。如果任务是“每个位置保存自己的结果”，那输出必须为每个逻辑位置提供独立存储。把两个任务混在一起，用最后一次写入的结果掩盖冲突，会使输出依赖执行顺序。

NumPy 的广播视图通常也会采取只读等保护，但本章的重点不是记住某个对象是否允许赋值，而是理解保护背后的原因。GPU Kernel 只拿到地址后，不会自动知道你想要什么别名语义。算子的高层包装函数必须建立合同，内核必须按合同实现。

### 3. 一个明确支持广播读取的完整参考

下面的函数只处理一维偏置加二维矩阵，范围刻意明确。它不声称实现全部 NumPy 广播规则：

~~~python
import numpy as np

def add_row_bias(matrix, bias):
    matrix = np.asarray(matrix)
    bias = np.asarray(bias)
    if matrix.ndim != 2:
        raise ValueError('matrix must be two-dimensional')
    if bias.ndim != 1 or bias.shape[0] != matrix.shape[1]:
        raise ValueError('bias must match the column count')
    out = np.empty(matrix.shape, dtype=np.result_type(matrix, bias))
    for row in range(matrix.shape[0]):
        for col in range(matrix.shape[1]):
            out[row, col] = matrix[row, col] + bias[col]
    return out

x = np.arange(6).reshape(2, 3)
b = np.array([10, 20, 30])
assert np.array_equal(add_row_bias(x, b),
                      np.array([[10, 21, 32], [13, 24, 35]]))
~~~

两个输入通过 asarray 变成具有 shape 的对象，但这不一定复制数据。随后先校验维数，再校验对应长度。输出新分配，不与输入共享存储。内层循环每次选择同一个列号的 bias，因此第二行复用第一行读过的三个偏置值。最后返回输出，而不是在输入上原地修改，这使别名合同更简单。

把这段程序变成 GPU 算子时，可以让每个线程负责一个输出位置，先把线性下标分解成行和列，再读取 matrix 的对应元素与 bias 的列元素。你现在已经知道数学语义、输出所有权和需要的下标，后面的并行化只是把这些工作分配给更多执行者，而不是重新定义计算。

## 第六课：负步长、反向视图与可访问范围

### 1. 反向读取为什么需要同时移动起点

对长度五的向量零、一、二、三、四做反向视图，逻辑结果应为四、三、二、一、零。可以把逻辑起点放在底层偏移四，再把元素步长设成负一。逻辑位置零得到偏移四；位置一得到三；依次减到零。只把步长改成负一却不移动起点，会访问到负偏移，属于错误描述。

二维反转第一维也一样。三行四列的数组反向排列行时，起始偏移移动到最后一行，即八，行步长变成负四，列步长仍为一。逻辑位置二、三的偏移是八加二乘负四再加三，结果为三，对应原来的第一行最后一个元素。

负步长并不意味着每个元素的字节顺序倒过来。一个四字节浮点数仍作为完整元素读取，改变的是元素之间的访问顺序。把反向张量误理解为反向字节序，会混淆两个完全不同的问题。字节序决定多字节数值内部如何排列，负步长决定相邻逻辑元素如何映射到存储。

### 2. 计算整个视图覆盖范围

给定形状和步长，不能总用“起点加最后下标的偏移”作为最大地址，因为负步长会让最后下标变成最小地址。对每个轴，零下标贡献零，最后合法下标贡献该轴长度减一乘步长。取这两个贡献的较小者累加，得到最小元素偏移；取较大者累加，得到最大元素偏移。

例如起点八、形状三乘四、步长负四和一。第一轴贡献范围是负八到零；第二轴是零到三。相加再加起点八，整体最小偏移是零，最大偏移是十一。它仍覆盖原来的十二个元素，只是逻辑访问次序改变。

这是一个范围检查，不是没有别名的证明。零步长广播的最小最大偏移可能完全处于分配内，却让多个逻辑下标重合。同样，某些非常规步长可能产生重叠。检查访问是否在边界内，与检查不同输出是否写到同一个地址，是两个不同任务。

## 第七课：reshape、flatten、ravel、view和复制的边界

### 1. 相同元素数只是必要条件

把十二个元素改成二行六列，元素数保持相同，因此有可能建立新的解释。但这并不保证任何输入布局都能通过只改描述完成。对于连续的一维存储，二行六列容易得到；对于经过转置和跨步切片的输入，逻辑顺序与底层顺序可能不再匹配新形状需要的规则步长。

reshape 的概念是保留指定逻辑遍历顺序并改变形状。具体 API 可能在能建立视图时共享存储，在不能建立视图时复制；不同框架又可能将严格 view 和允许复制的 reshape 分开。使用时不能只记住“reshape不复制”这一句错误口诀，而应查清所用接口的保证并用共享存储检查验证。

flatten 通常强调得到展平结果，但是否复制仍取决于具体 API 名称与实现合同。NumPy 的 flatten 返回副本，ravel 尽可能返回视图；这里的事实只属于这些具体接口，不能推广到所有框架同名函数。阅读跨框架代码时，先确认语义，再谈性能。

### 2. 一个改变访问顺序的例子

对三行四列的连续矩阵，按行展平得到零到十一。对转置视图按其逻辑行顺序展平，得到零、四、八、一、五、九、二、六、十、三、七、十一。这两个序列都包含同样的数，但顺序不同。若一个 Kernel 接收转置视图，却忽略其步长直接读取底层零到十一，它实际上执行了另一种遍历顺序。

这种错误在注意力头拆分中很常见。reshape 负责把一段特征分成头和头内维，transpose 负责交换轴的位置。如果顺序写反，最终 shape 也许相同，但“哪个特征属于哪个头”已经改变。仅测试输出形状无法发现这类问题，必须用可追踪的元素编号验证对应关系。

完整验证办法是给每个原元素一个唯一编号，写出目标元素应该来自哪个原下标，再逐点比较。这个方法不依赖模型有没有训练，也不需要 GPU。很多昂贵的模型数值问题，都可以先缩成一个十几元素的布局问题。

## 第八课：为真实Kernel定义布局合同

### 1. 三种可选设计

第一种设计只接受连续输入。包装函数检查维数、类型、设备和连续性，不满足就报错。这种设计的优点是地址简单、教学清晰、优化空间明确；缺点是调用者可能需要整理数据。对于入门算子，这通常是合理起点。

第二种设计支持显式步长。包装函数传入各轴步长，Kernel按统一寻址公式读取。它能够直接处理转置和切片，但地址计算更复杂，访问模式也可能不利于性能。支持读取非连续输入并不意味着支持任意重叠输出，输出合同仍要单独规定。

第三种设计在入口主动创建连续副本。它可以让底层 Kernel 保持简单，但必须说明可能分配额外内存、可能复制以及端到端计时范围。用户如果以为操作总是零复制，就可能误判显存峰值和延迟。接口便利性不能以隐藏重要成本为代价。

### 2. 合同应该写到什么程度

以二维矩阵加法为例，至少明确两个输入的形状关系、数据类型、所在设备、允许的步长、输出是否新分配、输入输出能否别名、空张量行为、整数溢出或浮点误差的处理。不是所有算子都必须支持所有情况，但每一种声称支持的情况都应该有对应验证。

“支持float32矩阵”还不够。一个 CPU float32 矩阵和一个 GPU float32 矩阵不能直接交给同一个只接受设备指针的 Kernel。两个 GPU 张量也可能在不同设备上。一个连续float32矩阵还可能存在零行或零列。精确合同减少的是歧义，而不是为了显得严谨堆积检查。

本卷现有 Triton 包装器采用明确的连续 CUDA float32 合同，并对矩阵尺寸设置教学上界。这样做使数值和地址推导容易核验。以后扩展任意 stride 时，应新增参数、测试和文档，再放宽检查，不能只删除检查让错误输入进入旧内核。

## 第九课：建立一个能暴露布局错误的测试体系

### 1. 测试输入要刻意破坏对称性

方阵容易掩盖行列交换，长宽相等时 shape 也不变；全零容易掩盖错误读取；每行相同的数据容易掩盖行步长错误；每列相同的数据容易掩盖列步长错误；恰好整除块大小的尺寸容易掩盖尾部错误。因此，第一组测试应使用非方阵、递增数、非整除长度、转置和跨步切片。

一个三乘五的矩阵比四乘四更适合抓住很多索引错误。你可以令元素值为一百乘行号加列号，这样读到二百零三就能立刻知道来自第二号行、第三号列。与简单递增序列相比，这种编码还把行列身份分开了，适合调试多维映射。

~~~python
import numpy as np

rows, cols = 3, 5
x = np.array([[100*r+c for c in range(cols)] for r in range(rows)])
t = x.T
assert t[4, 2] == 204
assert t[1, 0] == 1
assert t[0, 1] == 100
~~~

逐个断言使用的是非对称位置。只测零、零或者对角线，会让错误转置也有机会通过。测试不是随机按几个按钮，而是根据可能犯的错误构造能区分正确与错误实现的输入。

### 2. 逻辑正确、物理越界和重复写入分别检查

逻辑正确性检查输出值是否符合数学定义。越界检查则关注所有读取和写入地址是否处于分配范围。重复写入检查关注两个不同的工作单元是否会写同一个输出位置。在CPU教学模拟中，可以把每个输出地址的写入次数记录下来，要求恰好为一。

一个程序可能所有写入都在边界内，却把两行写到同一行，导致另一行未写；也可能每个位置都写一次，却读取了错误的输入；还可能在小输入上结果正确，但最后一个尾块读越界后碰巧拿到零。三种性质不能互相替代。

后续学习GPU调试器时，内存检查工具能帮助发现非法访问，但它不会自动知道你的矩阵乘法数学定义。反过来，数值测试偶然通过，也不能证明不存在非法访问。把数学oracle、地址边界和所有权检查分开，会让你更快定位故障属于哪一层。

## 第十课：从零实现一个教学张量描述器

下面的完整程序使用Python列表作为我们自己控制的“元素存储”。它不冒充NumPy内部实现，也不直接解引用真实内存地址。这样可以安全地实验任意步长，并把错误表现为清楚的异常。

~~~python
from dataclasses import dataclass
from itertools import product

@dataclass(frozen=True)
class TensorView:
    storage: list
    shape: tuple
    strides: tuple
    offset: int = 0

    def __post_init__(self):
        if len(self.shape) != len(self.strides):
            raise ValueError('rank mismatch')
        if any(type(n) is not int or n < 0 for n in self.shape):
            raise ValueError('shape must contain nonnegative integers')
        if any(type(s) is not int for s in self.strides):
            raise ValueError('strides must contain integers')
        if type(self.offset) is not int:
            raise ValueError('offset must be an integer')
        if any(n == 0 for n in self.shape):
            return
        low = self.offset
        high = self.offset
        for n, stride in zip(self.shape, self.strides):
            end = (n - 1) * stride
            low += min(0, end)
            high += max(0, end)
        if low < 0 or high >= len(self.storage):
            raise ValueError('view reaches outside storage')

    def address(self, index):
        if len(index) != len(self.shape):
            raise ValueError('wrong number of indices')
        result = self.offset
        for i, size, stride in zip(index, self.shape, self.strides):
            if type(i) is not int or not 0 <= i < size:
                raise IndexError('logical index out of range')
            result += i * stride
        return result

    def get(self, index):
        return self.storage[self.address(index)]

    def indices(self):
        return product(*(range(n) for n in self.shape))

    def values(self):
        return [self.get(index) for index in self.indices()]

    def transpose(self, order):
        if sorted(order) != list(range(len(self.shape))):
            raise ValueError('order must be a permutation')
        return TensorView(self.storage,
                          tuple(self.shape[i] for i in order),
                          tuple(self.strides[i] for i in order),
                          self.offset)

data = list(range(12))
a = TensorView(data, (3, 4), (4, 1))
t = a.transpose((1, 0))
assert a.get((1, 2)) == t.get((2, 1)) == 6
assert t.values() == [0, 4, 8, 1, 5, 9, 2, 6, 10, 3, 7, 11]
reverse_rows = TensorView(data, (3, 4), (-4, 1), 8)
assert reverse_rows.values()[:4] == [8, 9, 10, 11]
broadcast = TensorView([10, 20, 30], (2, 3), (0, 1))
assert broadcast.values() == [10, 20, 30, 10, 20, 30]
~~~

dataclass帮助定义存储描述的字段；frozen阻止重新给这些字段赋值，但不会让storage所指向的列表自动变成不可变。这一点非常重要：描述信息不变，不代表底层数据不会被其他引用修改。我们在此只提供读取接口，因此不用实现任意重叠写入的语义。

构造后的检查先验证秩一致，也就是形状与步长包含同样多的轴。随后检查形状长度和步长的类型。代码使用type精确检查整数，因而拒绝True；虽然Python里bool可以参与整数算术，但“行数True”不是这个教学接口接受的输入。

遇到零长度维度时，没有任何实际元素访问，所以不需要计算最大合法元素地址。非空情况则逐轴累积最小和最大可能偏移。这个算法依赖矩形下标域与线性步长映射：每个轴独立选择零或最后下标即可达到该轴贡献的极值。它不检查非重叠，因为读取视图允许广播和其他别名。

address先检查给定下标个数，再逐轴验证范围并累计偏移。get只负责按偏移读storage。将二者分开后，测试既可以检查地址，也可以检查读取值。values按逻辑下标顺序遍历，不是假设底层数据连续。transpose只重新排列shape和strides，保留同一个storage对象与offset。

这段实现还没有切片语法、数据类型、字节地址、设备、多线程、引用计数或复杂连续性判断。它的目标是让你完整拥有一个小而可理解的寻址模型，而不是用几十行代码声称复刻成熟张量框架。后续每增加一个功能，都应先给出合同，再增加验证。

## 第十一课：三类常见故障，逐步定位到错误的那一项

### 故障一：转置输入只有第一个元素正确

症状是连续输入全部通过，转置输入的零、零正确，其余位置大量错误。先记录输入shape、字节步长和元素宽度，换算出元素步长。再把错误Kernel的地址公式写出来。如果它使用row乘列数加col，就可以立即发现它假定最后一维连续。

最小反例取二行三列，转置后是三行二列。正确的转置位置零、一应读取原位置一、零，数值三；错误连续公式读取底层偏移一，数值一。只有两个位置就能说明问题，不需要启动一个大模型。修复要么传入真实步长，要么明确拒绝该输入并让调用者整理布局。

### 故障二：切片结果整体向后错一段

症状是切片的内部相对排列似乎正确，但所有值都来自后面的区域。检查调用者传入的是底层存储指针，还是切片首元素指针；再检查Kernel是否额外加storage_offset。如果两处都包含同一个偏移，就重复计算了起点。

把起始偏移临时改成一个特别容易识别的值，例如原矩阵第二行第二列，并打印前四个逻辑元素的预期底层编号。不要靠反复减一个常数直到样例通过，因为换一个切片后错误会重新出现。正确修复是统一指针基准，并把约定写入接口。

### 故障三：广播输出偶尔正确、换执行顺序就改变

先列出所有逻辑输出的物理地址。如果不同逻辑位置映射到同一地址，问题发生在输出所有权，而不是浮点舍入。顺序执行时可能总由最后一行覆盖前一行；并行执行时完成顺序不同，因此结果看起来不稳定。

若数学任务需要每个位置独立结果，就分配非重叠输出；若数学任务需要把多个贡献合并，就明确归约操作并选择确定的数学定义。加锁或原子操作不能替你决定数学语义。把“写同一位置”从意外行为改成明确归约，才是设计层面的修复。

## 第十二课：十二道递进练习与完整参考解

### 练习一：把元素偏移换成字节地址

题目：float16张量形状二乘三乘五，连续行优先布局，底层首地址二千零四十八，求下标一、二、四的地址。先独立写出步长，再换单位。

答案：最后一维步长一，中间维五，最外维十五。元素偏移为十五加十加四，等于二十九。float16每元素两字节，因此字节偏移五十八，地址二千一百零六。错误答案二千零七十七把元素数当作字节数；错误答案二千一百六十四则可能把两字节重复乘了两次。

### 练习二：为每个位置生成可追踪值

题目：建立三乘五数组，元素值为一百乘行加列。验证转置后的四、二与一、零位置，再验证每隔两列的切片。

~~~python
import numpy as np
x = np.array([[100*r+c for c in range(5)] for r in range(3)])
t = x.T
s = x[:, ::2]
assert t[4, 2] == 204
assert t[1, 0] == 1
assert s.tolist() == [[0, 2, 4], [100, 102, 104], [200, 202, 204]]
~~~

解释：切片的逻辑列号一对应原列号二，逻辑列号二对应原列号四。用这种编码，读到一百零四就能同时还原行号一和列号四。它比全一矩阵提供更多故障定位信息。

### 练习三：实现连续元素步长

~~~python
def contiguous_strides(shape):
    stride = 1
    result = []
    for size in reversed(shape):
        if type(size) is not int or size < 0:
            raise ValueError('invalid dimension')
        result.append(stride)
        stride *= size
    return tuple(reversed(result))

assert contiguous_strides((2, 3, 4)) == (12, 4, 1)
assert contiguous_strides((7,)) == (1,)
assert contiguous_strides(()) == ()
~~~

空shape表示标量描述，在这个函数里没有轴，所以步长元组也为空。含零维度时这里给出一种直接乘积规则，但不要据此替代所有框架对退化连续性的定义。题目要求的是生成一个连续布局描述，而不是判断任意描述是否连续。

### 练习四：给描述器添加字节地址方法

~~~python
def byte_address(view, index, storage_base, itemsize):
    if type(itemsize) is not int or itemsize <= 0:
        raise ValueError('itemsize must be positive')
    return storage_base + view.address(index) * itemsize

view = TensorView(list(range(12)), (3, 4), (4, 1))
assert byte_address(view, (1, 2), 1000, 4) == 1024
assert byte_address(view, (1, 2), 1000, 2) == 1012
~~~

答案的关键是复用已包含起始偏移的address结果，并且只乘一次itemsize。storage_base在合同中明确指底层存储首字节。若调用者已经传入视图首元素地址，就应采用另一个接口，而不是偷偷修改参数意义。

### 练习五：证明转置两次恢复逻辑关系

~~~python
data = list(range(15))
a = TensorView(data, (3, 5), (5, 1))
back = a.transpose((1, 0)).transpose((1, 0))
assert back.shape == a.shape
assert back.strides == a.strides
assert back.values() == a.values()
assert back.storage is a.storage
~~~

这组断言分别检查描述、数值和共享关系。仅比较数值不足以说明没有复制；仅比较shape不足以说明映射正确。二维交换执行两次得到原顺序，但三维任意排列的逆排列需要单独计算，不能默认把同一个排列再执行一次就恢复。

### 练习六：构造合法负步长视图

~~~python
a = TensorView(list(range(12)), (3, 4), (-4, 1), 8)
assert a.get((0, 0)) == 8
assert a.get((2, 3)) == 3
assert a.values() == [8, 9, 10, 11, 4, 5, 6, 7, 0, 1, 2, 3]
~~~

参考推导先找新逻辑首元素，对应原最后一行起点八；然后每行向前走四个元素，因此行步长负四。若把offset设成零，构造器就会检测到最小偏移为负，拒绝描述。这个失败也是题目的验收组成部分。

### 练习七：检测输出是否有重复地址

~~~python
def has_overlap(view):
    seen = set()
    for index in view.indices():
        address = view.address(index)
        if address in seen:
            return True
        seen.add(address)
    return False

assert not has_overlap(TensorView(list(range(6)), (2, 3), (3, 1)))
assert has_overlap(TensorView([1, 2, 3], (2, 3), (0, 1)))
~~~

枚举法适合小型参考与测试，不适合巨大张量的生产检查，因为时间和集合空间随元素数增长。它的价值在于定义清楚、容易验证，可作为更快判定算法的oracle。空视图没有重复访问，因此返回假。

### 练习九：修复一个错误读取器

题目中的错误实现总用行乘列数加列读storage，忽略offset和strides。完整修复不需要猜测不同特例，只需统一调用address：

~~~python
def read_matrix(view):
    if len(view.shape) != 2:
        raise ValueError('matrix required')
    rows, cols = view.shape
    return [[view.get((r, c)) for c in range(cols)] for r in range(rows)]

t = TensorView(list(range(12)), (4, 3), (1, 4))
assert read_matrix(t) == [[0, 4, 8], [1, 5, 9], [2, 6, 10], [3, 7, 11]]
~~~

验收还要加入非零offset和负步长视图。只修复转置而不支持合同中其他合法步长，通常意味着代码又添加了一个局部特判。统一寻址公式能把这些情况放到同一套推导中。

### 练习十：解释逻辑字节数和存储跨度

取长度十二的float32存储，每隔两元素选一个，共六个逻辑元素。逻辑有效载荷为二十四字节；最后选中的元素从偏移十开始，覆盖到该元素的第四个字节，因此从首选元素到末选元素末尾的跨度为四十四字节；底层原分配仍为四十八字节。三个数字分别回答不同问题，没有矛盾。

如果用逻辑有效载荷估计通信实际需要发送多少数据，还要看是否先打包；如果直接传输整个连续跨度，就可能包含间隙；如果框架保留整个底层存储，释放视图也不一定释放原分配。请把计算问题、传输问题和所有权问题分别写出。

### 练习十一：设计布局验收矩阵

参考答案至少包含连续非方阵、转置、跨列切片、非零起点切片、反向行、零行、长度一维、广播只读输入、重叠输出拒绝。每个用例都要写它针对的故障，例如转置针对硬编码行步长，非零起点针对偏移重复，广播针对零步长，零行针对无效launch。

然后把错误实现故意带回测试，确认至少一个对应测试失败。一个从未能击穿目标错误的测试，不能证明它覆盖了该错误。验收表不仅记录“运行成功”，还应记录“删除哪条正确逻辑后，它会失败”。

### 练习十二：把布局合同写成可审阅接口

完整答案示例：输入为两个同设备、同shape的二维float32张量；支持任意非负输入元素步长，包括只读广播；输出新分配为连续行优先且不与输入共享存储；空行返回空输出，不启动设备计算；零列不做读取；每个输出位置恰好写一次；不支持负步长时入口明确拒绝；测试同时检查数值和输入未被修改。

这不是唯一合法合同。你也可以选择只支持连续输入，但必须相应修改检查和测试。接口合同的好坏取决于它是否一致、可验证、适合目标调用链，而不是是否把所有可能情况都宣称支持。

## 第十三课：小项目——给一个算子写出完整的布局适配层

项目目标是实现二维矩阵加行偏置，并提供两个版本：一个只接受连续输入，一个接受任意合法只读视图。不要立刻做GPU优化，先让两个版本在相同数学输入上输出一致。

第一阶段使用本章TensorView作为输入，把结果写到新的连续storage。输入矩阵和偏置分别建立描述，偏置使用一维索引。第二阶段加入转置和切片，将同一组值以不同布局提供给函数。第三阶段加入一个故意忽略stride的错误版本，用验收矩阵证明测试能抓住它。第四阶段再把接口转换为NumPy数组，核对元素步长和字节步长的换算。

~~~python
def view_row_bias(matrix, bias):
    if len(matrix.shape) != 2 or len(bias.shape) != 1:
        raise ValueError('expected matrix and vector')
    rows, cols = matrix.shape
    if bias.shape[0] != cols:
        raise ValueError('column mismatch')
    output = []
    for r in range(rows):
        for c in range(cols):
            output.append(matrix.get((r, c)) + bias.get((c,)))
    return TensorView(output, (rows, cols), (cols, 1))

matrix = TensorView(list(range(12)), (4, 3), (1, 4))
bias = TensorView([10, 20, 30], (3,), (1,))
result = view_row_bias(matrix, bias)
assert result.values() == [10, 24, 38, 11, 25, 39, 12, 26, 40, 13, 27, 41]
~~~

完整提交物包括接口合同、至少九种布局用例、一个地址追踪表、错误版本的失败输出和一段解释：为什么这个实现可以接受转置，而后续连续CUDA版本不能直接接受。代码短并不意味着项目简单，因为你要同时解释逻辑关系、地址关系和所有权。

当这个项目通过后，再去看K03线程下标与K08 Triton program下标。你会发现并行代码里的row、col、offset不再是陌生符号，而是本章已掌握的寻址关系加上工作分配。后续性能优化则继续追问：这些正确地址由哪些线程同时访问，能否复用，是否需要同步。

## 第十四课：把布局知识带进真实的注意力张量

### 1. 从模型里的四个轴开始推导

实际注意力张量常常带有批次、序列、头和头内特征四个轴。假设批次为二、序列长度为三、头数为二、每头特征为四，某个投影结果采用二乘三乘二乘四的连续布局。给四个轴分别命名为B、T、H、D，比仅写一个四元组更容易检查语义。总元素数为四十八，连续元素步长从右向左推得二十四、八、四、一。

选择位置批次一、token二、头一、特征三。每个轴贡献分别为二十四、十六、四和三，总偏移四十七，正好是最后一个元素。再选择批次一、token零、头一、特征二，贡献为二十四、零、四、二，总偏移三十。第二个例子没有把各轴都取最后值，因此更适合验证各轴贡献是否独立正确。

某个attention接口需要B、H、T、D顺序，于是把中间两个轴交换。新shape为二乘二乘三乘四，元素步长为二十四、四、八、一。原位置B一、T零、H一、D二现在写成B一、H一、T零、D二，地址仍是二十四加四加零加二，等于三十。这个算式直接证明了轴置换没有改变对应元素的存储位置。

如果后面的Kernel误以为新shape自动意味着连续布局，就会采用二十四、十二、四、一的错误步长。同一个逻辑位置B一、H一、T零、D二会被算成三十八，读到另一个token或另一个头的内容。形状检查全部能通过，数值却已经混头。这也是为什么模型调试中“每层shape都对”仍不能排除严重错误。

### 2. 拆头和合头不能只凭最后形状正确

投影层常输出B、T、H乘D三个轴，然后reshape为B、T、H、D，再transpose为B、H、T、D。这里reshape拆分的是同一条连续特征轴：一个token的前D个输出属于第一个头，接下来的D个属于第二个头。这个分组约定必须与投影权重和后续接口一致。

假设一个token的八个投影值是零到七，两个头各四维。正确拆头得到头零为零、一、二、三，头一为四、五、六、七。如果先把数据按另一个轴顺序解释，再得到同样形状，可能变成头零取零、二、四、六，头一取一、三、五、七。两个结果shape完全相同，甚至每个头元素个数也正确，但计算的点积已经不同。

合头是拆头逻辑的逆过程。通常先把头轴和token轴换回，再把头与头内特征合并。如果跳过换轴直接reshape，可能把不同token的头交错到同一输出向量中。学习者应该用唯一编号逐点检查“输出第几个通道来自哪个头的哪个特征”，不能把reshape当作修复shape报错的万能操作。

~~~python
import numpy as np
raw = np.arange(2*3*2*4).reshape(2, 3, 8)
heads = raw.reshape(2, 3, 2, 4).transpose(0, 2, 1, 3)
restored = heads.transpose(0, 2, 1, 3).reshape(2, 3, 8)
assert np.array_equal(restored, raw)
assert heads[1, 1, 0, 2] == raw[1, 0, 6]
~~~

最后一个断言说明头号一、头内特征二对应原特征轴的一乘四加二，也就是六。它验证具体元素关系，前一个整体相等验证完整往返。两者结合比只确认shape更有教学价值，因为你既知道结论，也知道结论来自哪个映射。

### 3. GQA的共享是语义共享，不必先复制K/V

当query头数多于KV头数时，多个query头可能读取同一个KV头。这个关系可以通过头索引映射实现，也可以在某些参考计算中先repeat再计算。两种实现可能数学等价，但存储与访存成本不同。假设四个query头对应两个KV头，规定query头零和一使用KV头零，query头二和三使用KV头一，那么映射是整除二。

这里不能直接把整个头维写成一个简单零步长就解决，因为所有query头并非都使用同一个KV头，而是按组共享。你可以把query头拆成KV组数与组内query数两个轴，在组内轴使用共享读取；也可以在Kernel里显式算KV头号。哪一种描述更方便，取决于其余布局和并行分块。

这一例子说明，广播是特定的索引关系，不是所有共享都叫广播。理解逻辑头映射后，才能判断某个repeat是否必要、某个reshape是否保持分组、某个kernel是否真的节省KV存储。模型概念与存储概念在这里第一次紧密相遇。

## 第十五课：线性步长模型的边界，以及如何继续读复杂布局

### 1. 并非所有布局都能写成一组固定步长

本章大多数视图采用线性公式：起点加各轴下标乘固定步长。它能表达普通连续、转置、切片、反向和很多广播视图，但不能表达任意排列。比如把一维数组的逻辑位置按不规则列表映射到原位置，通常需要额外的索引数组。一个下标增加一，地址可能先加三再减一再加七，无法用固定stride概括。

分页KV也是一个例子。逻辑token位置先除以页大小得到逻辑页号，再通过页表找到物理页号，最后加页内偏移。页表是一层间接寻址，不等同于把整个历史写成一个固定连续stride。当物理页乱序分配时，跨页的地址跳跃不再固定，而页内仍可以保持简单步长。

分块矩阵布局也可能先把逻辑行列拆成块号和块内位置，再按块排列。假设四行四列矩阵按二乘二块存储，逻辑位置先决定属于哪个块，再决定块内偏移。块内的相邻列可能连续，但跨过块边界时地址计算会改变。不能把一个普通行优先公式到处套用后靠调整一个stride修好所有情况。

### 2. 完整手算一个二乘二分块布局

设四乘四矩阵元素为一百乘行加列。块按块行优先排列，每块内部也按行优先排列。四个块依次覆盖左上、右上、左下、右下。每块四个元素，块行数与块列数都为二。

求逻辑位置行二、列三。块行号是二整除二，等于一；块列号是三整除二，等于一；块线性编号是一乘二加一，等于三。块内行号是二余二，等于零；块内列号是三余二，等于一；块内偏移是一。最终底层偏移为三乘四加一，等于十三。

若使用普通行优先地址，行二列三会算成二乘四加三，等于十一。两种布局都是合法的，差别不是哪个公式天生正确，而是公式是否匹配数据实际如何存放。输入打包器和计算Kernel必须约定同一布局；只改其中一个，数值就会出错。

~~~python
def blocked_offset(row, col, rows, cols, tile):
    if rows % tile or cols % tile:
        raise ValueError('this simple layout requires full tiles')
    if not 0 <= row < rows or not 0 <= col < cols:
        raise IndexError('outside matrix')
    block_row, inner_row = divmod(row, tile)
    block_col, inner_col = divmod(col, tile)
    block_id = block_row * (cols // tile) + block_col
    return block_id * tile * tile + inner_row * tile + inner_col

assert blocked_offset(2, 3, 4, 4, 2) == 13
positions = [blocked_offset(r, c, 4, 4, 2)
             for r in range(4) for c in range(4)]
assert sorted(positions) == list(range(16))
~~~

最后的断言证明十六个逻辑元素恰好映射到十六个不同位置，没有遗漏也没有重叠。它还没有证明某个计算Kernel使用正确数值，所以你仍要建立打包和解包的往返测试。把映射双射检查与数学运算检查分开，是复杂布局调试的实用方法。

### 3. AoS与SoA：先区分元素的含义

假设每个记录有x、y、z三个float32字段。结构体数组方式把一条记录的三个字段放在一起，随后放下一条记录；分离数组方式把所有x连续放置，再分别保存所有y和z。二者都能表达同一批三维点，但不同访问任务会触及不同地址。

如果一个计算每次需要某个点的三个字段，记录内相邻可能方便；如果一批GPU线程各自只读取不同点的x字段，那么分离数组更容易让相邻线程读取相邻地址。这里不能抽象地说某一种永远更快，因为还取决于实际字段使用、加载宽度、缓存、对齐和后续计算。

把这个例子放回LLM，交错保存QKV、按头分开保存、按token分开保存，都是围绕消费者访问模式做出的布局选择。你应该先写消费者的索引关系，再比较布局，不要把某个框架的内部格式当成所有场景的唯一标准。

### 4. 为什么对齐不是“地址能整除四”这么简单

四字节元素通常至少需要满足其类型访问所要求的对齐，但更宽的向量化加载可能要求更严格的起点和布局条件。一个原始分配可以高度对齐，经过偏移一元素的切片后，逻辑首地址却可能不再满足十六字节向量加载的对齐要求。

因此，检查底层分配对齐不足以保证视图对齐。必须检查真正传给算子的逻辑数据指针，以及准备使用的访问宽度。将四个标量读取改成一次宽加载之前，还要确认最后一组是否不足四个元素、跨行时是否会读到不属于本行的数据、输入是否存在跨步。

本章不要求你记住每个硬件指令的具体对齐限制。进入某条实际指令或编译器生成路径时，再查它的合同。当前要建立的是一种推理顺序：先确定元素类型和有效范围，再确定每次访问宽度与起点，最后证明所有实际访问都合法。优化不能跳过前两步。

### 5. 存储生命周期也属于地址正确性

一个地址数值落在曾经分配过的范围内，不代表现在仍可访问。底层存储释放后，旧视图可能成为悬空引用；存储被复用于别的张量后，旧指针甚至可能读到看似合理的新数据。这类错误不是shape或stride公式能单独发现的，需要所有权和生命周期保证。

在Python张量框架里，视图通常通过对象引用等机制维持底层存储的生存期，但当你进入自定义C++扩展、异步GPU任务或外部指针接口时，必须明确是谁拥有存储、什么时候允许释放、计算何时真正结束。函数返回不一定等于GPU读取已经完成，这一点将在K13详细展开。

先在CPU小模型中理解“描述”和“存储”分离，再学习异步所有权，会比直接背record_stream或事件API更可靠。任何时候都可以用三个问题检查设计：谁分配，谁最后一次使用，谁确认使用完成后释放。答案缺少其中一项，就还没有建立完整的地址安全合同。

### 6. 追加验收：解释一个真实布局报错

假设某个自定义算子只接受连续矩阵，你传入转置视图后入口报错。正确处理流程不是立刻删除连续性检查，而是先确定任务是否允许复制，估计复制的数据量，观察后续调用次数，再决定整理布局或扩展Kernel。

若选择整理布局，记录整理前后的shape、stride、共享关系和端到端耗时；若选择扩展Kernel，新增stride参数并使用非方阵、偏移切片、长度一维验证；若决定不支持，则让报错说明接受的布局和可行转换方式。三条路线都有明确技术含义，没有一条可以靠“让错误信息消失”作为完成标准。

完成到这里，你已经不仅会代入一个地址公式，还能识别公式的适用范围、复杂布局需要的额外元数据、复制与共享的代价，以及存储生命周期为何必须纳入算子合同。接下来学C++指针和CUDA线程时，可以把每个新语法放回这些已经清楚的关系中。
