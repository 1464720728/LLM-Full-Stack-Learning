# K04　访存：合并访问、缓存、共享内存与 Bank

先修 K01、K03。你将学会把一个 Kernel 的地址表达式变成访存模式，区分减少数据量与提高带宽利用率，并知道为什么一行 padding 会改变性能。

## 1. 不同存储服务不同范围

寄存器保存线程附近的临时值，访问快但数量有限。Shared Memory 供同一 Block 内协作，生命周期通常与 Block 对应。L1/L2 缓存为访问提供自动复用机会；全局显存承担容量。HBM 与 GDDR 都是 GPU 外部显存技术，具体产品使用哪种不能单凭 Blackwell 家族名判断。

这些层级不是把全部模型权重逐层永久复制一遍。一个 Kernel 每次处理局部 Tile，将将要重复使用的数据放在更近的层级，再更新输出。资源越近、容量通常越有限，所以设计核心是“在局部保留什么、多久、由谁消费”。

寄存器不足时，编译器可能把临时值溢出到 local memory。这里的 local 指线程私有的地址空间，不保证物理上位于片上；溢出可能产生显存访问。见到变量写在函数内部，不等于它必然留在寄存器中。

## 2. 合并访问的手算模型

为了推理，先采用简化的 32 字节 sector 模型。32 个线程各读一个 float32，地址依次为 `0,4,8,...,124`，一共触及四个 sector。若每个线程跳过七个元素，地址变成 `0,32,64,...,992`，就触及三十二个 sector。有效数据仍是 128 字节，搬运与请求组织成本却可能更高。

若连续访问从地址 4 开始，则区间为 4 到 131，跨五个 sector。对齐、访问宽度、缓存命中和架构共同影响真实事务，因此本教材函数 `sectors` 只是地址几何模型，不能直接当作 Nsight 的测量值。它的价值在于让你从地址表达式提出可检验的性能假设。

```bash
python -m labs.kernels.run --lab 4
```

预期连续为 4、跨步为 32、偏移连续为 5。现在回到矩阵：若一 Warp 的相邻线程负责同一行的相邻列，行优先数据通常连续；若负责同一列的相邻行，地址间隔等于行宽。转置 Kernel 常用 Shared Memory 重新排列，使读与写两端都能形成较好的连续模式。

## 3. Bank conflict 与广播

采用简化模型：Shared Memory 被分为 32 个 bank，每个 32-bit word 的 bank 编号是 `word_address % 32`。线程 t 访问地址 t 时分布到不同 bank。线程 t 访问 `32*t` 时，每个地址都落到 bank 0；它们是不同 word，会形成冲突。若所有线程都读同一个 word，则可用广播机制，不应把它当成三十二个不同地址争用。

二维 tile `[32][32]` 按列读取时，word 间隔为 32。改成 `[32][33]`，下一行起点移动 33，模 32 后 bank 编号依次变化。这是经典 padding 技巧。但它依赖实际 dtype、访问指令和布局；不要把“所有二维数组都加一列”当作通用优化定律。

```bash
python -m labs.kernels.run --lab 5
```

输出 stride32 的最大冲突模型值为 32，stride33 为 1，同地址广播为 1。函数使用集合统计每个 bank 的不同 word，因此恰好区分了广播与不同地址冲突。

## 4. 复用要付出容量与同步成本

把 A、B 的 Tile 放进 Shared Memory 能让多个线程重复使用。但 Shared Memory 分配变大，单个 SM 能同时驻留的 Block 可能变少；屏障变多也可能抵消收益。是否值得缓存取决于复用次数、原先命中率、搬运方式和占用资源，不能只用“片上更快”四个字决定。

假设一个 Tile 有 16x16 个 float32，A、B 两份一共 2048 字节。每个线程只使用一次时，先复制到 Shared Memory 再读取可能只是多了一道步骤；若每个值被一整行或一整列反复使用，复制成本就可以被复用摊薄。缓存策略首先是算法数据流问题，其次才是 API 选择。

## 5. 练习与参考答案

1. **sector 手算。** 32 线程读取连续 float16，总共覆盖多少 32 字节 sector？答案：从对齐地址开始且仅考虑有效载荷时为 2；偏移起点、向量化和真实指令可能改变事务，说明假设。
2. **步长诊断。** 对 `A[M,K]`，Warp 内线程 t 读取 `A[t,0]`。当 K=128 时地址间隔是多少？答案：float32 为 512 字节；这通常比 `A[0,t]` 更不利于合并。给出另一种线程映射。
3. **广播反例。** 让所有线程读同一地址与读 `32*t`，为何不能仅按 bank 编号计数？答案：同 word 可广播，后者需要不同 word；参考函数按每个 bank 的地址集合计算。
4. **改造实验。** 把 bank 数设为 8，分别测试 stride=8 与 9，手画八线程地址表。验收：模型分别给出 8 与 1，且能说明它只是人为缩小的教学硬件。
5. **资源预算。** 若 SM 可供某 Kernel 使用的 Shared Memory 为 S，每块使用 B，单靠这个约束最多驻留几块？答案 `floor(S/B)`，但线程、寄存器和硬件块数上限可能进一步限制；不能只取这一个结果当最终 occupancy。
6. **源码任务。** 阅读 CUDA GEMM 的 `sa`、`sb`，写出每一份数据的装载者与消费者。参考：每个线程装一项 A 和 B，随后沿 K 小循环重复读；末尾屏障防止下一轮生产覆盖尚未消费的数据。

掌握门槛：看到一个地址式就能预测连续、跨步、广播、重叠写四类模式；为性能假设设计测量，而不是只凭变量名判断是否“高速缓存”。
