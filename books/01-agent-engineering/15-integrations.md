# A15 MCP、A2A 与真实框架：把组件接到生态，同时读懂协议变化

## 三种边界不要混用

模型 API 连接 Harness 与模型服务；工具协议连接宿主与外部工具提供方；Agent 间协议连接可独立工作的 Agent 应用。它们可以同时存在，但解决的问题不同。一个模型支持 function calling，不等于它自己实现了 MCP 客户端；一个 MCP server 暴露搜索工具，也不等于它能自主规划任务；两个 Agent 都能用同一个工具，也不等于它们之间已有任务委派协议。

MCP 的 host 负责组合模型、上下文、权限与客户端；client 与相应 server 通信；server 暴露工具、资源等能力。宿主决定哪些能力提供给当前模型，执行前还要进行本地策略判断。工具元数据来自外部服务，不应因此自动获得系统指令权威。协议标准化降低接入成本，但不能替你决定业务权限与信任边界。

A2A 的官方项目定位是让不透明 Agent 应用互相通信与协作。你可以委派任务而不要求对方暴露内部所有工具和推理实现。MCP 更适合思考“我如何调用这个能力”，A2A 更适合思考“我如何向这个 Agent 交付任务并跟踪状态”。两者有交叉场景，但不应把名字当成互相替代关系。[A2A 官方仓库](https://github.com/a2aproject/A2A)

## 版本变化是本章的重要实操内容

截至本卷核查日 2026-11-01，MCP 官方已发布 2026-07-28 规范，其核心变为无状态请求模式，旧的 initialize/initialized 交换与 Mcp-Session-Id 已退出这一版本核心；请求携带版本、客户端信息与能力元数据，可以使用可选 server/discover 了解能力。学习 2025 年教程时，应明确那是历史协议，不要把其握手流程误写成当前唯一方式。[官方发布说明](https://blog.modelcontextprotocol.io/posts/2026-07-28/)

当前 tools 规范要求必要 `_meta` 字段，即使正文示例为了简洁省略它们；完成结果包含 `resultType`。工具列表还涉及分页与缓存规则。接口实现者必须按选定规范核对，不能从一段省略版示例推断字段可有可无。[2026-07-28 tools 规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)

这里的重点不是背某次版本号，而是学会分辨：教程日期、规范版本、SDK 版本和服务端部署版本是否匹配。你应把版本作为测试输入，旧版本消息发给新实现时得到明确不兼容，而不是静默丢弃字段后“尽量跑”。

## 离线方法层实验

`integrations.ToolRPC` 是一个 JSON-RPC 工具方法练习。它支持 tools/list 与 tools/call，使用当前版本所需的元数据形式，并验证调用参数。它没有网络传输、认证、分页、通知、MRTR、资源与 prompts、完整缓存或 SDK 兼容测试，因此**不是完整 MCP server**。它的作用是让你亲手观察协议数据如何映射为本地 Tool。

运行：

```bash
python -m labs.agents.experiments 27-tool-rpc
```

第一次请求列出 add 的名字、描述与 inputSchema；第二次请求执行 17+25，返回 resultType=complete、text=42、isError=false。`request_message` 给每次请求加入 protocolVersion、clientInfo 和 clientCapabilities。删除 `_meta` 后应得到错误，而不是仍伪装当前版本成功。

JSON-RPC request id 与模型 tool call id 也不同。前者关联一次客户端—服务器请求响应，后者关联模型动作与模型观察。一个工具请求可能在网络层重试多次，HTTP request ID 又是另一层。建立一张关联表或 trace 字段，能够追踪三层身份，而不把所有字段都叫 id 后混在一起。

## 错误分层

JSON-RPC method not found 属于协议方法错误；未知工具或错误参数属于请求契约问题；工具找到了但查询数据库失败，通常属于工具执行结果。课程实现把协议错误放 error，把执行失败放 result 的 isError。真实规范细节以当前文档为准，关键是不要把所有失败都写成 HTTP 200 的普通文字“失败了”而失去机器可判定结构。

工具声明和参数 schema 从 server 来，并不意味着你应该无条件相信。宿主应过滤允许的 server 和 tool，限制输入输出大小，检查认证上下文，防止名称冲突与能力突然扩张。工具列表变化后缓存要失效，权限变化也不能继续使用旧授权下的缓存结果。检索卷中的租户与来源约束同样适用于 MCP 返回内容。

## 真实 SDK 接入任务

在完成离线方法实验后，进入 [MCP 官方 Python SDK](https://github.com/modelcontextprotocol/python-sdk)。先读当前 README 与兼容说明，记录 commit，再按其当前安装方式建立独立环境。实现一个只读课程文档查询工具，先只绑定 localhost，使用测试文档而非私有材料。用官方客户端或官方检查工具列出工具、调用、检查错误和退出行为。

验收不是“浏览器能打开一个端口”，而是工具元数据正确、调用结果可关联、缺失参数被拒绝、过大结果受限、客户端关闭后资源释放、版本不兼容给清楚错误。再把该客户端包装为本卷 Tool，让模型看到一个能力相同的工具，比较本地函数调用与远程协议调用的 trace 差别。

完整 SDK 例子不在本卷代码里假造，因为当前 SDK 版本和 API 需要实际安装验证。课程已经给出可运行方法层与清晰接入验收；你的任务是通过真实一手项目完成 transport、auth 和生命周期，而不是复制一段未知年代的 FastMCP 代码后以为所有版本通用。

## 框架阅读的四条路线

1. **mini-swe-agent：主循环与环境。** 追踪任务输入到模型，再到命令执行与观察，重点理解停止规则与失败返回。先做 A14 的小任务。
2. **LangGraph：状态、图、持久化与暂停。** 把 A11 的工单项目移植并测试恢复，重点读 checkpoint 与 interrupt，而不是只看画图 API。
3. **OpenAI Agents SDK：模型、工具、runner 与 tracing。** 从官方仓库入口找 Runner 与工具执行边界，检查你关心的模型提供方能否按其适配接口接入，不默认所有后端能力相同。
4. **MCP/A2A 官方实现：跨进程协议。** 对照规范理解消息与状态，不先把它们当“给模型加智商”的插件。

阅读真实工程时先固定一个可运行例子，再沿调用链找五个点：输入构造、模型调用、工具执行、状态保存、停止判定。每找到一个点就写一项小测试或打印一段脱敏结构。读完 README 和架构图不算完成源码学习；能够改变一个行为并预测回归影响，才说明你建立了代码级理解。

## 练习与参考解法

1. **三层 ID。** 写出模型 call_id、JSON-RPC id、HTTP request id 的映射记录。验收：网络重试不会被误认为模型提出了新动作。参考：业务幂等 key 再单独保存，不强行用某一个传输 ID 承担全部语义。

2. **版本拒绝。** 给 ToolRPC 发送旧版本或缺元数据请求。验收：明确错误，不能静默当作新版本。参考：历史协议支持应当是单独适配器，而不是在当前解析器中无限容错。

3. **完整 SDK 工具。** 将 arithmetic tool 暴露为实际 MCP server，再由客户端调用。验收：记录 SDK commit、规范版本、请求响应 fixture 和关闭行为。参考：方法层参考答案在 integrations.py，transport 与认证以已安装版本官方示例为准。

4. **工具名称冲突。** 两个 server 都暴露 search。验收：宿主有明确命名空间或映射，不随机选一个。参考：模型名称、server identity 和原始 tool name 分开存，结果带来源。

5. **A2A 任务模拟。** 不接外网，设计 submitted、working、input_required、completed、failed 等任务状态，并定义如何获取最终 artifact。验收：任务状态与一次 HTTP 响应生命周期分开。参考：具体标准枚举按实际 A2A 版本核对，练习先表达语义，再对齐官方 schema。

6. **同任务三实现。** 用自写 Harness、一个图框架和一个编码 Agent 框架实现相同小任务，固定预算与 verifier。验收：比较组件职责、恢复、可观察性和修改成本，不用“代码少”作为唯一指标。参考：写出你最终选择的两项具体理由和一项真实代价。

7. **规范升级演练。** 保存旧消息 fixture，再为新版本写显式转换或拒绝策略。验收：测试能告诉维护者哪些旧行为已经不兼容，而不是只更新一个版本字符串。参考：版本管理的目的在于保存语义证据，不是追求永远写 latest。

通过门槛：你可以把自写组件接入真实生态，同时对不支持能力明确报错；能够在规范变化时定位受影响层、更新测试和迁移状态，而不再完全依赖教程作者替你理解底层机制。
