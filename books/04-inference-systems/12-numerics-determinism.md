# S12 数值、量化与确定性：定位第一处分歧

先修浮点、softmax、S07、模型卷的量化基础。本章连接框架工程与精度评测：量化后任务分数低了一点，究竟是权重近似、采样、batch变化、工具环境，还是统计波动？你需要分层证据，而不是反复跑一个大benchmark等待平均值稳定。

## 1. 同一个数学表达式不一定同一个浮点结果

浮点数只有有限精度。使用float32，`(1e8 + -1e8) + 1`可得到1，而`1e8 + (-1e8 + 1)`可得到0，因为后者括号内的1在舍入时丢失。并行归约把数据分成不同块，可能改变加法树；batch size改变也可能触发不同tile、不同Kernel。

这不意味着某个实现错误。实数加法结合律成立，有限精度加法不严格满足。验证数值正确性需要误差标准、输入范围和参考精度。若两个最大logit非常接近，一个很小的变化就可能改变argmax，之后自回归上下文不同，输出快速分叉。

## 2. 至少区分四种复现目标

固定seed只约束随机流；固定执行路径限制Kernel/调度变化；bitwise确定要求位级相同；统计可复现关注重复实验的分布或结论一致。它们强度不同，也服务不同目的。

同一个请求独立重复一致，不代表与其他请求拼batch仍一致；同一张卡一致，不代表跨卡/跨架构一致；logits接近，不代表最终文本一致；最终选择题答案相同，也不代表每层数值相同。报告必须说明比较层级。

vLLM官方复现文档明确把默认行为与受约束复现区分，并把保证限制在相同硬件与版本等条件。SGLang固定快照的确定性文档列出后端与功能兼容矩阵。学习者应使用自己安装版本的支持矩阵，不能把“有确定性开关”推断为全部新模型、全部量化、全部并行组合已经验证。

## 3. 一个具体量化例子

对向量 `[-2,-0.3,0.1,0.8,1.7]` 做对称4bit教学量化，使用整数范围[-7,7]，scale=2/7。量化整数约为[-7,-1,0,3,6]，反量化为[-2,-0.285714,0,0.857143,1.714286]。最大绝对误差是0.1。

本例用[-7,7]而不是[-8,7]，以保持正负对称；真实格式和Kernel可能采用不同编码。scale、zero-point、分组大小、权重layout和累加dtype都是算法的一部分。W4A16表示权重与激活精度的组合，不足以唯一指定具体量化方法。

```bash
python -m labs.serving.experiments --lab quantization
```

代码验证理想逐元素round在没有截断溢出时误差不超过scale/2。矩阵输出误差还会受输入幅值和累加影响。权重最大误差很小，不自动意味着所有任务无损；有些敏感logit间隔很小，少量变化足够改分支。

## 4. 把实验分成三个层级

第一层是算子：固定输入张量，对比高精度参考与量化/替代Kernel输出，测绝对误差、相对误差、均方误差以及极端值。第二层是模型：固定token输入，teacher forcing下对齐每个位置logits、top-k集合、KL或选定logprob；必要时逐层捕获激活定位第一处分歧。第三层是任务：运行完整Agent或benchmark，统计成功率、成本与失败类型。

Teacher forcing意味着两模型始终接收同样的历史token，而不是各自生成历史。它能隔离“一处小变化引发后续输入完全不同”的放大效应。自由生成仍然重要，因为最终用户使用的就是那条链；两种评测回答不同问题，不能互相替代。

对Agent，环境观察也必须控制：文件顺序、时间戳、进程输出、网络内容、工具版本，都可能进入下一轮上下文。模型确定但环境不同，Agent轨迹仍会分叉。可录制工具观察并回放，以区分模型变化与环境变化，但回放不能代表真实交互成功率。

## 5. 实用的分歧定位流程

先固定模型revision、tokenizer、模板、输入token、采样参数和seed；然后固定并行拓扑与后端；确认请求是否经过相同缓存状态；比较prefill最后位置logits；若相同再比较采样；若不同则向前逐层二分定位；最后再放开batch、缓存、并行，观察哪项触发变化。

如果服务不暴露logits，可以先使用token logprob或离线小模型复现；不要假装最终文本diff能够精确定位某个Kernel。保存每次实验的config和输入哈希，避免“昨天测过一样”但实际换了镜像。

框架版本变化可能改算子、融合、通信归约和默认参数，因此升级验证要分“功能正确性、数值差异、性能差异”三张表。只看输出是否完全相同可能过于苛刻；只看任务平均分又可能漏掉严重的局部错误。验收阈值要根据用途定义。

## 6. 量化评测的统计问题

198题的选择题benchmark，一题就改变约0.505个百分点；如果量化差异小于这个量级，单次分数不够细。用配对分析：同一题、同一条件分别跑基线和量化，记录“都对、都错、基线对量化错、基线错量化对”。比只比较两个总准确率更能看清差异发生在哪些题。

多次采样要区分每题平均成功率、pass@k、best-of-k、majority vote，它们不是同一个指标。重复8次后取最好结果，与8次分数平均，不能都叫“测了8次”。对Agent还要固定harness、工具预算、最大步数、环境镜像、网络规则和verifier。

## 7. 练习与参考答案

1. **浮点结合律。** 用NumPy float32复现上文0与1的差异，改float64再用1e16构造同类例子。答案：更高精度扩大准确范围，但不让有限精度获得严格实数结合律。
2. **贪心翻转。** logits基线`[1.0000,0.9999]`，扰动`[-.0001,+.0001]`后第二项变最大。验收说明temperature=0仍会换输出；seed与这个例子无关。
3. **量化误差界。** 给`symmetric_quantize`输入全零。参考实现返回scale=1和全零，避免除0。再测离群值100与小值0.01共享scale时，小值可能量成0，说明per-tensor范围会损伤小量。
4. **batch矩阵。** 同一请求独跑、与短请求同batch、与长请求同batch、改变顺序、缓存冷/热各做一次。先在参考引擎验证全部一致，再在真实框架记录是否一致。出现差异时不直接归因量化，要逐项关掉变量。
5. **teacher-forcing设计。** 对两个模型固定同一token序列，比较每位置目标token的logprob与top1间隔；再自由生成比较文本。参考报告应能出现“logits差异小但轨迹分叉”与“任务答案仍相同”的情况，并解释三者不矛盾。
6. **评测调用链。** 固定一个Terminal-Bench任务，分别记录EvalScope、Harbor、harness、模型端点、verifier负责什么。答案必须指出端点参数是否真的被该harness使用；独立CLI可能有自己的配置。不要在不知道参数落点时宣称量化前后条件一致。

掌握门槛：能分开随机性、浮点不确定性和环境变化；能实现一个量化参考并验证误差；能设计teacher-forcing与自由生成两套实验；能解释为什么一个任务分数不足以定位量化损失。
