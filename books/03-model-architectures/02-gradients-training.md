# M02 损失、梯度与训练：从一次加法走到完整反向传播

模型里有很多浮点数，但“把输入乘上这些数”只解释了前向计算，还没有解释这些数从哪里来。训练要回答的是：怎样根据错误，判断每个参数应该往哪个方向改变、改变多少。本章从一个只有两个参数的模型开始，逐步推到计算图、矩阵反向、softmax 交叉熵、embedding 梯度和优化器。每个公式都要对应一个可观察的数值变化。

先修是 M01 的数组形状和矩阵乘法，以及基础卷的函数、循环和简单代数。你不需要提前修完一门微积分课；本章会给出所需的导数直觉、严格定义和运算规则。但“看过一个导数公式”不等于能使用它：你要用手算、差分和自动微分三条路线核对同一结果。

本章的基础实验包括 `python -m labs.models.run_lab autograd`、`python -m labs.models.run_lab softmax` 和 `python -m labs.models.gradient_trace`。所有核心实验只用 CPU。它们使用极小数据，让每个中间变量都可以打印；训练大模型时同样的规则会作用于更多参数和更复杂的计算图。

## 第一课：先定义我们到底希望模型做对什么

设输入是一个数 x，模型输出 $\hat y=wx+b$。w 控制输入变化时输出变化的幅度，b 控制整体偏移。给定训练样本 $(x,y)$，模型当前预测 $\hat y$ 与目标 y 的差称为误差或残差。我们不能只说“尽量接近”，还需要一个可计算的标量，比较不同参数设置的好坏。

本节使用平方损失 $L=\frac12(\hat y-y)^2$。平方保证正负误差都产生非负代价；前面的二分之一只是让求导后的公式更简洁。损失为零意味着该样本预测恰好等于目标；误差绝对值翻倍，平方损失变成四倍。因此这种目标会相对强调较大的偏差，但它并不适合所有任务和异常值分布。

取 x 等于二，w 等于三，b 等于负一，目标 y 等于四。先算乘法 $wx=6$，再加偏置得到预测五，误差为一，平方损失为二分之一。把 w 改成二点九，预测变成四点八，误差零点八，损失零点三二。这个小改动改善了目标，但我们不希望为每个参数都盲目试很多方向；梯度会提供局部方向信息。

这里必须区分三个东西：目标值 y、预测值 $\hat y$ 和损失 L。目标来自任务定义或训练数据，预测来自当前参数，损失衡量二者差异。模型输出一个“置信度很高”的数字并不自动意味着损失小；如果目标是另一个值，置信越高还可能使某些损失更大。损失函数不是模型自己的解释，而是训练者明确规定的判据。

训练集通常有多个样本。常见做法是对每个样本的损失求平均。若只有一条样本，平均与总和相同；若有八条样本，二者差八倍，梯度也差八倍。比较学习率或训练曲线前，必须确认损失的 reduction 是 sum 还是 mean，以及平均的分母是样本数、有效 token 数还是其他数量。

还要注意训练目标和最终业务能力不是同一个量。降低下一 token 交叉熵，不等于所有问答题都答对；降低某个人工语料上的损失，不证明能处理真实开放问题。本章先学会准确优化一个定义清楚的数学目标，后面的评估章节再讨论这个目标与泛化、校准和任务表现的关系。

## 第二课：导数是局部变化率，不是一个神秘符号

考虑一元函数 $f(w)=w^2$。在 w 等于三附近，把 w 增加一个小量 h，函数变化为 $(3+h)^2-9=6h+h^2$。除以 h，得到每单位输入变化对应的输出变化 $6+h$。当 h 越来越接近零，这个比值接近六，因此导数 $f'(3)=6$。

导数的定义是一个极限：$f'(w)=\lim_{h\to0}[f(w+h)-f(w)]/h$，在极限存在时成立。你可以先把它理解为“在当前点附近，函数最像哪条直线”。局部近似写为 $f(w+\Delta w)\approx f(w)+f'(w)\Delta w$。导数乘一个小改动，给出函数变化的一阶估计；改动过大时，忽略的高阶部分可能很明显。

还是 $w^2$。在三处，导数为六。若 $\Delta w=0.01$，一阶预测函数增加零点零六；真实增加为零点零六零一，差别只有零点零零零一。若 $\Delta w=2$，一阶预测增加十二，真实增加十六，误差已经不能忽略。因此梯度提供局部方向，并不保证任意大的步长都改善目标。

导数的符号有直接意义。正导数表示在当前位置向右小移，函数通常上升；负导数表示向右小移，函数通常下降；导数为零表示一阶变化消失，但不自动代表最小值。函数 $w^3$ 在零处导数为零，零却不是局部最小值。即使找到了损失梯度为零的点，也需要结合函数形状和任务判断。

我们只需先掌握几条常用规则。常数的导数是零，因为输入改变时它不变；w 的导数是一；$w^n$ 的导数为 $nw^{n-1}$；两项相加的导数等于各自导数相加；常数乘函数时，导数同样乘该常数。指数函数 $\exp(w)$ 的导数仍是 $\exp(w)$，自然对数 $\log(w)$ 的导数为 $1/w$，后者要求正输入。

不要把符号 $dL/dw$ 当成两个独立数字“dL 除 dw”随意计算。它表示损失相对参数的导数。在一些推导中，微分符号可以按严格规则组合，但初学时最稳妥的方式是将它读成“改变 w 一点时，L 在当前点怎样变”。这样遇到复杂下标，也不容易忘记究竟对谁求导。

## 第三课：多个参数时，梯度把每个方向的局部变化放在一起

模型通常不只有一个参数。对 $L(w,b)$，我们可以固定 b，只改变 w，得到偏导数 $\partial L/\partial w$；也可以固定 w，只改变 b，得到 $\partial L/\partial b$。把所有参数的偏导按固定顺序放到一起，就得到梯度向量。梯度的每个位置必须与对应参数位置一一匹配。

回到 $\hat y=wx+b$、$L=\frac12(\hat y-y)^2$。令误差 $e=\hat y-y$。改变预测 $\hat y$ 时，损失的导数是 e；改变 w 时，预测的导数是 x；改变 b 时，预测的导数是一。所以 $\partial L/\partial w=ex$，$\partial L/\partial b=e$。后面会用链式法则严格解释这种相乘。

代入 x 为二、w 为三、b 为负一、y 为四，误差为一，得到 w 梯度二、b 梯度一。若 w 减少零点零一，b 保持不变，损失的一阶变化约为负零点零二；若 b 减少零点零一，w 不变，损失的一阶变化约为负零点零一。两个梯度的单位不同，不能仅按数值大小断言哪个参数“更重要”。

若两个参数同时改变，一阶变化为 $\Delta L\approx (\partial L/\partial w)\Delta w+(\partial L/\partial b)\Delta b$。这就是梯度与参数改变量的点积。选择改变量与负梯度同方向，会让这个一阶点积非正，因此产生梯度下降的基本规则。这里的结论仍然局限于足够小的局部变化，步长过大可能越过低点。

梯度与参数拥有相同形状。标量参数对应标量梯度，矩阵参数对应同形状矩阵梯度。矩阵的第 i 行第 j 列梯度，表示只改变那个参数元素时，损失的局部变化率。所谓“对一个矩阵求导”，不需要想象一种完全不同的数学对象；可以先理解为对每个元素分别求偏导，再按原形状组织起来。

输入也可以有梯度。对于当前例子，$\partial L/\partial x=ew$，等于三。训练时我们通常更新参数而不更新普通训练数据，但输入梯度仍有用途，例如向更早一层传播、研究敏感性或优化某些可学习输入。一个变量有没有梯度与它是否会被优化器更新，是两个不同决定。

## 第四课：链式法则为什么要沿路径相乘、在分叉处相加

把一次计算拆成小步骤：$u=wx$，$v=u+b$，$e=v-y$，$L=\frac12e^2$。从输入到输出的顺序称为前向；从最终损失向前面变量计算影响，称为反向。反向时每个小操作只需知道自己的局部导数，再乘从后面传来的梯度。

对一个简单嵌套函数 $L=g(v)$、$v=f(w)$，链式法则给出 $dL/dw=(dL/dv)(dv/dw)$。直观上，w 的微小变化先使 v 改变，再由 v 的变化使 L 改变。第一段的放大率和第二段的放大率相乘，就是整条路径的放大率。这个解释比只记一个分式公式更容易迁移到多层网络。

在我们的数值例中，损失对误差的局部导数为一；误差对 v 的导数为一；v 对 u 的导数为一；u 对 w 的导数为 x，也就是二。整条路径相乘，得到 w 梯度二。u 对 x 的导数为 w，也就是三，所以 x 梯度三。v 对 b 的导数为一，因此 b 梯度一。

分叉时为什么相加？考虑 $f(x)=x^2+x$。x 通过平方路径影响结果，也通过直接相加路径影响结果。第一条路径贡献 $2x$，第二条贡献一，总导数为 $2x+1$。在 x 等于二时，梯度为五。若自动微分只保存最后一条路径的贡献，就可能错误得到一或四。

再考虑 $f(x)=x\cdot x$。虽然写成一个乘法，但乘法的两个输入都引用同一个 x。对左输入的局部导数是右边 x，对右输入的局部导数是左边 x；两项都要累加到同一个变量。因此总梯度是 $x+x=2x$。不能因为两个输入是同一个对象，就只执行一次贡献更新。

这就是反向代码常用 `+=` 而不是 `=` 的原因。梯度是来自所有使用路径的贡献总和。如果一个参数被多个 token、多个层调用位置或多个损失项使用，反向传播都必须把这些贡献累积。参数共享不仅节省存储，也明确改变了梯度汇总的位置。

你可以在纸上给每条边标出局部导数，再从损失节点向后走。每经过一条边乘其导数；若多条路径汇合到同一个节点，就把贡献相加。对于本章的小图，这种方法完全可操作；对于数十亿参数网络，自动微分系统做的仍是这种组织工作，只是用高效的向量化运算处理巨大数组。

## 第五课：计算图是实际执行出来的依赖关系

计算图中的节点表示中间值或参数，边表示一个值如何依赖另一个值。它不是仅仅把源代码画成流程图。源代码里一个循环可能执行多次，每次建立不同中间值；同一对象可能被多条路径引用；条件分支只会执行实际走到的那一支。动态图自动微分通常记录当前这次执行产生的依赖。

例如 `a = x * x; b = a + x`，图中有 x、a、b 三个主要值，a 的两个输入都指向 x，b 的输入是 a 和 x。反向传播需要先处理 b，再处理 a，最后得到 x 的完整梯度。若先处理 a，当时来自 b 的梯度还没传到 a，就会使用不完整信息。这说明反向顺序不是随意遍历。

拓扑排序提供了一个合适顺序：每个节点都排在其依赖之后。反向时倒着遍历，这样一个节点的所有下游使用者都会先完成梯度贡献，随后才将累计梯度传给它的上游。只要图是有向无环的，这种顺序就能建立。普通前向计算形成的对象依赖通常符合这一条件；递归或循环在展开成有限次执行后仍可以形成有限计算图。

为什么要记录已访问集合？因为共享节点可能从多条路径被递归访问。拓扑列表中每个节点只需出现一次，否则它的 backward 可能被重复执行，导致梯度过大。但节点内部对多个输入位置的贡献仍然要分别累加。这里“节点只处理一次”和“共享输入收到多次贡献”并不冲突，它们对应不同层次。

每次新的 backward 是否清空梯度，要看接口定义。本卷标量 Value 的 backward 先将本图所有节点梯度置零，再把根节点梯度设为一；许多深度学习框架则默认累积参数梯度，需要训练循环显式清零。读代码时不能把某个框架的行为想当然地套到另一份实现。

根节点的梯度为什么设为一？因为我们想计算最终标量损失对各节点的导数，而损失对自身的导数是一。如果输出不是标量，就需要指定一个上游向量，计算向量—雅可比乘积，或先把输出组合成标量目标。自动微分不凭空知道你希望如何综合多个输出。

## 第六课：亲手实现标量自动微分，并解释每一段责任

下面是一个完整、可运行的最小实现。它支持加法、乘法和 tanh。代码规模小，适合把每个字段与计算图对应起来；它不处理广播、设备、复杂 dtype、稀疏张量、原地修改版本或高阶导数，因此不能当成生产框架替代品。

```python
import math

class Scalar:
    def __init__(self, data, parents=()):
        self.data = float(data)
        self.grad = 0.0
        self.parents = tuple(parents)
        self.backward_local = lambda: None

    def __add__(self, other):
        other = other if isinstance(other, Scalar) else Scalar(other)
        out = Scalar(self.data + other.data, (self, other))
        def backward():
            self.grad += out.grad
            other.grad += out.grad
        out.backward_local = backward
        return out

    __radd__ = __add__

    def __mul__(self, other):
        other = other if isinstance(other, Scalar) else Scalar(other)
        out = Scalar(self.data * other.data, (self, other))
        def backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out.backward_local = backward
        return out

    __rmul__ = __mul__

    def tanh(self):
        t = math.tanh(self.data)
        out = Scalar(t, (self,))
        def backward():
            self.grad += (1.0 - t * t) * out.grad
        out.backward_local = backward
        return out

    def backward(self):
        order, seen = [], set()
        def visit(node):
            if node in seen:
                return
            seen.add(node)
            for parent in node.parents:
                visit(parent)
            order.append(node)
        visit(self)
        for node in order:
            node.grad = 0.0
        self.grad = 1.0
        for node in reversed(order):
            node.backward_local()

x = Scalar(2.0)
f = x * x + x
f.backward()
assert f.data == 6.0
assert x.grad == 5.0
```

`data` 是前向数值，`grad` 是当前反向计算累计的梯度，`parents` 保存这个值依赖哪些节点。它们不能互相替代：把 grad 写进 data 会破坏前向结果；只保存父节点而不保存如何求局部导数，也无法完成反向。小实现用一个闭包 `backward_local` 保存当前操作的局部反向逻辑。

加法的局部导数都是一，所以两个输入各自收到 out.grad。乘法则不同：左输入收到右输入的前向值乘 out.grad，右输入收到左输入的前向值乘 out.grad。这是为什么某些反向操作需要保存前向中间结果。若你在 backward 之前原地修改了父节点的 data，闭包读到的可能不是当时前向使用的值，梯度便失去对应关系。

tanh 的导数为 $1-\tanh^2(x)$。代码已经在前向得到 t，所以反向直接使用 $1-t^2$，不必重新计算 tanh。这个选择只是一个小例子：框架会在“保存中间结果占内存”和“反向重新计算花算力”之间取舍。激活检查点技术就是围绕这种取舍组织更大的计算段。

`__radd__` 和 `__rmul__` 使普通数字位于左侧时也能参与运算，例如 `2 * x`。它们不改变数学，只完善 Python 运算协议。类型检查把普通数字包装成 Scalar，让后面的代码统一处理节点。常数节点也可以收到梯度，但如果优化器不更新它们，它们仍然作为固定数值使用。

这个实现的身份判断使用对象本身，不是根据 data 是否相等。两个数值都为二的 Scalar 可以是两个独立参数，不应因为值相同就合并节点；同一个 Scalar 被重复使用，即使经过不同变量名引用，也必须累加到同一梯度。图的共享关系由对象身份决定，而不是由显示数值决定。

可以制造一个故障：将乘法 backward 中的 `+=` 改为 `=`，再计算 `x*x`。正确梯度是四，错误实现可能只保留两。再制造另一个故障：把拓扑遍历的 reversed 去掉，某些多层图的梯度会变成零或不完整。一个好的学习实验必须有能让错误版本失败的输入，而不是只跑一条恰好避开共享路径的直线图。

## 第七课：非线性激活怎样改变梯度流动

如果每一层都只是线性变换，多个层相乘仍然可以合并为一个线性变换。加入非线性激活，才能表达更丰富的输入输出关系。非线性不仅改变前向形状，也改变反向时哪些信息能通过、哪些区域会缩小或放大梯度。

ReLU 定义为 $\max(0,x)$。当 x 大于零时导数为一，当 x 小于零时导数为零；在零点不可微，工程实现通常选择某个约定值，常见为零。这里不能把“零处选择零”说成数学上唯一的导数，因为严格导数不存在。测试差分时如果正好跨过这个拐点，解析约定与对称差分可能不同，并不自动说明实现错误。

tanh 的输出位于负一到一之间，导数为 $1-\tanh^2(x)$。当输入很大或很小时，输出接近边界，导数接近零，称为饱和。若多层连续乘上很小的局部导数，上游梯度可能变得很小。梯度消失不是某个单独数字“消失”，而是链式乘积在深层传播中逐渐缩小。

sigmoid 定义为 $1/(1+\exp(-x))$，导数为 $\sigma(x)(1-\sigma(x))$。在零处输出二分之一，导数四分之一；在远离零的饱和区域，导数更小。SiLU 则是 $x\sigma(x)$，需要乘积法则，导数为 $\sigma(x)+x\sigma(x)(1-\sigma(x))$。不能把 SiLU 的导数误写成 sigmoid 的导数，因为前面还有一个 x 因子。

梯度爆炸同样来自链式传播。若某条长路径反复乘上大于一的有效放大率，梯度可能快速增大。真实网络还有矩阵方向、归一化、残差和不同路径，不能只用“层数越多必然爆炸”概括。但小标量链能帮助理解为何初始化尺度、归一化、残差和梯度裁剪会影响训练稳定性。

残差连接 $y=x+f(x)$ 的局部导数包含一条直接路径：$dy/dx=I+J_f$。这并不保证梯度永远稳定，因为 $J_f$ 可以复杂地放大或抵消，但它提供了一条不必穿过 f 内部所有操作的路径。后面的 Transformer 章节会从这个角度重新解释残差，而不只把它叫作“把输入加回来”。

## 第八课：矩阵乘法的反向传播从下标推出来

设 X 的形状为 $[N,D]$，W 的形状为 $[D,F]$，Y 等于 XW，形状为 $[N,F]$。单个输出元素 $Y_{nf}=\sum_d X_{nd}W_{df}$。假设从后面收到 G，定义为 $\partial L/\partial Y$，它与 Y 同形状。目标是求 $\partial L/\partial X$ 和 $\partial L/\partial W$。

固定一个 $X_{nd}$，它影响同一行的所有 $Y_{nf}$。每条路径的局部导数是 $W_{df}$，因此 $\partial L/\partial X_{nd}=\sum_f G_{nf}W_{df}$。这正是 $GW^\top$ 的第 n 行第 d 列，所以 $dX=GW^\top$。形状核对为 $[N,F]\times[F,D]=[N,D]$，与 X 一致。

固定一个 $W_{df}$，它被所有样本行共享，因此影响每个 $Y_{nf}$。贡献为 $X_{nd}G_{nf}$，对 n 求和，得到 $dW=X^\top G$。形状核对为 $[D,N]\times[N,F]=[D,F]$，与 W 一致。这里沿样本轴求和，直接来自同一参数被多行使用，而不是随意选择一个轴。

取 $X=[[1,2],[3,4]]$，$W=[[2,-1],[0,1]]$。前向 Y 为 $[[2,1],[6,1]]$。假设上游 G 为 $[[1,2],[3,4]]$。则 $dW=[[10,14],[14,20]]$：左上元素是一乘一加三乘三等于十；右上元素是一乘二加三乘四等于十四；左下元素二乘一加四乘三等于十四；右下元素二乘二加四乘四等于二十。

输入梯度 $dX=GW^\top$ 为 $[[0,2],[2,4]]$。例如第一行第一项是一乘二加二乘负一等于零；第二项是一乘零加二乘一等于二。这里某个梯度为零可能来自不同路径抵消，不表示该输入完全没有参与前向。观察一个零梯度时，要区分没有依赖、局部饱和、路径抵消和数值下溢。

```python
import numpy as np

X = np.array([[1., 2.], [3., 4.]])
W = np.array([[2., -1.], [0., 1.]])
G = np.array([[1., 2.], [3., 4.]])
Y = X @ W
dX = G @ W.T
dW = X.T @ G
np.testing.assert_allclose(Y, [[2, 1], [6, 1]])
np.testing.assert_allclose(dX, [[0, 2], [2, 4]])
np.testing.assert_allclose(dW, [[10, 14], [14, 20]])
```

若前向还有广播偏置 $\mathbf b$，每一行都加同一个 b，那么 $db=\sum_n G_{n,:}$。本例为 $[4,6]$。广播反向的一般原则是：前向被复制使用的轴，在反向把对应贡献求和收回。保持维度有时只是实现便利，最终梯度形状必须与原始参数形状一致。

对于更高维输入，线性层往往保留所有前导轴，只变换最后一轴。计算权重梯度时，需要对所有使用同一权重的位置求和，包括 batch 和时间轴。可以先把 $[B,T,D]$ 展平成 $[B\cdot T,D]$，按二维公式理解，再恢复输入梯度形状。这种展平是合并样本位置，不是改变每个位置的特征顺序。

## 第九课：softmax 把分数变成分布，但反向不能逐元素各算各的

给定实数分数 $z_1,\ldots,z_V$，softmax 定义 $p_i=\exp(z_i)/\sum_j\exp(z_j)$。每个输出非负，总和为一，因此可以作为一个离散分布。所有输出共同使用同一个分母，所以改变一个分数会影响所有概率。不能把 softmax 当成对每个元素独立应用的 sigmoid。

取分数 $[0,\log2,\log3]$。指数为一、二、三，总和六，概率为 $[1/6,1/3,1/2]$。如果把第二个分数提高，第二项指数变大，不仅第二项概率上升，其他两项概率也会下降，因为分母变大。这个耦合关系正体现在它的雅可比矩阵中。

对 i 与 j 不同的情况，$\partial p_i/\partial z_j=-p_ip_j$；对相同位置，$\partial p_i/\partial z_i=p_i(1-p_i)$。合起来写成 $p_i(\delta_{ij}-p_j)$，其中 $\delta_{ij}$ 在 i 等于 j 时为一，否则为零。这里不是要求你背下所有矩阵元素，而是理解“自己上升、其他项因归一化受到挤压”。

若已知上游梯度 g，也就是 $\partial L/\partial p$，不必真的构造一个 V 乘 V 的雅可比矩阵。利用公式可以得到 $dZ=p\odot(g-\sum_i g_ip_i)$。先算 g 与 p 的加权内积，再从每个 g 元素中减去这个标量，最后逐元素乘 p。复杂度与存储都比显式建立完整雅可比更好。

softmax 对所有分数同时加常数保持不变。因为分子与分母都乘同一个指数因子，最终比例抵消。因此我们可以先减去最大值，提高数值稳定性。这个操作不改变数学定义，却能避免对很大的正数直接取指数。训练中的稳定实现必须利用这类等价变换，而不是等到 NaN 出现后再随便替换成零。

全掩码行是额外契约。若所有分数都设为负无穷，直接套“减最大值”会出现负无穷减负无穷，得到 NaN。本卷 softmax 约定这种行返回全零，表示没有有效读取位置；它不是一个总和为一的普通概率分布。使用这个输出的上层代码必须知道这个边界，不能将全零行当成正常分类分布参与对数损失。

## 第十课：交叉熵为什么产生 p 减目标的梯度

对一个正确类别 y，负对数似然损失为 $L=-\log p_y$。如果正确类别概率接近一，损失接近零；如果概率很小，损失很大。它不是简单看 argmax 是否正确：两个模型都选对类别，一个给正确类别零点五一，另一个给零点九九，负对数似然会区分二者的置信分布。

将 softmax 代入，$L=\log\sum_j\exp(z_j)-z_y$。第一项对 $z_i$ 的导数是 $p_i$，第二项在 i 等于 y 时导数为一，否则为零。所以 $dL/dz_i=p_i-\mathbf1[i=y]$。这是分类和语言模型训练中最常见的梯度形式之一，但它来自完整归一化与对数目标，不是一个可以套到任意损失的口诀。

使用上一课分布 $[1/6,1/3,1/2]$，如果目标是编号一，也就是概率三分之一的类别，损失为 $\log3$，约一点零九八六。梯度为 $[1/6,-2/3,1/2]$。梯度下降会降低第零和第二个分数，提高目标分数。三个梯度相加为零，这与 softmax 对共同平移不敏感相一致。

如果目标改成编号二，损失变成 $\log2$，梯度为 $[1/6,1/3,-1/2]$。输入分数完全没有改变，目标一变，更新方向就变了。因此训练数据中的标签错误会直接推动模型学习错误方向；损失下降只能说明模型更符合给定标签，不能自动证明标签正确。

对多个样本取平均后，梯度也要除以样本数。若 logits 是 $[N,V]$，目标是长度 N 的整数数组，每行减去对应 one-hot，再除以 N。语言模型常把 batch 与时间位置展平成 N，但只有真正参与损失的位置才应计入分母。把填充位置也计进去，会改变有效梯度尺度。

```python
def cross_entropy_with_grad(logits, targets):
    logits = np.asarray(logits, dtype=np.float64)
    targets = np.asarray(targets, dtype=np.int64)
    if logits.ndim != 2 or targets.shape != (len(logits),) or len(logits) == 0:
        raise ValueError("nonempty [N,V] logits and [N] targets required")
    if not np.isfinite(logits).all():
        raise ValueError("finite logits required")
    if np.any(targets < 0) or np.any(targets >= logits.shape[1]):
        raise ValueError("target outside vocabulary")
    shifted = logits - logits.max(axis=1, keepdims=True)
    exp_values = np.exp(shifted)
    denom = exp_values.sum(axis=1, keepdims=True)
    probs = exp_values / denom
    log_z = np.log(denom[:, 0])
    loss = np.mean(log_z - shifted[np.arange(len(targets)), targets])
    grad = probs.copy()
    grad[np.arange(len(targets)), targets] -= 1.0
    return float(loss), grad / len(targets)

z = np.array([[0., np.log(2.), np.log(3.)]])
loss, grad = cross_entropy_with_grad(z, [1])
np.testing.assert_allclose(loss, np.log(3.))
np.testing.assert_allclose(grad, [[1/6, -2/3, 1/2]])
```

代码没有先求一个可能下溢为零的概率再取对数，而是直接用稳定的 log-sum-exp 形式计算损失。例如目标类别分数远低于最大值时，softmax 概率在有限精度下可能变成零，但对应的有限 logits 仍能产生有限且很大的损失。直接写 `-log(probs[target])` 在这种情况下会丢失本来可表示的信息。

这里使用自然对数，因此损失单位为 nats。若改用以二为底的对数，数值会按常数因子缩放。语言模型困惑度通常与平均负对数似然通过指数关系相连，但跨 tokenizer 比较每 token 损失要谨慎，因为 token 单位不同。不能把不同切分方案的两个损失数字直接当作同一尺度上的能力排名。

## 第十一课：embedding、广播、求和和重复索引的反向

embedding 前向从参数表中选行。若某个 ID 在多个位置出现，这些位置对同一参数行的梯度必须相加。假设词表三项、每项二维，输入 IDs 为 $[1,1,2]$，上游梯度依次为 $[1,2]$、$[3,4]$、$[5,6]$。那么 embedding 梯度第零行为零，第一行为 $[4,6]$，第二行为 $[5,6]$。

```python
ids = np.array([1, 1, 2])
upstream = np.array([[1., 2.], [3., 4.], [5., 6.]])
dE = np.zeros((3, 2))
np.add.at(dE, ids, upstream)
np.testing.assert_array_equal(dE, [[0, 0], [4, 6], [5, 6]])
```

不能想当然地使用 `dE[ids] += upstream` 代替 `np.add.at`。高级索引可能先取出临时数组，再把结果写回；重复索引的累加语义并不等同于逐次原地相加。最可靠的理解方式是先写普通循环 `for i, token_id in enumerate(ids): dE[token_id] += upstream[i]`，再确认所选向量化 API 保持同样语义。

广播的反向与重复索引类似，都是把多处使用的贡献汇总回共享来源。前向把一个 $[D]$ 偏置加到 $[B,T,D]$ 的每个位置，反向就沿 B 和 T 求和。若前向把一个标量乘到所有元素，标量梯度需要把所有对应贡献求和。很多“梯度 shape 对不上”的错误，本质是忘记把广播扩展过的轴收回。

求和操作的反向则把上游梯度分发给所有被求和的元素。若 $s=x_1+x_2+x_3$，上游梯度为七，那么每个 x 都收到七。均值会再除以元素数量。不能因为前向用了一个标量输出，就把反向也缩成一个标量而丢失每个输入位置的对应梯度。

reshape 的反向按原形状重新解释梯度；transpose 的反向使用逆轴排列。前向将 $[T,H,d]$ 转成 $[H,T,d]$，反向再换回原顺序。数学上这些操作只是重排元素，但实现时必须保持每个元素的身份。一个总元素数正确的 reshape 并不能修复错误的轴排列。

切片的反向是 scatter 回原始位置，未被读取的位置通常得到零梯度。若切片包含重复索引，仍然需要累加。padding 位置是否得到梯度取决于实际图中它被怎样使用，不能仅凭它叫“pad”就自动消失。损失 mask、attention mask 和 embedding 的特殊处理应分别检查。

## 第十二课：梯度下降、动量和 Adam 分别在记录什么

最简单的更新是 $\theta_{t+1}=\theta_t-\eta g_t$，其中 $g_t$ 是当前梯度，$\eta$ 是学习率。学习率不是参数的“改变百分比”，而是把梯度转换成参数改变量的系数。梯度单位、损失缩放和参数尺度都会影响合适的步长，因此不能只把一个项目的学习率复制到另一个项目。

对于平方函数 $L(w)=\frac12w^2$，梯度为 w。若学习率为零点一，每步变成旧值的零点九倍，逐渐接近零；若学习率为一，一步到零；若学习率为二，w 在正负之间等幅振荡；若学习率大于二，绝对值会扩大。这是一个精确可算的例子，说明正确梯度加错误步长仍可能发散。

动量在更新中保留过去梯度的平滑信息。一个常见形式是 $m_t=\beta m_{t-1}+(1-\beta)g_t$，再用 m 更新参数。它可以降低某些方向的短期抖动，也会使方向改变后保留惯性。不同实现可能把 $1-\beta$ 放在不同位置，数值尺度因此不同；读配置时要同时看公式和代码。

Adam 同时维护梯度的一阶指数平均 m 和平方梯度的指数平均 v，再用偏差修正后的 $\hat m/(\sqrt{\hat v}+\epsilon)$ 更新。平方梯度统计反映每个坐标近期梯度大小，而不是梯度方差的无偏估计。不要把 v 直接叫作“真实方差”，因为公式与样本方差不同。

第一步的数值可以手算。设梯度为零点二，$\beta_1=0.9$、$\beta_2=0.999$，初始 m、v 都为零。新 m 为零点零二，新 v 为零点零零零零四。除以偏差修正因子零点一和零点零零一后，$\hat m=0.2$、$\hat v=0.04$。忽略很小的 epsilon，更新方向的归一化值约为一，所以学习率零点一会使参数减少约零点一。

这不表示 Adam 永远每步只走学习率大小。后续梯度历史、符号变化、epsilon、不同坐标和权重衰减都会影响结果。第一步例子只是解释偏差修正为什么存在：零初始化的滑动平均在早期偏向零，需要按累计权重补偿。若恢复训练时只恢复模型参数而不恢复 m、v 和步数，后续更新不等于原训练的连续执行。

L2 正则化和解耦权重衰减也要区分。向损失加入 $\lambda\|\theta\|^2/2$ 会向梯度增加 $\lambda\theta$；在普通 SGD 中，它与某种参数衰减形式紧密相关。但经过自适应预条件后，把这个项混入梯度和在更新外单独衰减参数并不普遍等价。AdamW 的“W”涉及这种解耦，不能只把它理解为 Adam 换了名字。

## 第十三课：梯度累积、裁剪和训练模式的边界

显存不够时，可以把一个较大的 batch 拆成多个 microbatch，累计梯度后统一更新。但想与大 batch 平均损失等价，必须按有效样本或 token 数正确加权。若两个 microbatch 大小分别为二和六，简单平均两者的 mean loss，会让前两个样本权重过大；正确合并要乘各自有效计数再除总数。

梯度累积时通常每个 microbatch 都执行 backward，但只在一组结束后执行 optimizer.step。清零应在开始新组时进行，而不是每个 microbatch 之前都把历史贡献清掉。另一方面，也不能忘记在下一组开始前清零，否则不同优化步的梯度会无限混在一起。代码中的三个动作——前向、反向、更新——应分别追踪。

全局范数裁剪先把所有参数梯度看成一个长向量，计算其二范数。如果范数超过阈值 C，就把所有梯度乘同一个系数 $C/\|g\|$。例如梯度 $[3,4]$ 的范数为五，阈值二时，结果为 $[1.2,1.6]$。方向保持不变，长度变为二。逐元素截断则会得到不同方向，二者不是同一操作。

裁剪能限制一次更新前的梯度规模，但不能修复错误标签、NaN、错误的损失归一化或代码 bug。若梯度已包含非有限数，范数和缩放也可能非有限。训练日志应该分别记录损失、梯度范数、是否裁剪和非有限检查，不能把“裁剪后没崩溃”当成训练正确的证明。

训练模式与是否记录梯度也不是同一开关。在常见框架里，train/eval 改变 dropout、某些归一化层等模块行为；no_grad 或相应上下文控制是否构建反向图。一个模型可以处于 eval 模式但仍计算梯度，也可以处于 train 模式而不记录梯度。具体接口应查框架文档，但概念上要把“模块行为”和“微分记录”分开。

本卷 NumPy 参考没有 dropout，也不自动区分 train/eval；PyTorch 小项目则显式切换模式并使用 no_grad 做评估。不要因为两个实现都叫 forward，就假定它们保存了相同状态、使用了相同随机性。比较训练曲线或前向结果之前，要固定这些条件。

## 第十四课：用有限差分检查梯度，知道它什么时候会误导

自动微分给出的梯度也可能因为实现错误而不正确。有限差分提供一条独立检查路线：在参数某个位置分别加上和减去一个小量 h，计算两次损失，用 $[L(\theta+h)-L(\theta-h)]/(2h)$ 近似导数。它不需要知道反向公式，所以能发现解析梯度中的漏项、转置错误和重复索引问题。

```python
def numerical_gradient(fn, array, h=1e-5):
    work = np.array(array, dtype=np.float64, copy=True)
    grad = np.zeros_like(work)
    for index in np.ndindex(work.shape):
        old = work[index]
        work[index] = old + h
        plus = float(fn(work))
        work[index] = old - h
        minus = float(fn(work))
        work[index] = old
        grad[index] = (plus - minus) / (2 * h)
    return grad

numeric = numerical_gradient(lambda w: np.sum((X @ w) * G), W)
np.testing.assert_allclose(numeric, dW, rtol=1e-6, atol=1e-7)
```

h 太大时，局部曲率产生明显截断误差；h 太小时，两次几乎相等的浮点结果相减会丢失有效数字，舍入误差反而变大。没有一个 h 对所有 dtype、参数尺度和函数都完美。使用 float64、小规模输入，并尝试几个 h 值，通常比固定一个极小数然后盲目相信结果更可靠。

绝对误差和相对误差需要一起看。若真实梯度接近零，相对误差分母很小，数值可能显得巨大；若梯度规模很大，只有绝对误差又可能不公平。常见比较会同时给 atol 与 rtol。你还应该打印最大误差对应的参数名和索引，而不是只报告一个整体 PASS。

有随机性的函数必须控制随机状态。若两次损失计算使用不同 dropout mask、不同数据抽样或不同增强，差值就不再只来自参数扰动。先关闭随机性或固定同一随机状态，再做梯度检查。否则你会把随机噪声误认为导数，而自动微分可能反而是正确的。

不可微点也需要单独处理。ReLU 的零点、top-k 选择边界、argmax 和硬阈值都可能让对称差分与某个局部梯度约定不同。不要简单扩大容差掩盖问题；应该说明当前点是否可微，测试是否跨过分支边界，训练实际采用了什么约定。MoE 的硬路由章节会再次用到这个判断。

梯度检查很昂贵。若有 P 个参数元素，逐元素差分要约两 P 次前向，所以只适合小模型、少量参数或随机方向检查。它的角色是建立正确性证据，不是代替训练中的反向传播。先在极小模型上把每条路径验清，再扩大规模，比在巨大模型上发现损失不下降后盲目调参更有效。

## 第十五课：一次完整训练步的手算与可运行代码

我们用三个样本训练直线 $y=2x+1$。输入为负一、零、一，目标为负一、一、三。模型仍是 $wx+b$，初始 w、b 都为零，损失使用平均半平方误差。第一步预测全零，误差为一、负一、负三；损失为 $(1+1+9)/(2\cdot3)=11/6$。

w 梯度是误差乘输入的平均：$[1\cdot(-1)+(-1)\cdot0+(-3)\cdot1]/3=-4/3$。b 梯度是误差平均：$(1-1-3)/3=-1$。使用学习率零点一后，w 变成 $2/15$，约零点一三三三；b 变成零点一。你应该先在纸上得到这两个数，再运行程序。

```python
xs = np.array([-1., 0., 1.])
ys = 2 * xs + 1
w, b = 0.0, 0.0
history = []
for step in range(200):
    prediction = w * xs + b
    error = prediction - ys
    loss = 0.5 * np.mean(error * error)
    dw = np.mean(error * xs)
    db = np.mean(error)
    history.append((loss, w, b, dw, db))
    w -= 0.1 * dw
    b -= 0.1 * db

np.testing.assert_allclose(history[0][0], 11/6)
np.testing.assert_allclose(history[0][3], -4/3)
np.testing.assert_allclose(history[0][4], -1)
assert history[-1][0] < history[0][0]
np.testing.assert_allclose([w, b], [2., 1.], atol=1e-5)
```

这段代码清楚分开了前向、损失、梯度和更新。history 在更新前保存当前参数和梯度，因此第零条记录对应初始模型。如果你把记录放在更新后却仍打印旧损失，就会把不同时间点的数据放在同一行，造成错误分析。训练日志的时间语义也必须明确。

为什么同时计算 dw、db 后再更新？如果先更新 w，再用新 w 重新计算 db，而其他项仍使用旧前向，就变成另一种算法，不再是对同一损失点的标准同步梯度下降。在这个线性例子里也许仍会收敛，但不能用“结果差不多”掩盖实现定义的改变。神经网络中混用不同参数版本会更难诊断。

验证集应该用于观察泛化，而不是参与每一步梯度更新。这个小例子只有确定性直线，难以展示真实过拟合；你可以添加噪声、减少训练点、改用高次多项式，再观察训练损失和独立测试误差的差别。但要明确数据生成规则，不能把随机噪声样本上的偶然结果包装成普遍结论。

训练停止也需要明确判据。固定步数可用于可复现实验；基于验证集的早停则需要定义指标、耐心值、改进阈值和最佳参数保存。看到一两步损失上升，不一定意味着训练失败，尤其在随机 mini-batch 下；但连续非有限值、梯度全零或固定 batch 无法过拟合，都值得优先检查实现。

### 15.1 把一条两层网络的反向完全展开

现在把单直线升级为两层网络，以免你只会对一个标量求导。输入是一个样本的两个特征 $[1,2]$。第一层权重为 $[[1,-1],[1,1]]$，偏置全零。输入乘第一层权重得到 $[3,1]$，两项都为正，因此 ReLU 后仍是 $[3,1]$。第二层权重取二阶单位矩阵，偏置仍为零，所以两个类别的 logits 为 $[3,1]$。

目标是第二个类别，即编号一。为了稳定求 softmax，减去最大值三，得到 $[0,-2]$。指数为一和约零点一三五三三五，分母约一点一三五三三五。概率为约零点八八零七九七和零点一一九二零三。目标概率很低，所以损失约二点一二六九二八。这个数比随机均匀二分类的自然对数损失约零点六九三更大，说明模型不仅预测错，而且偏向错误类别。

从交叉熵传回 logits 的梯度是 $[p_0,p_1-1]$，即约 $[0.880797,-0.880797]$。正的第一项意味着降低第一个 logit 能局部降低损失；负的第二项意味着提高第二个 logit 能局部降低损失。两项相加为零，仍体现共同平移不影响概率的性质。不要把这两个数当成对权重的最终梯度，它们目前只针对 logits。

第二层的输入为 $[3,1]$，所以第二层权重梯度是输入列向量与 logits 梯度行向量的外积。第一行约为 $[2.642391,-2.642391]$，第二行约为 $[0.880797,-0.880797]$。为什么第一行是三倍？因为第一个隐藏特征的当前数值是三，一个权重小改动会被这个输入值放大三倍。第二层偏置则每项直接收到对应 logits 梯度。

隐藏表示梯度等于 logits 梯度乘第二层权重转置。因为当前第二层是单位矩阵，结果仍为 $[0.880797,-0.880797]$。这个相等只是我们为了手算特意选择单位矩阵造成的，不能由此误以为反向总是把梯度原样复制。把第二层改成任意非对角矩阵，隐藏梯度就会混合两个输出方向的贡献。

第一层的 ReLU 输入两项都为正，局部导数为一，所以穿过激活后的梯度不变。如果第一项预激活变成负数，对应局部导数为零，这条路径的梯度会被截断；如果恰好为零，则涉及先前讨论的不可微点约定。本例故意避开零点，使有限差分能够稳定验证普通可微区域的解析结果。

第一层权重梯度再次是外积，但这次使用原输入 $[1,2]$。第一行约为 $[0.880797,-0.880797]$，第二行约为 $[1.761594,-1.761594]$。第一层偏置梯度与激活前梯度相同。输入梯度则要乘第一层权重转置，得到约 $[1.761594,0]$。第二个输入梯度为零来自两条贡献抵消，而不是这个输入没有参与预测。

下面给出完整实现，参数名带层号，避免在同一个公式里把两张权重矩阵混淆。它同时返回损失和所有参数梯度。每个缓存变量都有明确用途：预激活决定 ReLU 导数，隐藏表示用于第二层参数梯度，原输入用于第一层参数梯度。若以后想节省缓存，就必须说明哪些值可以重算。

```python
def two_layer_loss(params, sample, target):
    pre = sample @ params["W1"] + params["b1"]
    hidden = np.maximum(pre, 0.)
    logits = hidden @ params["W2"] + params["b2"]
    loss, dz_batch = cross_entropy_with_grad(logits[None, :], [target])
    dz = dz_batch[0]
    grads = {}
    grads["W2"] = np.outer(hidden, dz)
    grads["b2"] = dz.copy()
    dh = dz @ params["W2"].T
    da = dh * (pre > 0)
    grads["W1"] = np.outer(sample, da)
    grads["b1"] = da.copy()
    dx = da @ params["W1"].T
    return loss, grads, dx

params = {
    "W1": np.array([[1., -1.], [1., 1.]]),
    "b1": np.zeros(2),
    "W2": np.eye(2),
    "b2": np.zeros(2),
}
sample = np.array([1., 2.])
initial_loss, grads, dx = two_layer_loss(params, sample, 1)
np.testing.assert_allclose(initial_loss, np.log1p(np.exp(2.)))
np.testing.assert_allclose(dx[1], 0., atol=1e-12)
for name in params:
    def objective(candidate, name=name):
        changed = dict(params)
        changed[name] = candidate
        return two_layer_loss(changed, sample, 1)[0]
    numeric = numerical_gradient(objective, params[name])
    np.testing.assert_allclose(grads[name], numeric, atol=1e-7, rtol=1e-6)

updated = {name: value - 0.01 * grads[name] for name, value in params.items()}
next_loss = two_layer_loss(updated, sample, 1)[0]
assert next_loss < initial_loss
```

注意差分目标里使用 `dict(params)` 建立新的字典，再替换当前被扰动的参数数组。它没有深复制其他权重，因为目标函数只读取它们，不做原地修改。若你的 forward 会改参数或缓存到共享数组里，这种浅复制就不再安全。梯度检查不仅检验公式，也要求前向函数在重复调用时具有可理解的状态行为。

循环里 `name=name` 把本次参数名绑定到函数默认参数，避免闭包在延迟使用时读到循环结束后的最后一个 name。这里是 Python 语言细节与数值验证的交叉点。你不必一开始就熟悉所有闭包规则，但遇到测试只检查最后一个参数的怪现象，应想到函数捕获的变量是否与你预期相同。

一次小更新使固定样本损失下降，是有用但不充分的检查。若某个错误梯度碰巧也有下降分量，小步仍可能改善损失；因此我们还对每个参数做了独立差分。反过来，正确梯度配上太大学习率也可能让损失上升。要把梯度正确性、更新算法和学习率选择分开验证。

这个两层例子还可以扩成一个三阶段项目。第一阶段保留单样本和两隐藏单元，要求每个梯度都能手算。第二阶段加入多个样本，验证参数梯度沿 batch 求和与 mean 的分母。第三阶段把 ReLU 改成 tanh，并验证相同参数形状下反向公式必须随激活改变。每次只改变一个机制，才能知道哪个测试在检验什么。

### 15.2 训练恢复需要恢复的是一段过程

保存权重能恢复一个前向函数，但未必能恢复原来的训练过程。使用 SGD 且没有动量时，所需状态相对少；使用 Adam 时，还需要一阶平均、二阶平均、步数等优化器状态。若采用学习率调度器，还要恢复调度进度。若在某个 batch 中途保存，梯度累积状态与有效样本计数也可能属于恢复边界。

随机状态同样影响后续训练。参数初始化、样本打乱、dropout、数据增强和采样都可能使用随机数。只保存一个最初 seed，不保证能从中间准确继续，因为随机数生成器已经消耗了很多次。若要恢复同一随机序列，应保存当前生成器状态，或设计可按步数与样本身份重建的确定性方案。

数据读取位置也不能漏。假设权重和优化器都恢复到第一百步，但数据迭代器重新从开头开始，后续看到的样本顺序就与不中断训练不同。对普通教学实验，这也许仍能学习；对精确复现、故障分析或比较算法，它却是实质差异。恢复报告应明确承诺的是“继续训练有效”还是“逐步数值等同于未中断”。

还有一种危险情形是保存文件时只写了一半。读取半个 checkpoint 不应被当成合法模型。常见办法是先写临时文件，确认完整后再原子替换正式路径，并保存必要的结构信息和校验。文件系统的具体原子性条件需要结合部署环境，但概念上要区分“一个文件名出现了”和“完整状态已经可靠保存”。

在本卷的 NumPy 小模型中，保存格式包含参数、配置和字符表，目的是恢复前向与生成。它没有保存完整训练器的全部随机与优化器状态，因此不能把其 load 方法宣传成精确续训。你可以在 M15 的项目中扩展一个训练状态格式，保留原来的简单模型文件作为推理资产，分别测试两种用途。

最直接的恢复验收是分叉实验：路径甲连续训练二十步；路径乙训练十步，保存并重新创建所有对象，再训练十步。若你声称精确恢复，就要比较每一步的 batch、损失、参数和优化器状态，而不只是最终损失大致接近。若只声称功能性恢复，也要证明重载后预测符合保存时的参数，而不是恰好重新训练出一个相似模型。

### 15.3 怎样读一条训练日志，避免把不同问题混在一起

一条有用的日志至少应说明训练步、已处理的有效 token 或样本数、当前学习率、训练损失以及评估的时点。对于本章小模型，还可以记录梯度范数、参数范数和更新范数。每个量都有自己的单位和意义，不能把“loss 下降了”当成唯一观察。

梯度范数很大不一定意味着参数更新很大。Adam 等优化器会按历史统计重新缩放梯度；权重衰减也可能产生不依赖当前数据梯度的变化。因此想知道模型参数实际改变多少，可以比较更新前后参数的差，并计算相对更新比率。这个指标也不是越小越好，而是帮助发现“学习率看着很小，某层却变化异常大”的情况。

训练损失与验证损失的采样方式要一致解释。训练日志可能只记录当前随机 batch，验证日志可能对固定完整数据求平均；两条曲线的波动尺度自然不同。若验证集也每次随机抽少量样本，看到一次上升不能立刻判断过拟合。先写清评估数据和聚合方式，再讨论曲线趋势。

损失突然变小可能来自错误而非进步。例如标签泄漏到输入、目标未右移、损失 mask 把困难位置全部屏蔽、分母错误地越来越大，都会产生好看的数字。对应的诊断是打印实际输入目标、有效位置数量和一个固定样本的逐位置损失。把总损失拆开观察，通常比盲目增加训练步数更有效。

损失一直等于某个常数，也有多种原因。可能参数没有被优化器包含，可能梯度被清零的时机不对，可能 forward 使用了旧参数副本，可能所有输入都被映射成同一个未知 ID。每种情况都能用小检查区分：比较更新前后参数，打印非零梯度数量，追踪参数对象身份，查看输入编码分布。不要把所有现象都归结为模型太小。

数值稳定和语义正确应分别检查。没有 NaN 只能说明运算没有产生明显非有限值；它不能证明标签正确、数据划分合理或梯度对应了预期目标。同样，损失在下降不代表模型没有泄漏验证数据。可靠训练实验需要数学、代码、数据和评价四方面的证据相互支持。

### 15.4 梯度路径与离散选择之间的分界

神经网络里不是每一步都能像矩阵乘法那样平滑求导。把 logits 取 argmax 得到整数 ID，会丢掉大量分数变化信息。某个 logit 小幅变化但没有改变最大项时，选出的 ID 完全不变；跨过最大值边界时，ID 又会突然跳变。因此不能把一个普通整数 token 当成连续变量，期待自动微分直接给出有用的“选词梯度”。

这解释了训练时常直接对完整 logits 计算交叉熵，而不是先选出一个 token，再对这个整数与目标做平方误差。token ID 的数值差本来就没有语义距离，且 argmax 路径的微分性质也不适合这种做法。训练目标应建立在可学习的概率分布或明确的离散优化估计上，不能因为推理最终要选 token，就把推理选择机械插进监督训练损失。

后面的强化学习会处理采样动作与奖励之间的关系，但那不是把环境反馈穿过所有离散步骤直接微分。策略梯度利用动作概率的对数和奖励构造估计，需要说明采样分布、基线、方差和信用分配。这里先建立边界：普通反向传播擅长沿已知可微计算图传递局部导数；外部程序执行、字符串解析或人类评分不会自动变成这样的图。

MoE 的 top-k 也包含离散选择。已选专家的计算和选中权重可以有梯度，但“哪个专家进入集合”在普通硬选择下不是处处平滑变化的。实际训练设计会明确路由概率、辅助损失、负载约束和可能的近似。你在 M08 看到 router 梯度时，应逐项追踪它经过哪些连续路径，而不是把“框架能 backward”理解成所有离散决策都被精确求导。

这项认识也能帮助读源码。某段代码中的 detach、停止梯度或在 no_grad 中计算参考量，通常是在定义优化目标的依赖关系，而不只是为了省内存。去掉这些操作可能使目标函数发生改变，即使前向数值一模一样。比较两个训练实现时，既要比较 forward 的值，也要比较哪些变量被允许影响梯度。


再做一个能区分准确率与损失的两分类实验。目标始终为第一类，模型甲给它零点五一，模型乙给它零点九九。两者贪心预测都正确，准确率相同，但负对数似然明显不同。反过来，如果标签本身标错，过度自信的模型会受到更大损失。因此你应同时理解任务结果和分布质量，而不是只看一个百分比。

最后检查一次更新顺序：先用当前参数完成前向，再由这个损失反向，确认梯度有限，按算法处理裁剪或缩放，然后更新参数，最后为下一次累计清理梯度。某些框架把清理放在前向之前同样可以正确，但关键是它不能擦掉本次尚未使用的梯度，也不能让上一步梯度意外进入下一步。把这几行代码画成时间表，能比记住某个固定模板更准确地理解训练循环。

## 综合练习：十二道完整练习与诊断答案

**练习一：平方损失的完整导数。** 对 x 等于三、w 等于二、b 等于一、目标 y 等于五，写出所有中间值和梯度。答案：乘积六，预测七，误差二，损失二；损失对预测梯度二，对 w 梯度六，对 b 梯度二，对 x 梯度四。若把平方损失定义成没有二分之一的形式，所有这些损失梯度会再乘二，必须与定义保持一致。

**练习二：共享路径。** 用 Scalar 计算 $f=x^3+x^2$，x 等于二。前向结果十二，导数 $3x^2+2x=16$。实现可以写 `x*x*x + x*x`，随后 backward。这个例子同时覆盖一个对象被多次使用和多个中间乘法节点；把局部梯度赋值写成覆盖会失败。

**练习三：实现平方操作。** 为 Scalar 增加 `square` 方法，前向创建 data 的平方，父节点只记录 self，反向向 self.grad 加 `2*self.data*out.grad`。它与 `x*x` 的结果和梯度应相同。下面给出可直接挂到类上的完整函数。

```python
def square(self):
    out = Scalar(self.data * self.data, (self,))
    def backward():
        self.grad += 2 * self.data * out.grad
    out.backward_local = backward
    return out

Scalar.square = square
a = Scalar(3.)
a.square().backward()
assert a.grad == 6.
```

**练习四：tanh 差分。** 在输入零点三处比较 Scalar 的解析梯度与中央差分。答案的判据是两者在明确容差内接近，不要求背某个小数。再把输入改成二十，观察解析梯度和差分都接近零，并解释这来自饱和，不能据此证明所有实现分支正确。


**练习五：矩阵梯度。** 使用本章 X、W、G 的数值，独立写三重循环计算 dW，再与矩阵表达式比较。完整参考如下。关键是外层枚举参数位置 d、f，内层沿所有样本 n 累加，体现每个权重被多条样本共享。

```python
slow_dW = np.zeros_like(W)
```

**练习六：softmax 平移不变性。** 对分数 $[1,2,3]$ 与 $[1001,1002,1003]$ 使用稳定实现，比较概率。答案应一致到浮点误差；如果直接指数计算后出现无穷与 NaN，说明没有利用平移等价性。不要把溢出后的 NaN 改成均匀分布，那会改变原问题。

```python
def stable_softmax(z):
    z = np.asarray(z, dtype=np.float64)
    shifted = z - z.max()
    p = np.exp(shifted)
    return p / p.sum()

np.testing.assert_allclose(stable_softmax([1,2,3]),
                           stable_softmax([1001,1002,1003]))
```

**练习八：重复 embedding ID。** 输入 $[2,2,2]$，上游三行分别为 $[1,0]$、$[0,2]$、$[3,4]$。答案只有第二号参数行非零，等于 $[4,6]$。既要用循环实现，也要用 `np.add.at` 实现，并检查其他行保持零。若错误实现只保留最后一行，说明没有做共享参数贡献累加。

**练习九：不等大小 microbatch。** 一个批次有四条样本，拆成一条和三条。参考答案应按各 microbatch 样本数加权其 mean loss 和 mean gradient，而不是简单各占一半。完整代码使用直线模型验证大 batch 与拆分累计一致。

```python
x = np.array([-2., -1., 1., 3.])
y = 2*x + 1
w, b = 0.4, -0.2
def grad_part(xp, yp):
    e = w*xp + b - yp
    return np.array([np.mean(e*xp), np.mean(e)])
whole = grad_part(x, y)
combined = (grad_part(x[:1], y[:1]) * 1
            + grad_part(x[1:], y[1:]) * 3) / 4
np.testing.assert_allclose(whole, combined)
```

**练习十：实现全局范数裁剪。** 输入多个形状不同的梯度数组，先合并统计平方和，再用同一缩放系数处理每一个数组。完整参考会拒绝非有限梯度，避免 NaN 被误当作可以裁剪的普通大值。

```python
def clip_global(grads, maximum):
    if maximum <= 0 or not np.isfinite(maximum):
        raise ValueError("finite positive maximum required")
    if not all(np.isfinite(g).all() for g in grads):
        raise ValueError("nonfinite gradient")
    norm = math.sqrt(sum(float(np.sum(g*g)) for g in grads))
    factor = min(1., maximum / max(norm, 1e-30))
    return [g * factor for g in grads], norm

clipped, norm = clip_global([np.array([3.]), np.array([4.])], 2.)
assert norm == 5.
np.testing.assert_allclose(np.concatenate(clipped), [1.2,1.6])
```

**练习十一：定位损失不下降。** 有四个候选错误：更新时用了加梯度、梯度每次都为零、目标右移了两次、评估前没有关闭随机 dropout。答案不能统称“调学习率”：第一项先检查一小步是否沿下降方向；第二项检查图是否断开和参数是否收到梯度；第三项打印输入与标签逐位置对应；第四项固定评估模式和随机条件。每种错误都应设计一个最小观察，而不是直接重跑完整训练。
