# M02　模型怎样学会：损失、链式法则与真正的反向传播

[本卷导航](README.md) · 前置：[M01](01-tokens-tensors.md) · 下一章：[注意力](03-attention.md)

你不需要先掌握整本数学分析。本章只要求理解函数“输入一些数，返回一些数”，并会对小矩阵做乘法。目标是独立判断一段训练循环到底更新了什么，为什么 loss 下降并不能直接证明模型有用，以及如何用数值实验检查自己写的梯度。

## 1. 参数、输入、激活、状态不要混在一起

在 `y=x*w+b` 中，`x` 可以是训练样本，`w,b` 是参数，`y` 是激活。训练改变参数，让同一类输入产生更合适的输出。推理通常冻结参数；它仍会产生新的激活、KV cache 或循环状态，但这不等于模型在线学习了新知识。

例如向 Agent 提供一段新资料，回答变好，可能只是资料进入上下文；重启会话后效果消失，并不能叫“修改了权重”。将对话保存到检索数据库是外部记忆；修改 embedding、投影矩阵才是参数学习。它们都能影响行为，却在持久性、成本、可撤销性上不同。

## 2. 从斜率理解导数

令 `f(w)=(2w-6)^2`。`w=1` 时输出 16；`w=1.01` 时输出 15.8404，说明往增大 w 的方向走能降低损失。导数是这种局部变化率的极限：`f'(w)=4(2w-6)`，在 w=1 时为 -16。梯度下降 `w_new=w-lr*f'(w)`，若学习率为 0.1，得到 2.6，损失为 0.64。

若学习率改为 1，就跳到 17，损失反而爆炸。梯度告诉你局部方向，不保证任意步长都好。真实模型的高维损失面更复杂，因此需要监测梯度范数、验证集、学习率和数值稳定性，而不是简单地重复 `backward()`。

数值差分不需要导数公式：

$$ f'(w)\approx\frac{f(w+\epsilon)-f(w-\epsilon)}{2\epsilon}. $$

但 ε 并非越小越好：太小会让两个相近浮点结果相减丢失有效位，太大又不再近似局部变化。检查 float64 小实验时，可以从 `1e-5` 开始，再试 `1e-4`、`1e-6`，观察结论是否稳定。

## 3. 链式法则是一张依赖图

写 `z=x*x`、`y=z+z+x`，在 x=2 时，y=10。沿两条 z 分支返回的梯度都要累加：`dy/dz=2`，`dz/dx=2x=4`，加上直接分支 1，所以 `dy/dx=9`。如果反向传播中使用赋值 `=` 而不是累加 `+=`，共享节点的贡献会被覆盖。

`Value` 实现了这个过程。每个节点记录：前向数值、当前梯度、依赖的子节点、局部反向函数。`backward()` 先按依赖建立拓扑顺序，再反向遍历。为什么不直接随便遍历所有节点？因为一个节点的完整梯度必须等所有下游贡献都回到它之后才能继续传给上游。

```python
x = Value(2)
z = x * x
y = z + z + x
y.backward()
# x.grad == 9
```

乘法节点 `out=a*b` 的局部规则是 `a.grad += b.data*out.grad`、`b.grad += a.data*out.grad`。加法节点分别复制上游梯度。`tanh` 节点使用 `1-tanh(x)^2`。这三种操作已足够构成小型神经网络的数学骨架。

注意本卷 `Value.backward()` 每次会清空整张图梯度，这是为初学者设定的明确语义。PyTorch 的叶子参数梯度默认会累积，因此训练循环通常需要 `zero_grad`。不要把一个教学实现的 API 习惯误当全部框架的行为。

## 4. 交叉熵为何等于“提高正确答案概率”

若一个位置有三种候选，模型概率为 `[0.2,0.3,0.5]`，正确标签是第 3 类，损失就是 `-ln(0.5)≈0.6931`。改成正确类概率 0.8，损失约 0.2231；概率越低，罚得越重。这里使用自然对数，单位是 nats/token；如果改用 log2，数值单位是 bits/token。比较报告时先确认单位。

令 logits 为 `z_j`，softmax 为 `p_j`，则单样本交叉熵对 logits 的梯度是 `p_j - 1[j=y]`。正确类梯度通常为负，梯度下降减去这个负数，就会提高它的 logit；其他类梯度为正，更新后会降低它们。

全零三类 logits 的概率都是 1/3，标签为第 3 类，梯度是 `[1/3,1/3,-2/3]`。三项和为零。这与 softmax 对整体平移不变一致：给所有 logits 加同一常数，不改变概率，也不应改变损失。

极端 logits `[1000,-1000]` 且正确类为第二类时，直接 `-log(softmax(...)[1])` 可能因概率下溢成零而变成无穷。稳定写法从 logits 计算 `logsumexp(z)-z_y`，得到有限的 2000。我们的 `cross_entropy` 先减最大值，再计算 log-sum-exp；测试明确覆盖这个情况。

## 5. 矩阵梯度与重复 embedding 的累加

若 `Y=XW`，已知损失对 Y 的梯度 `G`，则 `dW=XᵀG`、`dX=GWᵀ`。看形状就能帮助核查：`X:(N,D)`、`W:(D,V)`、`G:(N,V)`，所以 `XᵀG:(D,V)` 正好匹配参数 W。形状无法证明数学完全正确，但能快速排除大批错误。

Embedding 更特别。若输入 ID 为 `[1,1,3]`，表的第 1 行在前向用了两次，反向必须把两份梯度加到同一行。NumPy 的高级索引赋值 `grad[ids] += values` 对重复索引不等于逐项累加；本卷使用 `np.add.at`。这个例子说明：正确的数学公式仍可能被库的索引语义破坏。

每类参数至少抽查一个数值差分坐标。只检查输出层不够，因为下层可能仍有错误。`test_all_parameter_gradient_types` 对 embedding、两层权重和两个 bias 都进行检查，并专门让输入 token 重复。

## 6. 训练循环中的每一行承担什么责任

```python
logits = model(inputs)             # 用当前参数计算
loss = criterion(logits, targets)  # 定义本轮优化目标
optimizer.zero_grad()             # 清除上一轮梯度
loss.backward()                   # 求当前梯度，不更新权重
clip_grad_norm_(parameters, 1.0)   # 可选：限制异常大梯度
optimizer.step()                  # 真正修改权重
```

`backward()` 不是训练的全部，`eval()` 也不自动停止梯度记录。训练/评估模式控制 dropout、某些归一化层等行为；禁用 autograd 则是另一件事。推理代码需要同时理解这两种状态，避免把随机 dropout 误认为模型采样随机性。

验证集应在切窗口之前划分。若先生成大量相互重叠的窗口再随机拆分，训练集与验证集可能共享几乎完整的上下文，导致评估过于乐观。即使先切原始文本，本卷重复人工语法仍然具有高度同分布特征，因此只能作为训练机制实验，不能用验证 loss 宣称通用语言能力。

## 7. 实验、故障与完整解答

运行 `python -m labs.models.run_lab autograd` 和 `python -m labs.models.run_lab softmax`，然后执行 `python -m unittest tests.test_models_core.LanguageProjectTests -v`。

1. **标量导数。** 对 `y=x*x+x` 令 x=-2，手算与运行比较。答案：y=2、梯度=-3。若得到 -2 或 1，检查分支累加。
2. **共享节点故障。** 把 `Value` 中一个 `+=` 改为 `=`，预测哪类测试会失败。答案：重复使用 x 或 z 的路径；只用单链式运算的测试可能仍通过，说明测试必须包含分叉计算图。
3. **CE 梯度。** logits 全零、四类、标签 1，写出梯度。答案：`[.25,-.75,.25,.25]`；两个样本取平均时每个样本梯度还要除 2。验收：与差分误差小于 `1e-6`。
4. **学习率实验。** 在 tiny LM 中分别用 0.03、0.3、3.0，固定数据与 seed，绘制或记录前后 loss。参考分析不是“最大值一定发散”，而是比较步长、裁剪、非线性和批次噪声；只凭一次下降不能判定普适最优值。
5. **累积梯度。** 两个小批次等大，分别算 mean loss 后各除 2，再累积梯度，验证与合并大批次梯度一致。参考：若直接相加，梯度会扩大两倍；批次不等大时应按样本数加权。
6. **隔离数据泄漏。** 构造唯一标识行，将重叠窗口随机分组与先切文本两种方案比较交集。参考验收：报告同一原始位置是否跨组，而不是仅比较窗口对象地址。数据划分是学习协议的一部分。
