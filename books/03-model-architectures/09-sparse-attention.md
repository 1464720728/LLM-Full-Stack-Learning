# M09　局部、块稀疏与压缩注意力：哪些连接可以省略

[本卷导航](README.md) · 前置：[M03](03-attention.md) · 下一章：[线性注意力](10-linear-attention.md)

“稀疏”必须说明稀疏在哪：FFN 专家选择、token-token 连接、权重矩阵零值、路由索引，都是不同问题。本章只研究注意力连接。你的第一项能力是把一种策略画成允许矩阵，第二项能力是不用完整分数矩阵实现它，第三项能力是证明它和**同一 mask 的稠密参考**等价。

## 1. Sliding window 的精确定义

本卷 window=3 表示当前位置最多读取自己及前两个位置。位置 i 允许的 j 满足 `j<=i` 且 `j>i-window`。对于 T=5，允许关系逐行为 `[0]`、`[0,1]`、`[0,1,2]`、`[1,2,3]`、`[2,3,4]`。

有的库把 window 参数定义为只包含过去的数量，有的同时给左右窗口，有的把当前 token 单独计算。因此“window=128”不能脱离文档直接比较。实现前先写集合关系，能减少 off-by-one 错误。

局部窗口每层只看邻近位置，但多层叠加后有效依赖可以传播得更远。例如两层、每层向前看两步，最高层当前位置最多间接依赖四步前的表示；具体范围还受边界、全局层和其他结构影响。这不等同直接读取所有历史，信息在逐层压缩中可能损失。

## 2. 加入全局 token 的代价与收益

`local_global_mask` 可让每隔若干位置出现的 global key 始终被后续位置读取。这样旧信息有长程通路，但 global token 的表示能否承载所需内容取决于训练。人工指定“每第 8 个 token 全局”只是结构演示，不自动解决检索精度。

允许集合是局部窗口与全局 key 的并集，因此重复位置只能计算一次。若直接分别算两个 softmax 再把输出相加，一般不等于在并集上做一次 softmax；两个子集分别归一化会改变相对权重。本卷把并集先表示为布尔 mask，再取索引。

手算 T=4、window=2、global_stride=3：位置3局部能看2、3，全局能看0、3，合并得到0、2、3，不是四项记录。重复计入3会人为增加它的权重。

## 3. 稠密 mask 参考和真正稀疏执行

把完整 `(T,T)` scores 算出来再设大量位置为负无穷，数学上是稀疏连接，计算上却仍进行了很多本可以省掉的点积。我们的 `sparse_attention` 对每行先取得允许的 key 索引，只计算这些点积，故返回 `visited` 作为实际计算的连接数。

它使用 Python 循环，在 CPU 小矩阵上不一定比 NumPy 的大矩阵乘法快。减少 FLOPs 不保证实际耗时减少，尤其当调度开销、内存访问和向量化利用率变化时。这个实现负责算法正确性，不负责宣称性能。

块稀疏把连接按矩形 tile 分组，利于 GPU 执行。它可能计算少量块内本来无效的位置，换取更规整的访存与矩阵指令。这是算法稀疏度和硬件效率之间的实际权衡。算子卷会让你将这种集合关系落到 block pointer 与 mask 上。

## 4. 压缩不是简单删除

除了选择少量原 token，还可以先把历史块压缩成摘要，再对摘要 attention。我们的 `compressed_sparse_attention` 用每块 K/V 的均值作为摘要，再根据当前 query 对压缩 key 的分数选 top-k；局部最近 token 仍保留原始值。

这不是 CSA 的完整实现。真实压缩器可以有学习参数、重叠窗口、专门的 indexer、位置编码、量化和跨层复用。我们选择均值是为了让学生能手算并观察信息损失：如果两个值是 +1 和 -1，均值变成0，查询再想恢复其中某个原值通常已经不可能。

压缩块的时间边界必须严格：只有块的最后位置已经在允许历史内，摘要才可被读取。假设块 `[4,5]`，当前位置为4，不能为了方便提前用完整块平均值，否则位置5的信息泄漏。测试改动最后 token 后检查所有更早输出不变，覆盖这种常见错误。

本实验还避免局部原始记录与压缩记录覆盖同一历史区间，便于定义单一语义。真实模型可能有意让它们重叠，并通过训练学习利用两种表示；那是另一种明确设计，不能把本实验的无重叠约定当普遍要求。

## 5. Top-k indexer 和核心 attention 不必相同

Indexer 的职责是快速筛选候选，core attention 再精确计算所选记录的权重。Indexer 可以使用更低维表示或不同打分函数。筛选错误会让重要记录根本到不了核心 attention，所以后者再精确也无法读取被漏掉的证据。

这与 RAG 中先召回再重排有结构上的相似，但模型内部 attention indexer 和外部文档检索不是同一层系统。外部检索结果作为新 token 输入模型；内部稀疏选择直接决定某层读哪些历史状态。可用类比帮助理解，不可混淆接口。

评估 indexer 应同时测选择质量、计算成本、状态存储、训练稳定性和最终任务表现。只测“每步选了多少块”无法说明模型能力；只测最终分数也难定位是压缩、索引还是核心计算带来的损失。

## 6. 实验流程与诊断

```bash
python -m labs.models.run_lab sparse
python -m labs.models.run_lab compressed
python -m labs.models.compare
```

先看 mask，再比较同 mask 稠密与 gather 输出，最后记录 visited。压缩版一般不会与原始全 attention 输出相等，这是预期，因为函数变了。若要检查压缩版正确性，应建立同一压缩规则的显式参考，而不是把全部误差叫 kernel bug。

常见故障：把 mask 方向反过来；window 参数少算当前项；global key 不受因果限制；选中索引未与 value 同步排序；空集合 softmax 出 NaN；压缩块包含未来；选择 top-k 时拿了最小值。这些都可以构造 3–8 个 token 的小例子发现，不需要占用 H100。

## 7. 练习与参考解

1. **画 6×6 mask。** window=2、global_stride=3。验收：每行只含过去与当前，位置5允许0、3、4、5。若出现6或未来项，先修索引。
2. **连接数计算。** 无全局项、T=5、window=3，连接数1+2+3+3+3=12；完整因果连接15。答案必须按本章包含当前 token 的定义计算。
3. **验证两 softmax 不等价。** 构造一个局部 score=0 和一个全局 score=2。并集权重约0.1192/0.8808；分开 softmax 后每项权重都是1。参考：需要统一归一化或正确合并在线统计量。
4. **实现块稀疏。** 按2×2 tile 标记允许块，再逐块累积 scores。验收：与自己定义的 block mask 稠密参考一致；报告块内额外连接数，不把它假装成原滑窗精确连接数。
5. **压缩泄漏实验。** 故意让未完成的块参与均值，然后改变未来 token。参考：更早输出发生变化，因果不变量测试应失败；修复条件是整个压缩块必须完成，或压缩器只使用已到达前缀。
6. **Indexer 召回。** 用全 attention 权重最大的位置作自造参照，统计压缩 top-k 是否保留相关块。参考：这不是任务真实标签，只是分析 oracle；报告 k 增加时召回变化和连接数，避免单一“越稀疏越好”结论。
7. **真实源码拓展。** 对来源表中的 DeepSeek-V4/4.1，分别定位压缩、索引、局部支路和跨层复用，而不是把全部概括为 MLA。完成后写一张状态表：每层存什么、哪层重算、哪层复用。部署前再按真实配置算容量。

通过标准：你能写出不同稀疏模式的精确集合定义，独立实现 gather 版，并利用因果性测试抓到压缩引入的泄漏。
