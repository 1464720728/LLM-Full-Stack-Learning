# M01　从一个汉字到一块张量：模型真正接收什么

[本卷导航](README.md) · 下一章：[微分、损失与训练](02-gradients-training.md)

本章的目标是让你看到 `x = embedding[token_ids]` 时，能解释每个对象是什么、每个维度表示什么，以及这一步为什么既不是搜索词义，也不是把文字直接塞给神经元。先完成基础卷的 Python 列表、函数与 NumPy 数组。仅需 CPU，数据都在代码中，不下载模型。

## 1. 把五种不同的对象分开

人读到的是字符串，例如 `猫 eats.`。计算机保存这个字符串时，通常需要一种字符编码。UTF-8 把字符表示为字节序列：英文字符经常占一个字节，汉字通常占三个字节，部分表情占四个字节。字符、字节、token 三者不能混为一谈。一个 tokenizer 可以把几个字节合并为一个 token，也可能把一个汉字拆成多个 token；因此不能把“中文一个字一个 token”当容量计算的定律。

Tokenizer 的输出是**整数索引**。索引 8 和索引 9 的数字接近，不意味着对应的文字语义接近；给整个词表重新编号、同时重排 embedding 和输出层，模型表达的函数可以保持不变。整数只是地址。真正可学习的表示来自 embedding 表。

假设词表只有 `['猫','狗','跑','坐']`，每个 token 用三个浮点数表示，embedding 表形状就是 `(4,3)`：

```text
猫 → 第0行 → [ 0.2, -0.1, 0.5]
狗 → 第1行 → [ 0.3,  0.0, 0.4]
跑 → 第2行 → [-0.2,  0.8, 0.1]
坐 → 第3行 → [ 0.1,  0.7, 0.2]
```

输入 `猫 跑` 变成 `[0,2]`，索引表取两行，得到 `(2,3)`。这些数值是本章自造的，不能据此断言某一维表示“动物”、另一维表示“动作”。真实表征通常是分布式的，单一坐标没有稳定的人工命名。

之后模型让每个位置的表示结合上下文。最初“猫”的向量只由 token ID 决定；经过注意力之后，“猫跑”和“猫坐”中的同一个位置可能获得不同隐藏状态。最后输出投影把每个隐藏状态变成词表上每一个候选 token 的分数，即 logits。Logits 是未归一化实数，softmax 才把它变成和为 1 的概率向量。采样器从这个分布挑选下一个 token。

## 2. 一步一步追踪张量形状

本卷先约定 `B` 是批次、`T` 是序列长度、`D` 是隐藏宽度、`V` 是词表大小、`H` 是头数。惯例不是自然法则；不同库会把维度换顺序，因此读代码必须读操作，而不是只凭变量名猜。

| 对象 | 典型形状 | 元素的意义 |
|---|---|---|
| `token_ids` | `(B,T)` | 每个样本每个位置的词表索引 |
| `embedding_weight` | `(V,D)` | 可训练的 token 表示表 |
| `x` | `(B,T,D)` | 每个位置当前的隐藏表示 |
| `output_weight` | `(D,V)` | 把隐藏表示投影到候选词表 |
| `logits` | `(B,T,V)` | 每个位置对下一 token 的分数 |
| `targets` | `(B,T)` | 每个位置应该预测的真实 token |

取 `B=2,T=4,D=3,V=5`。`x @ W` 只收缩最后一维，因此 `(2,4,3) @ (3,5)` 得到 `(2,4,5)`。这不是分别给两个样本写两个模型；同一组权重在所有位置、所有样本上共享。共享参数是神经网络能够处理不同长度输入的重要原因之一。

若把 `x.reshape(B*T,D)` 后再乘 `W`，再恢复形状，数值应相同；但如果先错误地交换 `T`、`D` 再硬 reshape，结果虽然维度仍可能“凑得上”，元素语义却已经改变。形状正确只是必要条件，不是充分条件。练习中必须使用 `np.arange` 这样的可追踪值检查布局，随机数容易掩盖错误。

## 3. reshape 和 transpose 为什么不是同一件事

`reshape` 重新解释线性元素序列的分组方式；`transpose` 改变坐标轴对应关系。以 `(T,D)=(3,8)`、`H=2` 为例，一个 token 的八个通道应分成两个四维头：

```python
x = np.arange(24).reshape(3, 8)
heads = x.reshape(3, 2, 4).transpose(1, 0, 2)
# heads.shape == (2, 3, 4)
# 第0个头：取每个 token 的前4个通道。
```

如果直接 `x.reshape(2,3,4)`，第一头会把前一个 token 的后四个通道误当作下一位置，头和时间混在一起。很多“模型不报错但结果很差”的问题正来自这种静默错误。`split_heads` 与 `merge_heads` 是一对互逆函数；单元测试先验证二者能精确恢复输入，然后才测试注意力公式。

数组还具有 dtype、strides、device 等属性。`shape` 描述索引空间；dtype 决定每个元素怎样编码；strides 描述各轴索引增加一时，内存地址跳多少字节；device 表示数据在哪个计算设备。两个同形状张量可以有不同 strides。转置通常能形成视图，而不立即搬数据；需要连续内存的算子可能随后产生复制。算子卷会沿这条线解释为什么“只是换个维度”也会影响性能。

## 4. Byte tokenizer 与 BPE 的可观察差别

运行：

```bash
python -m labs.models.run_lab tokenization
python -m labs.models.run_lab tensor_shapes
```

`ByteTokenizer` 的词表固定为 256，编码可逆，但它不追求模型训练效率。一个 token 对应一个 UTF-8 字节，所以汉字可能被拆开。必须等完整字节串再严格解码；把一个汉字的第一个字节单独 decode 会抛错。这也解释流式文本输出为什么可能需要增量解码器，不能把任意 token 片段直接当完整 Unicode 字符串。

`bpe_train` 是字符级合并演示：统计相邻符号对，选频次最高的一对，把它们连接起来，重复若干次。频次相同用确定性的字典序打破平局，使实验可复现。真实 tokenizer 还涉及预分词、字节编码、规范化、special tokens、已有词表以及固定合并规则；本实验没有复刻这些产品行为。

手算 `abab`：最初符号为 `a,b,a,b`，相邻对 `ab` 出现 2 次，`ba` 出现 1 次。先合并 `ab` 得到两个 `ab`。若继续训练，合并 `(ab,ab)` 得到一个符号 `abab`。这不能说明更短 token 序列一定更好：词表越大，embedding 和输出投影越大；罕见长词也可能缺少足够训练统计。

## 5. 数据与标签必须错开一格

给定序列 `[猫,跑,了,句号]`，自回归训练可以使用输入 `[猫,跑,了]`、标签 `[跑,了,句号]`。位置 0 的输出预测位置 1，而不是复述位置 0。如果错用同位置 token 作为标签，模型可以学到把自己的输入复制出去，loss 会下降，但不具备你以为训练出来的续写能力。

长度 `T` 的训练块产生 `T` 个监督位置，并不要求生成过程同时生成 `T` 个新 token。训练时真实前缀已知，可以通过因果 mask 一次并行计算所有位置；生成时未来 token 未知，下一步输入依赖本步采样结果，必须迭代。这是以后 prefill 与 decode 讨论的起点。

Padding 也不能直接算作普通标签。不同长度样本组成批次时，补齐部分需要明确的 attention mask 和 loss mask。前者控制可见信息，后者控制哪些位置参与损失，二者解决不同问题；只遮掉损失不一定遮掉信息泄漏。

## 6. 递进练习与参考解

1. **手算字节与字符。** 记录 `len('猫a')`、UTF-8 字节数和本实验 token 数。验收：分别为 2、4、4。解释编码层与分词层的关系；不能据此推广到其他 tokenizer。
2. **写 embedding 查表。** 给上述四行表和 `[0,2,0]`，不用循环生成 `(3,3)`。参考：`table[np.array([0,2,0])]`；第 0、2 行必须相同。然后把 ID 置为 4，确认越界而不是静默取某个 token。
3. **抓布局错误。** 实现错误的 `reshape(2,3,4)`，与正确 `split_heads` 比较。参考诊断：正确 `heads[0,1]` 是 `[8,9,10,11]`，错误版本是 `[4,5,6,7]`。写测试断言这个具体坐标，而非只断言形状。
4. **设计词表重编号实验。** 将词表置换，重排 embedding 行和输出投影列，同时改 token IDs。验收：对应文字的概率相同。参考步骤：构造旧 ID→新 ID 的映射，再按逆置换生成新参数表；只重排输入表而不重排输出层会改变标签语义。
5. **实现训练窗口。** 输入整数 `0..9`，上下文长度 3。参考第一个样本为 `[0,1,2]→3`，最后一个为 `[6,7,8]→9`，共 7 个窗口。与逐位置 Transformer 标签方案比较：一个预测单点，一个窗口产生多个预测位置，二者都能训练 LM。
6. **拓展：检查实际 tokenizer。** 在自己可下载的小模型中记录 tokenizer 文件、词表长度、special token IDs 和三段中英文编码；不下载大权重。验收是可复现报告，不是“中文大概多少 token”。参考读取路径从模型卡到 tokenizer 配置，再验证 encode/decode，遇到非可逆规范化要记录原因。

完成后你应能在白纸上画出字符串→字节/分词→ID→embedding→隐藏状态→logits→概率的全链路，并能解释五个对象的形状。若仍把 token ID 当连续语义值，先不要进入注意力公式。
