# M05　写出一台完整的稠密自回归解码器

[本卷导航](README.md) · 前置：[M04](04-original-transformer.md) · 下一章：[KV 与 GQA](06-kv-gqa.md)

你已经有 attention 和 encoder-decoder，现在要把现代常见 decoder-only 结构从头连起来。本章的“稠密”主要指每个 token 都执行该层完整的 FFN 参数路径，不是说 attention 必须全连接，也不等于所有矩阵元素都非零。一个模型完全可以稠密 FFN 配合局部注意力。

## 1. 删掉 encoder 后，任务怎样统一

Decoder-only 把任务说明、用户问题、已有回答和必要分隔标记组织到一条序列里。模型始终预测下一 token。问答、翻译、写代码可以共享这套生成接口，但 prompt 组织、训练数据、special token 和 loss mask 会影响具体行为。

这不意味着模型内部主动识别了聊天协议。`system`、`user` 等结构通常先经 chat template 编码为具体字符串或特殊 token，再由 tokenizer 变成 ID。把同一条消息用两个不匹配模板发送给同一权重，输入 token 序列就变了。读模型结构和读 Harness 协议必须在这个接口处接起来。

本卷 `TinyDecoder` 不实现任何厂商 chat template，直接接受整数序列。它使用随机权重，只证明计算路径正确；它会产生 logits，却不应该被期待回答自然语言。下一项目才训练一个小模型。

## 2. PreNorm 与残差的执行顺序

每层做：

$$ U=X+\operatorname{Attention}(\operatorname{RMSNorm}(X)), $$
$$ Y=U+\operatorname{SwiGLU}(\operatorname{RMSNorm}(U)). $$

X 通过残差直接保留，子层学习在这条流上增加新的变换。PreNorm 的梯度存在绕过子层的恒等路径，但这不意味着深层训练完全没有稳定性问题。残差幅度、初始化、归一化、优化器等仍会共同影响信号传播。

`rms_norm` 计算 `x / sqrt(mean(x*x)+eps)`，不减均值。对 `[1,3]`，均方根为 √5，输出约 `[0.4472,1.3416]`；LayerNorm 的输出则约 `[-1,1]`。两者各有定义，不能因“都叫归一化”互相替换而保持 checkpoint 等价。

真实 RMSNorm 常有可训练逐通道权重；我们的 NumPy 机制版省略该参数，注明为简化。若要加载真实权重，就必须补全 norm 的精度、epsilon、gain、bias 等细节，不能仅把矩阵塞进类似形状的类。

## 3. SwiGLU 不是“多乘一个 sigmoid”那么简单

给输入 x，同时产生 gate 和 up 两条投影：

$$ g=\operatorname{SiLU}(xW_g),\quad u=xW_u,\quad y=(g\odot u)W_d. $$

SiLU 为 `z*sigmoid(z)`。它既不是硬开关，也不是只能在 0–1 之间的门值；负输入可产生小的负输出，正大输入近似线性。`g` 与 `u` 做逐元素乘法，再用 down 投影回隐藏维度。

若 D=4、中间宽度 F=8，则 Wg、Wu 各有 32 个参数，Wd 有 32 个，共 96 个，忽略 bias。普通两层 ReLU FFN 若中间宽度也是 8，则只有 64 个。公平比较架构不能只让“中间宽度相等”；要明确比较参数量、FLOPs，还是固定宽度的表现。

手算 x 为 `[1,0]`，Wg、Wu 都取单位矩阵、Wd 也为单位矩阵，那么输出是 `[SiLU(1),0]≈[0.7311,0]`。这只是函数检查，不代表这种初始化能训练出好模型。

## 4. RoPE 是对匹配空间做旋转

对一对通道 `(a,b)`，位置 p 对应角度 θ，旋转为 `(a cosθ-b sinθ, a sinθ+b cosθ)`。旋转保持二范数，但改变与其他位置向量的点积。若 Q、K 使用相同频率体系，二者旋转后的内积只依赖位置差与原始向量的关系，这提供相对位置信息。

本卷 `rope` 按相邻通道成对旋转。不同模型可能采用相邻配对或半区配对，也可能只旋转部分通道。两种布局如果对应权重没有同步转换，不能混用。读代码时应检查切片方式，而不是只看到函数名 RoPE 就认为兼容。

测试 `test_rope_relative_inner_product` 比较位置 `(4,9)` 与 `(0,5)` 的点积，它们具有相同距离，应在误差范围内一致。另一个测试验证范数保持。两个测试都需要；只保持范数并不能证明你采用了正确的位置频率。

RoPE 基数、缩放和长上下文外推会影响模型行为。不能把 `max_position_embeddings` 改大就认为模型学会了更长上下文；服务端允许分配长度，与训练后的长程质量是两个问题。对新的 RoPE scaling 策略应同时阅读训练报告与实现配置。

## 5. 一层完整的形状账本

以默认 `dim=16,heads=4,kv_heads=2,hidden=32` 为例：

| 阶段 | 形状 |
|---|---|
| 输入 x | `(T,16)` |
| q 投影 | `(T,16)`→`(4,T,4)` |
| k/v 投影 | 各 `(T,8)`→`(2,T,4)` |
| GQA 输出 | `(4,T,4)` |
| 合并与 output 投影 | `(T,16)` |
| gate/up | 各 `(T,32)` |
| down 后 | `(T,16)` |
| 最后词表投影 | `(T,32)`，因为本实验 vocab=32 |

模型的 `forward()` 按层读取同一完整序列；`step()` 一次处理一个新 token 并返回 cache。它们不是两个不同模型，必须共享参数且产生等价 logits。本卷没有用“生成结果看起来一致”替代浮点比较，而是逐位置比较完整 logits。

注意 Q 的头数与隐藏维度不能随意整除。当前实现要求 D 能整除 heads、heads 能整除 kv_heads、head_dim 为偶数以使用成对 RoPE。构造时主动校验这些条件，比等到矩阵乘法里出现难懂报错更适合学习与工程维护。

## 6. 读源码时区分配置、参数与执行

配置决定尺寸与选用的结构；参数决定这个结构中的具体函数；执行路径决定如何在当前输入和硬件上计算。两个模型拥有同样 config，只能说明许多结构超参数相同，不能说明权重相同或能力相同。反过来，两个实现类名字不同，也可能在同一组参数下计算数学等价的函数。

推理框架可能把三个投影合成一块参数，执行 fused QKV GEMM；也可能分开存储。它还可能把 norm 与 residual add 融合成一个 kernel。源码模块边界与论文方框并非一一对应。阅读方法是追踪张量和参数，而不是只找同名类。

一个有效练习是给每行代码标三种颜色：改变模型函数的运算、改变布局的运算、改变执行效率的运算。例如换 ReLU 为 SiLU 会改变函数；transpose 改布局；在相同精度语义下把连续投影合并通常主要改变执行组织。

## 7. 练习与参考解

运行 `python -m labs.models.run_lab decoder`、`python -m labs.models.run_lab rope`。

1. **参数计算。** 默认一个 block 的 q/k/v/o 参数分别为 256/128/128/256；三条 FFN 投影共 1536，总 2304。两层加 embedding 512 与 output 512，总 5632。验收：与程序输出一致；norm gain 未包含，因为机制版省略了它。
2. **RMSNorm 手算。** 输入 `[3,4]`，忽略 ε，分母 √12.5，输出约 `[0.8485,1.1314]`。比较向量均值是否归零。答案：不归零，因为没有去均值。
3. **改激活函数。** 在副本把 SiLU 替换为 ReLU，保持权重与 seed。验收：形状和因果性仍通过，logits 不再相同。参考结论：结构修改不等同数值优化，不能沿用同一正确性 oracle。
4. **故意破坏 RoPE offset。** 在 step 中固定 position=0。验收：full/cache 测试失败，单步 position 0 测试可能仍通过。说明必须覆盖长度大于 1 的路径。
5. **加一层。** 将 layers 从 2 改成 3，解释参数增加量与 cache 列表长度。答案：新增一个 block，cache 中每层独立；共享同一 cache 张量会混淆不同投影空间。
6. **实现权重共享输出头。** 将 output 设为 embedding.T。验收：参数计数扣除独立输出矩阵，前向仍能运行。参考分析：词表与隐藏维度允许这种绑定，但对已有独立训练权重直接绑定会改变模型。
7. **源码迁移。** 找一个已核实小型开源 decoder 的 config，列出与本实现的差异：位置、norm、bias、头数、激活、tie embeddings、特殊输出处理。交付一张逐项表；“大体都是 Transformer”不算完成。

通过标准是能独立实现前向并用 shape、参数量、因果性与 cache 等价四种证据验证它。训练能力在 M15 验收。
